## 람다식

자바에서 함수형 프로그래밍(functional programming)을 구현하는 방식

매개변수로 받은 자료만을 사용하도록 만든 함수

<br/>

### 문법 1

```java
public String hello() { 
   return "Hello World!"; 
}

// 예시 
() -> "Hello World!";
```

<br/>

- 익명 함수 만들기
  
- 두 수를 입력 받아 더하는 add() 함수
- 함수 이름, 반환 형을 없애고 → 를 사용

```java
int add(int x, int y) {
	return x + y;
}

// 예시
(int x, int y) -> {return x + y;}
```

<br/>

### 문법 2

```java
매개변수(하나인 경우) 자료형과 괄호 생략하기
str -> {System.out.println(str);}

매개변수가 두개인 경우 괄호를 생략할 수 없음
x, y -> {System.out.println(str);} // 에러 발생

중괄호 안의 구현부가 한 문장인 경우 중괄호 생략
str -> System.out.println(str);

중괄호 안의 구현부가 한 문장이라도 'return' 이 있다면 중괄호 생략 X
str -> return str.length(); // 에러 발생

중괄호 안의 구현부가 반환문이 하나라면 return 과 중괄호 모두 생략
(x, y) -> x + y; // 두 값을 더하여 반환함.
str -> str.length(); // 문자열의 길이를 반환함.
```

## 함수형 인터페이스

- 람다식을 선언하기 위한 인터페이스
  
- 익명 함수와 매개 변수만으로 구현되므로 단 하나의 메서드만을 가져야 함
- @*FunctionalInterface* 어너테이션 사용해주기.


<br/>

### 예제1)

```java
@FunctionalInterface
interface MyNumber {

	int getMaxNumber(int num1, int num2);
}

class aaa {
	public static void main(String[] args) {

		// 이렇게 하는 이유.
		// 함수명 인터페이스는 메서드를 딱 하나만 선언 해야 되는 것이다.
		// 만약 MyNumber 인터페이스에서 int getaaaa(int x, int y);
		// 이렇게 선언을 했다면 이 코드에서 에러가 발생 하는 것이다.
		// 왜?? 인터페이스에서 어떤 걸 사용해야 될지 모르기 때문인 것이다.
		// 그리하여 함수명 인터페이스는 메서드를 딱 하나만 선언 해야 한다.
		// 인터페이스를 구별하기 위해 @FunctionalInterface 어너테이션을 사용하자.
		MyNumber maxNum = (x, y) -> (x >= y)? x: y;
		//	    매개변수 받는구간 //  리턴 한다는 구간
		
		int max = maxNum.getMaxNumber(10, 20);
		System.out.println(max);

	}
}

출력값.
20
```

## 람다식으로 메서드를 구현하고 호출하면 내부에서 
익명 클래스가 생성됨.

- 자바는 객체지향 프로그램이므로, 객체 없이 메서드가 호출 될 수가 없다.
    - 즉, 객체가 생성되야 메서드가 호출된다.
    
- 람다식으로 메서드를 구현하고 호출하면 내부에서 익명 클래스가 생성됨

```java
MyNumber aaa = new MyNumber() {
			
   @Override
   public int getMaxNumber(int num1, int num2) {
				
       // (x, y) -> (x >= y)? x: y;
       return 0;
   }
};
```

### 에러 코드 수정.

함수형 인터페이스 사용.

```java
@FunctionalInterface
interface MyLambdaFunction {
    int max(int a, int b);
}

public class Lambda {
    public static void main(String[] args) {
        MyLambdaFunction lambdaFunction = (int a, int b) -> a > b ? a : b;

        System.out.println(lambdaFunction.max(3, 5));
    }
}
```

## 함수를 변수처럼 사용하는 람다식

변수처럼 사용하는 람다식은 위에 했던 코드들을 말한다.

그리고 이제 매개변수로 전달하는 람다식 하고, 반환 값으로 쓰이는 람다식을 보자.

```java
@FunctionalInterface
interface PrintString {

	void showString(String str); // 스트링을 출력해내는 일

}

class aaa {
	public static void main(String[] args) {

		PrintString lamdbaPrint = str -> System.out.println(str);

		// 변수로 출력.
		lamdbaPrint.showString("변수로 출력하기!!");

		// 매개변수로 출력하기.
		showMyString(lamdbaPrint);

		// 리턴값으로 출력하기.
		// 매개변수가 익명 객체가 만들어져서 showString() 매개변수로 
		// 들어갈때 리턴값 출력 22 가 먼저 들어가기 때문에 
		// "리턴값 출력 22" 부터 출력 되는 것이다.
		PrintString reStr = returnPrint();
		reStr.showString("리턴값 출력 22");
	}

	public static void showMyString(PrintString lambda) {

		lambda.showString("매개변수로 출력하기!!");

	}

	public static PrintString returnPrint() {
		return s -> System.out.println(s + "리턴값 출력 11");
	}

}
```

## 궁금증!

```java
람다를 두 번 만들면 객체가 두 개 생기나
```

경우에 따라 다르다.

```java
static Runnable makeStateless() { return () -> {}; }
static Runnable makeCapturing(int n) { return () -> { int x = n; }; }
```

<br/>

### 결과

```java
상태 없는 람다 두 개가 같은 객체? true
값을 캡처한 람다 두 개가 같은 객체? false
```

<br/>

바깥 값을 안 쓰는 람다는 한 번만 만들어서 재사용한다.

들고 갈 상태가 없으니 여러 개일 이유가 없는 것이다.

<br/>

앞의 싱글톤 패턴 글에서 본 것과 같은 발상이다.

`무상태면 하나만 있어도 된다.`

<br/>

값을 캡처하면 그 값마다 달라야 하니 새로 만든다.

## invokedynamic 이라는 명령이 쓰인다

바이트코드를 보면 람다 자리에 이 명령이 있다.

```java
invokedynamic #2, 0    // InvokeDynamic #0:run:()Ljava/lang/Runnable;
```

<br/>

앞의 익명 글에서 본 대로 익명 클래스는 `.class` 파일이 만들어지는데,

람다는 `이 자리에서 이런 걸 만들어라` 는 지시만 바이트코드에 남는다.

<br/>

실제로 만드는 것은 `LambdaMetafactory` 가 실행 중에 한다.

<br/>

그래서 자바 8에서 람다를 넣으면서 바이트코드 스펙을 안 바꿔도 됐다.

`invokedynamic` 은 자바 7에 이미 있던 명령이기 때문이다.

## 함수형 인터페이스여야 한다

메서드가 하나뿐인 인터페이스만 람다로 쓸 수 있다.

```java
@FunctionalInterface
public interface Runnable {
    void run();
}
```

<br/>

`@FunctionalInterface` 는 없어도 된다. 있으면 컴파일러가 검사해줄 뿐이다.

메서드를 하나 더 추가하면 컴파일 오류가 난다.

<br/>

`default` 와 `static` 메서드는 개수에 안 들어간다.

```java
@FunctionalInterface
public interface Comparator<T> {
    int compare(T o1, T o2);                    // 추상 메서드는 하나

    default Comparator<T> reversed() { ... }    // 이건 세지 않는다
    static <T> Comparator<T> naturalOrder() { ... }
}
```

<br/>

앞의 인터페이스의 Default Method 글에서 본 그 기능 덕분에

`Comparator` 에 `reversed()`, `thenComparing()` 을 붙이면서도 람다로 쓸 수 있는 것이다.

<br/>

## 표준 함수형 인터페이스를 외우기보다

이름 규칙만 알면 된다.

```java
Supplier<T>       - 받는 것 없이 준다        () -> T
Consumer<T>       - 받고 안 준다             T -> ()
Function<T, R>    - 받고 준다                T -> R
Predicate<T>      - 받고 boolean 을 준다      T -> boolean
Runnable          - 받지도 주지도 않는다      () -> ()
```

<br/>

앞에 `Bi` 가 붙으면 인자가 두 개다.

```java
BiFunction<T, U, R>
BiConsumer<T, U>
```

<br/>

`Int`, `Long`, `Double` 이 붙으면 박싱을 피하는 버전이다.

```java
IntPredicate       - int -> boolean.  Predicate<Integer> 와 달리 박싱이 없다
ToIntFunction<T>   - T -> int
```

<br/>

앞의 오토박싱 & 언박싱 글에서 본 그 비용을 피하려고 따로 만든 것이다.

<br/>

## 메서드 참조로 더 줄일 수 있다

```java
x -> x.getName()        ->  Member::getName
x -> System.out.println(x)  ->  System.out::println
x -> new Member(x)      ->  Member::new
```

<br/>

네 가지 형태가 있다.

```java
정적 메서드     Integer::parseInt
인스턴스 메서드  System.out::println      (특정 객체의)
타입의 메서드    String::length           (호출 대상이 인자가 된다)
생성자          ArrayList::new
```

<br/>

세 번째가 헷갈린다.

```java
list.stream().map(String::length)
// 는 사실
list.stream().map(s -> s.length())
```

<br/>

인자로 들어온 것이 호출 대상이 되는 형태다.

## 람다가 항상 좋은 건 아니다

디버깅이 불편하다.

```java
at La.lambda$test$0(La.java:20)
```

<br/>

스택 트레이스에 `lambda$메서드명$번호` 로 나온다.

같은 메서드에 람다가 여럿이면 어느 것인지 세어봐야 한다.

<br/>

중단점을 걸기도 애매하다. 한 줄에 여러 람다가 있으면 더 그렇다.

<br/>

그리고 체크 예외를 못 던진다.

```java
list.forEach(x -> {
    Files.readString(Path.of(x));      // IOException. 컴파일 오류
});
```

<br/>

`Consumer.accept` 가 `throws` 를 선언하지 않았기 때문이다.

<br/>

앞의 체크 예외, 언체크 예외 글에서 본 그 문제라,

감싸서 런타임 예외로 바꾸는 코드가 붙게 된다.

```java
try {
    Files.readString(Path.of(x));
} catch (IOException e) {
    throw new UncheckedIOException(e);
}
```

<br/>

이러면 짧게 쓰려고 람다를 썼는데 더 길어진다.

<br/>

## 그래도 얻는 게 크다

앞의 스트래티지 패턴 글에서 본 대로,

전략 하나 만들려고 클래스를 만들던 것이 한 줄이 됐다.

```java
Collections.sort(list, new Comparator<Member>() {
    public int compare(Member a, Member b) {
        return a.getName().compareTo(b.getName());
    }
});
```

```java
list.sort(Comparator.comparing(Member::getName));
```

<br/>

여섯 줄이 한 줄이 된 것이다.

`동작을 값처럼 넘긴다` 는 게 자바에서 처음 자연스러워진 지점이라고 보면 된다.
