## 게시판 글 등록, 상세보기 기능 구현

<br/>

### 1. 디비 생성

```sql
# 게시판 테이블
CREATE TABLE post (
    id           int auto_increment,
    title        varchar(30) not null,
    content      varchar(50) not null,
    writer       varchar(30) not null,
    created_date datetime    not null,
    hit          int default 0,
    heart        int default 0,
    primary key (id)

);
```

<br/><br/>

### 2. domain 을 생성해준다.

```java
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class Post {
    private int id;
    private String title;
    private String content;
    private String writer;
    private LocalDateTime createdDate;
    private int hit;
}
```

<br/><br/>

### 3. dto → PostDto

```java
@Data
public class PostDto {
    private int id;
    private String title;
    private String content;
    private String writer;
    private LocalDateTime createdDate;
    private int hit;
}
```

<br/><br/>

### 4. Controller 

```java
@Controller
@RequiredArgsConstructor
@Slf4j
public class PostController {

    private final PostService postService;

    // 게시판 전체 출력
    @GetMapping("/post")
    public String post(Model model) {
        model.addAttribute("list", postService.postList());
        return "posts/post-list";
    }

    // 게시판 상세 보기
    @GetMapping("/post-view")
    public String viewPost(Model model, @RequestParam int id) {
        model.addAttribute("post", postService.getPost(id));
        return "posts/post-view";
    }

    // 게시글 작성
    @GetMapping("/new-post")
    public String newPost(Model model) {
        model.addAttribute("postDto", new PostDto());
        return "posts/new-post";
    }

    // 게시글 저장
    @PostMapping("/new-post")
    public String savePost(PostDto postDto, @AuthenticationPrincipal User user) {
        postService.savePost(postDto, user.getUsername());
        return "redirect:/post";
    }
}
```

<br/><br/>

### 5. Service 작성하기.
    
```java
@Service
@RequiredArgsConstructor
@Transactional
public class PostService {
    private final PostMapper postMapper;

    public List<Post> postList() { // 게시글 리스트 반환
        return postMapper.postList();
    }

    public Post getPost(int id) { // 게시판 상세 보기
        return postMapper.getPost(id); 
    }

    public void savePost(PostDto postDto, String userId) { // 저장하는 기능
        postDto.setCreatedDate(LocalDateTime.now());
        postDto.setWriter(userId);
        postMapper.savePost(postDto);
    }
}
```

<br/><br/>
    

### 6. mapper 인터페이스 작성하기.

@Repository
public interface PostMapper {

### 7. 다음 xml 을 생성해준다.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper
        PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN"
        "http://mybatis.org/dtd/mybatis-3-mapper.dtd">

<mapper namespace="com.project.facegram.mapper.PostMapper">

    <!-- 디비에서 모든 데이터를 꺼내서 도메인 객체로 반환한다는 것이다.-->
    <select id="postList" resultType="com.project.facegram.domain.Post">
        select *
        from post;
    </select>

    <!-- id가 getPost로 오는 int 타입이 있다.-->
    <!-- 그 숫자 id랑 디비에 있는 id랑 같은걸 찾아주는 것이다.-->
    <!-- 만약 디비에 있다면 디비에 있는 id를 도메인 객체로 반환한다.-->
    <select id="getPost" parameterType="int" resultType="com.project.facegram.domain.Post">
        select *
        from post
        where id = #{id};
    </select>

    <!-- id가 savePost로 오는 객체 도메인이 있다.-->
    <!-- 그중에서 title, content, writer, created_date 만 -->
    <!-- 디비에 새로 저장하는 것이다.-->
    <insert id="savePost" parameterType="com.project.facegram.dto.PostDto">
        insert into post (title, content, writer, created_date)
        values (#{title}, #{content}, #{writer}, #{createdDate})
    </insert>

</mapper>
```

## 궁금증!

```java
Mapper 인터페이스와 XML 이 어떻게 연결되는가
```

앞의 MyBatis 적용 글에서 본 그 구조다. 이름 두 개로 이어진다.

```java
public interface PostMapper {
    void savePost(PostDto postDto);
    PostDto getPost(int id);
}
```

```xml
<mapper namespace="com.example.facegram.mapper.PostMapper">
    <insert id="savePost">...</insert>
    <select id="getPost" resultType="PostDto">...</select>
</mapper>
```

<br/>

```java
namespace 가 인터페이스의 전체 이름과 같아야 한다
id 가 메서드 이름과 같아야 한다
```

<br/>

하나라도 틀리면 애플리케이션이 뜰 때 이렇게 나온다.

```java
Invalid bound statement (not found): PostMapper.getPost
```

<br/>

구현체는 우리가 안 만든다. MyBatis가 실행 중에 프록시를 만들어서 등록한다.

앞의 스프링 데이터 JPA 글에서 본 것과 같은 방식이다.

<br/>

## 상세보기에서 조심해야 할 것

```java
@GetMapping("/post-view")
public String postView(Model model, int id) {
    model.addAttribute("post", postService.getPost(id));
    return "posts/post-view";
}
```

<br/>

없는 `id` 를 넣으면 `null` 이 모델에 담긴다.

```java
http://localhost:8080/post-view?id=99999
```

<br/>

화면에서 `${post.title}` 을 꺼내려다 예외가 난다.

타임리프는 `null` 에 접근하면 `SpelEvaluationException` 을 던진다.

<br/>

그래서 서비스에서 미리 막는 편이 낫다.

```java
public PostDto getPost(int id) {
    PostDto post = postMapper.getPost(id);
    if (post == null) {
        throw new PostNotFoundException("게시글을 찾을 수 없습니다");
    }
    return post;
}
```

<br/>

그리고 앞의 API 예외 처리 글에서 본 대로 처리한다.

```java
@ResponseStatus(HttpStatus.NOT_FOUND)
public class PostNotFoundException extends RuntimeException { }
```

<br/>

앞의 HTTP 상태코드 (4xx, 5xx) 글에서 본 대로, 없는 것은 `404` 여야 한다.

`500` 이 나가면 서버 버그로 오해하게 된다.

<br/>

## id 를 int 로 받는 것

```java
public String postView(Model model, int id)
```

<br/>

앞의 스프링 타입 컨버터 글에서 본 대로, `"3"` 이라는 문자열이 `3` 으로 바뀌어 들어온다.

<br/>

그런데 숫자가 아닌 값이 오면 변환에 실패한다.

```java
http://localhost:8080/post-view?id=abc
```

<br/>

`int` 는 `null` 을 못 담으니 `400` 이 나간다.

`Integer` 로 받으면 `null` 이 들어와서 나중에 `NullPointerException` 이 난다.

<br/>

앞의 래퍼 클래스 글에서 본 그 차이가 여기서 실제로 갈린다.

`int` 로 두는 편이 오히려 안전하다. 잘못된 입력을 앞에서 걸러주기 때문이다.

<br/>

## 경로로 받는 방식도 있다

```java
@GetMapping("/posts/{id}")
public String postView(@PathVariable int id, Model model) { ... }
```

<br/>

앞의 리소스 식별 글에서 본 대로 이쪽이 더 권장된다.

```java
/post-view?id=3    -> 동작을 주소에 담았다
/posts/3           -> 자원을 주소로 가리킨다
```

<br/>

`post-view` 라는 이름 자체가 `보기` 라는 동작이다.

`GET` 이라는 메서드가 이미 `조회` 를 뜻하니 중복이다.

<br/>

## 글 등록에서 작성자를 어디서 가져오는가

앞의 게시판을 만들며 어려웠던점 글에서 본 그 지점이다.

```java
@PostMapping("/new-post")
public String savePost(BoardDto boardDto, @AuthenticationPrincipal User user) {
    boardService.savePost(boardDto, user.getUsername());
    return "redirect:/post";
}
```

<br/>

`boardDto` 안에 `writer` 필드가 있어도 그 값을 쓰면 안 된다.

앞의 클라이언트 서버 구조 글에서 본 대로, 클라이언트가 보낸 값은 조작될 수 있다.

<br/>

`writer` 를 `BoardDto` 에서 아예 빼두면 실수할 여지가 없어진다.

앞의 검증 - Form 전송 객체 분리 글에서 본 `화면에서 받을 것만 담는다` 가 이 얘기다.
