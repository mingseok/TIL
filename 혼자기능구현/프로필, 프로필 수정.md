## 프로필 실행 시켜볼때 주의해야 될 점. 

프로필을 만들기 전에 회원가입 되어 DB에 저장되어 있는 것들은 프로필 페이지에 들어 갈 수가 없다. 왜??



프로필 기능을 만들기도 전에 회원가입 되어 들어 갈 수 없는 것이다.

내 로직을 보면 회원 가입을 하면서 동시에 프로필을 만들기 때문이다.

create table profile (
    id            int auto_increment primary key,
    member_id     int not null,
    bio           varchar(25),
    url           varchar(30),
    profile_image mediumblob,
    CONSTRAINT FOREIGN KEY (member_id) REFERENCES members (id) ON DELETE CASCADE
    -- ON DELETE CASCADE 옵션을 적용하면 부모 테이블에서 row 를 삭제할 경우

);

## @Data 에 대해서 `@Data` 는

`@Getter`, `@Setter`, `@RequiredArgsConstructor`, `@ToString`, 

`@EqualsAndHashCode`을 한꺼번에 설정해주는 매우 유용한 어노테이션.

따라서 @NoArgsConstructor 은 내가 직접 달아 줘야 한다.

```java
@Data
@NoArgsConstructor
public class ProfileDto {
    private int memberId;
    private String bio; // 한줄 소개
    private String url; // 프로필 링크
    private String profileImage; // 프로필 이미지

    // 처음 딱 프로필을 들어간다면, memberId 만 출력된다. (나머지는 없다)

    // Profile profile = settingsService.getMemberProfile(member.getId());
    // 위에 코드를 가져오는 것이다. 즉, 쉽게 생각하자면
    // 디비에 있는 profile 테이블을 그대로 가져와 this를 이용해 Dto에 저장하는 하는 것이다.
    public ProfileDto(Profile profile) {
        this.memberId = profile.getMemberId();
        this.bio = profile.getBio();
        this.url = profile.getUrl();
        this.profileImage = profile.getProfileImage();
    }
}
```

### service → `MemberService` 수정하기.

```java
@Service
@Transactional
@RequiredArgsConstructor
@Slf4j
public class MemberService implements UserDetailsService { // 시큐리티 사용하기 위한 인터페이스

    private final MemberMapper memberMapper;
    private final PasswordEncoder passwordEncoder;
    private final SettingsService settingsService;

    // 추가 login_id = #{loginId}
    public Member getMember(String loginId) {
        return memberMapper.getMember(loginId);
    }

    public void joinMember(MemberDto memberDto) {

        // 여기서 현재시간으로 로직 수정 한것이다.
        memberDto.setJoinDate(LocalDateTime.now());

        memberDto.setMemberPwd(passwordEncoder.encode(memberDto.getMemberPwd()));

        memberMapper.joinMember(memberDto); // 디비에 보내는 코드이다.

        // 회원가입을 하면서 프로필을 바로 생성하는 것이다.
        // 그렇기 때문에 memberMapper.joinMember(memberDto); 회원 가입이 완료 된 후에
        // 이 코드를 작성 해야 하는 것이다. (= 밑에 적은 이유)

        // 코드 해석 순서.
        // 1. memberMapper.getMember() xml로 보낼건데 매개변수는
        // 2. memberDto.getLoginId() 가 되는 것이다. (= 타입은 String 이다)
        // 3. 그리고 settingsService.createProfile() 메서드 안에 매개변수로는
        // 4. Member 객체가 된다.
        // 5. 최종적으로 settingsService.createProfile(Member) -> 이렇게 되는 것이다.
        settingsService.createProfile(memberMapper.getMember(memberDto.getLoginId()));
    }

    // 시큐리티 인터페이스 메서드
    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        // 로그인 아이디 input 박스의 name=username 으로 되어 있으므로 그 username을 매개변수로 받는 것이다.

        Member member = memberMapper.getMember(username); // 로그인 아이디로 member를 찾음

        if (member == null) {
            throw new UsernameNotFoundException(username);
        }

        // 객체 생성이랑 같은 부분이다. 즉 이거랑 같은것이다.
        //new User(member.getLoginId(), member.getMemberPwd(), "USER");
        return User.builder()
                .username(member.getLoginId())
                .password(member.getMemberPwd())
                .roles("USER") // 권한 이름인 것이다. 즉, 어드민일때랑 사용자일때 다른것 처럼 이런 느낌인 것이다.
                .build();
    }
}
```

controller → `SettingsController` 코드 작성

```java
@Controller
@RequiredArgsConstructor
@Slf4j
public class SettingsController {

    private final SettingsService settingsService;
    private final MemberService memberService;

    @GetMapping("/profile")
    public String profileView(@AuthenticationPrincipal User user, // 로그인한 사용자의 정보를 파라메터로 받고 싶을때 사용
                              Model model) {

        Member member = memberService.getMember(user.getUsername());
        Profile profile = settingsService.getMemberProfile(member.getId());

        model.addAttribute("profileDto", new ProfileDto(profile));

        return "settings/profile";
    }

    @PutMapping("/profile")
    public String updateProfile(@ModelAttribute ProfileDto profileDto,
                                @AuthenticationPrincipal User user, // 로그인한 사용자의 정보를 파라메터로 받고 싶을때 사용
                                Model model){

        Member member = memberService.getMember(user.getUsername()); 
        settingsService.updateProfile(profileDto, member.getId());

        return "redirect:/profile";
    }
}
```

## 궁금증!

```java
@Data 를 엔티티에 붙이면 무엇이 만들어질까?
```

앞의 롬복이 만드는 메소드들이 생성되는 시점은 글에서 `javap` 로 확인한 그 목록이다.

```java
@Data
public class Order {
    private Long id;
    private String name;
}
```

```java
public class Order {
  public Order();
  public java.lang.Long getId();
  public java.lang.String getName();
  public void setId(java.lang.Long);
  public void setName(java.lang.String);
  public boolean equals(java.lang.Object);
  protected boolean canEqual(java.lang.Object);
  public int hashCode();
  public java.lang.String toString();
}
```

<br/>

두 줄짜리 클래스에서 아홉 개가 나온다.

## 그중 세 가지가 문제가 된다

### 첫번째) setter 가 전부 열린다

```java
profile.setMemberId(999);      // 남의 프로필로 바꿔치기
```

<br/>

앞의 불변 객체 글에서 본 대로, 아무 데서나 상태를 바꿀 수 있으면 규칙을 지킬 수가 없다.

<br/>

`member_id` 는 프로필이 만들어질 때 정해지고 바뀌면 안 되는 값이다.

`setter` 가 있으면 그 규칙이 코드 어디에도 없게 된다.

<br/>

### 두번째) toString 이 연관 객체를 따라간다

`Profile` 이 `Member` 를 갖고 `Member` 가 `Profile` 을 가지면 서로를 계속 따라간다.

<br/>

앞의 DTO 글에서 실제로 돌려봤을 때 `StackOverflowError` 가 났다.

```java
결과 -> StackOverflowError - 서로를 계속 따라간다
```

<br/>

### 세번째) equals 와 hashCode 가 모든 필드를 쓴다

앞의 equals, hashCode 글에서 본 문제다.

```java
바꾸기 전 조회 = 내 차
바꾼 뒤 조회   = null
map 크기       = 1
```

<br/>

`Map` 이나 `Set` 에 넣은 뒤 필드를 바꾸면 못 찾게 된다.

<br/>

도메인에는 `@Getter` 만 붙이고 나머지는 의도가 드러나는 메서드로 두는 편이 낫다.

## 프로필 이미지를 DB 에 넣는 것

```sql
profile_image mediumblob
```

<br/>

앞의 테이블 작성 글에서 짚은 그 선택이다.

```java
DB 에 넣으면 - 백업이 한 번에 된다. 트랜잭션으로 묶인다
             대신 DB 가 커지고, 조회할 때마다 이미지가 딸려 온다
파일로 두면  - DB 는 경로만 갖는다. 조회가 가볍다
             대신 파일과 DB 를 따로 관리해야 한다
```

<br/>

`mediumblob` 은 최대 `16MB` 다. 요즘 휴대폰 사진 한 장이 그 정도 된다.

<br/>

그리고 `SELECT * FROM profile` 을 하면 이미지까지 전부 읽어온다.

목록 화면에서 `bio` 만 필요한데도 이미지를 다 가져오는 셈이다.

<br/>

앞의 DB 인덱스 글에서 본 대로, 행이 크면 한 페이지에 담기는 행이 줄어들고 읽을 페이지가 늘어난다.

이미지를 분리하면 이 문제가 사라진다.

```sql
-- 이미지를 따로 둔다
CREATE TABLE profile_image (member_id INT PRIMARY KEY, image MEDIUMBLOB);

-- 또는 경로만 둔다
ALTER TABLE profile ADD COLUMN image_url VARCHAR(255);
```

## 프로필이 없는 회원

원문의 `다시 회원가입 한 후에 프로필 페이지 들어가 보기` 가 이 문제를 가리킨다.

<br/>

회원가입할 때 프로필을 안 만들면, 프로필 화면에서 `null` 이 나온다.

<br/>

두 가지 방법이 있다.

```java
1. 회원가입할 때 빈 프로필을 같이 만든다
   @Transactional
   public void joinMember(MemberDto dto) {
       memberMapper.save(dto);
       profileMapper.save(new Profile(dto.getId()));    // 빈 프로필
   }

2. 조회할 때 없으면 빈 객체를 준다
   public Profile getProfile(int memberId) {
       Profile profile = profileMapper.findByMemberId(memberId);
       return profile != null ? profile : Profile.empty(memberId);
   }
```

<br/>

`1번` 이 더 낫다. `프로필은 회원당 하나 반드시 있다` 는 규칙이 데이터에 드러나기 때문이다.

<br/>

앞의 서비스 계층 글에서 본 대로, 이 둘을 트랜잭션으로 묶어야 한다.

회원만 만들어지고 프로필이 안 만들어지면 그 규칙이 깨진다.
