### PostController

```java
@Controller
@RequiredArgsConstructor
@Slf4j
public class PostController {
    private final PostService postService;

    // 게시판 전체 출력
    @GetMapping("/post")
    public String post(Model model) {
        model.addAttribute("list", postService.postList());
        return "posts/post-list";
    }

    // 게시판 상세 보기
    @GetMapping("/post-view")
    public String viewPost(Model model, @RequestParam int id) {
        model.addAttribute("post", postService.getPost(id));
        return "posts/post-view";
    }

    // 게시글 작성
    @GetMapping("/new-post")
    public String newPostForm(Model model) {
        model.addAttribute("postDto", new PostDto());
        return "posts/new-post";
    }

    // 게시글 저장
    @PostMapping("/new-post")
    public String newPost(PostDto postDto, @AuthenticationPrincipal User user) {
        postService.savePost(postDto, user.getUsername());
        return "redirect:/post";
    }

    @GetMapping("/update/{id}")
    public String updatePostForm(Model model, @PathVariable int id) {
	// ("/update/{id}") 사용 이유는 게시판 상세보기 화면에서 
	// 해당 id도 같이 보낸다고 생각하면 되는 것이다.

        model.addAttribute("postDto", new PostDto());
        model.addAttribute("post", postService.getPost(id));
        return "posts/update-post";
    }

    @PutMapping("/update")
    public String updatePost(@ModelAttribute PostDto postDto) {
        postService.updatePost(postDto);
	
        // 업데이트만 했는데, 어떻게 다시 디비에서 꺼내 오는가?? "난 수정만 했을뿐인데?"
        // 그 이유는 바로 밑에 return redirect 로 /post를 실행 시키기 때문인 것이다.
        // 그러면 다시 postService.postList() 가 실행 되는 것이다.
        return "redirect:/post";
    }

    @DeleteMapping("/delete/{id}")
    @ResponseBody
    public String deletePost(@PathVariable int id) {
        postService.deletePost(id);
        return "/post";
    }
}
```

### PostService 추가 해주기.

```java
@Service
@RequiredArgsConstructor
@Transactional
public class PostService {
    private final PostMapper postMapper;

    public List<Post> postList() {
        return postMapper.postList(); // 게시글 리스트 반환
    }

    public Post getPost(int id) {
        return postMapper.getPost(id);
    }

    public void savePost(PostDto postDto, String userId) {
        postDto.setCreatedDate(LocalDateTime.now());
        postDto.setWriter(userId);
        postMapper.savePost(postDto);
    }

    @Transactional
    public void updatePost(PostDto postDto) {
        postMapper.updatePost(postDto);
    }

    @Transactional
    public void deletePost(int id) {
        postMapper.deletePost(id);
    }

}
```

## 궁금증!

```java
수정과 삭제에서 제일 먼저 확인해야 할 것
```

`이 글이 내 글인가` 다. 이걸 안 하면 남의 글을 지울 수 있다.

```java
@PostMapping("/post-delete")
public String deletePost(int id) {
    postService.deletePost(id);
    return "redirect:/post";
}
```

<br/>

이 코드는 `id` 만 받는다. 누가 요청했는지 안 본다.

<br/>

브라우저 개발자 도구로 `id` 를 바꿔서 보내면 남의 글이 지워진다.

앞의 클라이언트 서버 구조 글에서 본 그 문제다.

<br/>

## 서버에서 확인해야 한다

```java
@PostMapping("/post-delete")
public String deletePost(int id, @AuthenticationPrincipal User user) {
    postService.deletePost(id, user.getUsername());
    return "redirect:/post";
}
```

```java
public void deletePost(int id, String loginId) {
    PostDto post = postMapper.getPost(id);
    if (post == null) {
        throw new PostNotFoundException();
    }
    if (!post.getWriter().equals(loginId)) {
        throw new AccessDeniedException("본인 글만 삭제할 수 있습니다");
    }
    postMapper.deletePost(id);
}
```

<br/>

앞의 HTTP 상태코드 (4xx, 5xx) 글에서 본 대로 이건 `403` 이다.

로그인은 했는데 권한이 없는 상황이기 때문이다.

## 화면에서 버튼을 숨기는 것으로는 부족하다

```html

`curl` 로 직접 보내면 그대로 처리된다.

```

앞의 Validation, @Validated 글에서 본 것과 같은 구조다.

## SQL 에서 한 번에 막을 수도 있다

조회하고 검사하고 지우는 것을 한 쿼리로 줄일 수 있다.

```xml
<delete id="deletePost">
    DELETE FROM post WHERE id = #{id} AND writer = #{writer}
</delete>
```

<br/>

`writer` 가 다르면 `0` 건이 지워진다.

```java
int deleted = postMapper.deletePost(id, loginId);
if (deleted == 0) {
    throw new AccessDeniedException();
}
```

<br/>

앞의 조회수 글에서 본 `읽고 계산해서 쓰지 말고 DB 에서 처리하라` 와 같은 발상이다.

조회와 삭제 사이에 남이 끼어들 틈이 없어진다.

<br/>

## 삭제하면 댓글과 좋아요는 어떻게 되는가

앞의 테이블 작성 글에서 본 문제가 여기서 드러난다.

```sql
create table comment (
    post_id  int not null,      -- 외래 키가 없다
    ...
);

create table likes (
    post_id   int not null,
    FOREIGN KEY (post_id) REFERENCES post (id)    -- 외래 키가 있다
);
```

<br/>

`likes` 에는 외래 키가 있는데 `ON DELETE CASCADE` 가 없다.

그래서 좋아요가 달린 글은 삭제가 안 된다.

```sql
Cannot delete or update a parent row: a foreign key constraint fails
```

<br/>

`comment` 에는 외래 키가 아예 없어서, 글을 지워도 댓글이 그대로 남는다.

없는 글에 달린 댓글이 DB에 계속 쌓이는 것이다.

<br/>

## 세 가지 선택지가 있다

```java
1. ON DELETE CASCADE 를 건다
   -> 글을 지우면 댓글과 좋아요가 같이 사라진다

2. 애플리케이션에서 순서대로 지운다
   @Transactional
   public void deletePost(int id) {
       commentMapper.deleteByPostId(id);
       likeMapper.deleteByPostId(id);
       postMapper.deletePost(id);
   }

3. 소프트 삭제
   UPDATE post SET deleted = true WHERE id = ?
```

<br/>

앞의 테이블 작성 글에서 본 대로, 남의 댓글이 얽혀 있으면 `3번` 이 나을 때가 많다.

`2번` 은 트랜잭션으로 묶어야 한다. 중간에 실패하면 반쪽만 지워지기 때문이다.

<br/>

앞의 서비스 계층 글에서 본 대로, 이 묶음이 곧 하나의 업무 단위다.
