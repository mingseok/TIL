## 궁금증!

```java
연관관계 편의 메서드를 어느 쪽에 두어야 할까
```

`더 자주 쓰는 쪽` 에 둔다. 양쪽에 다 두면 안 된다.

```java
// Member 쪽에 둔 경우
public void changeTeam(Team team) {
    this.team = team;
    team.getMembers().add(this);
}

// Team 쪽에 둔 경우
public void addMember(Member member) {
    members.add(member);
    member.setTeam(this);
}
```

<br/>

둘 다 두면 실수로 둘 다 부르게 되고, 그러면 컬렉션에 같은 회원이 두 번 들어간다.

<br/>

## 이름을 setter 처럼 짓지 않는다

```java
public void setTeam(Team team) { ... }      // 단순 대입처럼 보인다
public void changeTeam(Team team) { ... }   // 뭔가 더 한다는 것이 드러난다
```

<br/>

앞의 객체는 객체스럽게 사용한다 글에서 본 그 얘기다.

`set` 이라고 이름 붙이면 읽는 사람이 `필드 하나만 바꾸겠지` 라고 생각한다.

<br/>

## 컬렉션은 필드에서 초기화한다

```java
@OneToMany(mappedBy = "team")
private List<Member> members = new ArrayList<>();     // 여기서 초기화
```

<br/>

두 가지 이유가 있다.

<br/>

### 첫번째) null 검사를 안 해도 된다

```java
team.getMembers().add(member);      // null 이면 NullPointerException
```

<br/>

앞의 래퍼 클래스 사용 이유는 글에서 본 그 문제다. `null` 은 항상 사고의 원인이다.

<br/>

### 두번째) 하이버네이트가 컬렉션을 바꿔치기한다

엔티티를 영속 상태로 만들면 하이버네이트가 자기 컬렉션 구현체로 바꾼다.

```java
System.out.println(team.getMembers().getClass());
// 저장 전 : class java.util.ArrayList
// 저장 후 : class org.hibernate.collection.spi.PersistentBag
```

<br/>

변경을 추적해야 하기 때문이다. 앞의 영속성 컨텍스트 글에서 본 변경 감지의 컬렉션 버전이다.

<br/>

그래서 컬렉션을 통째로 갈아끼우면 안 된다.

```java
team.setMembers(new ArrayList<>());     // 추적 대상이 사라진다
```

<br/>

하이버네이트가 자기가 만든 컬렉션을 잃어버려서 예상 못 한 동작이 나온다.

컬렉션은 `add`, `remove` 로만 다루는 것이 안전하다.

<br/>

## 양방향에서 toString 을 조심한다

앞의 DTO 글에서 실제로 돌려봤을 때 이렇게 됐다.

```java
결과 -> StackOverflowError - 서로를 계속 따라간다
```

<br/>

`@Data` 나 `@ToString` 을 붙이면 그대로 재현된다.

<br/>

그래서 연관관계 필드를 제외해야 한다.

```java
@ToString(exclude = "team")
```

<br/>

앞의 롬복이 만드는 메소드들이 생성되는 시점은 글에서 본 대로,

`@Data` 는 `equals`, `hashCode`, `toString` 을 전부 만든다.

엔티티에는 `@Getter` 만 붙이는 편이 안전한 이유가 이것이다.

<br/>

## 저장 순서가 중요하다

```java
Team team = new Team("팀A");
Member member = new Member("민석");
member.changeTeam(team);

em.persist(member);      // team 이 아직 비영속이면?
```

<br/>

```java
IllegalStateException: org.hibernate.TransientPropertyValueException:
object references an unsaved transient instance
```

<br/>

`member` 를 저장하려면 `team_id` 가 필요한데, `team` 이 아직 식별자가 없기 때문이다.

<br/>

`team` 을 먼저 저장하거나, 앞의 영속성 전이 CASCADE 글에서 본 `CascadeType.PERSIST` 를 쓴다.

```java
em.persist(team);        // 먼저 저장
em.persist(member);
```

<br/>

앞의 기본 키 매핑 글에서 본 `IDENTITY` 와 `SEQUENCE` 차이가 여기서도 영향을 준다.

`SEQUENCE` 면 `persist` 시점에 식별자를 받아오니 `INSERT` 순서를 하이버네이트가 조정할 수 있다.
