## 동적 쿼리

동적 쿼리를 해결하는 두가지 방식

- `BooleanBuilder`

- `where` 다중 파라미터 사용 → 실무에서 많이 사용

<br/><br/>

## BooleanBuilder 사용

- builder는 `and`, `or`로 조립 할수 있다는 장점이 있다

```java
/**
 * 유저 이름이 member1이고,
 * 나이가 10살인 사람을 찾고 싶은 경우이다.
 */
@Test
public void 동적쿼리_BooleanBuilder() throws Exception {
    String usernameParam = "member1";
    Integer ageParam = 10;
    
    List<Member> result = searchMember(usernameParam, ageParam);
    Assertions.assertThat(result.size()).isEqualTo(1);
}

// 여기로 들어오는 파라미터가 null인가, 아닌가에 따라서 달라지는 것이다.
private List<Member> searchMember(String usernameCond, Integer ageCond) {
    BooleanBuilder builder = new BooleanBuilder();
    
    if (usernameCond != null) {
        builder.and(member.username.eq(usernameCond));
        // 풀이 하자면, usernameCond가 null이 아니면,
        // builder에 and() 조건을 넣어주는 것이된다.
    }
    if (ageCond != null) {
        builder.and(member.age.eq(ageCond));
    }
    return queryFactory
            .selectFrom(member)
            .where(builder) // 여기가 포인트인 것이다
            .fetch();
}
```

## 동적 쿼리 - Where 다중 파라미터 사용

이 방법을, 실무에서 많이 사용한다

- where 조건에 null 값은 무시된다.

- 메서드를 다른 쿼리에서도 재활용 할 수 있다.
- 쿼리 자체의 가독성이 높아진다.

```java
@Test
public void 동적쿼리_WhereParam() throws Exception {
    String usernameParam = "member1";
    Integer ageParam = 10;
    
    List<Member> result = searchMember2(usernameParam, ageParam);
    Assertions.assertThat(result.size()).isEqualTo(1);
}

private List<Member> searchMember2(String usernameCond, Integer ageCond) {
    return queryFactory
            .selectFrom(member)
            .where(usernameEq(usernameCond), ageEq(ageCond))
            .fetch();
}

private BooleanExpression usernameEq(String usernameCond) {
    if (usernameCond == null) {
        return null;
    }
    return member.username.eq(usernameCond);
}

private BooleanExpression ageEq(Integer ageCond) {
    if (ageCond == null) {
        return null;
    }
    return member.age.eq(ageCond);
}
```
<br/>

## 궁금증!

```java
BooleanBuilder 와 where 다중 파라미터 중 무엇을 쓸까
```

두 방식이 있고 결과는 같은데 읽기가 다르다.

```java
// BooleanBuilder
public List<Member> search(String name, Integer age) {
    BooleanBuilder builder = new BooleanBuilder();
    if (name != null) {
        builder.and(member.name.eq(name));
    }
    if (age != null) {
        builder.and(member.age.eq(age));
    }
    return queryFactory.selectFrom(member).where(builder).fetch();
}
```

```java
// where 다중 파라미터
public List<Member> search(String name, Integer age) {
    return queryFactory.selectFrom(member)
            .where(nameEq(name), ageEq(age))
            .fetch();
}

private BooleanExpression nameEq(String name) {
    return name != null ? member.name.eq(name) : null;
}

private BooleanExpression ageEq(Integer age) {
    return age != null ? member.age.eq(age) : null;
}
```

<br/>

`where()` 에 `null` 을 넘기면 그 조건이 무시된다.

그래서 `if` 문 없이도 동적 쿼리가 된다.

<br/>

## 두 번째가 나은 이유

### 조건을 재사용할 수 있다

```java
private BooleanExpression nameEq(String name) { ... }
```

<br/>

이 메서드를 다른 쿼리에서도 부를 수 있다.

`BooleanBuilder` 는 그 메서드 안에서만 쓰이고 끝난다.

<br/>

### 조합할 수 있다

```java
private BooleanExpression nameAndAgeEq(String name, Integer age) {
    return nameEq(name) == null ? null : nameEq(name).and(ageEq(age));
}
```

<br/>

앞의 클래스와 메소드의 사용 이유는 글에서 본 대로,

의미 있는 이름으로 묶으면 쿼리 본문이 읽기 쉬워진다.

```java
.where(isActive(), inPeriod(start, end))
```

<br/>

### 쿼리 본문만 봐도 조건이 보인다

`BooleanBuilder` 는 `where(builder)` 라고만 되어 있어서

무슨 조건인지 보려면 위쪽 `if` 문을 읽어야 한다.

<br/>

## null 을 조심해야 한다

`and` 로 이을 때 앞이 `null` 이면 `NullPointerException` 이 난다.

```java
nameEq(null).and(ageEq(30));      // 터진다
```

<br/>

그래서 `where` 에 나열하는 방식이 안전하다. QueryDSL이 `null` 을 알아서 걸러준다.

<br/>

조합해야 한다면 `BooleanBuilder` 를 안에서 쓰는 방법도 있다.

```java
private BooleanBuilder nameOrAge(String name, Integer age) {
    return new BooleanBuilder().or(nameEq(name)).or(ageEq(age));
}
```

<br/>

## 조건이 하나도 없으면 전체 조회가 된다

```java
search(null, null)
```

```sql
SELECT * FROM member       -- WHERE 가 없다
```

<br/>

앞의 DB 인덱스 글에서 본 `SCAN` 이 그대로 나온다.

`10만` 건이면 `10만` 건을 다 읽어서 응답한다.

<br/>

그래서 최소 조건을 강제하거나 페이징을 붙여두는 편이 안전하다.

```java
if (name == null && age == null) {
    throw new IllegalArgumentException("검색 조건을 하나 이상 입력해주세요");
}
```

<br/>

앞의 페이징과 정렬 글에서 본 대로, 무조건 페이징을 거는 것도 방법이다.

`LIMIT` 이 있으면 최악의 경우에도 그만큼만 읽는다.

<br/>

## 빈 문자열도 조건으로 들어간다

```java
search("", null)
```

```sql
WHERE name = ''            -- 아무것도 안 나온다
```

<br/>

`null` 만 걸러내면 빈 문자열이 통과한다.

앞의 Bean Validation 글에서 본 `@NotNull 과 @NotBlank 의 차이` 가 여기서도 나온다.

```java
private BooleanExpression nameEq(String name) {
    return StringUtils.hasText(name) ? member.name.eq(name) : null;
}
```

<br/>

`hasText` 는 `null`, `""`, `"   "` 를 전부 걸러준다.

앞의 자바 API를 사용하자 글에서 본 대로, 직접 만들기 전에 있는 것을 찾아보면 된다.
