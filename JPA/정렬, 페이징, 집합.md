## 정렬, 페이징, 집합



### 회원 정렬 순서

- 회원 나이 내림차순`(desc)`

- 회원 이름 올림차순`(asc)`
- 단 2에서 회원 이름이 없으면 마지막에 출력`(nulls last)`
    - `nullsLast()`, `nullsFirst()` : `null` 데이터 순서 부여

```java
@Test
public void sort() {
    em.persist(new Member(null, 100));
    em.persist(new Member("member5", 100));
    em.persist(new Member("member6", 100));

    List<Member> result = queryFactory
            .selectFrom(member)
            .where(member.age.eq(100))
            .orderBy(member.age.desc(), member.username.asc().nullsLast())
            .fetch();
}
```

`member5` → `member6` → `null` 순으로 출력

## 집합

실무에서 `Tuple`을 많이 사용하지 않는다

`DTO`로 직접 뽑는 방법이 있는데, 그 방법을 많이 사용한다고 한다

```java
@Test
public void aggregation() {
    List<Tuple> result = queryFactory
            .select(
                    member.count(),   // member가 몇명이야
                    member.age.sum(), // 모든 회원들의 나이 더하기
                    member.age.avg(), // 모든 회원들의 나이 평균
                    member.age.max(), // 최대
                    member.age.min()  // 최소
            )
            .from(member)
            .fetch();

    // Tuple타입을 꺼내기 위해선?
    Tuple tuple = result.get(0);
    assertThat(tuple.get(member.count())).isEqualTo(4);
    assertThat(tuple.get(member.age.sum())).isEqualTo(100);
    assertThat(tuple.get(member.age.avg())).isEqualTo(25);
}
```

<br/>

### ex) 팀의 이름과 각 팀의 평균 연령을 구해라.

```java
@Test
public void group() throws Exception {
    List<Tuple> result = queryFactory
            .select(team.name, member.age.avg())
            .from(member)
            .join(member.team, team)
            .groupBy(team.name)
            .fetch();

    Tuple teamA = result.get(0);
    Tuple teamB = result.get(1);

    assertThat(teamA.get(team.name)).isEqualTo("teamA");
    assertThat(teamA.get(member.age.avg())).isEqualTo(15); // (10 + 20) / 2
}
```

## 궁금증!

```java
정렬에서 null 을 어디에 둘지 정할 수 있을까
```

```java
member.age.desc().nullsLast()
member.age.asc().nullsFirst()
```

<br/>

DB마다 기본 동작이 다르다.

```java
MySQL      - NULL 을 가장 작은 값으로 본다 (오름차순이면 앞에)
PostgreSQL - NULL 을 가장 큰 값으로 본다 (오름차순이면 뒤에)
Oracle     - PostgreSQL 과 같다
```

<br/>

그래서 DB를 옮기면 정렬 결과가 달라진다.

앞의 DB 접근 (임베디드 모드) 글에서 본 `테스트는 통과하는데 운영에서 다르다` 의 한 예다.

<br/>

명시적으로 적어두면 어느 DB에서든 같아진다.

## 집계 함수는 Tuple 로 나온다

```java
List<Tuple> result = queryFactory
        .select(member.count(), member.age.sum(), member.age.avg())
        .from(member)
        .fetch();

Tuple tuple = result.get(0);
Long count = tuple.get(member.count());
```

<br/>

`Tuple` 은 QueryDSL 전용 타입이다.

앞의 TypeQuery, Query, 프로젝션 글에서 본 `Object[]` 보다는 낫지만 여전히 불편하다.

<br/>

그리고 리포지토리 밖으로 내보내면 안 된다.

`Tuple` 을 서비스나 컨트롤러가 받으면 QueryDSL 의존성이 그쪽으로 퍼진다.

<br/>

앞의 프로젝션 글에서 본 DTO로 바꿔서 내보내는 편이 낫다.

```java
.select(Projections.constructor(StatDto.class,
        member.count(), member.age.sum(), member.age.avg()))
```

## groupBy 와 having

```java
queryFactory.select(team.name, member.age.avg())
        .from(member)
        .join(member.team, team)
        .groupBy(team.name)
        .having(member.age.avg().gt(30))
        .fetch();
```

<br/>

`where` 와 `having` 의 차이를 헷갈리기 쉽다.

```java
where  - 그룹으로 묶기 전에 거른다
having - 묶은 뒤에 거른다
```

<br/>

집계 결과로 거르려면 `having` 이어야 한다.

`where` 에는 `avg()` 를 쓸 수 없다. 아직 묶기 전이라 평균이라는 것이 없기 때문이다.

<br/>

성능 관점에서는 `where` 로 걸러낼 수 있는 것은 `where` 로 하는 편이 낫다.

묶을 데이터가 줄어들기 때문이다.

```java
.where(member.deleted.isFalse())      // 먼저 거른다
.groupBy(team.name)
.having(member.age.avg().gt(30))      // 묶은 뒤에 거른다
```

## count 를 셀 때 주의할 것

```java
member.count()          -> COUNT(m)
member.name.count()     -> COUNT(m.name)
```

<br/>

앞의 attribute data type 글에서 본 대로 `COUNT` 는 `null` 을 안 센다.

`name` 이 `null` 인 회원이 있으면 두 결과가 다르다.

<br/>

전체 개수를 원하면 `member.count()` 를 쓴다.

<br/>

## 페이징은 offset 과 limit 으로 한다

```java
queryFactory.selectFrom(member)
        .orderBy(member.id.desc())
        .offset(20)
        .limit(10)
        .fetch();
```

<br/>

앞의 페이징과 정렬 글에서 본 문제가 그대로 적용된다.

```java
OFFSET 이 커질수록 느려진다 - 읽고 버리는 방식이라
```

<br/>

그리고 `orderBy` 를 반드시 넣어야 한다.

없으면 순서가 보장되지 않아서, 같은 페이지를 두 번 요청했을 때 다른 결과가 나올 수 있다.

<br/>

정렬 기준이 유일하지 않을 때도 마찬가지다.

```java
.orderBy(member.age.desc())              // 나이가 같으면 순서가 불확실하다
.orderBy(member.age.desc(), member.id.desc())   // id 로 확정한다
```

<br/>

앞의 페이징과 정렬 글에서 본 커서 방식으로 가려면 이 `id` 가 반드시 필요하다.
