## 검색 조건 쿼리

### 기본 검색 쿼리 문법

ex) 이름이 `member1`이면서, 나이가 `10`살인 사람을 조회해가 되는 것이다.


```java
@Test
public void search() {
    queryFactory
            .select(member)
            .from(member)
            .where(member.username.eq("member1")
                    .and(member.age.eq(10)))
            .fetchOne();
}
```

<br/><br/>

## and(), or() 같은 경우

(기존 코드는 위에 코드이다.)

and()를 생략하고 `','` 로 대처할 수 있다

이런식으로 사용하자


```java
@Test
public void search() {
    queryFactory
            .select(member)
            .from(member)
            .where(
                    member.username.eq("member1"),
                    member.age.eq(10)
            )
            .fetchOne();
}
```

## JPQL이 제공하는 모든 검색 조건 제공

```java
member.username.eq("member1") // username = 'member1'
member.username.ne("member1") //username != 'member1'
member.username.eq("member1").not() // username != 'member1'
// ne와 .not()은 같은 동작


member.username.isNotNull() //이름이 is not null


/**
 *  in쿼리: 나이가 10살이거나 20인사람 찾을때
 */
member.age.in(10, 20) // age in (10,20)
member.age.notIn(10, 20) // age not in (10, 20)
member.age.between(10,30) //between 10, 30


member.age.goe(30) // age >= 30
member.age.gt(30) // age > 30
member.age.loe(30) // age <= 30
member.age.lt(30) // age < 30


member.username.like("member%") //like 검색
member.username.contains("member") // like ‘%member%’ 검색
member.username.startsWith("member") //like ‘member%’ 검색
```

## 궁금증!

```java
where 에 콤마로 나열하는 것과 and 로 잇는 것이 같은가
```

결과는 같은데 `null` 처리가 다르다.

```java
.where(member.name.eq("민석"), member.age.eq(30))          // 콤마
.where(member.name.eq("민석").and(member.age.eq(30)))      // and
```

<br/>

둘 다 `WHERE name = ? AND age = ?` 가 된다.

<br/>

차이는 하나가 `null` 일 때다.

```java
.where(nameEq(null), ageEq(30))              // null 은 무시된다 -> WHERE age = ?
.where(nameEq(null).and(ageEq(30)))          // NullPointerException
```

<br/>

앞의 동적 쿼리 글에서 본 그 이유로, 콤마 방식이 동적 쿼리에 훨씬 편하다.

<br/>

## 자주 쓰는 조건 메서드

```java
eq / ne / isNull / isNotNull
in / notIn / between
gt(>) / goe(>=) / lt(<) / loe(<=)
like / contains / startsWith / endsWith
```

<br/>

`contains` 가 편하다. `%` 를 자동으로 붙여준다.

```java
member.name.contains("민")        ->  name LIKE '%민%'
member.name.startsWith("민")      ->  name LIKE '민%'
member.name.like("민%")           ->  직접 적는다
```

<br/>

앞의 DB 인덱스 글에서 확인한 대로, 앞에 `%` 가 붙으면 인덱스를 못 쓴다.

```sql
LIKE '%@test.com'  ->  `--SCAN member
LIKE 'user1%'      ->  `--SEARCH member USING INDEX
```

<br/>

`contains` 는 편한데 그만큼 느리다. `startsWith` 로 될 일이면 그쪽이 낫다.

<br/>

## 타입이 안 맞으면 컴파일이 안 된다

앞의 JPQL vs Querydsl 글에서 본 그 이득이다.

```java
member.name.goe("민석")      // StringPath 에도 goe 가 있다 (사전순 비교)
member.age.contains("30")    // 컴파일 에러. NumberPath 에는 contains 가 없다
```

<br/>

앞의 Querydsl 설정 글에서 본 대로 필드마다 타입에 맞는 객체가 생성되기 때문이다.

<br/>

## in 절에 빈 컬렉션을 넘기면

```java
member.id.in(List.of())
```

<br/>

앞의 @Query, 값, DTO 조회하기 글에서 본 그 문제다.

`IN ()` 이 되어 DB에 따라 문법 오류가 난다.

<br/>

QueryDSL은 이 경우를 처리해주기는 하는데, 버전에 따라 다르다.

넘기기 전에 확인하는 편이 안전하다.

```java
private BooleanExpression idIn(List<Long> ids) {
    return (ids == null || ids.isEmpty()) ? null : member.id.in(ids);
}
```

<br/>

## null 비교는 eq 로 하면 안 된다

```java
member.team.eq(null)         // 이렇게 쓰면 안 된다
member.team.isNull()         // 이렇게 쓴다
```

<br/>

SQL에서 `= NULL` 은 항상 거짓이기 때문이다.

앞의 attribute data type 글에서 본 대로 `NULL` 은 `모름` 이라 `같다` 를 판단할 수 없다.

```sql
WHERE team_id = NULL      -- 아무것도 안 나온다
WHERE team_id IS NULL     -- 팀이 없는 회원이 나온다
```

<br/>

## 조건을 상수처럼 쓸 수 있다

```java
private static final BooleanExpression NOT_DELETED = member.deleted.isFalse();
```

<br/>

`Q` 클래스의 `member` 가 `static final` 이라 이렇게 둘 수 있다.

앞의 Querydsl 설정 글에서 본 그 필드다.

```java
public static final QMember member = new QMember("member");
```

<br/>

다만 조건에 파라미터가 들어가면 상수로 못 둔다.

그때는 앞의 동적 쿼리 글에서 본 대로 메서드로 뽑는다.
