## 클라우드 컴퓨팅과 리전, 가용영역

<br/>

## 클라우드 컴퓨팅이란

서버를 사는 대신 빌리는 것이다.

```java
직접 운영  - 서버를 사고, 전기와 네트워크를 연결하고, 고장나면 부품을 갈아야 한다
클라우드   - 화면에서 클릭하면 몇 분 뒤 서버가 생긴다. 쓴 시간만큼 돈을 낸다
```

<br/>

`쓴 만큼 낸다` 가 핵심이다.

트래픽이 적은 새벽에는 줄이고 낮에는 늘릴 수 있다. 직접 운영하면 최대치에 맞춰 사놓고 새벽에 놀린다.

<br/><br/>

## 세 가지 층

```java
IaaS  - 가상 서버를 빌린다. 운영체제부터 내가 관리      (EC2)
PaaS  - 플랫폼을 빌린다. 코드만 올리면 실행된다          (Elastic Beanstalk, Heroku)
SaaS  - 완성된 소프트웨어를 쓴다                        (Gmail, Slack)
```

<br/>

RDS는 IaaS와 PaaS 사이다. 서버는 AWS가 관리하는데 DB 설정은 내가 한다.

앞의 RDS - 관리형 데이터베이스 글에서 이 경계를 본다.

<br/><br/>

## 리전(Region)

AWS 데이터센터가 모여 있는 지역이다. 서울, 도쿄, 버지니아, 프랑크푸르트 같은 단위다.

```java
ap-northeast-2   서울
ap-northeast-1   도쿄
us-east-1        버지니아 북부. 가장 오래되고 가장 크다
```

<br/>

리전을 고르는 기준은 두 가지다.

```java
지연 시간  - 사용자가 한국이면 서울. 물리적 거리가 곧 응답 속도
법과 규제  - 개인정보를 국외로 못 보내는 경우
```

<br/>

앞의 TCP 3 way handshake 글에서 본 대로 연결 하나에 왕복이 여러 번이다.

서울과 버지니아 사이 왕복이 약 200ms니, 핸드셰이크에 TLS까지 더하면 첫 요청에 1초 가까이 든다.

<br/>

리전끼리는 기본으로 격리되어 있다.

서울에서 만든 EC2는 도쿄 콘솔에서 안 보인다. 리전을 잘못 골라놓고 `내 서버가 사라졌다` 고 놀라는 일이 흔하다.

<br/><br/>

## 가용영역(Availability Zone)

리전 안에서 물리적으로 떨어진 데이터센터 묶음이다.

```java
ap-northeast-2a
ap-northeast-2b
ap-northeast-2c
ap-northeast-2d
```

<br/>

서울 리전에 네 개가 있다.

같은 리전이지만 건물이 다르고, 전원과 네트워크가 따로다. 하나가 정전이 나도 다른 것은 돈다.

<br/>

가용영역끼리는 전용 회선으로 이어져 있어서 지연이 1~2ms다.

리전 간 200ms와 비교하면 거의 같은 곳이라고 봐도 된다.

<br/><br/>

## 왜 두 개 이상에 걸쳐야 하나

서버 두 대를 같은 가용영역에 두면, 그 건물이 문제가 생길 때 둘 다 죽는다.

```java
같은 AZ 에 2대   - 서버 장애는 견딘다. 건물 장애는 못 견딘다
다른 AZ 에 1대씩 - 둘 다 견딘다
```

<br/>

앞의 ALB - 로드밸런서 글에서 본 로드밸런서가 여러 가용영역에 걸치도록 만들어져 있는 이유다.

RDS의 Multi-AZ도 같다. 다른 가용영역에 대기 서버를 둔다.

<br/>

가용영역 하나만 쓰다가 그 영역에 장애가 나서 서비스가 몇 시간 멈춘 사례가 실제로 있다.

AWS의 SLA도 `두 개 이상의 가용영역에 배포했을 때` 를 전제로 한다.

<br/><br/>

## 가용영역 이름이 계정마다 다르다

내 계정의 `2a` 와 남의 계정의 `2a` 가 같은 건물이 아니다.

<br/>

AWS가 계정마다 이름을 섞어서 붙인다. 모두가 `a` 만 쓰면 한 건물에 몰리기 때문이다.

물리적으로 같은 곳인지 확인하려면 `AZ ID`(apne2-az1 같은 것)를 봐야 한다.

<br/>

계정 두 개를 쓰면서 `같은 2a 에 있으니 가깝겠지` 하면 틀릴 수 있는 것이다.

<br/><br/>

## 전 세계에 공통인 것

```java
리전 단위    - EC2, RDS, VPC, S3 버킷
글로벌 단위  - IAM, Route 53, CloudFront
```

<br/>

IAM 사용자는 리전이 없다. 한 번 만들면 전 세계에서 쓴다.

앞의 CloudFront - CDN 글에서 본 대로 CloudFront는 전 세계 엣지에 뿌려지는 것이라 리전이 없다.

<br/>

콘솔 우측 상단의 리전 선택이 `Global` 로 바뀌는 서비스가 이것들이다.

<br/><br/>

## 정리

```java
클라우드    - 서버를 빌린다. 쓴 만큼 낸다
리전       - 지역. 사용자 가까운 곳. 리전끼리 격리
가용영역    - 리전 안의 독립된 데이터센터. 두 개 이상에 걸쳐야 장애를 견딘다
글로벌     - IAM, Route 53, CloudFront 는 리전이 없다
```
