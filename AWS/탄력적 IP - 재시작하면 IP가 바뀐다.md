## 탄력적 IP - 재시작하면 IP가 바뀐다

<br/>

## EC2 의 퍼블릭 IP 는 빌린 것이다

인스턴스를 만들면 퍼블릭 IP가 하나 붙는다. 그런데 이건 내 것이 아니다.

```java
stop -> start   하면 다른 IP 가 온다
```

<br/>

AWS가 쓸 수 있는 공인 IP 풀에서 하나 꺼내 잠깐 빌려준 것이다. 멈추면 반납되고 켜면 다른 것을 받는다.

<br/>

`reboot` 는 안 바뀐다. 운영체제만 다시 시작하는 것이라 인스턴스가 살아 있다.

`stop` 은 인스턴스가 물리 서버에서 내려오는 것이라 바뀐다.

<br/><br/>

## 실제로 겪은 일

개발 서버의 API가 전부 타임아웃이 났다. 화면(정적 파일)은 멀쩡했다.

```java
브라우저 -> CloudFront -> (API 경로) -> EC2:8080
```

<br/>

CloudFront가 API 요청을 EC2로 넘기는데, 그 오리진이 EC2의 퍼블릭 DNS 이름으로 잡혀 있었다.

```java
ec2-13-xxx-xxx-xxx.ap-northeast-2.compute.amazonaws.com
```

<br/>

이 이름에 IP가 박혀 있다. 인스턴스를 멈췼다 켜니 IP가 바뀌었고, 이 DNS 이름도 바뀌었다.

CloudFront는 옛 이름을 계속 찌르고 있었다. 그 주소에는 이제 아무것도 없으니 타임아웃이다.

<br/>

정적 파일은 S3에서 오니 멀쩡해서, 화면은 뜨는데 데이터만 안 나오는 모양이 됐다.

앞의 타임아웃은 왜 반드시 걸어야 하나 글에서 본 `응답 없는 주소` 상황이 실제로 생긴 것이다.

<br/>

탄력적 IP를 붙여서 끝났다.

<br/><br/>

## 탄력적 IP(Elastic IP)

내 계정에 고정으로 할당받는 공인 IP다.

```java
할당받는다 -> 인스턴스에 붙인다 -> 인스턴스를 멈추고 켜도 그대로
```

<br/>

인스턴스를 바꿔도 된다. 떼서 새 인스턴스에 붙이면 같은 IP로 새 서버가 응답한다.

앞의 무중단 배포 글에서 본 것과는 다른, 가장 단순한 서버 교체 방법이다.

<br/><br/>

## 요금

```java
인스턴스에 붙어 있다    - 2024 년부터 시간당 $0.005. 공인 IPv4 자체에 요금
안 붙어 있다           - 시간당 $0.005 = 월 약 $3.6. 쓰지도 않는데 나간다
```

<br/>

할당만 하고 안 쓰는 것에 요금을 매기는 이유가 있다. 공인 IPv4 주소가 전 세계적으로 부족해서, 잡아두고 안 쓰는 것을 막으려는 것이다.

<br/>

인스턴스를 지우고 탄력적 IP를 안 반납하면 매달 나간다.

앞의 AWS 비용 글에서 본 `안 쓰는 자원 요금` 의 대표다.

<br/>

계정에 이름 없는 탄력적 IP가 있으면 무엇에 쓰는지 확인해야 한다.

지웠다가 알고 보니 로드밸런서가 쓰던 것이면 서비스가 끊긴다. 지우기 전에 `연결 대상` 을 봐야 한다.

<br/><br/>

## 사설 IP 는 안 바뀐다

```java
퍼블릭 IP  - stop/start 에 바뀐다
사설 IP    - 인스턴스가 살아 있는 동안 고정. terminate 해야 반납
```

<br/>

앞의 VPC 글에서 본 대로 사설 IP는 내 VPC 안의 주소라 AWS 풀과 상관없다.

<br/>

그래서 VPC 안에서 서버끼리 부를 때는 사설 IP나 사설 DNS를 쓴다. 안정적이고, 데이터 전송 요금도 안 붙는다.

퍼블릭 IP로 부르면 인터넷을 거쳐 돌아 들어오고 요금이 붙는다.

<br/><br/>

## 더 나은 방법 : IP 를 아예 안 쓴다

탄력적 IP도 근본 해결은 아니다.

```java
Route 53 도메인 -> ALB -> EC2
```

<br/>

앞의 ALB 글에서 본 로드밸런서는 자기 DNS 이름을 가진다. 뒤의 EC2가 몇 대든 IP가 뭐든 상관없다.

앞의 Route 53 글에서 본 Alias 레코드로 도메인을 ALB에 붙이면, EC2를 갈아치워도 도메인은 그대로다.

<br/>

```java
IP 를 직접 쓴다       - 바뀌면 깨진다
탄력적 IP           - 안 바뀐다. 서버 한 대 구조에 맞다
ALB + 도메인         - IP 를 아무도 모른다. 여러 대, 무중단 배포에 맞다
```

<br/>

위의 장애도 CloudFront 오리진이 EC2 DNS가 아니라 ALB였다면 안 났을 일이다.

<br/><br/>

## 정리

```java
퍼블릭 IP 는 stop/start 에 바뀐다. reboot 는 안 바뀐다
IP 를 어딘가에 박아두면 그때 깨진다. 실제로 겪었다
탄력적 IP 는 고정. 안 붙어 있으면 요금. 지울 때 연결 대상 확인
근본은 IP 를 안 쓰는 구조. 도메인 -> ALB
```
