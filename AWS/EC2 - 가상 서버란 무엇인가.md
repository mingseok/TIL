## EC2 - 가상 서버란 무엇인가

<br/>

## EC2 란

Elastic Compute Cloud. 빌려 쓰는 가상 서버다.

```java
물리 서버 한 대 위에 가상 서버 여러 대가 돈다
내가 받는 것은 그 중 하나. 운영체제부터 내 것이다
```

<br/>

앞의 process를 설명해 주세요 글에서 본 대로 운영체제가 프로세스를 격리하듯, 하이퍼바이저가 가상 서버를 격리한다.

옆 가상 서버가 누구 것인지 알 수 없고 볼 수도 없다.

<br/><br/>

## 인스턴스 타입

```java
t3.micro     vCPU 2, 메모리 1GB     - 프리티어. 테스트용
t3.small     vCPU 2, 메모리 2GB
t3.medium    vCPU 2, 메모리 4GB
m5.large     vCPU 2, 메모리 8GB     - 범용
c5.large     vCPU 2, 메모리 4GB     - 컴퓨팅 최적화
r5.large     vCPU 2, 메모리 16GB    - 메모리 최적화
```

<br/>

이름을 읽는 법이 있다.

```java
t3.medium
│ │  └ 크기
│ └ 세대
└ 계열 (t=버스트, m=범용, c=컴퓨팅, r=메모리)
```

<br/>

## t 계열의 함정 : CPU 크레딧

`t3` 는 버스트 타입이다. 평소에는 CPU를 조금만 쓰고, 필요할 때 잠깐 100%를 쓴다.

```java
평소 CPU 사용이 기준(t3.small 은 20%) 아래면 크레딧이 쌓인다
기준을 넘으면 크레딧을 쓴다
크레딧이 바닥나면 기준까지만 쓸 수 있다. 서버가 갑자기 느려진다
```

<br/>

부하 테스트를 하다가 `처음엔 빠른데 몇 분 뒤 느려진다` 면 이것이다.

`unlimited` 모드를 켜면 크레딧이 없어도 쓰는데 추가 요금이 붙는다.

<br/>

앞의 스레드 풀 글에서 본 대로 `코어 수` 기준으로 풀 크기를 잡는데,

`t3.small` 의 vCPU 2개는 `항상 2개` 가 아니라 `평균 0.4개` 인 셈이다.

<br/><br/>

## 인스턴스의 생명주기

```java
pending -> running -> stopping -> stopped -> (start) -> running
                   -> shutting-down -> terminated
```

<br/>

`stop` 과 `terminate` 가 다르다.

```java
stop       - 끈다. 디스크(EBS)는 남는다. 다시 켤 수 있다. 컴퓨팅 요금 안 나감, 디스크 요금은 나감
terminate  - 없앤다. 디스크도 기본 설정이면 같이 지워진다. 되돌릴 수 없다
```

<br/>

그리고 `stop -> start` 하면 퍼블릭 IP가 바뀐다.

앞의 탄력적 IP 글에서 이것 때문에 실제로 겪은 장애를 본다.

<br/><br/>

## 디스크는 따로 있다 : EBS

EC2 인스턴스와 디스크(EBS 볼륨)는 별개 자원이다.

```java
인스턴스 = CPU + 메모리
EBS      = 디스크. 네트워크로 연결되어 있다
```

<br/>

인스턴스를 바꿔도 EBS를 떼어서 새 인스턴스에 붙일 수 있다.

메모리를 늘리려고 `t3.small -> t3.medium` 으로 바꾸는 것이 `stop -> 타입 변경 -> start` 로 끝나는 이유다.

디스크는 그대로 있으니까.

<br/>

앞의 페이지 캐시 글에서 본 디스크 속도는 EBS에서 `gp3` 같은 볼륨 타입으로 정해진다.

네트워크 디스크라 로컬 SSD보다 느리고, IOPS를 돈으로 산다.

<br/><br/>

## AMI : 서버의 스냅샷

Amazon Machine Image. 운영체제와 설치된 것들을 통째로 찍은 이미지다.

```java
Amazon Linux 2023
Ubuntu 24.04
내가 만든 AMI - 자바, 톰캣, 설정까지 다 깔린 상태
```

<br/>

같은 서버를 여러 대 띄울 때 AMI를 만들어두면 클릭 한 번이다.

앞의 무중단 배포 글에서 본 블루그린이 새 서버를 빨리 띄워야 하는데, AMI가 있으면 그게 된다.

<br/><br/>

## 인스턴스 메타데이터

인스턴스 안에서만 접근되는 주소가 있다.

```java
http://169.254.169.254/latest/meta-data/
```

<br/>

앞의 사설 IP, CIDR, 서브넷 글에서 본 링크 로컬 주소다. 인터넷으로 라우팅되지 않는다.

여기서 인스턴스 ID, 리전, 붙어 있는 IAM 역할의 임시 자격 증명을 읽는다.

<br/>

앞의 액세스 키를 코드에 넣지 않는 법 글에서 본 `DefaultCredentialsProvider` 가 마지막에 여기를 찌른다.

코드에 키가 없어도 S3에 접근되는 이유가 이 주소다.

<br/>

그래서 이 주소가 보안의 급소이기도 하다.

서버에서 임의 URL을 가져오는 기능(SSRF)이 있으면 공격자가 이 주소를 넣어 자격 증명을 빼낸다.

IMDSv2는 토큰을 먼저 받아야 하게 바꿔서 이걸 막는다.

<br/><br/>

## 정리

```java
EC2       - 가상 서버. 운영체제부터 내 책임
타입      - 계열.세대.크기. t 계열은 CPU 크레딧 함정
stop      - 디스크 남음, IP 바뀜.  terminate - 전부 사라짐
EBS       - 디스크는 별개 자원. 떼고 붙일 수 있다
메타데이터  - 169.254.169.254. 자격 증명이 여기서 나온다. IMDSv2 로 보호
```
