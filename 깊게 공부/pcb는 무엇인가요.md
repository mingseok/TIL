## pcb가 무엇인가요?

pcb는 운영 체제가 프로세스를 표현한 자료구조이다.

<br/>

pcb에는 프로세스의 중요한 정보가 포함되어 있기 때문에,

일반 사용자가 접근하지 못하도록 보호된 메모리 영역 안에 저장이 된다.

<br/>

일부 운영 체제에서 pcb는 커널 스택의 위치 합니다.

```java
커널 스택이란? -> 운영체제 그 자체를 커널이라고 한다.
```

이 메모리 영역은 보호를 받으면서도 비교적 접근하기가 편리하다.

<br/><br/>

## pcb에 저장되는 것들은 무엇이 있는지 설명하시오

pcb는 운영체제가 process에 대해 필요한 정보를 모아놓은 자료구조입니다.

pcb에는 일반적으로 다음과 같은 정보가 포함됩니다.

- 프로세스 state : 이 프로세스가 실행이 되고 있는지, 아니면 아직 cpu 할당을 받지 못했는지 아니면 

    따로 어떤 작업을 하느라 바쁜지 이런 스테이트를 적어 놓은 정보이다.

- 프로세스 number : 이게 몇번째 프로세스인지 고유한 번호가 있을 건데, 그것을 말한다.

- 프로세스 counter: 해당 프로세스가 다음에 실행할 명령어의 주소

- Registers : 컴퓨터 구조에 따라 다양한 수와 유형을 가진 값들

<br/><br/>

## 프로세스의 state에는 어떤 것들이 있나요?

프로세스는 실행, 준비, 봉쇄, 세가지 상태로 구분됩니다.

- 실행 : 프로세스가 cpu를 점유하고 명령을 수행중인 상태

- 준비 : cpu만 할당받으면 즉시 명령을 수행할 수 있도록 준비된 상태
- 봉쇄 : cpu를 할당받아도 명령을 실행할 수 없는 상태
<br/><br/>

## 궁금증!

```java
PCB 에 있다는 것들을 실제로 볼 수 있나
```

운영체제가 PCB를 그대로 보여주지는 않는데, `ps` 명령이 그 안의 값들을 꺼내서 보여준다.

```java
$ ps -o pid,ppid,stat,pri,nice,wchan,time,rss,vsz,comm -p $$

  PID  PPID STAT PRI NI WCHAN    TIME    RSS      VSZ COMM
71680 70150 Ss    31  0 -     0:00.02   3216 435310976 /bin/zsh
```

<br/>

열 하나하나가 PCB의 항목이다.

```java
PID   - 프로세스 번호
PPID  - 부모 프로세스 번호. 누가 나를 만들었는지
STAT  - 상태. S 는 대기, s 는 세션 리더
PRI   - 우선순위. 스케줄러가 누구를 먼저 돌릴지 정할 때 본다
NI    - nice 값. 사용자가 조정할 수 있는 우선순위
WCHAN - 무엇을 기다리며 잠들어 있는지
TIME  - 지금까지 CPU 를 쓴 시간
RSS   - 실제 물리 메모리 사용량
VSZ   - 가상 주소 공간 크기
```

<br/>

`ps` 가 이걸 찍을 수 있다는 것 자체가, 운영체제가 프로세스마다 이 정보를 어딘가에 들고 있다는 증거다.

그 어딘가가 PCB인 것이다.

<br/><br/>

## 상태가 세 가지라고 배웠는데 실제 값은 더 많다

```java
$ ps -axo stat | cut -c1 | sort | uniq -c

 712 S     <- 대기 (sleeping)
   4 R     <- 실행 중이거나 실행 대기 (running / runnable)
   1 U     <- 인터럽트 불가 대기 (디스크 I/O 중)
```

<br/>

교과서의 `실행 / 준비 / 봉쇄` 가 실제 운영체제에서는 이렇게 표기된다.

```java
R  -> 실행 또는 준비
S  -> 봉쇄. 신호를 받으면 깨어난다
U  -> 봉쇄. 신호로도 못 깨운다 (디스크 작업이 끝나야)
T  -> 멈춤 (Ctrl+Z 로 정지시킨 것)
Z  -> 좀비. 끝났는데 부모가 아직 거두지 않음
```

<br/>

교과서보다 상태가 더 잘게 나뉘어 있다. `봉쇄` 안에서도 깨울 수 있는지 없는지를 구분하는 것이다.

<br/><br/>

## 717 개 중 실제로 도는 것은 4 개

위 분포가 그대로 말해준다.

```java
프로세스 717 개
CPU 를 쓰고 있거나 쓰려고 줄 서 있는 것  = 4 개
나머지 713 개                            = 무언가를 기다리며 잠들어 있다
```

<br/>

코어가 10개인 컴퓨터다.

돌아갈 준비가 된 프로세스가 4개니 코어가 남는다.

<br/>

대부분의 프로세스는 대부분의 시간을 기다리는 데 쓴다.

키 입력을 기다리고, 네트워크 응답을 기다리고, 디스크를 기다린다.

<br/>

그래서 코어 10개짜리 컴퓨터가 프로세스 700개를 굴릴 수 있는 것이다.

앞의 멀티 쓰레드 글에서 본 `웹 요청은 대부분 기다리는 시간이다` 가 시스템 전체에서도 똑같이 성립한다.

<br/><br/>

## 상태가 바뀌는 것이 곧 스케줄링이다

```java
준비 -> 실행   : 스케줄러가 CPU 를 준다
실행 -> 준비   : 시간을 다 썼다. 뒤로 가서 다시 줄을 선다
실행 -> 봉쇄   : I/O 를 요청했다. 끝날 때까지 기다린다
봉쇄 -> 준비   : I/O 가 끝났다. 다시 줄을 선다
```

<br/>

`실행 -> 봉쇄` 가 중요하다.

프로세스가 스스로 CPU를 내놓는 유일한 경로이기 때문이다.

<br/>

`Thread.sleep()` 을 부르면 그 스레드는 봉쇄 상태로 들어간다.

앞의 async 코드 구현 글에서 `Thread.sleep(3000)` 을 blocking 의 예로 든 것이 정확히 이 전이다.

CPU를 놓고 3초 뒤에 깨워달라고 운영체제에 맡기는 것이다.

<br/><br/>

## PCB 가 커널 영역에 있어야 하는 이유

원문에 `일반 사용자가 접근하지 못하도록 보호된 메모리 영역` 이라고 적혀 있다.

<br/>

만약 프로세스가 자기 PCB를 고칠 수 있다면 이런 게 가능해진다.

```java
내 우선순위를 최고로 올린다
내 CPU 사용 시간을 0 으로 지운다
다른 프로세스의 상태를 봉쇄로 바꿔버린다
```

<br/>

그래서 PCB는 커널만 손댈 수 있는 곳에 두고, 프로세스는 `ps` 처럼 읽기만 할 수 있다.

<br/>

`nice` 값을 바꾸는 `renice` 명령도 남의 것을 올리려면 관리자 권한이 필요하다.

우선순위를 낮추는 것은 누구나 되지만 올리는 것은 막혀 있다.

<br/>

앞의 프록시 패턴 글에서 본 `접근 제어` 를 운영체제 수준에서 하는 것이라고 보면 된다.
