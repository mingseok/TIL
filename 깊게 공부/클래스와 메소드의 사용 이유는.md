## 클래스와 메소드의 사용 이유는?

<br/>

## 클래스(class)란?

자바에서 클래스(class)란 객체를 정의하는 틀 또는 설계도와 같은 의미로 사용됩니다.

자바에서는 이러한 설계도인 클래스를 가지고, 여러 객체를 생성하여 사용하게 됩니다.

클래스는 객체의 상태를 나타내는 필드(field)와 객체의 행동을 나타내는 메소드(method)로 구성됩니다.

<br/>

즉, 필드(field)란 클래스에 포함된 변수(variable)를 의미합니다.

또한, 메소드(method)란 어떠한 특정 작업을 수행하기 위한 명령문의 집합이라 할 수 있습니다.

<br/>

## 클래스를 사용하는 이유가 무엇인가요?

### 코드 재사용성

클래스는 기능을 캡슐화하고 인스턴스를 여러 번 생성하여 재사용할 수 있도록 돕습니다. 

<br/>

### 모듈화

클래스를 사용하면 큰 프로젝트를 작은 모듈로 분할할 수 있습니다. 

각 클래스는 특정 기능 또는 역할을 수행하며, 이러한 모듈화는 코드의 구조를 더 명확하게 만들어줍니다.

<br/>

### 표준 라이브러리와 프레임워크

자바는 많은 표준 라이브러리와 프레임워크가 제공되므로, 

클래스를 사용하여 이러한 라이브러리와 프레임워크의 기능을 활용할 수 있습니다.

<br/>

## 메소드(method)란?

어떠한 특정 작업을 수행하기 위한 명령문의 집합이라 할 수 있습니다.

<br/>

## 메소드를 정의하고 사용하는 목적이 무엇인가요?

1. `(중요)` 불필요한 중복되어 사용하는 코드를 메소드로 정의하고 호출함으로써 가독성을 높일 수 있다는 것입니다
    
2. 코드에 문제 생길 때 문제가 되는 메소드만 수정하면 됨으로써 유지보수에 도움이 된다.

<br/>

## 메소드 오버로딩이란?

하나의 클래스에 같은 이름의 메소드를 둘 이상 정의할 수 없습니다.

<br/>

하지만 메소드 오버로딩을 이용하면, 같은 이름의 메소드를 중복하여 정의할 수 있습니다.

매개변수의 개수나 타입을 다르게 하여 같은 이름의 또 다른 메소드를 작성하는 것입니다.

이러한 메소드 오버로딩을 사용함으로써 메소드에 사용되는 이름을 절약할 수 있습니다.

<br/>

<br/>

## 궁금증!

```java
"매개변수의 개수나 타입을 다르게 하면" 이라고 했는데, 반환 타입만 다르면 안 될까?
```

안 된다. 컴파일 에러가 난다.

```java
class Ov1 {
    int calc(int a) { return a; }
    String calc(int a) { return "" + a; }
}
```

```java
error: method calc(int) is already defined in class Ov1
    String calc(int a) { return "" + a; }
           ^
```

<br/>

컴파일러가 두 메서드를 구분할 때 보는 것은 `이름 + 매개변수 목록` 까지다.

이것을 `시그니처` 라고 하는데, 반환 타입은 여기에 포함되지 않는다.

```java
calc(int)  <- 여기까지가 시그니처. 반환 타입은 안 본다
```

<br/>

이유는 호출하는 쪽을 보면 알 수 있다.

```java
calc(10);          // 반환값을 안 받는다면?
```

반환 타입으로 구분한다면 이 줄에서 어느 쪽을 불러야 할지 정할 수가 없다.

<br/>

## 어느 것이 불릴지는 컴파일할 때 정해진다

이게 오버라이딩과 결정적으로 다른 점이다.

```java
public class Ov2 {
    public static void main(String[] args) {
        Object object = "문자열이 담겨 있다";
        print(object);

        print("직접 문자열로 넘기면");

        print(null);
    }

    static void print(Object value) { System.out.println("Object 버전"); }
    static void print(String value) { System.out.println("String 버전"); }
}
```

<br/>

### 결과

```java
Object 버전
String 버전
String 버전
```

<br/>

첫 줄이 중요하다. `object` 안에 실제로 들어 있는 것은 `String` 인데 `Object 버전` 이 불렸다.

컴파일러가 `object` 라고 적힌 변수의 `선언된 타입` 만 보고 정해버렸기 때문이다.

```java
오버로딩 -> 컴파일할 때, 변수에 적힌 타입을 보고 정한다
오버라이딩 -> 실행할 때, 객체에 실제로 들어 있는 타입을 보고 정한다
```

<br/>

세 번째 `print(null)` 이 `String 버전` 인 것도 재밌다.

`null` 은 아무 타입에나 들어갈 수 있는데, 이럴 때는 `더 구체적인 쪽` 을 고른다.

`String` 이 `Object` 의 자식이니까 `String` 쪽이 더 구체적이라고 보는 것이다.

<br/>

만약 `print(String)` 과 `print(Integer)` 두 개만 있었다면 어느 쪽도 더 구체적이지 않아서

`reference to print is ambiguous` 라는 컴파일 에러가 났을 것이다.

<br/>

## 메서드를 나누는 진짜 기준

원문의 `중복을 줄인다` 는 결과일 뿐이고, 나누는 기준은 따로 있다.

`이 메서드는 무엇을 하는가` 를 한 문장으로 말할 수 있으면 잘 나눈 것이다.

<br/>

```java
void order(Long memberId, Long itemId, int count) {
    Member member = memberRepository.findById(memberId).orElseThrow();
    Item item = itemRepository.findById(itemId).orElseThrow();

    if (item.getStock() < count) {
        throw new IllegalStateException("재고 부족");
    }
    item.setStock(item.getStock() - count);

    int price = item.getPrice() * count;
    if (member.getGrade() == Grade.VIP) {
        price = price * 90 / 100;
    }

    orderRepository.save(new Order(member, item, count, price));
}
```

<br/>

이 메서드가 하는 일을 한 문장으로 말하려면 `조회하고, 재고 확인하고, 재고 줄이고, 할인 계산하고, 저장한다` 가 된다.

`~하고` 가 네 번 들어가면 나눌 때가 된 것이다.

<br/>

```java
void order(Long memberId, Long itemId, int count) {
    Member member = findMember(memberId);
    Item item = findItem(itemId);

    item.removeStock(count);
    int price = calculatePrice(member, item, count);

    orderRepository.save(new Order(member, item, count, price));
}
```

<br/>

줄 수는 비슷한데 읽는 부담이 다르다.

`무엇을 하는지` 만 위에서 훑고, `어떻게 하는지` 가 궁금하면 그때 들어가면 되기 때문이다.

```java
메서드 이름 = 무엇을 하는가
메서드 본문 = 어떻게 하는가
```

<br/>

`재고 부족` 검사가 `item.removeStock()` 안으로 들어간 것도 눈여겨볼 만하다.

재고를 아는 것은 `Item` 이니까, 재고가 모자란지 판단하는 것도 `Item` 의 몫인 것이다.

메서드를 어디에 둘지 정하는 기준은 `그 데이터를 가진 쪽` 이다.
