## 상속받는 자식 클래스를 생성하면 부모 객체는 생성 될까?


자식 클래스를 생성하면 부모 클래스의 객체가 자동으로 생성되지는 않습니다. 

자식 클래스는 부모 클래스의 특성과 메서드를 상속받지만, 부모 클래스의 객체는 명시적으로 생성한다.


<br/>

`super()`라는 키워드를 사용하여 부모 클래스의 생성자를 호출하고, 

그에 따라 부모 클래스의 생성자가 실행됩니다. 

<br/>

만약 부모 클래스의 기본 생성자가 있는 경우에는 `super()`를 사용하지 않아도 자동으로 호출되지만, 

부모 클래스의 매개변수를 받는 생성자가 있다면 명시적으로 `super()`를 사용하여 호출해야 합니다.

<br/>

예를 들어, 다음은 자식 클래스가 부모 클래스를 상속하고 부모 클래스의 생성자를 호출하는 예시입니다:

```java
class 부모클래스 {
    부모클래스() {
        System.out.println("부모 클래스의 생성자");
    }
}

class 자식클래스 extends 부모클래스 {
    자식클래스() {
        super(); // 부모 클래스의 생성자 호출
        System.out.println("자식 클래스의 생성자");
    }
}

public class Main {
    public static void main(String[] args) {
        자식클래스 자식객체 = new 자식클래스();
    }
}
```

<br/>

이 경우, 자식클래스를 생성하면 먼저 부모클래스의 생성자가 호출되고, 

그 후에 자식클래스의 생성자가 호출됩니다.

<br/>

## 궁금증!

```java
부모 생성자가 실행되었으니, 부모 객체도 하나 만들어진 것 아닐까?
```

여기가 헷갈리기 쉬운 부분이다. 생성자가 실행된 것과 객체가 만들어진 것은 다른 얘기다.

<br/>

`new Child()` 를 하면 힙에는 객체가 `하나만` 만들어진다.

부모 생성자는 그 하나뿐인 객체에서 `부모가 물려준 부분을 채우는` 역할로 실행되는 것이다.

<br/>

## 확인해보자

객체마다 다른 값을 주는 `System.identityHashCode()` 와 실제 타입을 알려주는 `getClass()` 를 찍어봤다.

```java
public class One {
    public static void main(String[] args) {
        Child child = new Child();
        System.out.println("바깥에서 본 것  = " + System.identityHashCode(child)
                + " / " + child.getClass().getSimpleName());
    }
}

class Parent {
    Parent() {
        System.out.println("부모 생성자 안 = " + System.identityHashCode(this)
                + " / " + this.getClass().getSimpleName());
    }
}

class Child extends Parent {
    Child() {
        System.out.println("자식 생성자 안 = " + System.identityHashCode(this)
                + " / " + this.getClass().getSimpleName());
    }
}
```

<br/>

### 결과

```java
부모 생성자 안 = 2060468723 / Child
자식 생성자 안 = 2060468723 / Child
바깥에서 본 것  = 2060468723 / Child
```

세 줄이 전부 같은 번호다. 객체는 하나뿐이라는 뜻이다.

<br/>

더 눈여겨볼 것은 오른쪽이다. `부모 생성자 안` 에서 찍었는데도 타입이 `Parent` 가 아니라 `Child` 다.

부모 생성자 안의 `this` 조차도 자식 객체를 가리키고 있는 것이다.

```java
new Child()
-> 힙에 Child 객체 하나가 만들어진다 (부모가 물려준 필드까지 자리를 잡고 나온다)
-> 부모 생성자가 실행되어 부모 몫의 필드를 채운다
-> 자식 생성자가 실행되어 자식 몫의 필드를 채운다
```

객체가 두 개 만들어지고 하나로 합쳐지는 것이 아니라, 처음부터 하나짜리 객체를 위아래로 나눠서 채우는 것이다.

<br/>

## 그래서 조심할 것이 하나 생긴다

부모 생성자가 돌 때 `this` 는 이미 자식 객체다.

그 말은, 부모 생성자에서 메서드를 부르면 `자식이 오버라이드한 쪽` 이 불린다는 뜻이다.

```java
class Parent {
    Parent() {
        print();
    }

    void print() {
        System.out.println("부모의 print");
    }
}

class Child extends Parent {
    private String name = "민석";

    @Override
    void print() {
        System.out.println("이름 = " + name);
    }
}
```

<br/>

### 결과

```java
이름 = null
```

`민석` 이 아니라 `null` 이 나온다.

부모 생성자가 도는 시점에는 자식의 필드 초기화가 아직 시작도 안 했기 때문이다.

<br/>

아직 다 만들어지지 않은 객체의 메서드를, 부모가 먼저 불러버린 셈이다.

```java
생성자에서 오버라이드 가능한 메서드를 호출하면 안 되는 이유
```

<br/>

## super()는 왜 항상 첫 줄이어야 하는가

`super()` 를 두 번째 줄에 적으면 컴파일 에러가 난다.

```java
Child() {
    this.name = "민석";
    super();          // 컴파일 에러
}
```

<br/>

부모가 물려준 필드가 아직 준비되지 않은 상태에서 자식이 먼저 무언가를 하면 위험하기 때문이다.

아래에서부터 채우는 것이 아니라 위에서부터 채워 내려와야, 자식이 부모 필드를 믿고 쓸 수 있다.

<br/>

그래서 `super()` 를 안 적어도 컴파일러가 첫 줄에 자동으로 넣어준다.

앞에서 본 `아무것도 없는 빈 클래스` 를 `javap` 로 열었을 때 `Object` 의 생성자를 부르고 있던 것도 같은 이유다.

```java
어떤 객체를 만들든, 최상위 Object의 생성자부터 차례로 실행되고 내려온다
```
