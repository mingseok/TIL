## 배열의 index는 왜 0부터 시작하나요?

처음 프로그래밍에 입문 했을 때 0부터 시작하는 것이, `“그냥 그런가보다”` 하고 

받아들이고 넘어갔었는데, 이번 기회에 알아보면 좋을 것 같다는 생각을 하게 되었다.

<br/>

## 이유는?

- `0`부터 시작하는 인덱스는 자연스럽고 직관적이며,
    
    배열의 첫 번째 원소가 항상 `0`번 인덱스라는 점에서 이점이 있다고 합니다
    
- `0`부터 시작하는 인덱스는 메모리 주소를 계산하기 쉽게 만들어준다고 합니다

<br/>

## 자연스럽고 직관적이다?

최단경로 알고리즘 으로 유명한 다익스트라는 그가 작성한 하나의 메모를 통해 구간을 표현하는 

다음 `4가지` 표현식 중 가장 자연스럽고 직관적인 방법을 도출하는 하나의 의견을 제안했습니다.

```java
-- 가장 작은 자연수 N 을 포함하는 구간을 표현한다고 가정하겠습니다 --

a. 2 <= i < 13 // -> 직관적인 표현
b. 1 < i <= 12
c. 2 <= i <= 12
d. 1 < i < 13
```

`a` 와 같은 `반닫힌구간` 을 사용하면, 좀 더 의미에 맞고 직관적인 표현이 가능하다고 한다

<br/>

## 메모리 주소 계산이 쉬워진다

프로그래밍 언어에서 특정 영역의 메모리 주소는 기준 주소와 `offset` 으로 계산됩니다.

<br/>

기준 주소가 `a` 이고 각 프레임의 크기가 `s` 라고 할때,

`i` 번째 프레임의 주소값은 다음과 같은 등차수열의 일반항을 통해 계산할 수 있습니다.

```java
a + s * (i - 1) // 1-based

a + s * i       // 0-based
```



여기서 `0-based` 방식은 런타임에 계산하기에 좀 더 효율적이라는 이점이 있습니다.

또한 이는 `모듈러` 연산을 통한 인덱스 매핑을 수행할때도 간결하게 표현이 가능해집니다.

앞서 살펴본 이러한 여러가지 장점들 때문에 많은 프로그래밍 언어에서 `0-based indexing` 을 채택 한다고 합니다.

<br/>

## 궁금증!

```java
"주소 계산이 효율적이다"라고 하는데, 자바에서도 그런가?
```

자바는 포인터를 직접 못 다루지만 바이트코드를 보면 흔적이 남아 있다.

```java
int read(int[] array, int index) {
    return array[index];
}
```

<br/>

이걸 `javap -c` 로 열어보면 이렇다.

```java
  0: aload_1     // 배열을 꺼내고
  1: iload_2     // 인덱스를 꺼내서
  2: iaload      // 그 자리를 읽는다
  3: ireturn
```

인덱스가 손대지 않은 채로 그대로 들어간다.

<br/>

만약 `1-based` 였다면 `iaload` 전에 `1` 을 빼는 명령이 하나 더 들어가야 했을 것이다.

배열을 읽을 때마다 매번 그 뺄셈이 들어가는 셈이다.

```java
0-based -> 받은 인덱스를 그대로 쓴다
1-based -> 읽을 때마다 1을 빼야 한다
```

<br/>

## 반닫힌 구간이 실제로 편한 이유

`a` 표현이 직관적이라는 말이 코드에서는 이렇게 나타난다.

<br/>

### 첫번째) 길이를 뺄셈 하나로 구한다

```java
// 0-based, [start, end)
int length = end - start;

// 1-based, [start, end]
int length = end - start + 1;
```

`+ 1` 이 붙느냐 안 붙느냐인데, 이 `+1` 을 빠뜨리는 실수가 생각보다 자주 난다.

<br/>

### 두번째) 구간을 나눌 때 겹치지도 비지도 않는다

`10` 개를 반으로 나눈다고 해보자.

```java
[0, 5)  와  [5, 10)
```

앞 구간의 끝과 뒷 구간의 시작이 같은 숫자다.

`5` 라는 숫자 하나만 정하면 되고, 겹치거나 빠지는 칸이 생길 수가 없다.

<br/>

닫힌 구간이면 `[0, 4]` 와 `[5, 9]` 가 되어서 경계에 숫자가 두 개 필요하다.

`4` 와 `5` 를 각각 맞춰야 하니 하나 틀리면 바로 겹치거나 빠진다.

<br/>

### 세번째) 빈 구간을 자연스럽게 표현한다

```java
[3, 3)   // 아무것도 없는 구간
```

시작과 끝이 같으면 빈 구간이다.

닫힌 구간에서는 `[3, 2]` 처럼 끝이 시작보다 작은 이상한 표기를 써야 한다.

<br/>

그래서 반복문이 이렇게 생긴 것이다.

```java
for (int i = 0; i < array.length; i++) { ... }
```

`i < length` 라고 쓰면 도는 횟수가 그대로 `length` 다.

`i <= length - 1` 이라고 쓸 일이 없다.

<br/>

## 그럼 범위를 벗어나면 어떻게 되는가

주소를 그냥 계산할 뿐이라면, 범위를 넘겨도 옆 메모리를 읽어버릴 것 같다.

그래서 자바는 읽기 전에 항상 검사를 한 번 한다.

```java
int[] array = new int[3];
System.out.println(array[3]);
System.out.println(array[-1]);
```

```java
Index 3 out of bounds for length 3
Index -1 out of bounds for length 3
```

<br/>

`C` 였다면 그냥 옆 메모리를 읽고 이상한 값을 돌려줬을 것이다.

자바는 배열이 자기 길이를 알고 있어서, 매번 확인하고 넘으면 예외를 던진다.

주소 계산이 빠른 것은 가져가되, 안전 장치는 따로 붙여둔 셈이다.

<br/>

## 참고로 0부터가 절대적인 규칙은 아니다

`1` 부터 시작하는 언어도 있다.

- `MATLAB`, `R`, `Fortran`, `Lua`

수학이나 통계에서 쓰는 언어들이다. 사람이 세는 방식과 맞추는 쪽을 택한 것이다.

<br/>

`0-based` 는 `메모리 주소를 다루던 언어의 사고방식` 이 그대로 굳은 결과에 가깝다.

`C` 에서 `a[i]` 는 문법적으로 `*(a + i)` 와 완전히 같다. 배열 이름이 곧 시작 주소이기 때문이다.

<br/>

자바는 포인터를 없앴지만, `C` 계열 문법을 그대로 물려받으면서 인덱스 규칙도 같이 가져온 것이다.
