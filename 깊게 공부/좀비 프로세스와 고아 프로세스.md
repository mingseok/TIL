## 좀비 프로세스와 고아 프로세스

<br/>

## 프로세스가 끝나면 바로 사라지지 않는다

프로세스가 `exit` 하면 메모리는 돌려주지만, 앞의 pcb는 무엇인가요 글에서 본 PCB는 남는다.

종료 코드를 부모가 가져가야 하기 때문이다.

```java
자식이 끝난다 -> PCB 만 남는다 (좀비)
부모가 wait() 한다 -> 종료 코드를 읽고 PCB 를 지운다
```

<br/>

부모가 `wait()` 를 안 하면 PCB가 영원히 남는다. 이것이 좀비다.

<br/><br/>

## 궁금증!

```java
좀비를 직접 만들어서 볼 수 있나
```

자식을 만들고 자식은 즉시 끝나게 하고, 부모는 `wait()` 없이 3초 잤다.

```java
pid = fork()
if pid == 0: exit(0)          # 자식: 바로 종료
else: sleep(3)                # 부모: 안 거두고 잠
```

<br/>

### 결과

```java
  PID   PPID STAT COMM
74758  74756 ZN   <defunct>
```

<br/>

`STAT` 이 `Z` 다. `<defunct>` 는 `이미 죽었음` 이라는 표시다.

<br/>

메모리도 CPU도 안 쓴다. 프로세스 테이블의 한 줄과 PID 하나만 차지한다.

<br/>

그런데 그 한 줄이 문제다. PID는 유한하다.

좀비가 수만 개 쌓이면 새 프로세스를 못 만든다. 앞의 process를 설명해 주세요 글에서 본 `fork` 가 실패하는 것이다.

<br/><br/>

## 고아는 반대다

부모가 먼저 죽으면 자식은 고아가 된다.

```java
sh -c 'sleep 3 &'             # sh 가 sleep 을 띄우고 바로 끝난다
```

<br/>

### 결과

```java
  PID  PPID COMM
74410     1 sleep       <- PPID 가 1
```

<br/>

`PPID` 가 1이다. `init`(macOS는 `launchd`)이 입양했다.

<br/>

고아는 좀비와 달리 문제가 안 된다.

`init` 이 자식들의 `wait()` 를 대신 해주기 때문이다. 고아가 끝나면 `init` 이 바로 거둔다.

<br/>

정리하면 이렇다.

```java
좀비 - 자식이 죽었는데 부모가 안 거둠. 부모 잘못. 쌓이면 문제
고아 - 부모가 죽어서 init 이 입양. 정상. init 이 거둬준다
```

<br/><br/>

## 자바에서는 좀비가 잘 안 생긴다

`ProcessBuilder` 로 자식을 만들고 `waitFor()` 를 안 부르면 좀비가 될 것 같은데, 안 된다.

```java
Thread.getAllStackTraces() 에서 이름에 reaper 가 들어간 스레드:
  스레드 발견: process reaper
```

<br/>

JVM이 `process reaper` 라는 데몬 스레드를 띄워서 자식 종료를 자동으로 거둔다.

내가 `waitFor()` 를 안 불러도 이 스레드가 대신 `wait()` 한다.

<br/>

그래서 자바 프로그램은 좀비를 남기지 않는다. 대신 `Process.exitValue()` 는 나중에라도 읽을 수 있다. 리퍼가 종료 코드를 보관해두기 때문이다.

<br/><br/>

## 컨테이너에서 좀비가 생기는 이유

도커 컨테이너의 첫 프로세스(PID 1)가 `init` 역할을 해야 한다.

```java
CMD ["java", "-jar", "app.jar"]       # java 가 PID 1
```

<br/>

이러면 `java` 가 `init` 이다. 그런데 `java` 는 `init` 이 할 일을 모른다.

컨테이너 안에서 다른 프로세스가 고아를 남기면, PID 1인 `java` 가 입양하는데 거두지는 않는다.

좀비가 쌓인다.

<br/>

그래서 진짜 `init` 을 앞에 둔다.

```java
docker run --init ...                  # tini 를 PID 1 로
ENTRYPOINT ["tini", "--", "java", "-jar", "app.jar"]
```

<br/>

`tini` 가 PID 1이 되어 고아를 입양하고 거둬준다.

<br/>

앞의 시그널과 graceful shutdown 글에서 본 시그널 전달 문제도 같은 이유로 생긴다.

PID 1은 시그널을 특별하게 다루기 때문에, `java` 가 PID 1이면 `SIGTERM` 을 받고도 기본 동작으로 안 죽는 경우가 있다.

<br/><br/>

## 서버에서 좀비를 발견하면

```java
$ ps -axo pid,ppid,stat,comm | awk '$3 ~ /^Z/'
```

<br/>

좀비 자체는 `kill` 할 수 없다. 이미 죽은 것을 죽일 수는 없다.

<br/>

부모를 찾아서 부모에게 `SIGCHLD` 를 보내거나, 부모를 죽인다.

부모가 죽으면 좀비가 고아가 되고, `init` 이 거둔다.

<br/>

근본 원인은 부모 프로그램이 `wait()` 를 안 한 것이니, 그 프로그램을 고쳐야 한다.

자바라면 위에서 본 대로 JVM이 해주니, 보통은 자바가 아닌 스크립트나 네이티브 프로그램이 원인이다.
