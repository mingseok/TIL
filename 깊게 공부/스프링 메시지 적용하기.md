## 메시지 적용하기

메시지들을 설정으로 일관성있게 관리하는 것이다.

<br/><br/>

## `application.properties` 파일에 등록하기.

```
spring.messages.basename=messages,config.i18n.messages
```

<br/>

### 애매한 점

설정하지 않는다면 `messages` 하나만 읽어 드리는 것이다.

`messages.properties` 파일을 모두 인식한다.

```java
// 이렇게 하지 않고
spring.messages.basename=messages,config.i18n.messages

// 이렇게만 해도 되는건지 모르겠다. 일단 둘다 해보기.
spring.messages.basename=messages 

// 2개 추가 하고 싶을때.
spring.messages.basename=messages,errors
```

<br/><br/>

## 파일 만들기 -> `messages.properties`

resources 파일을 선택하여 만들어야 된다.

![이미지](/programming/img/입문108.PNG)

<br/><br/>

## 이렇게 설정하여 불러와 사용하면 되는 것이다.

```
hello=안녕
hello.name=안녕 {0}
```

`{0}` 같은 경우는 값을 변경(치환) 하도록 하는 것이다.

- 즉, `"안녕 Spring"` 이 출력 된다면 밑에 설명.
    - '안녕'은 기존 설정한 것.

    - {0} 은 'Spring'으로 치환 되는 것이다.

<br/><br/>

## `messages.properties` 작성하기

label이라고 앞에 붙인 이유는 다른것과 구분하기 위해 지정한 것이다.

```
label.item=상품
label.item.id=상품 ID
label.item.itemName=상품명
label.item.price=가격
label.item.quantity=수량

page.items=상품 목록
page.item=상품 상세
page.addItem=상품 등록
page.updateItem=상품 수정

button.save=저장
button.cancel=취소
```

## 사용 방법

위 `messages.properties` 파일이랑 같이 보기

![이미지](/programming/img/입문109.PNG)

타임리프의 메시지 표현식 `th:text="#{...}"` 를 사용 한다.

<br/>

예를 들어서 방금 등록한 `상품`이라는 이름을 조회하려면 `messages.properties` 파일에서 

설정한 `th:text="#{label.item}"` 이라고 하면 된다.

<br/>

### 렌더링 전 / 후 비교

```
-- 렌더링 전 --
<div th:text="#{label.item}"></h2>

-- 렌더링 후 --
<div>상품</h2>
```

## 궁금증!

```java
메시지를 파일로 빼면 뭐가 좋은 걸까? 어차피 문구 하나 바꾸는 건데
```

같은 문구가 여러 화면에 흩어져 있을 때 진가가 나온다.

```java
addForm.html   : <label>상품명</label>
editForm.html  : <label>상품명</label>
items.html     : <th>상품명</th>
item.html      : <label>상품명</label>
```

<br/>

기획에서 `상품명` 을 `상품 이름` 으로 바꿔달라고 하면 네 파일을 다 열어야 한다.

하나라도 빠뜨리면 화면마다 다른 말이 나온다.

<br/>

메시지로 빼두면 `messages.properties` 한 줄만 고치면 끝난다.

```java
label.item.itemName=상품 이름
```

<br/>

앞의 뷰 리졸버 글에서 본 `논리 이름과 실제를 분리한다` 와 같은 구조다.

```java
화면은 label.item.itemName 이라는 "이름" 만 안다
실제 문구는 파일에 있다
-> 문구가 바뀌어도 화면 코드는 안 바뀐다
```

<br/>

## 국제화는 파일 이름으로 갈린다

원문의 설정에서 `basename=messages` 라고 준 것이 이렇게 동작한다.

```java
messages.properties         <- 기본 (아무 것도 안 맞을 때)
messages_en.properties      <- 영어
messages_ko.properties      <- 한국어
messages_ja.properties      <- 일본어
```

<br/>

파일 이름 뒤에 언어 코드를 붙이면 스프링이 알아서 골라준다.

<br/>

## 어느 언어인지는 어떻게 아는가

브라우저가 보내는 헤더를 본다.

```java
Accept-Language: ko-KR,ko;q=0.9,en-US;q=0.8,en;q=0.7
```

<br/>

`q` 는 선호도다. 한국어를 가장 원하고, 없으면 영어도 괜찮다는 뜻이다.

스프링은 이 순서대로 맞는 파일을 찾는다.

```java
ko-KR 로 messages_ko_KR.properties 를 찾는다 -> 없다
ko 로 messages_ko.properties 를 찾는다        -> 있다. 이걸 쓴다
```

<br/>

하나도 없으면 `messages.properties` 를 쓴다. 그래서 기본 파일은 반드시 있어야 한다.

<br/>

이 판단을 하는 것이 `LocaleResolver` 다. 기본 구현이 `AcceptHeaderLocaleResolver` 이고,

이름 그대로 `Accept-Language` 헤더만 본다.

<br/>

## 헤더 말고 다른 기준을 쓰고 싶다면

사용자가 화면에서 언어를 직접 고르게 하는 경우가 많다.

이때는 `LocaleResolver` 를 갈아끼운다.

```java
@Bean
public LocaleResolver localeResolver() {
    CookieLocaleResolver resolver = new CookieLocaleResolver("lang");
    resolver.setDefaultLocale(Locale.KOREA);
    return resolver;
}
```

<br/>

`lang` 이라는 쿠키에 언어를 저장해두고 그것을 보는 방식이다.

앞의 프론트 컨트롤러 글에서 본 `갈아끼울 수 있는 자리` 가 여기에도 있는 것이다.

```java
AcceptHeaderLocaleResolver - 브라우저 헤더를 본다 (기본값)
CookieLocaleResolver       - 쿠키를 본다
SessionLocaleResolver      - 세션을 본다
```

<br/>

## 메시지에 값을 끼워 넣을 수 있다

```java
hello.name=안녕하세요 {0}님
```

```java
messageSource.getMessage("hello.name", new Object[]{"민석"}, locale);
// -> 안녕하세요 민석님
```

<br/>

`{0}`, `{1}` 자리에 순서대로 들어간다.

<br/>

이게 국제화에서 특히 중요하다. 언어마다 어순이 다르기 때문이다.

```java
ko : {0}님이 {1}개를 주문했습니다
en : {0} ordered {1} items
ja : {0}さんが{1}個注文しました
```

<br/>

문자열을 `+` 로 이어 붙이는 방식이었다면 어순이 다른 언어를 표현할 수 없다.

```java
"안녕하세요 " + name + "님"     // 영어로는 이 순서가 안 맞는다
```

<br/>

앞의 Bean Validation 글에서 본 검증 메시지도 같은 구조를 쓴다.

```java
max=최대 {0} 까지 허용합니다
range={0} ~ {1} 사이여야 합니다
```

<br/>

## 파일이 바뀌어도 재시작을 안 하려면

기본 설정으로는 메시지 파일을 고쳐도 반영이 안 된다.

한 번 읽어서 캐시해두기 때문이다.

```java
spring.messages.cache-duration=0     # 캐시하지 않는다 (개발용)
```

<br/>

운영에서는 캐시를 켜두는 것이 맞다.

메시지를 꺼낼 때마다 파일을 읽으면 그만큼 느려지기 때문이다.

<br/>

메시지를 자주 바꿔야 한다면 파일 대신 DB에서 읽게 만들기도 한다.

`MessageSource` 가 인터페이스라서, 구현체를 만들어 등록하면 된다.

앞의 PSA 글에서 본 `인터페이스 뒤로 숨겨두면 갈아끼울 수 있다` 가 여기서도 통한다.
