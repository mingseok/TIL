## 배열의 선언과 메모리 할당

```
배열이란? -> 배열은 같은 타입의 데이터를 연속적으로 저장한 자료구조입니다.
```

<br/>

## 배열의 특징?

`'정적'`이라는 점과 `'연속적'`이라는 것입니다. 

`정적` : 처음 배열의 크기가 정해지면 크기를 변경할 수 없음을 뜻합니다. 



`연속적` :  메모리 상에서 배열의 첫번째 요소는 두번째 요소와 연이어 붙어있다는 것을 말합니다. 

- 즉, 모든 요소들이 저장된 위치는 연속적으로 붙어있습니다.

<br/>

## 변수에 배열 직접 할당

```java
int[] nums = {12, 37, 44};
```

<br/>

### 아래와 같은 형식으로 저장됩니다.

`스택 영역`에 변수 `nums`가 할당되며, 이 변수 `nums`는 정수형, 배열타입 객체를 참조합니다. 

<br/>

나머지 배열 요소들은 연속적으로 저장되게 되는데, `37`은 `#54214`, `44`는 `#54215` 등의 방식입니다.

그렇기에, 코드를 실행하여 보면, 변수가 참조하고 있는 배열 객체의 주소가 출력 되는 걸 알 수 있습니다.

## new 연산자를 통한 배열 생성

```java
int[] nums = new int[3];
nums[0] = 12;
nums[1] = 37;
nums[2] = 44;
```

<br/>

![이미지](/programming/img/입문389.PNG)

이처럼 `new`연산자를 통해 배열을 할당하게 되면, `힙 영역`에 초기화 된 배열이 생성되게 됩니다.

<br/>

그 이후에, 인덱스를 통해 데이터를 삽입할 수 있게 되는 것입니다. 

여기서 주목할 점은 배열이 초기값을 가지며 할당된다는 것입니다.

## 궁금증!

```java
"연속적으로 붙어 있다"는 게 실제로 성능 차이를 만들까?
```

만든다. 같은 데이터를 순서만 바꿔서 훑어보면 바로 나온다.

```java
int[][] matrix = new int[8000][8000];

// 붙어 있는 순서대로
for (int row = 0; row < N; row++) {
    for (int col = 0; col < N; col++) {
        sum += matrix[row][col];
    }
}

// 건너뛰면서
for (int col = 0; col < N; col++) {
    for (int row = 0; row < N; row++) {
        sum += matrix[row][col];
    }
}
```

<br/>

### 결과

```java
행 먼저 (붙어 있는 순서대로) = 54ms
열 먼저 (건너뛰면서)        = 282ms
```

<br/>

읽는 값도 개수도 똑같은데 `5` 배가 넘게 차이가 난다.

<br/>

CPU는 메모리에서 값을 하나만 가져오지 않는다. 근처에 있는 것까지 한 덩어리로 캐시에 담아온다.

붙어 있는 순서로 읽으면 이미 캐시에 들어와 있는 값을 계속 쓰게 되고,

건너뛰면서 읽으면 매번 캐시에 없는 값을 찾으러 메모리까지 다시 가야 한다.

```java
연속적이다 -> 다음에 읽을 것이 이미 캐시에 와 있다
```

배열이 `LinkedList` 보다 순회가 빠른 이유도 이것이다.

<br/>

## 그런데 다차원 배열은 연속이 아니다

`int[8000][8000]` 이 `6400만` 칸짜리 한 덩어리일 것 같지만 그렇지 않다.

```java
int[][] matrix = new int[3][4];

System.out.println("matrix 타입      = " + matrix.getClass().getSimpleName());
System.out.println("matrix[0] 타입   = " + matrix[0].getClass().getSimpleName());
System.out.println("matrix[0] 주소   = " + System.identityHashCode(matrix[0]));
System.out.println("matrix[1] 주소   = " + System.identityHashCode(matrix[1]));
```

<br/>

### 결과

```java
matrix 타입      = int[][]
matrix[0] 타입   = int[]
matrix[0] 주소   = 498931366
matrix[1] 주소   = 622488023
```

<br/>

`matrix[0]` 과 `matrix[1]` 의 주소가 다르다. 서로 다른 객체라는 뜻이다.

자바에 진짜 `2차원 배열` 은 없고, `배열을 담은 배열` 이 있을 뿐이다.

```java
matrix      -> int[] 를 3개 담고 있는 배열 (주소 3개)
matrix[0]   -> int 를 4개 담고 있는 배열
matrix[1]   -> 또 다른 int 4개짜리 배열 (matrix[0] 과 떨어져 있다)
```

<br/>

한 행 안에서는 연속이지만, 행과 행 사이는 연속이 아니다.

위의 `5` 배 차이가 나온 것도 정확히는 `행 안에서의 연속성` 덕분이다.

<br/>

## 그래서 이런 것도 된다

행마다 길이를 다르게 잡을 수 있다.

```java
int[][] jagged = new int[3][];      // 뒤쪽 길이를 비워둔다
jagged[0] = new int[1];
jagged[1] = new int[5];

System.out.println("jagged[0].length = " + jagged[0].length);
System.out.println("jagged[1].length = " + jagged[1].length);
```

```java
jagged[0].length = 1
jagged[1].length = 5
```

<br/>

진짜 2차원 배열이었다면 불가능한 일이다.

각 행이 독립된 객체라서 길이를 따로 정할 수 있는 것이다.

<br/>

## 배열도 객체다

`new` 로 만들고 힙에 올라가니 당연하지만, 확인해보면 재밌는 점이 있다.

```java
int[] numbers = new int[3];

System.out.println(numbers.getClass().getSimpleName());   // int[]
System.out.println(numbers.length);                       // 3
System.out.println(numbers.toString());                   // [I@1b6d3586
```

<br/>

`getClass()` 도 되고 `toString()` 도 된다. `Object` 를 상속받는 객체이기 때문이다.

`[I` 는 `int 배열` 이라는 뜻의 내부 표기다.

<br/>

그런데 `length` 만 좀 특이하다. 메서드가 아니라 필드처럼 생겼는데, 우리가 정의한 필드는 아니다.

배열 객체를 만들 때 JVM이 길이를 헤더에 적어두고, `arraylength` 라는 전용 명령어로 읽는다.

```java
문자열 길이 -> text.length()   (메서드)
배열 길이   -> numbers.length  (JVM이 헤더에 적어둔 값)
```

<br/>

크기를 바꿀 수 없다는 것도 여기서 나온다.

헤더에 길이가 박힌 채로 딱 그만큼의 공간을 잡고 만들어지기 때문에, 나중에 늘릴 방법이 없다.

<br/>

## 크기를 바꾸고 싶으면 ArrayList

`ArrayList` 도 내부는 그냥 배열이다.

```java
public class ArrayList<E> {
    transient Object[] elementData;
    private int size;
}
```

<br/>

꽉 차면 더 큰 배열을 새로 만들고 기존 내용을 복사해서 옮긴다.

`StringBuilder` 가 커지는 방식과 똑같은데, 그쪽이 `2배 + 2` 라면 `ArrayList` 는 `1.5배` 다.

```java
배열      -> 크기 고정, 대신 군더더기가 없다
ArrayList -> 크기 자동 조절, 대신 옮겨 담는 비용이 가끔 든다
```

미리 크기를 알고 있다면 `new ArrayList<>(1000)` 처럼 잡아두는 것이 좋다는 얘기도 여기서 나온다.
