## Multi process에 대해서 설명해 주세요

multi process란 2개 이상의 process가 동시에 실행되는 것을 말합니다.

동시에라는 말은 동시성(concurrency)와 병렬성(parallelism) 두 가지를 의미합니다.

<br/>

동시성은 cpu core가 1개일 때, 여러 process를 짧은 시간동안 번갈아 

가면서 연산을 하게 되는 시분할 시스템으로 실행되는 것입니다.

<br/>

병렬성은 cpu core가 여러개일 때, 각각의 core가 각각의 

procese를 연산함으로써 process가 동시에 실행되는 것입니다.

<br/>

### 알고 있기

```java
한개의 cpu core는 당연히 한번에 하나의 연산밖에 못한다.
그런데 어떻게 동시에 여러 프로세스를 처리할까?

→ 정답은 "동시성"이다.
```

<br/><br/>

## 그렇다면 동시성이란?

우리는 컴퓨터로 게임도 하면서, 노래도 들으면서, 카톡도 받고, 메일도 보낸다.

cpu는 하나 이기에, 하나밖에 못한다. 

<br/>

그렇기에 cpu가 빠르게 돌아가면서 노래도 틀었다가 게임 했다가 

카톡도 받았다가 하면서 연산이 끊기지 않게 하는 것이 동시성입니다.

<br/>

### 동시성은 시분할로 동시에 실행되는 것 처럼 보이게 합니다.

그리고 왔다갔다 하는 과정을 컨텍스트 스위칭이라고 합니다.

```java
컨텍스트 스위칭이 발생할 경우
이전의 프로세스의 상태를 pcb에 저장하고, 새로운 프로세스의 pcb를 읽어서
저장되어 있는 상태를 복구하는 작업이 이루어 집니다.
```

<br/>

### 병렬성은 뭐야?

cpu가 여러개 이기에, 동시에 각자 프로세스를 연산하면 되는 것이다.

- 실제로 동시에 여러 작업이 처리 된다.

<br/><br/>

## Multi process란?

multi process란 2개 이상의 process가 동시에 실행되는 것을 말합니다.

이 때 process들은 cpu와 메모리를 공유하게 됩니다.

<br/>

### 어떻게?

메모리의 경우에는 여러 process들이 각자의 memory영역을 차지하여 동시에 적재됩니다.

반면 하나의 cpu는 매 순간 하나의 process만 연산할 수 있다.

<br/>

하지만 cpu의 처리 속도가 워낙 빨라서 짧은 시간 동안 여러 process들이 

cpu에서 번갈아 실행되기 때문에 사용자 입장에서는 여러 프로그램이 동시에 실행되는 것처럼 보인다.

<br/>

이처럼 cpu의 작업시간을 여러 process들이 조금씩 나누어 

쓰는 시스템을 `시분할 시스템`이라고 부른다.

<br/><br/>

## cpu의 연산과 PC register

CPU는 PC register가 가리키고 있는 명령어를 읽어들여 연산을 진행한다.

PC register에는 다음에 실행될 명령어의 주소값이 저장되어 있다.

<br/>

멀티 프로세스 시스템에서는 프로세스1이 진행되고 있을 때는 

프로세스1의 코드 영역을 PC register가 가리키다가,프로세스2가 진행되면 

프로세스2의 코드 영역을 pc 레지스터가 가리키게 됩니다. 

<br/>

CPU는 PC register가 가리키는 곳에 따라 process를 변경해가면서 명령어를 읽어들이고 연산을 하게 됩니다.

<br/>

## 궁금증!

```java
동시성과 병렬성의 차이를 숫자로 볼 수 있나
```

같은 양의 계산(덧셈 4억 번)을 스레드 수만 바꿔서 나눠 돌렸다.

이 컴퓨터는 코어가 10개다.

```java
Runtime.getRuntime().availableProcessors()   // = 10
```

<br/>

### 결과

```java
같은 총량을  1 스레드로 = 254 ms
같은 총량을  2 스레드로 = 128 ms     <- 정확히 절반
같은 총량을 10 스레드로 =  38 ms     <- 코어 수까지는 거의 비례해서 준다
같은 총량을 40 스레드로 =  35 ms     <- 코어 수를 넘으면 더 안 준다
```

<br/>

1개에서 10개까지는 시간이 거의 `1/n` 으로 줄었다. 이게 병렬성이다.

코어 10개가 실제로 동시에 계산했기 때문이다.

<br/>

40개로 늘려도 35ms다. 더 줄지 않는다.

코어는 10개뿐이니 나머지 30개는 기다리다가 번갈아 도는 것이다. 이게 동시성이다.

<br/>

원문의 두 정의가 한 실험 안에 다 나온 것이다.

```java
스레드 수 ≤ 코어 수  -> 병렬. 진짜 동시에 돈다
스레드 수 > 코어 수  -> 동시성. 번갈아 돈다. 동시에 도는 것처럼 보일 뿐
```

<br/><br/>

## 코어 10개인데 스레드가 3189개

지금 이 컴퓨터의 상태를 찍어봤다.

```java
$ sysctl -n hw.ncpu       -> 10 코어
$ ps -ax | wc -l          -> 716 프로세스
$ ps -axM | wc -l         -> 3189 스레드
```

<br/>

코어 10개가 스레드 3189개를 굴리고 있다.

<br/>

앞의 pcb는 무엇인가요 글에서 본 상태 분포가 이걸 가능하게 한다.

```java
 712 S   <- 대기
   4 R   <- 실행 중이거나 실행 대기
```

<br/>

3189개 중 실제로 CPU를 원하는 것은 손에 꼽는다.

나머지는 키 입력, 네트워크, 타이머를 기다리며 잠들어 있다.

원문의 `게임하면서 노래 들으면서 카톡 받는다` 가 되는 이유는 CPU가 빨라서가 아니라, 그것들 대부분이 대부분의 시간에 아무것도 안 하고 있기 때문이다.

<br/><br/>

## 시분할이 언제 손해가 되나

CPU만 쓰는 일이면 코어 수 이상의 스레드는 의미가 없다. 위에서 봤다.

<br/>

그런데 기다리는 일이 섞이면 얘기가 달라진다.

```java
스레드 1: DB 응답을 300ms 기다린다  -> 이 동안 코어가 놀고 있다
스레드 2: 그 코어를 받아서 계산한다  -> 놀던 시간을 채운다
```

<br/>

앞의 멀티 쓰레드 글에서 본 톰캣 기본 스레드 200개가 이 계산에서 나온 숫자다.

코어는 몇 개 안 되지만 요청 대부분이 DB나 외부 API를 기다리니, 그 빈 시간을 다른 요청으로 채우는 것이다.

<br/>

정리하면 이렇다.

```java
CPU 를 쓰는 일    -> 스레드 = 코어 수. 더 늘리면 스위치 비용만 든다
기다리는 일      -> 스레드 > 코어 수. 기다리는 동안 다른 것을 돌린다
```

<br/><br/>

## 멀티 프로세스는 언제 멀티 스레드보다 나은가

원문에 크롬 얘기가 나온다. 탭마다 프로세스를 따로 둔다.

<br/>

앞의 process를 설명해 주세요 글에서 확인한 대로, 프로세스는 메모리를 공유하지 않는다.

```java
[부모] shared = 0
  [자식] shared 를 999 로 바꿈
[부모] 자식이 끝난 뒤 shared = 0     <- 영향 없음
```

<br/>

그래서 탭 하나가 죽어도 다른 탭은 멀쩡하다.

스레드였으면 힙을 공유하니 하나가 메모리를 망가뜨리면 전부 죽는다.

<br/>

대가는 비용이다.

```java
스레드 하나   = 0.06 ms
프로세스 하나 = 4.00 ms       <- 60 배 넘게
```

<br/>

크롬은 탭이 수십 개 수준이라 이 비용을 감수할 수 있다.

웹 서버는 초당 수천 요청이라 못 감수한다. 그래서 스레드를 쓴다.

<br/><br/>

## 자바 서버는 보통 프로세스 하나다

JVM 하나가 프로세스 하나다. 그 안에서 스레드를 수백 개 돌린다.

<br/>

멀티 프로세스가 필요하면 애플리케이션 안에서 `fork` 하는 대신 밖에서 한다.

```java
같은 jar 를 서버 두 대에 띄운다
컨테이너를 세 개 띄우고 앞에 로드밸런서를 둔다
```

<br/>

이러면 원문의 `IPC` 가 네트워크 통신이 된다.

프로세스끼리 메모리를 못 공유하니 상태는 DB나 Redis 같은 바깥에 둔다.

<br/>

앞의 WAS 서버와 WEB 서버의 이해 글에서 본 블루그린 배포가 이 구조 위에서 가능한 것이다.

프로세스가 독립적이라 하나를 내리고 올려도 다른 하나는 요청을 계속 받는다.

<br/>

멀티 프로세스의 `독립적이라 안전하다` 는 장점을 한 컴퓨터 안이 아니라 여러 컴퓨터에 걸쳐 쓰는 셈이다.
