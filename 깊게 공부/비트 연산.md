## 비트 연산

<br/>

## 정수는 비트 32개다

```java
Integer.toBinaryString(5)  = 00000000000000000000000000000101
Integer.toBinaryString(-5) = 11111111111111111111111111111011
```

<br/>

`-5` 가 저렇게 되는 이유가 2의 보수다.

```java
5 의 비트를 전부 뒤집고 (~5) -> 1 을 더한다 -> -5
```

<br/>

맨 앞 비트가 1이면 음수다. 그래서 `int` 의 범위가 `-2^31 ~ 2^31 - 1` 로 음수 쪽이 하나 더 크다.

<br/>

앞의 Comparable과 Comparator 글에서 본 `Integer.MAX_VALUE + 1` 이 음수가 되는 것도 이 표현 때문이다.

`0111...1` 에 1을 더하면 `1000...0` 이 되고, 맨 앞이 1이니 음수다.

<br/><br/>

### 시프트

```java
1 << 10   = 1024           (2 의 10 제곱. 곱셈보다 빠르다)
-16 >> 2  = -4             (부호 유지. 나누기 4)
-16 >>> 2 = 1073741820     (부호 무시. 0 으로 채움)
```

<br/>

`>>` 는 왼쪽을 부호 비트로 채우고, `>>>` 는 0으로 채운다.

음수에서만 차이가 난다.

<br/>

앞의 이진 탐색 글에서 본 `(lo + hi) >>> 1` 이 `>>>` 를 쓴 이유다.

`lo + hi` 가 오버플로로 음수가 되어도 `>>>` 로 나누면 올바른 양수가 나온다.

<br/>

### 시프트의 함정

```java
1 << 33 = 2        <- 2^33 이 아니다
```

<br/>

`int` 는 32비트라 시프트 양을 32로 나눈 나머지만 쓴다. `33 % 32 = 1` 이라 `1 << 1` 이다.

`long` 이면 64로 나눈다.

<br/>

앞의 비트마스크로 부분집합을 만들 때 `1 << n` 에서 `n` 이 31을 넘으면 여기서 틀린다.

<br/><br/>

## 마스크 : 플래그 여러 개를 int 하나에

```java
READ = 1, WRITE = 2, EXEC = 4          // 각자 다른 비트

flags |= READ | EXEC;                  // 켠다      -> 101
(flags & WRITE) != 0                   // 켜져 있나 -> false
flags &= ~WRITE;                       // 끈다
flags ^= READ;                         // 뒤집는다
```

<br/>

`chmod 755` 가 이것이다.

```java
7 = 111 = rwx
5 = 101 = r-x
```

<br/>

`boolean` 8개 대신 `int` 하나다. 앞의 객체 헤더와 메모리 정렬 글에서 본 대로 8바이트가 4바이트가 된다.

객체가 수백만 개면 의미 있는 차이다.

<br/>

자바 API에서도 이 방식이 있다.

```java
Modifier.isPublic(method.getModifiers())        // 리플렉션의 접근 제한자
Pattern.compile(regex, Pattern.CASE_INSENSITIVE | Pattern.MULTILINE)
```

## 나머지 연산 대신 &

```java
37 % 16 = 5,  37 & 15 = 5      <- 같다
37 % 10 = 7,  37 & 9  = 1      <- 다르다
```

<br/>

나누는 수가 2의 거듭제곱일 때만 `& (n-1)` 이 `% n` 과 같다.

`n-1` 이 하위 비트가 전부 1인 마스크가 되기 때문이다. `16 - 1 = 15 = 1111`.

<br/>

앞의 해시 테이블 충돌과 리사이즈 글에서 본 `HashMap` 이 버킷을 찾을 때 이걸 쓴다.

용량을 2의 거듭제곱으로 유지하는 이유가 이 한 줄 때문이다.

앞의 큐 글에서 본 `ArrayDeque` 의 원형 인덱스도 같다.

<br/><br/>

## 자주 쓰는 것들

```java
Integer.bitCount(255)        = 8     (1 의 개수. popcount)
Integer.highestOneBit(100)   = 64    (100 이하 최대 2 의 거듭제곱)
Integer.numberOfTrailingZeros(8) = 3 (2 의 몇 제곱인가)
(n & 1) == 0                 -> 짝수
(n & (n - 1)) == 0           -> 2 의 거듭제곱인가 (n > 0)
x ^ x = 0,  x ^ 0 = x        -> XOR 의 성질
```

<br/>

마지막 XOR 성질로 유명한 문제가 있다.

```java
배열에서 하나만 빼고 전부 두 번씩 나온다. 하나만 나온 것을 찾아라
-> 전부 XOR 하면 두 번 나온 것은 0 이 되고 하나만 남는다
```

<br/>

앞의 완전탐색 글에서 본 비트마스크 부분집합도 이 연산들이다.

```java
for (int mask = 0; mask < (1 << n); mask++)
    if ((mask & (1 << i)) != 0)    // i 번째가 포함됐나
```

## 네트워크와 저수준에서

```java
IP 주소 192.168.1.10 을 int 하나로   - 4 바이트를 8 비트씩 시프트해서 합친다
서브넷 마스크 /24                   - 상위 24 비트가 1. ip & mask 로 네트워크 주소
RGB 색상 0xFF8800                  - (rgb >> 16) & 0xFF 가 빨강
```

<br/>

앞의 엔디언(Byte Order) 글에서 본 대로 바이트를 합치고 쪼갤 때 시프트와 마스크가 기본 도구다.

```java
int value = (b[0] & 0xFF) << 24 | (b[1] & 0xFF) << 16 | (b[2] & 0xFF) << 8 | (b[3] & 0xFF);
```

<br/>

`& 0xFF` 를 빼먹으면 `byte` 가 `int` 로 바뀔 때 부호가 확장되어 상위 비트가 1로 채워진다.

`byte` 가 부호 있는 타입이라 생기는 함정이다.

<br/><br/>

## 정리

```java
음수 = 2 의 보수. 맨 앞 비트가 부호
>> 는 부호 유지, >>> 는 0 채움. 시프트 양은 32 로 나눈 나머지
& (n-1) 은 n 이 2 의 거듭제곱일 때 % n. HashMap 이 쓴다
플래그는 int 하나에 비트로. chmod, Modifier, Pattern 플래그가 이 방식
```

<br/>

앞의 분기 예측 글에서 본 `분기 없는 코드` 도 비트 연산으로 만들었다.

`if` 를 산술로 바꾸는 도구가 결국 이것들이다.
