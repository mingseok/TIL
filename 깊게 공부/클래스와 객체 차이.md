## 클래스와 객체 차이


클래스는 객체를 만들어내기 위한 설계도 혹은 틀 이라고 할 수 있고, 객체를 생성하는데 사용합니다.

객체는 설계도(클래스)를 기반으로 생성되며, 자신의 고유 이름과 상태, 행동을 갖습니다.

<br/>

여기서 상태는 필드(fields), 행동은 메소드(Method)라고 표현합니다.

객체에 메모리가 할당되어 실제로 활용되는 실체는 '인스턴스'라고 부릅니다.


<br/>

## 클래스와 객체

- 클래스의 정의 : 클래스란 객체를 정의해 놓은 것이다.

- 클래스의 용도 : 클래스는 객체를 생성하는데 사용된다.

- 객체의 정의: 실제로 존재하는 것, 사물 또는 개념
- 객체의 용도: 객체가 가지고 있는 기능과 속성에 따라 다름

```
유형의 객체: 책상, 의자, 자동차, TV
무형의 객체: 수학공식, 프로그램 에러와 같은 논리나 개념
```

<br/>

## JVM 메모리 위치

`클래스` : 실행 시 클래스는 JVM 메모리의 `클래스 영역(Class Area)`에 로드된다.

`인스턴스` : `힙 영역(Heap Area)`에 새로운 인스턴스(객체)를 생성할 수 있다.

<br/>


## 예를 들어보면,

붕어빵은 붕어빵 틀이라는 곳에서 무한히 만들어집니다.

이 때 붕어빵을 객체라고 한다면, 붕어빵 틀을 클래스라고 할 수 있습니다.

<br/>

실제로 우리가 먹는 것은 붕어빵이지 붕어빵 틀이 아닙니다.

즉 클래스 또한, 객체를 생성하는데 사용될 뿐 객체 그 자체가 아닙니다.

<br/>

## 정리

- 객체(Object)란 자신 고유의 속성을 가지는 유형의 객체, 추상적인 모든 대상.

- 클래스(Class)란 객체들을 소프트웨어 내에서 구현하기 위해 만든 설계도이다.
    - 이를 통해 생성된 객체 하나하나를 인스턴스(Instance)라고 부른다.
    
    - 대체로 객체와 인스턴스는 혼용해서 표현한다.

<br/>

## 궁금증!

```java
붕어빵 틀은 하나뿐인데, 클래스도 메모리에 하나만 있는 걸까?
```

그렇다. 그리고 그 클래스도 사실은 객체다.

```java
Member a = new Member("민석");
Member b = new Member("영한");

System.out.println("a = " + System.identityHashCode(a) + " / " + a.getName());
System.out.println("b = " + System.identityHashCode(b) + " / " + b.getName());

System.out.println("a.getClass() == b.getClass() : " + (a.getClass() == b.getClass()));
System.out.println("a.getClass() == Member.class : " + (a.getClass() == Member.class));
System.out.println("클래스 객체도 주소가 있다 = " + System.identityHashCode(Member.class));
```

<br/>

### 결과

```java
a = 498931366 / 민석
b = 1933863327 / 영한

a.getClass() == b.getClass() : true
a.getClass() == Member.class : true
클래스 객체도 주소가 있다 = 724542711
```

<br/>

인스턴스 `a` 와 `b` 는 주소가 다르다. 서로 다른 객체라는 뜻이다.

그런데 둘의 `getClass()` 는 `==` 로 비교해도 `true` 가 나온다. 같은 객체를 보고 있는 것이다.

<br/>

클래스가 로드될 때 그 클래스를 설명하는 `Class` 객체가 딱 하나 만들어진다.

`Member.class` 라고 적어서 꺼내 쓰는 것이 바로 그 객체다.

```java
붕어빵     -> new 할 때마다 새로 만들어진다
붕어빵 틀  -> 클래스가 로드될 때 하나만 만들어지고, 계속 그것을 쓴다
```

<br/>

리플렉션이 가능한 이유가 이것이다.

`Class` 객체가 필드 목록과 메서드 목록을 들고 있어서, 실행 중에 그걸 물어볼 수 있다.

스프링이 `@Autowired` 붙은 필드를 찾아내는 것도 이 정보를 읽는 것이다.

<br/>

## 인스턴스마다 따로인 것과 하나뿐인 것

객체를 두 개 만들었을 때 무엇이 두 벌이고 무엇이 한 벌일까.

```java
class Member {
    private static int count = 0;   // 몇 개를 만들든 하나
    private final String name;      // 객체마다 하나씩

    Member(String name) {
        this.name = name;
        count++;
    }

    String getName() {              // 코드는 한 벌만 존재한다
        return name;
    }

    static int getCount() {
        return count;
    }
}
```

<br/>

```java
System.out.println("만들어진 개수 = " + Member.getCount());
```

```java
만들어진 개수 = 2
```

<br/>

`name` 은 `a` 에 하나, `b` 에 하나씩 따로 있다. 그래서 `민석` 과 `영한` 이 각각 나온다.

`count` 는 몇 개를 만들든 하나뿐이라, 두 객체가 같은 숫자를 같이 올린다.

<br/>

메서드도 마찬가지다. `getName()` 의 코드가 객체마다 복사되는 것이 아니다.

코드는 클래스 쪽에 한 벌만 있고, 부를 때 `어떤 객체에 대해서인지` 만 같이 넘긴다.

```java
a.getName()   -> getName 코드에 "a" 를 넘겨서 실행
b.getName()   -> 같은 코드에 "b" 를 넘겨서 실행
```

<br/>

메서드 안에서 쓰는 `this` 가 바로 그 넘어온 객체다.

`static` 메서드에 `this` 가 없는 이유도 여기서 나온다. 넘겨받는 객체가 없기 때문이다.

<br/>

## 그래서 붕어빵 비유를 조금 더 정확히 하면

```java
붕어빵 틀 (클래스)      -> 어떤 모양인지 적힌 정보 + 굽는 방법(메서드 코드), 하나만 존재
붕어빵 (인스턴스)       -> 틀로 찍어낸 실체, 만들 때마다 새로 생김
붕어빵에 든 팥 (필드)   -> 붕어빵마다 다를 수 있음
가게 판매 개수 (static) -> 붕어빵이 몇 개든 가게에 하나
```

객체는 자기 상태만 들고 있고, 행동은 클래스가 들고 있다.

`객체를 만든다` 는 것은 정확히는 `그 클래스의 상태를 담을 자리를 힙에 하나 잡는다` 는 뜻인 것이다.
