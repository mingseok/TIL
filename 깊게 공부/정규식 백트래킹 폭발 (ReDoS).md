## 정규식 백트래킹 폭발 (ReDoS)

<br/>

## 정규식은 어떻게 매칭하나

대부분의 정규식 엔진은 백트래킹 방식이다.

```java
패턴의 첫 부분을 맞춰본다
-> 안 맞으면 한 글자 물러나서 다른 방법으로 맞춰본다
-> 전부 실패하면 그 앞으로 물러난다
```

<br/>

`갔다가 안 되면 돌아온다` 가 백트래킹이다.

앞의 깊이 우선 탐색의 예제 글에서 본 그 백트래킹과 같은 것이다.

<br/><br/>

## 궁금증!

```java
어떤 패턴이 얼마나 느려지나
```

`(.*a){12}` 를 `aaaa...a!` 에 매칭했다. 끝에 `!` 가 있어서 매칭이 실패하는 입력이다.

<br/>

### 결과

```java
길이 24 =  184 ms
길이 26 =  560 ms
길이 28 = 1485 ms
길이 30 = 3690 ms
```

<br/>

글자 2개 늘어날 때마다 2.5배씩 늘어난다. 지수적이다.

<br/>

길이 40이면 수십 분이다. 사용자가 입력창에 `a` 40개와 `!` 를 넣으면 서버 코어 하나가 몇 분간 묶인다.

이걸 ReDoS(정규식 서비스 거부)라고 부른다.

<br/><br/>

## 왜 폭발하나

`.*` 12개가 `a` 24개를 나누는 모든 방법을 시도하기 때문이다.

```java
첫 .* 가 24개 전부 먹고 -> 다음 a 가 없어서 실패 -> 23개 먹고 -> ... 
둘째 .* 도 같은 방식으로
열두 번째까지
```

<br/>

조합 수가 지수적으로 는다. 마지막 `!` 때문에 어떻게 나눠도 실패하는데, 실패를 확정하려면 전부 시도해야 한다.

<br/>

앞의 완전탐색 글에서 본 `2^n` 이 정규식 안에서 일어나는 것이다.

<br/><br/>

## 자바 9 이후 엔진은 고전적인 것을 막아놨다

교과서의 대표 예시들을 돌려봤다.

```java
(a+)+$       n=16~28 : 전부 0 ms
(a|aa)+$     n=16~28 : 전부 0 ms
(x+x+)+y     n=16~28 : 전부 0 ms
```

<br/>

전부 순식간에 끝났다. 폭발하지 않는다.

<br/>

자바 9에서 정규식 엔진에 최적화가 들어갔다. 중첩 반복에서 같은 위치를 다시 시도하는 것을 기억해서 건너뛴다.

그래서 `(a+)+` 형태로는 이제 안 터진다.

<br/>

그런데 `(.*a){12}` 는 터졌다. `{n}` 반복 안의 `.*` 는 그 최적화가 못 잡는 모양이다.

`자바는 ReDoS 에 안전하다` 가 아니라 `일부 패턴만 막았다` 는 것이다.

<br/><br/>

## 위험한 모양

```java
중첩 반복           (a+)+, (a*)*, ([a-z]+)*
겹치는 선택지의 반복  (a|a)+, (a|ab)*, (\w+\s?)*
반복 안의 .*        (.*a){n}
```

<br/>

공통점은 `같은 문자열을 여러 방법으로 나눠 맞출 수 있다` 는 것이다.

나누는 방법이 여럿이면 실패할 때 전부 시도한다.

<br/>

이메일 검증에 흔한 것도 해당된다.

```java
^([a-zA-Z0-9]+\.?)+@
```

<br/>

`abc.def.ghi` 를 `+` 와 `\.?` 가 여러 방법으로 나눌 수 있다.

<br/><br/>

## 막는 방법

```java
1. 사용자 입력에는 길이 제한을 먼저 건다     - 이메일 254자, 이름 50자
2. 중첩 반복을 피한다                       - (a+)+ 대신 a+
3. 소유 한정자 / 원자 그룹                   - a++ , (?>a+) : 물러나지 않는다
4. 타임아웃을 건다                           - 자바 정규식에는 없다. 다른 스레드에서 돌리고 interrupt
5. 백트래킹 없는 엔진                        - RE2, Rust regex. 자바는 RE2J 라이브러리
```

<br/>

`1번` 이 제일 확실하다.

위 실험에서 길이 24는 184ms지만 길이 12는 0ms다. 입력이 짧으면 지수 폭발도 작은 수다.

<br/>

`3번` 의 소유 한정자는 자바 정규식에 있다.

```java
(a+)+$      -> 물러난다
(a++)+$     -> a++ 는 먹은 것을 안 돌려준다. 시도가 한 가지로 준다
```

<br/><br/>

## 정규식 자체의 비용

```java
매번 Pattern.matches()    = 72 ms   (20만 번)
compile 한 번 재사용       = 13 ms
```

<br/>

`String.matches()` 와 `Pattern.matches()` 는 부를 때마다 컴파일한다.

패턴을 상수로 빼서 `Pattern.compile` 을 한 번만 하면 5배 빠르다.

```java
private static final Pattern PHONE = Pattern.compile("\\d{3}-\\d{4}");
```

<br/>

`String.split(",")` 도 안에서 정규식을 쓴다. 한 글자면 최적화 경로를 타지만, 두 글자 이상이면 매번 컴파일한다.

<br/><br/>

## 정리

```java
백트래킹 정규식은 실패하는 입력에서 지수적으로 느려질 수 있다. 실측 2 글자당 2.5 배
자바 9+ 는 (a+)+ 류를 막았지만 (.*a){n} 류는 여전히 터진다
사용자 입력 정규식은 길이 제한이 먼저. 중첩 반복을 피하고 소유 한정자를 쓴다
Pattern 은 상수로 빼서 재사용한다
```

<br/>

앞의 해시 테이블 충돌과 리사이즈 글에서 본 해시 충돌 공격과 같은 부류다.

`입력 하나로 서버 CPU 를 태우는` 공격이고, 둘 다 `최악 경우의 시간 복잡도` 를 노린다.
