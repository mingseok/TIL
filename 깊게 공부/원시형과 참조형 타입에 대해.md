## 원시형과 참조형 타입에 대해

`원시 타입`은 정수, 실수, 문자 등의 실제 데이터 값을 저장하는 타입이고,

`참조 타입`은 객체의 번지를 참조하는 타입으로 메모리 번지 값을 통해 객체를 참조하는 타입

<br/>

## 각각 메모리에 저장되는 위치는?

- 원시타입은 `'스택' 메모리`에 값이 존재합니다

- 참조타입은 하나의 인스턴스이기 때문에 ‘스택’ 메모리에는 참조값만 있고, 실제 값은 힙 메모리에 존재합니다
    

원시 타입보다 참조 타입이 사용하는 메모리양이 압도적으로 높습니다

<br/>

## 궁금증!

```java
"원시형은 스택에 있다" 라는 말은 항상 맞을까?
```

메서드 안에서 선언한 지역 변수라면 맞다. 그런데 필드로 선언하면 얘기가 달라진다.

```java
public class Where {
    public static void main(String[] args) {
        Box box = make();
        System.out.println("메서드가 끝난 뒤 = " + box.value);
    }

    static Box make() {
        int local = 10;      // 이 int는 make()가 끝나면 사라진다
        Box box = new Box();
        box.value = local;   // 이 int는?
        return box;
    }
}

class Box {
    int value;
}
```

<br/>

### 결과

```java
메서드가 끝난 뒤 = 10
```

`make()` 의 스택 프레임은 이미 사라졌는데 `box.value` 는 살아 있다.

스택에 있었다면 프레임과 함께 없어졌어야 하는 값이다.

`int` 지만 객체 안에 들어 있는 필드라서, 그 객체가 있는 힙에 같이 따라간 것이다.

<br/>

## 위치를 정하는 것은 타입이 아니라 선언한 자리다

원시형이냐 참조형이냐가 정하는 것은 위치가 아니라, `그 칸에 무엇이 들어가는가` 이다.

```java
원시형  -> 그 칸에 값이 통째로 들어간다
참조형  -> 그 칸에 주소만 들어가고, 실제 객체는 힙에 따로 있다
```

위치는 그 변수를 어디에 선언했는지가 정한다.

```java
메서드 안 지역 변수 int      -> 스택 프레임 안
필드로 선언한 int            -> 객체 안 (= 힙)
메서드 안 지역 변수 String   -> 주소는 스택, 객체는 힙
필드로 선언한 String         -> 주소도 객체 안(힙), 객체도 힙
static 으로 선언한 int       -> 객체마다 있는 것이 아니라 클래스 쪽에 딸려 있다
```

`int` 라고 무조건 스택인 것이 아니고, 참조형이라고 무조건 힙에만 있는 것도 아니다.

<br/>

## 생각해보기 ex1)

메서드에 넘겼을 때 원본이 바뀌는지 보자.

```java
public class Copy {
    public static void main(String[] args) {
        int number = 10;
        change(number);
        System.out.println("원시형 = " + number);

        Box box = new Box();
        box.value = 10;
        change(box);
        System.out.println("참조형 = " + box.value);

        Box other = new Box();
        other.value = 10;
        replace(other);
        System.out.println("바꿔치기 = " + other.value);
    }

    static void change(int value) {
        value = 99;
    }

    static void change(Box box) {
        box.value = 99;
    }

    static void replace(Box box) {
        box = new Box();
        box.value = 99;
    }
}

class Box {
    int value;
}
```

<br/>

### 결과

```java
원시형 = 10
참조형 = 99
바꿔치기 = 10
```

앞의 두 줄은 예상대로다. 값을 복사해서 넘기면 원본이 안 바뀌고, 주소를 복사해서 넘기면 같은 객체를 가리키니 원본이 바뀐다.

<br/>

재밌는 것은 세 번째 줄이다.

`replace()` 안에서 `box` 에 새 객체를 넣었는데 바깥의 `other` 는 그대로 `10` 이다.

넘어간 것은 객체 자체가 아니라 `주소를 적어둔 값` 이기 때문이다.

그 값을 다른 주소로 덮어써봐야 바깥 변수와는 상관이 없는 것이다.

```java
자바는 참조형도 "주소값을 복사해서" 넘긴다
-> 객체 안을 고치는 것은 통하고, 객체를 통째로 바꿔치기 하는 것은 안 통한다
```

## 생각해보기 ex2)

메모리 차이가 얼마나 나는지 직접 재보자. `1000만` 개씩 담아본다.

```java
public class Size {
    static final int N = 10_000_000;

    public static void main(String[] args) {
        System.out.println("int[]     : " + measure(true) + "MB");
        System.out.println("Integer[] : " + measure(false) + "MB");
    }

    static long measure(boolean primitive) {
        System.gc();
        long before = used();
        Object keep;
        if (primitive) {
            int[] array = new int[N];
            for (int i = 0; i < N; i++) array[i] = i;
            keep = array;
        } else {
            Integer[] array = new Integer[N];
            for (int i = 0; i < N; i++) array[i] = i;
            keep = array;
        }
        long after = used();
        return (after - before) / 1024 / 1024;
    }

    static long used() {
        Runtime r = Runtime.getRuntime();
        return r.totalMemory() - r.freeMemory();
    }
}
```

<br/>

### 결과

```java
int[]     : 38MB
Integer[] : 200MB
```

`5` 배가 넘게 차이가 난다.

`int` 는 `4` 바이트짜리 값이 배열에 그대로 줄지어 들어간다.

반면 `Integer` 는 배열에 주소만 들어가고, 그 주소가 가리키는 곳에 객체가 따로 하나씩 만들어진다.

객체는 값 말고도 헤더를 달고 있어서, 숫자 하나 담자고 그보다 몇 배 큰 공간을 쓰게 되는 것이다.

<br/>

```java
느리다는 얘기가 나오는 것도 여기서다.
주소를 따라 한 번 더 건너가야 하고, 계산할 때는 박싱과 언박싱까지 붙는다.
다만 이건 래퍼 클래스 얘기지, 참조형 전부가 박싱을 하는 것은 아니다.
```

## 원시 타입과 참조 타입 차이

1. `Null` 포함 가능 여부

    - 원시타입은 `null`을 담을 수 없지만, 참조 타입은 가능하다

2. 제네릭 타입에서 사용 가능 여부

    - 원시타입은 제네릭 타입에서 사용할 수 없지만, 참조 타입은 가능하다

3. `==` 가 무엇을 비교하는지

    - 원시타입의 `==` 는 값을 비교한다
    - 참조타입의 `==` 는 값이 아니라 주소를 비교한다

<br/>

`3번` 때문에 문자열을 `==` 로 비교하면 안 된다는 말이 나오는 것이다.

담긴 글자가 같아도 서로 다른 객체면 주소가 다르니 `false` 가 나온다.

내용을 보고 싶으면 `equals` 로 비교해야 한다.
