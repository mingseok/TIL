## 불변 객체 설명 / 불변 객체나 final을 굳이 사용해야 하는 이유가 있나요?

## 불변 객체가 무엇인가?

불변 객체는 객체 생성 이후 내부의 상태가 변하지 않는 객체를 말합니다.

즉, 한 번 생성된 불변 객체의 상태는 그 이후에 변경할 수 없다.

<br/>

Java에서는 필드가 원시 타입인 경우 final 키워드를 사용해 불변 객체를 

만들 수 있고, 
참조 타입일 경우엔 추가적인 작업이 필요합니다.

<br/>

## 궁금증!

```java
"추가적인 작업"이라는 게 무엇일까? final만 붙이면 되는 것 아닌가?
```

`final` 이 지켜주는 것은 `그 칸에 담긴 값` 하나뿐이다.

원시 타입이면 값이 곧 전부라서 그걸로 끝난다.

그런데 참조 타입은 그 칸에 주소가 담겨 있다. `final` 은 주소를 못 바꾸게 막을 뿐,

그 주소가 가리키는 객체 안이 바뀌는 것은 막지 못한다.

```java
import java.util.ArrayList;
import java.util.List;

public class Immutable {
    public static void main(String[] args) {
        List<String> hobbies = new ArrayList<>();
        hobbies.add("독서");

        Person person = new Person("민석", hobbies);
        System.out.println("생성 직후 = " + person.getHobbies());

        hobbies.add("등산");
        System.out.println("바깥 리스트를 건드린 뒤 = " + person.getHobbies());

        person.getHobbies().add("낚시");
        System.out.println("getter로 받아서 건드린 뒤 = " + person.getHobbies());
    }
}

class Person {
    private final String name;
    private final List<String> hobbies;   // final을 붙였다

    Person(String name, List<String> hobbies) {
        this.name = name;
        this.hobbies = hobbies;
    }

    List<String> getHobbies() {
        return hobbies;
    }
}
```

<br/>

### 결과

```java
생성 직후 = [독서]
바깥 리스트를 건드린 뒤 = [독서, 등산]
getter로 받아서 건드린 뒤 = [독서, 등산, 낚시]
```

`final` 을 붙였는데도 `Person` 의 상태가 두 번이나 바뀌었다.

구멍이 두 군데다.

- 생성자로 받은 리스트를 그대로 들고 있어서, 넘겨준 쪽이 계속 그 리스트를 쥐고 있다

- `getter` 가 내부 리스트를 그대로 내줘서, 받은 쪽이 마음대로 고칠 수 있다

<br/>

## 그래서 들어올 때와 나갈 때 둘 다 막아야 한다

이것을 `방어적 복사` 라고 부른다.

```java
class Person {
    private final String name;
    private final List<String> hobbies;

    Person(String name, List<String> hobbies) {
        this.name = name;
        this.hobbies = new ArrayList<>(hobbies);   // 들어올 때 복사
    }

    List<String> getHobbies() {
        return List.copyOf(hobbies);               // 나갈 때도 막는다
    }
}
```

<br/>

### 결과

```java
바깥 리스트를 건드린 뒤 = [독서]
getter로 받은 것에 추가 = UnsupportedOperationException
```

이제 바깥에서 아무리 흔들어도 `Person` 은 그대로다.

`final` 은 시작일 뿐이고, 참조 타입까지 불변으로 만들려면 이 두 가지가 같이 가야 하는 것이다.

<br/>

## 불변 객체나 final 키워드를 사용해 얻는 이점

1. `Thread-Safe`하여 병렬 프로그래밍에 유용하며, 동기화를 고려하지 않아도 된다.

    - 공유 자원이 불변이기 때문에 항상 동일한 값을 반환하기 때문

2. 실패 원자적인 메소드를 만들 수 있다.
    - 어떠한 예외가 발생되더라도 메소드 호출 전의 상태를 유지할 수 있어
        
        예외 발생 전과 똑같은 상태로 다음 로직 처리 가능
        
3. 부수효과를 피해 오류를 최소화 할 수 있다.
    - 부수효과 : 변수의 값이 바뀌거나 객체의 필드 값을 설정하거나
        
        예외나 오류가 발생하여 실행이 중단되는 현상
        
4. 메소드 호출 시 파라미터 값이 변하지 않는다는 것을 보장할 수 있다.

5. 가비지 컬렉션 성능을 높일 수 있다.

<br/>

## 1번이 성립하는 이유

동시성 문제는 `누군가 값을 읽는 도중에 다른 누가 그 값을 바꿔서` 생긴다.

읽는 동작만 있으면 아무리 많은 스레드가 동시에 들어와도 서로 방해할 일이 없다.

불변 객체는 쓰는 동작 자체가 없으니, 지킬 것이 없어서 락도 필요 없는 것이다.

```java
가변 객체 -> 읽는 사람과 쓰는 사람이 섞인다 -> 순서를 정해줘야 한다 (락)
불변 객체 -> 읽는 사람만 있다               -> 정해줄 순서가 없다
```

<br/>

## 2번은 코드로 보면 확실하다

`잔액에서 빼고 나서 검사` 하는 가변 객체와, `검사를 통과해야 만들어지는` 불변 객체를 비교해보자.

```java
class MutableMoney {
    private int amount;

    void minus(int value) {
        this.amount -= value;
        if (this.amount < 0) {
            throw new IllegalStateException("잔액 부족");
        }
    }
}

class ImmutableMoney {
    private final int amount;

    ImmutableMoney(int amount) {
        if (amount < 0) {
            throw new IllegalArgumentException("잔액 부족");
        }
        this.amount = amount;
    }

    ImmutableMoney minus(int value) {
        return new ImmutableMoney(this.amount - value);
    }
}
```

<br/>

잔액 `1000` 원에서 `3000` 원을 빼려다 예외가 났을 때 각각 얼마가 남아 있을까.

```java
예외 후 가변 객체 = -2000
예외 후 불변 객체 = 1000
```

가변 쪽은 이미 깎아놓고 나서 예외를 던졌기 때문에, 실패했는데도 잔액이 `-2000` 으로 망가져 있다.

불변 쪽은 새 객체를 만들다가 실패한 것이라 원래 객체는 손도 대지 않았다.

```java
실패했으면 아무 일도 없었던 것처럼 남아야 한다 -> 이것이 실패 원자성
```

<br/>

## 그럼 단점은 없는가?

값을 바꿀 때마다 새 객체를 만들어야 한다.

`1000` 원에서 `1` 원씩 천 번 빼면 객체가 천 개 만들어지는 것이다.

<br/>

그런데도 불변을 권하는 이유는, 이렇게 만들어진 객체 대부분이 금방 죽기 때문이다.

금방 죽는 객체를 치우는 것은 GC가 가장 잘하는 일이라서 생각만큼 비싸지 않다.

원문의 `5번` 이 말하는 것이 이 얘기다.

<br/>

다만 `for` 문 안에서 큰 객체를 계속 새로 만드는 식이면 얘기가 달라진다.

문자열을 반복문에서 `+` 로 붙이면 안 된다는 것도 결국 같은 이유인 것이다.
