## 스프링 컨테이너 내부 동작

<br/>

## 스프링 컨테이너란?

스프링에서 `의존관계 주입(Dependency Injection, DI)`을 이용하여 
애플리케이션을 

구성하는 여러 빈들의 `생명주기(Lifecycle)`와 애플리케이션의 서비스 실행 등을 관리하며 

생성된 인스턴스들에게 기능을 제공하는 것이 `스프링 컨테이너` 입니다.

```java
컨테이너에 적절한 설정만 있다면 개발자의 개입 없이도,
작성된 코드를 컨테이너가 빈을 스스로 참조한 뒤 알아서 관리한다.
```

<br/><br/>

## **빈 팩토리**

빈 팩토리는 스프링 컨테이너의 가장 기본적인 형태입니다.

- 빈을 `생성`하고, 의존관계를 `설정`하는 기능을 담당하는 가장 기본적인 `IoC 컨테이너`이다.

```java
"스프링 컨테이너는 빈 팩토리를 확장하고 다양한 부가 기능을 추가한 것입니다."
```

<br/><br/>

## 스프링 컨테이너

`ApplicationContext`를 → 스프링 컨테이너라 한다.

`ApplicationContext`는 `BeanFactory`를 구현하고 있어 
`BeanFactory`의 확장된 버전이라고 생각하면 좋다.

<br/>

### 참고로

- '빈 팩토리(BeanFactory)'라고 말할 때는 빈을 `생성`하고 관계를
    `설정`하는 `IoC`의 `기본 기능`에 초점을 맞춘 것이고,
    
- `ApplicationContext`는 별도의 정보를 `참고`해서, `빈의 생성`, `관계 설정` 등의
    `제어를 총괄`하는 것에 초점을 맞춘 것이다.
    

```java
"BeanFactory" vs "ApplicationContext"
두 컨테이너 중 특별한 이유가 없다면 "ApplicationContext"를 사용해야 한다고 한다.
```

<br/>

### 그 이유로는

- `Environment`
    - 프로파일을 `설정`하고, 어떤 것을 사용할지 `선택`할 수 있게 해주며,
        
        `소스 설정` 및 `프로퍼티` 값을 가져오게 해준다.
        
- `MessageSource`
    
    메시지에 대한 국제화을 제공하는 인터페이스이다.
    
    - 소프트웨어가 언어에 `종속적`이지 않고, `한국어든`, `영어든` 동시에
        
        입력해서 사용할 수 있어야 하는 것을 `만족` 시켜주는 것을 말한다.
<br/>

## 궁금증!

```java
"ApplicationContext 는 BeanFactory 의 확장" 이라는데, 무엇이 더 붙어 있는 걸까?
```

`instanceof` 로 하나씩 확인해봤다.

```java
AnnotationConfigApplicationContext context = new AnnotationConfigApplicationContext(ContConfig.class);

System.out.println("BeanFactory               = " + (context instanceof BeanFactory));
System.out.println("EnvironmentCapable        = " + (context instanceof EnvironmentCapable));
System.out.println("MessageSource             = " + (context instanceof MessageSource));
System.out.println("ApplicationEventPublisher = " + (context instanceof ApplicationEventPublisher));
System.out.println("ResourcePatternResolver   = " + (context instanceof ResourcePatternResolver));
```

<br/>

### 결과

```java
BeanFactory               = true
EnvironmentCapable        = true
MessageSource             = true
ApplicationEventPublisher = true
ResourcePatternResolver   = true
```

<br/>

다섯 개를 전부 구현하고 있다. 각각이 하나씩의 능력이다.

```java
BeanFactory               - 빈을 만들고 꺼내주는 기본 기능
EnvironmentCapable        - 프로파일과 설정값 (application.yml, 환경변수)
MessageSource             - 국제화 메시지
ApplicationEventPublisher - 이벤트 발행과 구독
ResourcePatternResolver   - classpath:*.xml 같은 패턴으로 파일 읽기
```

<br/>

원문에서 `Environment` 와 `MessageSource` 를 이유로 든 것이 이 목록의 일부다.

`ApplicationContext` 는 이 인터페이스들을 다 물려받은 `모아놓은 인터페이스` 인 셈이다.

<br/>

이렇게 나눠놓은 덕분에, 빈이 필요한 것만 주입받을 수 있다.

```java
@Component
@RequiredArgsConstructor
class MyBean {
    private final ApplicationEventPublisher publisher;   // 이벤트 발행만 필요하면 이것만
}
```

<br/>

`ApplicationContext` 통째로 주입받으면 그 빈이 컨테이너 전체를 알게 된다.

필요한 조각만 받으면 결합도가 낮아진다.

<br/>

## 빈은 언제 만들어지는가

컨테이너가 뜰 때 다 만드는지, 꺼낼 때 만드는지 찍어봤다.

```java
@Configuration
class ContConfig {
    @Bean Heavy heavy() { return new Heavy(); }
}

class Heavy {
    Heavy() { System.out.println("(Heavy 생성)"); }
}
```

<br/>

### 결과

```java
--- ApplicationContext 는 미리 다 만든다 ---
    (Heavy 생성)
  컨테이너 준비 끝. 지금까지 만들어진 Heavy = 1
  이제 getBean 호출
  getBean 후 Heavy = 1
```

<br/>

`getBean()` 을 부르기도 전에 이미 만들어져 있다.

컨테이너가 뜨는 시점에 싱글톤 빈을 전부 미리 만들어두는 것이다.

<br/>

`getBean()` 을 불러도 다시 만들지 않고 만들어둔 것을 꺼내준다.

앞의 싱글톤 레지스트리 글에서 본 `Map` 에서 꺼내는 것이다.

<br/>

## 미리 만드는 이유

빈을 만들다가 실패하면 컨테이너가 아예 안 뜬다.

의존성이 빠졌거나 설정이 틀렸으면 시작할 때 바로 알 수 있는 것이다.

```java
미리 만든다 -> 문제가 있으면 뜨지도 않는다 (배포 직후에 알게 된다)
나중에 만든다 -> 일단 뜨고, 그 기능을 처음 쓰는 사용자가 에러를 만난다
```

<br/>

앞의 DI 글에서 본 순환 참조 검출도 이 덕분이다.

시작할 때 다 만들어보니까 순환 참조가 바로 드러난다.

<br/>

다만 미리 만들면 시작이 느려진다. 빈이 수천 개면 그만큼 걸린다.

정말 무거운 빈은 `@Lazy` 를 붙여서 처음 쓸 때 만들게 미룰 수 있다.

```java
@Bean
@Lazy
Heavy heavy() { return new Heavy(); }
```

<br/>

## 그럼 BeanFactory 는 언제 쓰는가

거의 안 쓴다. `ApplicationContext` 가 상위 호환이기 때문이다.

<br/>

`BeanFactory` 는 빈을 미리 만들지 않고 꺼낼 때 만든다.

메모리가 극도로 부족한 환경을 염두에 둔 설계인데, 요즘은 그럴 일이 거의 없다.

<br/>

실제로 우리가 만나는 것도 `ApplicationContext` 다.

`@SpringBootApplication` 을 돌리면 `AnnotationConfigServletWebServerApplicationContext` 가 뜬다.

이름이 길지만 결국 `ApplicationContext` 의 한 종류다.

```java
BeanFactory      -> 개념상의 뿌리. 직접 쓸 일은 없다
ApplicationContext -> 실제로 우리가 쓰는 것
```
