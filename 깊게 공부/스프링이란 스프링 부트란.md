## 스프링이란? / 스프링 부트란?

<br/>

## 스프링이 뭔가?

스프링은 자바 언어 기반의 프레임워크로 객체 지향 애플리케이션을 개발할 수 있게 도와주는 프레임워크 이다.

스프링의 기본철학은 특정 기술에 종속되지 않고, 객체를 관리할 수 있는 프레임워크를 제공하는 것입니다.

<br/>

그리하여 컨테이너로 자바 객체를 관리하면서 의존성 주입과 제어의 역전을 통해 결합도를 낮추게 됩니다.

<br/>

## 스프링 부트는 뭔가?

스프링 부트는 스프링을 편리하게 사용하기 위해 도와주는 기술 입니다.

즉, 스프링 부트를 통해서 스프링 프레임워크를 사용하는 것입니다. (이것만 가지고 돌아가는 프로젝트가 아니다)

<br/>

## 스프링 부트 장점은?

- `Tomcat` 같은 웹 서버를 내장해서 별도의 웹 서버를 설치하지 않아도 됩니다.

- 빌드 구성을 위한 `starter` 종속성 제공
    - 즉, 라이브러리를 사용할 때 여러개 묶어서 사용해야 되는데, 그런 부분에 대해서
        
        편하게 하나만 사용하면 starter가 나머지 라이브러리도 같이 가져오는 것이다.

<br/>

## 궁금증!

```java
"편리하게 사용하도록 도와준다" 는 게 구체적으로 무엇을 해주는 것일까?
```

크게 두 가지다. 하나는 라이브러리 묶음이고, 다른 하나는 설정 자동화다.

<br/>

## 첫번째) starter는 버전까지 맞춰준다

원문에서 `여러 개를 묶어서 가져온다` 고 한 부분인데, 사실 더 중요한 것은 버전이다.

<br/>

부트 없이 스프링 MVC를 쓰려면 이렇게 적어야 한다.

```java
implementation 'org.springframework:spring-webmvc:6.1.5'
implementation 'org.springframework:spring-web:6.1.5'
implementation 'com.fasterxml.jackson.core:jackson-databind:2.17.0'
implementation 'jakarta.servlet:jakarta.servlet-api:6.0.0'
implementation 'org.apache.tomcat.embed:tomcat-embed-core:10.1.20'
// ...
```

<br/>

여기서 `jackson` 버전을 하나 잘못 적으면 실행 중에 `NoSuchMethodError` 가 난다.

컴파일은 되는데 돌리면 터지는, 제일 찾기 어려운 부류의 문제다.

<br/>

부트를 쓰면 한 줄이다.

```java
implementation 'org.springframework.boot:spring-boot-starter-web'
```

<br/>

버전도 안 적는다. 부트가 `이 버전에서 서로 잘 도는 조합` 을 알고 있어서 대신 맞춰준다.

이 조합표를 `BOM(Bill of Materials)` 이라고 한다.

```java
starter 가 해주는 일
  = 필요한 라이브러리를 묶어서 + 서로 충돌하지 않는 버전으로 가져온다
```

<br/>

## 두번째) 자동 구성이 설정을 대신 적어준다

이쪽이 더 크다. 부트가 없으면 설정을 전부 손으로 적어야 한다.

```java
@Configuration
@EnableWebMvc
public class WebConfig implements WebMvcConfigurer {
    @Bean
    public ViewResolver viewResolver() { ... }

    @Bean
    public DataSource dataSource() { ... }

    @Bean
    public EntityManagerFactory entityManagerFactory() { ... }

    @Bean
    public PlatformTransactionManager transactionManager() { ... }
    // 계속 이어진다
}
```

<br/>

부트는 이걸 미리 만들어두고 `조건이 맞으면 자동으로 켠다`.

<br/>

부트 jar 안을 열어보면 목록이 그대로 들어 있다.

```java
$ unzip -p spring-boot-autoconfigure.jar \
    META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports

org.springframework.boot.autoconfigure.aop.AopAutoConfiguration
org.springframework.boot.autoconfigure.context.MessageSourceAutoConfiguration
org.springframework.boot.autoconfigure.context.LifecycleAutoConfiguration
...
```

<br/>

부트 모듈 전체를 합쳐 세어보면 `173` 개의 자동 구성 클래스가 들어 있다.

애플리케이션이 뜰 때 이 목록을 읽어서, 조건에 맞는 것만 실제로 적용한다.

<br/>

## 조건은 어떻게 판단하는가

이름부터 `@Conditional` 로 시작하는 어노테이션들이 붙어 있다.

```java
@ConditionalOnClass(DataSource.class)          // 이 클래스가 클래스패스에 있으면
@ConditionalOnMissingBean(DataSource.class)    // 내가 직접 만든 빈이 없으면
@ConditionalOnProperty("spring.datasource.url") // 이 설정값이 있으면
```

<br/>

`@ConditionalOnMissingBean` 이 특히 중요하다.

`내가 직접 등록한 것이 있으면 자동 구성은 물러난다` 는 뜻이기 때문이다.

```java
아무것도 안 하면      -> 부트가 기본값으로 만들어준다
내가 @Bean 을 만들면  -> 내 것이 쓰이고 부트 것은 안 만들어진다
```

<br/>

`ObjectMapper` 를 직접 등록하면 부트가 만든 것이 사라지는 이유가 이것이다.

편의를 제공하되 개발자가 원하면 언제든 빼앗아올 수 있게 만들어둔 것이다.

<br/>

## 톰캣이 내장된다는 말은

원문의 `Tomcat 같은 웹 서버를 내장한다` 는 부분도 실물이 있다.

```java
tomcat-embed-core
tomcat-embed-el
tomcat-embed-websocket
```

<br/>

`spring-boot-starter-web` 을 넣으면 이 jar 들이 같이 딸려온다.

톰캣이 그냥 라이브러리로 들어와 있는 것이다.

<br/>

그래서 흐름이 뒤집힌다.

```java
예전 : 톰캣을 설치하고 -> 내 war 파일을 톰캣 안에 넣는다
지금 : 내 jar 안에 톰캣이 들어 있고 -> java -jar 로 그냥 실행한다
```

<br/>

`main` 메서드로 웹 서버가 뜨는 것이 이 때문이다.

`SpringApplication.run()` 이 톰캣을 코드로 띄우고, 거기에 `DispatcherServlet` 을 등록한다.

<br/>

배포할 때 서버에 톰캣을 깔 필요가 없어지고, 컨테이너 이미지에도 JDK만 있으면 된다.

```java
스프링      = 객체를 관리해주는 프레임워크 (핵심)
스프링 부트 = 그 스프링을 바로 쓸 수 있게 차려놓은 상태 (편의)
```

원문의 `이것만 가지고 돌아가는 프로젝트가 아니다` 라는 말이 이 관계를 가리킨다.
