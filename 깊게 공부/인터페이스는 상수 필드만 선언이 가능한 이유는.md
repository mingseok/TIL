## 인터페이스는 상수 필드만 선언이 가능한 이유는?

<br/>

## 일단, 인터페이스 목적은 뭔가?

클래스에게 특정 메서드의 구현을 강제하고, 서로 다른 클래스가 공통의 동작을 보장하기 위한 것이다.

```
궁금증) 인터페이스는 상수 필드만 선언이 가능하다고 한다. 이유가 뭘까?
```

### 그 이유는

클래스와 달리 객체를 생성해서 사용할 수 없기 때문이다.

즉, 인터페이스는 클래스가 아니라는 점을 기억해야 한다.


<br/>

## 더 자세히 말해보면, 상수의 일관성이다.

인터페이스 내에서 필드를 상수로 취급하는 이유는 인터페이스가 제공하는 값이 변경되지 않아야 함을 의미한다. 

```java
즉, 상수는 변경되지 않는 고정된 값이므로, 서로 다른 클래스가 동일한 상수를 공유하여 일관성을 유지할 수 있습니다.
```

<br/>

### 다중 상속 지원

여러 인터페이스에서 동일한 메서드 시그니처를 가지는 경우, 

클래스에서 어떤 메서드를 호출해야 하는지 혼란이 생길 수 있다.

상수 필드의 충돌을 방지하기 위해 인터페이스에서 상수만 사용할 수 있으므로, 

다중 상속 시에 메서드 충돌과 관련된 혼란을 방지할 수 있습니다.

<br/>

### 구현 강제

인터페이스는 클래스에게 메서드 구현을 강제하기 위한 것이므로, 

상수 외의 다른 필드나 변수를 정의하는 것은 인터페이스의 목적과 일치하지 않다. 

<br/>

## 정리 하자면,

자바에서는 인터페이스에서 상수만 사용 가능하도록 함으로써 

인터페이스의 역할과 의도를 보다 명확하게 유지하고, 

일관성과 다중 상속 지원하며, API의 설계와 확장성을 촉진한다.

<br/>

## 인터페이스 상수 필드 주의사항

- 인터페이스에 선언된 필드는 모두 `public static final`이고, 생략 가능하다.

- 선언과 동시에 초기값 지정이다.

    - 정적 클래스 상수값처럼 `static` 블록을 통한 초기화 불가능하다.

<br/>

## 궁금증!

```java
"public static final 이 생략 가능하다"고 했는데, 정말 그런지 확인해보자
```

값을 안 주면 바로 컴파일 에러가 난다.

```java
interface Config {
    int TIMEOUT;
}
```

```java
error: = expected
    int TIMEOUT;
               ^
```

`final` 이 자동으로 붙기 때문에, 선언과 동시에 값을 주지 않으면 안 되는 것이다.

<br/>

값을 준 뒤에 바꾸려고 해도 막힌다.

```java
interface Config {
    int TIMEOUT = 30;
}

class Impl implements Config {
    void change() {
        TIMEOUT = 60;
    }
}
```

```java
error: cannot assign a value to static final variable TIMEOUT
        TIMEOUT = 60;
        ^
```

에러 메시지에 `static final variable` 이라고 나온다. 적지 않았는데도 붙어 있다는 뜻이다.

<br/>

## 진짜 이유는 상태를 가질 수 없기 때문이다

인터페이스에 일반 필드를 허용하면 무슨 일이 생길지 생각해보면 답이 나온다.

```java
interface A {
    int count = 0;      // 만약 이게 인스턴스 필드라면
}

interface B {
    int count = 0;      // 여기도 있다면
}

class C implements A, B { }   // C 안에 count 가 몇 개일까?
```

<br/>

`C` 는 두 인터페이스를 다 구현했다. `count` 가 두 개인지 하나인지 정할 수가 없다.

자바가 클래스 다중 상속을 막은 이유가 정확히 이 문제 때문인데, 인터페이스에서 같은 일이 반복되는 것이다.

```java
클래스 다중 상속을 막은 이유 = 상태를 여러 벌 물려받으면 답이 없기 때문
-> 인터페이스도 상태를 가지면 똑같은 문제가 생긴다
-> 그래서 인터페이스에는 상태를 못 두게 했다
```

<br/>

상수는 상태가 아니다. 객체마다 달라지지 않고 값도 안 바뀐다.

`A.count` 든 `B.count` 든 그냥 이름표가 붙은 숫자라서 충돌해도 `A.count` 라고 적어 구분하면 끝난다.

<br/>

## Java 8부터는 메서드 얘기가 좀 달라졌다

원문의 `구현 강제` 는 `Java 7` 까지의 얘기다. 지금은 인터페이스에 구현을 넣을 수 있다.

```java
interface PayClient {
    void pay(int amount);                    // 추상 메서드 (Java 7 이전부터)

    default void payTwice(int amount) {      // Java 8 - 기본 구현
        pay(amount);
        pay(amount);
    }

    static PayClient none() {                // Java 8 - static 메서드
        return amount -> { };
    }

    private void log(String message) {       // Java 9 - private 메서드
        System.out.println(message);
    }
}
```

<br/>

그런데 여기서도 필드는 여전히 `public static final` 뿐이다.

메서드 구현은 허용됐지만 `상태를 가지는 것` 은 끝까지 허용하지 않은 것이다.

```java
동작(메서드)은 여러 곳에서 물려받아도 괜찮다 -> Java 8부터 열어줬다
상태(필드)는 여러 곳에서 물려받으면 안 된다  -> 지금도 막혀 있다
```

## default 메서드가 겹치면 어떻게 되는가

```java
interface A {
    default String hello() { return "A"; }
}

interface B {
    default String hello() { return "B"; }
}

class C implements A, B {
}
```

<br/>

```java
error: types A and B are incompatible;
class C implements A, B {
^
  class C inherits unrelated defaults for hello() from types A and B
```

컴파일러가 못 정하겠다고 손을 든다.

<br/>

이럴 때는 구현 클래스가 직접 골라줘야 한다.

```java
class C implements A, B {
    @Override
    public String hello() {
        return A.super.hello();     // A 쪽을 쓰겠다
    }
}
```

`A.super.hello()` 라는 문법이 이때 쓰라고 만들어진 것이다.

<br/>

## 상수 인터페이스는 안티패턴이다

인터페이스에 상수를 둘 수 있다고 해서, 상수만 모아놓은 인터페이스를 만드는 경우가 있다.

```java
interface Constants {
    int MAX_SIZE = 100;
    String PREFIX = "ORDER-";
}

class OrderService implements Constants {   // 상수 쓰려고 implements
    // ...
}
```

<br/>

이건 권장되지 않는다. `implements` 는 `나는 이 타입이다` 라는 선언인데,

`OrderService` 가 `Constants` 라는 타입이라는 말은 아무 의미가 없기 때문이다.

<br/>

내부에서 쓰려고 만든 상수가 구현하는 순간 공개 API가 되어버리는 문제도 있다.

나중에 그 상수를 지우려고 하면, 밖에서 쓰고 있을지 몰라 못 지운다.

<br/>

상수만 필요하다면 `final class` 에 `static` 으로 두고 그냥 가져다 쓰는 것이 낫다.

```java
final class Constants {
    static final int MAX_SIZE = 100;

    private Constants() {
    }
}
```
