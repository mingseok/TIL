## 자바는 어떻게 실행되나요? (간단하게 답변)

1. 컴파일러가 자바소스를 바이트 코드로 변환한다.

2. class Loader가 바이트 코드를 런타임 데이터 영역으로 로드 시킨다
3. 로딩된 바이트 코드가 실행 엔진에 의해서 실행되게 된다.


<br/>


## 1) Java 소스 코드 작성 및 컴파일.

- `소스 코드 작성:` 먼저 개발자는 .java 확장자를 가진 파일에 Java 소스 코드를 작성합니다.

- `컴파일:` 작성된 Java 소스 코드는 Java 컴파일러 `(javac)`를 통해 바이트코드로 변환됩니다.

  이때 생성되는 `.class` 파일은 JVM이 이해할 수 있는 바이트코드로 구성됩니다.


## 2) 바이트코드 실행.

- `JVM` (Java Virtual Machine): 바이트코드로 변환된 `.class` 파일은 JVM에 의해 실행됩니다.

  JVM은 Java 프로그램이 `어느 운영 체제에서든` 실행될 수 있도록 해주는 가상 머신입니다.

- `바이트코드 해석 및 실행:` JVM은 바이트코드를 해석하여, 운영 체제에 맞는 기계어로 변환하고, 이를 실행합니다.


## 3) 독립성.

Java의 핵심적인 특징 중 하나는 플랫폼 독립성입니다. 

바이트코드는 JVM만 설치되어 있으면 어떤 운영 체제에서도 동일하게 실행될 수 있습니다. 


## 4) JIT 컴파일러.

- `JIT (Just-In-Time) 컴파일러:` 실행 중에 JVM은 성능을 최적화하기 위해

  바이트코드의 일부를 JIT 컴파일러를 통해 기계어로 미리 변환할 수 있습니다.

  - 이렇게 하면 프로그램이 더 빠르게 실행될 수 있습니다.


- 이렇게 Java 프로그램은 작성된 소스 코드가 컴파일된 후, JVM에서 바이트코드가 해석되고 실행되는 과정을 통해 실행됩니다.

  이 과정은 Java의 독립성을 보장하며, 다양한 운영 체제에서 동일한 프로그램을 실행할 수 있도록 해줍니다.

## 궁금증!

```java
".class 파일이 바이트코드다" 라고 하는데, 실제로 그 안에는 뭐가 들어 있을까?
```

직접 열어보면 된다. 가장 간단한 프로그램을 하나 만들어보자.

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("안녕");
    }
}
```

<br/>

컴파일한 다음 파일 정체부터 확인해보면 이렇게 나온다.

```java
$ file Hello.class
Hello.class: compiled Java class data, version 68.0

$ xxd Hello.class | head -1
00000000: cafe babe 0000 0044 001d 0a00 0200 0307
```

<br/>

맨 앞 `4` 바이트가 `cafe babe` 다.

JVM은 파일을 열자마자 이 값부터 확인한다. 이게 아니면 자바 클래스 파일이 아니라고 판단하고 거부한다.

파일 확장자가 아니라 파일 내용 맨 앞으로 정체를 확인하는 것이다.

<br/>

## 그 안의 바이트코드는 이렇게 생겼다

```java
$ javap -c Hello.class

public class Hello {
  public Hello();
    Code:
       0: aload_0
       1: invokespecial  // Method java/lang/Object."<init>":()V
       4: return

  public static void main(java.lang.String[]);
    Code:
       0: getstatic      // Field java/lang/System.out:Ljava/io/PrintStream;
       3: ldc            // String 안녕
       5: invokevirtual  // Method java/io/PrintStream.println
       8: return
}
```

<br/>

기계어도 아니고 자바 소스도 아닌, 그 중간쯤 되는 명령어들이다.

- `getstatic` : `System.out` 을 꺼내 온다

- `ldc` : 상수 `"안녕"` 을 꺼내 온다
- `invokevirtual` : `println` 을 호출한다

이 명령어들은 특정 CPU의 것이 아니라 `JVM이라는 가상의 컴퓨터` 를 위한 명령어다.

그래서 이 파일을 그대로 들고 어느 OS로 가든 똑같이 돌아가는 것이다.

<br/>

## JIT가 실제로 얼마나 일을 하는가

`4번` 에서 JIT가 성능을 최적화한다고 했는데, 얼마나 차이가 나는지 직접 재볼 수 있다.

`-Xint` 옵션을 주면 JIT를 끄고 인터프리터로만 실행한다.

```java
public class Run {
    public static void main(String[] args) {
        long start = System.currentTimeMillis();
        long sum = 0;
        for (int i = 0; i < 500_000_000L; i++) {
            sum += i % 7;
        }
        System.out.println("합 = " + sum + " / " + (System.currentTimeMillis() - start) + "ms");
    }
}
```

<br/>

### 결과

```java
$ java Run
합 = 1499999994 / 468ms

$ java -Xint Run
합 = 1499999994 / 4217ms
```

같은 코드인데 `9` 배 차이가 난다.

<br/>

평소에 우리가 쓰는 자바는 인터프리터로만 도는 것이 아니다.

처음에는 인터프리터로 읽어가면서 실행하다가, 자주 도는 부분을 발견하면 그 부분만 기계어로 바꿔놓고

그 다음부터는 바꿔둔 기계어를 쓴다. 위 반복문이 그 덕을 본 것이다.

```java
바이트코드는 어디서든 돌게 해주고, JIT는 그걸 느리지 않게 해준다
```

## 전체를 다시 보면

```java
Hello.java
   | javac
Hello.class  (cafe babe 로 시작하는 바이트코드)
   | 클래스 로더가 읽어서 메모리에 올린다
Runtime Data Area
   | 실행 엔진
인터프리터로 실행하다가, 자주 도는 곳은 JIT가 기계어로 바꿔서 실행
```

`한 번 작성해서 어디서든 돌린다` 는 말이 가능한 이유가 가운데의 `.class` 파일이다.

OS마다 다른 것은 JVM이지, 우리가 만든 `.class` 파일이 아닌 것이다.
