## 자바 메모리 구조가 어떻게 되어 있나요?

자바 메모리 구조는 크게 5가지 영역으로 구분되어 있습니다.

우선, 스레드마다 PC Register, JVM stack, Native Method stack이 있고, 공통 스레드로는 Heap 영역과 class 영역이 있습니다

- ### PC Register
  
  - 현재 수행중인 JVM 명령어가 들어가 있고, JVM stack은 매개변수, 지역변수, 리턴정보들이 저장되어 있습니다.
 
  - `역할:` 현재 스레드가 실행 중인 JVM 명령어의 주소를 저장하는 공간입니다.
    - 각 스레드마다 독립적으로 존재하며, 스레드가 실행 중인 메서드의 명령어 주소를 가리킵니다.
   
  - `특징:` 스레드별로 독립적이므로, 스레드 간의 간섭이 없습니다.
    - 스레드가 새로운 메서드를 호출하면, 해당 메서드의 첫 번째 명령어 주소로 업데이트됩니다.

- ### JVM Stack

  - `역할:` 메서드 호출 시마다 프레임(Frame)이 생성되어 해당 메서드의 매개변수, 지역변수, 리턴 값, 그리고 연산 중간 결과 등을 저장합니다.

    - 메서드 호출이 끝나면 해당 프레임은 제거됩니다.
   
  - `특징:` 스택은 LIFO(Last In, First Out) 구조로 관리됩니다.

    - 또한, 스택 크기는 제한적이므로 너무 깊은 재귀 호출은 StackOverflowError를 발생시킬 수 있습니다.


- ### Native Method stack
  
  - `역할:` 자바 이외의 네이티브 언어(C, C++ 등)로 작성된 메서드를 호출할 때 사용되는 스택 영역입니다.
  
    - JVM은 네이티브 메서드를 호출할 수 있는 기능을 제공하며, 이때 필요한 데이터와 제어 정보를 관리합니다.

  - `특징:` 자바 메서드와 달리 네이티브 메서드 호출 시 JVM이 아닌 운영체제에 의존적입니다.

- ### Class 영역

  - 클래스 별로 전역변수, 정적 변수, 메소드 정보들이 저장되게 됩니다
 
  - `역할:` 클래스와 관련된 메타데이터, 정적 변수, 상수, 메서드 정보, 그리고 필드 데이터가 저장됩니다.
    
    - JVM이 클래스를 로드할 때 클래스별로 필요한 정보들이 이 영역에 저장됩니다.
    
  - `특징:` Method Area는 Heap 영역의 일부로 취급되며, 모든 스레드에서 공유됩니다.

    - 이 영역의 데이터는 애플리케이션의 수명 동안 유지되지만, GC(Garbage Collection)의 대상이 될 수 있습니다.

- ### Heap 영역은 

  - 런타임중 생성되는 객체들이 동적으로 할당되는 곳입니다.
 
  - `역할:` 자바 객체 및 배열이 동적으로 할당되는 공간입니다.
  
    - 모든 스레드에서 공유되며, 객체의 수명이 끝나면 GC가 이 영역을 청소합니다.
      
  - `구조:` Heap은 객체는 주로 Young Generation에 할당되고, 살아남은 객체는 Old Generation으로 이동합니다.

```java

```

각 영역이 꽉 찼을 때 나는 에러가 다르다. 그걸로 확인해볼 수 있다.

## JVM Stack이 넘치면

메서드를 부를 때마다 프레임이 쌓이니, 끝없이 재귀하면 언젠가 꽉 찬다.

```java
public class Depth {
    static int depth = 0;

    public static void main(String[] args) throws Exception {
        try {
            recurse();
        } catch (StackOverflowError e) {
            System.out.println("기본 스택 깊이 = " + depth);
        }

        Thread thread = new Thread(null, () -> {
            depth = 0;
            try {
                recurse();
            } catch (StackOverflowError e) {
                System.out.println("스택을 1MB로 준 스레드 = " + depth);
            }
        }, "small", 1024 * 1024);
        thread.start();
        thread.join();
    }

    static void recurse() {
        depth++;
        recurse();
    }
}
```

<br/>

### 결과

```java
기본 스택 깊이 = 46160
스택을 1MB로 준 스레드 = 23198
```

<br/>

여기서 두 가지를 볼 수 있다.

- 스택이 꽉 차면 `StackOverflowError` 가 난다. `Exception` 이 아니라 `Error` 다.

- 스레드를 만들 때 스택 크기를 따로 줄 수 있고, 깊이가 그만큼 달라진다

스택 크기를 스레드별로 정할 수 있다는 것 자체가, 스택이 스레드마다 따로 있다는 증거다.

<br/>

전체 스레드의 기본 스택 크기는 `-Xss` 옵션으로 바꾼다.

```java
java -Xss512k Depth
```

<br/>

## Heap이 넘치면

힙은 공유 영역이라 스레드와 상관없이 전체가 하나다.

```java
List<byte[]> list = new ArrayList<>();
int count = 0;
try {
    while (true) {
        list.add(new byte[1024 * 1024]);
        count++;
    }
} catch (OutOfMemoryError e) {
    list = null;
    System.out.println(e);
    System.out.println("담긴 개수 = " + count + "MB");
}
```

<br/>

### 결과

```java
$ java -Xmx64m Oom

java.lang.OutOfMemoryError: Java heap space
담긴 개수 = 31MB
```

<br/>

`-Xmx64m` 으로 `64MB` 를 줬는데 `31MB` 에서 터졌다.

힙 전부를 객체에 쓸 수 있는 것이 아니라, 앞에서 본 `Young` 과 `Old` 로 나눠 쓰고

이사 갈 공간까지 비워둬야 하기 때문이다.

```java
StackOverflowError -> 스레드 하나의 스택이 꽉 찼다 (스레드별)
OutOfMemoryError   -> 힙 전체가 꽉 찼다 (공유)
```

<br/>

## Class 영역에 대한 보충

원문에 `Method Area는 Heap 영역의 일부로 취급` 이라고 되어 있는데, 이건 `Java 7` 까지의 얘기다.

<br/>

`Java 7` 까지는 `PermGen` 이라는 이름으로 힙 안에 있었다.

크기가 고정이라 클래스를 많이 로드하면 `OutOfMemoryError: PermGen space` 가 자주 났다.

<br/>

`Java 8` 부터는 `Metaspace` 로 바뀌면서 힙 밖의 네이티브 메모리로 나갔다.

기본적으로 크기 제한이 없어서, 필요하면 OS 메모리가 허락하는 만큼 늘어난다.

```java
Java 7 이하 -> PermGen, 힙 안, 크기 고정
Java 8 이상 -> Metaspace, 힙 밖(네이티브), 크기 제한 없음
```

<br/>

그래서 `Java 8` 이후로는 `PermGen` 관련 에러를 볼 일이 없어졌다.

대신 무제한이라서, 클래스를 계속 만들어내는 코드가 있으면 OS 메모리를 다 먹을 수도 있다.

`-XX:MaxMetaspaceSize` 로 상한을 걸어둘 수 있다.

<br/>

## 정리해서 다시 보면

```java
[ 스레드마다 하나씩 ]
PC Register        - 지금 실행 중인 명령어 위치
JVM Stack          - 메서드 호출마다 프레임, 지역변수와 매개변수  -> StackOverflowError
Native Method Stack - C/C++ 로 된 메서드용

[ 모든 스레드가 공유 ]
Heap               - new 로 만든 객체와 배열                  -> OutOfMemoryError: Java heap space
Metaspace          - 클래스 정보, 메서드 정보, static         -> OutOfMemoryError: Metaspace
```

`스레드마다 있는 것` 과 `공유하는 것` 의 경계가 곧 동시성 문제가 생기는 경계이기도 하다.

지역 변수에는 동기화를 안 걸어도 되지만 필드에는 걸어야 하는 이유가 여기에 있다.
