## 박싱을 해야 하고, 언박싱을 해야 하는 이유는?

<br/>

## 박싱(boxing), 언박싱(un-boxing)

- 박싱은 기본 자료형의 데이터를 래퍼 클래스의 객체로 만드는 과정을 의미합니다

- 언박싱은 래퍼 클래스의 데이터를 기본 자료형으로 얻어내는 과정을 말합니다.

### (예 : int → Integer 박싱 / Integer → int 언박싱)

| Boxing | Primitive 자료형 -> Wrapper 클래스 |
| --- | --- |
| Unboxing | Wrapper 클래스 -> Primitive 자료형 |

<br/>

## 박싱을 해야 하고, 언박싱을 해야 하는 이유는?

메모리 성능을 효율적으로 관리하기 위해 박싱과 언박싱이 필요합니다.

- `기본 타입`은 메모리에 직접 값을 저장하므로 효율적 입니다.

- `참조 타입`은 메모리에 객체의 주소값을 저장합니다.

    - 그렇기에, 메모리 사용 측면에서 비효율적일 수 있습니다.

<br/>

## 자바는 모든 객체를 힙에 저장합니다.

그런데, `힙` 영역은 상대적으로 `스택` 영역에서 불러올 때보다 속도가 떨어집니다. 

<br/>

속도를 버려가면서, `primitive` 타입으로 표현해도 문제되지 않는 부분까지 

일부러 래퍼 클래스로 만드는 것은 불필요하기에 래퍼클래스만을 활용하지 않는다는 것입니다.

```
그리하여 `래퍼 클래스`는 이 두 가지 타입 사이의 다리 역할을 해줍니다. 
원시 타입을 래퍼 클래스로 박싱(Boxing)하면, 원시 타입도 객체 지향 프로그래밍에 적합하게 활용할 수 있게 됩니다.
```

<br/>

## 예시)

`ArrayList` 같은 컬렉션은 원시 타입을 직접 담을 수 없습니다. 

하지만 원시 타입을 래퍼 클래스로 박싱 하면 컬렉션에 저장할 수 있게 됩니다.

```java
List<Integer> list = new ArrayList<>();

for (int i = 0; i < 10; i++) {
    list.add(i);  // i는 자동으로 Integer 객체로 박싱된다.
}
```

<br/>

### 반대로,

래퍼 클래스의 값을 원시 타입처럼 취급해야 할 때는 언박싱(Unboxing)이 필요하게 됩니다. (=자동 언박싱 된다)

```java
Integer boxedInt = new Integer(123);
int autoUnboxedInt = boxedInt; // 자동 언박싱
```

<br/>

## 궁금증!

```java
"자동으로" 박싱된다고 하는데, 그 자동이 정확히 무엇을 넣어주는 것일까?
```

컴파일러가 대신 코드를 적어준다. 바이트코드를 보면 그대로 보인다.

```java
void auto() {
    Integer boxed = 10;          // 박싱
    int unboxed = boxed;         // 언박싱
    List<Integer> list = new ArrayList<>();
    list.add(20);                // 박싱
    int first = list.get(0);     // 언박싱
}
```

<br/>

### 컴파일 결과

```java
invokestatic   // Method java/lang/Integer.valueOf:(I)Ljava/lang/Integer;
invokevirtual  // Method java/lang/Integer.intValue:()I
invokestatic   // Method java/lang/Integer.valueOf:(I)Ljava/lang/Integer;
invokeinterface// InterfaceMethod java/util/List.add
invokeinterface// InterfaceMethod java/util/List.get
invokevirtual  // Method java/lang/Integer.intValue:()I
```

<br/>

박싱 자리마다 `Integer.valueOf()` 가, 언박싱 자리마다 `intValue()` 가 들어가 있다.

우리가 안 적었을 뿐이지 호출은 그대로 일어나는 것이다.

```java
Integer boxed = 10;      ->  Integer boxed = Integer.valueOf(10);
int unboxed = boxed;     ->  int unboxed = boxed.intValue();
```

<br/>

## valueOf가 new보다 나은 이유

원문 마지막의 `new Integer(123)` 은 지금은 쓰면 안 된다. `Java 9` 부터 deprecated 됐다.

`valueOf` 가 쓰이는 이유는 캐시 때문이다.

```java
public static Integer valueOf(int i) {
    if (i >= -128 && i <= 127) {
        return IntegerCache.cache[i + 128];   // 미리 만들어둔 것을 준다
    }
    return new Integer(i);
}
```

<br/>

`-128 ~ 127` 은 미리 만들어두고 재사용한다. 자주 쓰이는 작은 숫자를 매번 만들지 않으려는 것이다.

`new Integer(123)` 은 이 캐시를 무시하고 무조건 새로 만든다. 그래서 없앤 것이다.

<br/>

그런데 이 캐시 때문에 `==` 비교가 이상하게 동작한다.

```java
Integer a = 127, b = 127;
Integer c = 128, d = 128;

System.out.println(a == b);   // true
System.out.println(c == d);   // false
```

`127` 까지는 같은 객체를 주니까 `true` 고, `128` 부터는 새로 만드니까 `false` 다.

```java
래퍼 클래스는 항상 equals 로 비교하자
```

## 언박싱이 NullPointerException을 만든다

```java
Integer nothing = null;
int value = nothing;
```

```java
NullPointerException
```

<br/>

`nothing.intValue()` 로 바뀌어 들어가니, `null` 에 메서드를 부르는 셈이 된다.

코드에는 메서드 호출이 안 보이는데 `NullPointerException` 이 나서 처음엔 당황스럽다.

<br/>

실무에서 자주 걸리는 자리는 이런 곳이다.

```java
Map<String, Integer> counts = new HashMap<>();
int count = counts.get("없는키");        // get 이 null 을 돌려주고 -> 터진다
```

`getOrDefault` 를 쓰거나 `Integer` 로 받아서 확인해야 한다.

```java
int count = counts.getOrDefault("없는키", 0);
```

## 반복문 안에서는 비용이 크다

`1000만` 번 더하면서 `long` 과 `Long` 을 비교해봤다.

```java
long sum = 0;
for (int i = 0; i < 10_000_000; i++) sum += i;
```

```java
Long sum = 0L;
for (int i = 0; i < 10_000_000; i++) sum += i;
```

<br/>

### 결과

```java
long   : 1ms
Long   : 34ms
```

<br/>

`Long` 쪽은 한 바퀴마다 `longValue()` 로 꺼내고, 더한 뒤 `Long.valueOf()` 로 다시 싸맨다.

`1000만` 개의 객체를 만들었다 버린 것이다. 앞에서 말한 `힙이 스택보다 느리다` 는 얘기가 여기서 숫자로 나온다.

<br/>

그래서 변수 타입을 정할 때는 이렇게 나누면 된다.

```java
값을 계산하는 지역 변수      -> 기본형
컬렉션이나 제네릭에 들어갈 것 -> 래퍼 클래스
null 로 "없음" 을 표현해야 할 것 -> 래퍼 클래스
```

<br/>

`IntStream` 이나 `LongStream` 같은 기본형 전용 스트림이 따로 있는 것도 같은 이유다.

`Stream<Integer>` 를 쓰면 원소마다 박싱이 일어나기 때문에, 숫자만 다룰 때는 전용 스트림이 훨씬 빠르다.
