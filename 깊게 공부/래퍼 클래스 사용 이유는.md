## 래퍼 클래스 사용 이유는?

<br/>

## 래퍼 클래스란?

기본 자료형(Primitive data type)에 대한 객체 표현을 Wrapper class라고 합니다.

기본 자료형의 값을 감싸 `객체` 형태로 만든 것이 바로 래퍼 클래스이다.


### 자료형에는 두가지가 있다.

1. 기본형(=primary) → `int a = 1;`

2. 참조형(=reference) → `new` 연산자를 사용하여 객체로 만든 것을 참조형이라고 한다. → `Human b = new Human();`
    

<br/>

## 래퍼 클래스의 특징은?

1. `'=='` 연산자가 불가능하다

    - `‘==’` 비교자는 `primary`때랑 `reference`때랑 다르다

        - `primary` 때는 값을 비교한다.

        - `reference` 때는 참조 주소를 비교한다.

2. `Immutable`(=불변) 하다는 특징이다.
   
    - `Integer a = 1;` 이라고 되어 있다고 생각해보자.

        - `1`에서 `2`로 수정 하였다면, `2`라는 객체가 새로 생성되어서 변경된다.

        - 즉, 기존값이 변경되는 것이 아니고, 새로운 값이 할당된다는 것이다.

<br/>

## 사용 이유

기본 자료형의 값을 굳이 래퍼 클래스로 포장하는 이유는 제네릭, 자료구조 등 기본 자료형이 아닌 


레퍼런스 타입을 필요로 하는 경우가 많고, 메서드를 갖고 있어 다양하게 활용이 가능하기 때문이다.

<br/>

## 궁금증!

```java
"==" 이 안 된다고 했는데, 왜 어떤 경우에는 되는 것처럼 보일까?
```

직접 찍어보면 이상한 결과가 나온다.

```java
Integer a = 127, b = 127;
Integer c = 128, d = 128;

System.out.println("127 == 127 : " + (a == b));
System.out.println("128 == 128 : " + (c == d));
System.out.println("equals     : " + c.equals(d));
```

<br/>

### 결과

```java
127 == 127 : true
128 == 128 : false
equals     : true
```

같은 코드인데 `127` 은 `true` 고 `128` 은 `false` 다.

<br/>

`Integer` 는 `-128 ~ 127` 사이의 값을 미리 만들어두고 재사용한다.

작은 숫자는 워낙 자주 쓰이니까 매번 새로 만들지 말자는 것이다.

<br/>

그래서 `127` 까지는 미리 만들어둔 같은 객체를 주니까 주소가 같고, `128` 부터는 새로 만드니까 주소가 다르다.

```java
-128 ~ 127  -> 미리 만들어둔 것을 재사용 -> == 가 우연히 true
그 밖의 값    -> 매번 새로 만든다        -> == 는 false
```

<br/>

이게 위험한 이유는, 테스트할 때는 작은 숫자를 쓰다가 실제 데이터에서 큰 숫자가 들어오면

그제서야 틀리기 시작한다는 것이다. 래퍼 클래스는 무조건 `equals` 로 비교해야 한다.

<br/>

## 언박싱에도 함정이 있다

```java
Integer nothing = null;
int value = nothing;      // 무슨 일이 벌어질까
```

<br/>

### 결과

```java
NullPointerException
```

`Integer` 를 `int` 로 받는 순간 컴파일러가 `nothing.intValue()` 를 넣어준다.

`null` 에 대고 메서드를 부르는 셈이라 `NullPointerException` 이 나는 것이다.

<br/>

DB에서 값을 못 찾아 `null` 이 들어왔는데, 그걸 `int` 로 받는 순간 터진다.

에러 메시지에는 `null` 이라는 말만 나오지 어느 줄인지 감이 안 잡혀서 찾기도 어렵다.

```java
Integer 를 int 로 받을 때는 null 인지 먼저 확인하자
```

<br/>

## 성능 차이는 어느 정도인가

`1000만` 번 더하면서 `long` 과 `Long` 을 비교해봤다.

```java
long sum = 0;
for (int i = 0; i < 10_000_000; i++) sum += i;
```

```java
Long sum = 0L;
for (int i = 0; i < 10_000_000; i++) sum += i;   // 한 바퀴마다 박싱 + 언박싱
```

<br/>

### 결과

```java
long   : 1ms
Long   : 34ms
```

`30` 배가 넘게 차이가 난다.

<br/>

`Long` 쪽은 한 바퀴 돌 때마다 객체를 꺼내서(언박싱) 더하고, 결과를 다시 객체로 싸서(박싱) 넣는다.

`1000만` 번 도는 동안 객체를 `1000만` 개 만들었다 버린 것이다.

```java
반복문 안에서는 래퍼 클래스를 쓰지 말자
```

## 그럼 언제 래퍼 클래스를 써야 하는가

원문에서 말한 대로 `기본형을 쓸 수 없는 자리` 에 쓴다.

- 제네릭 : `List<int>` 는 안 되고 `List<Integer>` 만 된다

- 컬렉션 : `Map<String, Integer>` 처럼 값 자리에 객체만 들어간다
- `null` 이 필요할 때 : 값이 `없음` 과 `0` 을 구분해야 한다면 기본형으로는 표현할 수 없다

<br/>

세 번째가 실무에서 제일 자주 걸린다.

```java
class Member {
    private int age;        // 나이를 안 적은 사람과 0살인 사람을 구분할 수 없다
    private Integer age;    // null 이면 "안 적음" 이라고 볼 수 있다
}
```

<br/>

JPA 엔티티에서 기본형 대신 래퍼 클래스를 쓰라는 얘기가 나오는 것도 이 때문이다.

DB 컬럼이 `nullable` 인데 필드를 `int` 로 잡아두면, `null` 이 들어오는 순간 값을 받을 방법이 없다.
