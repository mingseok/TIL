## 스프링에서 빈을 등록하는 방법


### 빈을 등록하는 방법은 기본적으로 2 가지가 있습니다.

1. 우선 가장 쉬운 방법으로 `@Component` 어노테이션을 사용하는 것입니다.
    - `@Controller`, `@Service`, `@Repository`는 모두 `@Component`를 포함하고 있습니다.

1. 설정 클래스를 따로 만들어 `@Configuration` 어노테이션을 붙이고,
    
    해당 클래스 안에서 빈으로 등록할 메소드를 만들어 `@Bean` 어노테이션을 
    
    붙여주면 자동으로 해당 타입의 빈 객체가 생성됩니다.
<br/>

## 궁금증!

```java
두 가지라고 했는데, 컨테이너에 직접 넣는 방법은 없을까?
```

있다. 세 번째 방법으로 `registerBean()` 이 있다.

```java
AnnotationConfigApplicationContext context = new AnnotationConfigApplicationContext();
context.register(RegConfig.class);
context.registerBean("직접등록", Manual.class);   // 세 번째 방법
context.refresh();
```

<br/>

### 결과

```java
--- 등록된 빈과 이름 ---
  regConfig    -> RegConfig$$SpringCGLIB$$0
  직접등록      -> Manual
  orderService -> OrderService     (@Service 로 등록)
  payService   -> PayService       (@Bean 으로 등록)
```

<br/>

`직접등록` 이라는 한글 이름으로도 잘 들어간다.

`@Component` 도 `@Bean` 도 결국은 이 등록 작업을 대신 해주는 것뿐이다.

<br/>

실무에서는 잘 안 쓰지만, 조건에 따라 빈을 넣었다 뺐다 해야 할 때 쓴다.

스프링 부트가 자동 구성을 할 때 내부적으로 하는 일도 결국 이것이다.

<br/>

## 등록 방식에 따라 저장되는 내용이 다르다

스프링은 빈을 만들기 전에 `어떻게 만들지` 를 `BeanDefinition` 이라는 곳에 적어둔다.

두 방식이 여기서 어떻게 다른지 꺼내봤다.

```java
BeanDefinition def = context.getBeanDefinition("orderService");   // @Service 로 등록
System.out.println("클래스       = " + def.getBeanClassName());
System.out.println("팩토리메서드 = " + def.getFactoryMethodName());

BeanDefinition def2 = context.getBeanDefinition("payService");    // @Bean 으로 등록
System.out.println("클래스       = " + def2.getBeanClassName());
System.out.println("팩토리메서드 = " + def2.getFactoryMethodName());
```

<br/>

### 결과

```java
orderService 클래스       = demo.OrderService
orderService 팩토리메서드 = null

payService   클래스       = null
payService   팩토리메서드 = payService
```

<br/>

정확히 반대로 채워져 있다.

- `@Component` 방식 : 클래스 이름이 적혀 있다. 스프링이 그 클래스를 직접 `new` 한다

- `@Bean` 방식 : 클래스는 비어 있고 메서드 이름이 적혀 있다. 그 메서드를 불러서 반환값을 받는다

<br/>

`@Bean` 쪽 클래스가 `null` 인 이유는, 메서드를 실행해봐야 무엇이 나올지 알기 때문이다.

메서드 안에서 조건에 따라 다른 구현체를 반환할 수도 있으니 미리 정할 수가 없다.

```java
@Component -> "이 클래스로 만들어라"
@Bean      -> "이 메서드를 불러서 나오는 걸 써라"
```

<br/>

## 그래서 언제 무엇을 쓰는가

`@Component` 는 내가 만든 클래스에만 붙일 수 있다.

소스 파일에 어노테이션을 적어야 하기 때문이다.

<br/>

외부 라이브러리 클래스는 손댈 수가 없으니 `@Bean` 으로 등록해야 한다.

```java
@Bean
public ObjectMapper objectMapper() {          // 내가 만든 클래스가 아니다
    return new ObjectMapper()
            .registerModule(new JavaTimeModule());
}
```

<br/>

만드는 과정에 설정이 필요할 때도 `@Bean` 이 낫다.

위처럼 만들고 나서 뭔가를 더 해줘야 한다면 `@Component` 로는 표현할 방법이 없다.

```java
내가 만든 클래스 + 그냥 new 하면 됨 -> @Component
외부 라이브러리 클래스              -> @Bean
만들면서 설정을 해줘야 함           -> @Bean
```

<br/>

## 빈 이름은 어떻게 정해지는가

- `@Component` : 클래스 이름의 첫 글자를 소문자로 바꾼 것. `OrderService` -> `orderService`

- `@Bean` : 메서드 이름 그대로. `payService()` -> `payService`

<br/>

이름을 직접 주고 싶으면 이렇게 한다.

```java
@Component("주문서비스")
@Bean(name = "결제서비스")
```

<br/>

이름이 겹치면 조용히 덮어써지거나 에러가 난다.

스프링 부트는 기본적으로 덮어쓰기를 막아놨다.

```java
BeanDefinitionOverrideException: Invalid bean definition with name '...'
```

같은 이름의 빈을 두 군데서 등록했다는 뜻이라, 어느 쪽을 지울지 정해야 한다.
