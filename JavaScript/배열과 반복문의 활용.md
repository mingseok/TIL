## 배열과 반복문의 활용

여기서 `document.querySelectorAll('a');` 코드의 ‘a’ 는 `a태그`를 의미 하는 것이다.

만약, ‘body’ 라고 되어 있으면 `body태그`인 것이다.

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>Title</title>
</head>
<body>

<h1><a href="index.html">WEB</a></h1>
	
<input id="night_day" type="button" value="night" onclick="
    var target = document.querySelector('body');
    if(this.value === 'night'){
      target.style.backgroundColor = 'black';
      target.style.color = 'white';
      this.value = 'day';

      var alist = document.querySelectorAll('a');
      var i = 0;
      while(i < alist.length){
        alist[i].style.color = 'powderblue';
        i = i + 1;
      }
							   
      
    } else {
      target.style.backgroundColor = 'white';
      target.style.color = 'black';
      this.value = 'night';

      var alist = document.querySelectorAll('a');
      var i = 0;
      while(i < alist.length){
        alist[i].style.color = 'blue';
        i = i + 1;
      }
    }
  ">

</body>
</html>
```

## 궁금증!

```java
반복문 종류가 왜 이렇게 많은가
```

각자 다루는 것이 다르다.

```javascript
for (let i = 0; i < arr.length; i++)   인덱스. break 가 된다
for (const x of arr)                   값. break 가 된다
for (const k in obj)                   키. 객체용
arr.forEach(x => ...)                  값. break 가 안 된다
arr.map / filter / reduce              새 배열을 만든다
```

<br/>

## for...in 을 배열에 쓰면 안 된다

```javascript
const arr = ['a', 'b'];
for (const i in arr) console.log(typeof i);      // "string"
```

<br/>

인덱스가 문자열로 나온다.

<br/>

그리고 프로토타입에 추가된 속성까지 돈다.

```javascript
Array.prototype.custom = 1;
for (const i in arr) console.log(i);      // 0, 1, custom
```

<br/>

라이브러리가 프로토타입을 건드리면 반복문이 이상해지는 것이다.

<br/>

배열에는 `for...of` 를 쓴다.

<br/>

## forEach 는 중간에 못 멈춘다

```javascript
arr.forEach(x => {
    if (x > 3) break;      // SyntaxError
    if (x > 3) return;     // 이건 continue 처럼 동작한다
});
```

<br/>

`return` 은 그 한 번만 건너뛴다. 전체를 멈추지는 않는다.

<br/>

앞의 스트림 글에서 본 자바의 문제와 같다.

`흐름 제어가 있으면 반복문이 낫다.`

<br/>

멈춰야 하면 `some` 이나 `find` 를 쓴다.

```javascript
arr.some(x => { ... return 조건; });      // true 를 반환하면 멈춘다
```

<br/>

`some` 을 반복문 대용으로 쓰는 건 의도가 안 드러나서 좋지는 않다.

<br/>

## map 과 forEach 를 구분해야 한다

```javascript
arr.map(x => x * 2)        새 배열을 돌려준다
arr.forEach(x => x * 2)    undefined 를 돌려준다
```

<br/>

`map` 을 부작용 목적으로 쓰면 안 된다.

```javascript
arr.map(x => console.log(x));      // 새 배열이 만들어져서 버려진다
```

<br/>

읽는 사람이 `이 배열을 어디 쓰나` 를 찾게 된다.

<br/>

앞의 스트림 글에서 본 자바의 `peek` 와 같은 얘기다.

`반환값을 안 쓸 거면 그 메서드가 아니다.`

<br/>

## reduce 를 남용하지 않는 게 낫다

```javascript
const total = items.reduce((sum, item) => sum + item.price, 0);
```

<br/>

이 정도는 읽기 좋다.

<br/>

그런데 이렇게 되면 곤란하다.

```javascript
const result = items.reduce((acc, item) => {
    if (!acc[item.category]) acc[item.category] = [];
    acc[item.category].push(item);
    return acc;
}, {});
```

<br/>

앞의 스트림 글에서 본 `groupingBy` 를 손으로 짠 것이다.

<br/>

`Object.groupBy` 가 최근에 표준에 들어왔다.

```javascript
Object.groupBy(items, item => item.category)
```

<br/>

브라우저 지원을 확인하고 써야 한다.

<br/>

## 배열 복사가 얕다

```javascript
const copy = [...arr];
const copy2 = arr.slice();
```

<br/>

둘 다 한 겹만 복사한다.

```javascript
const arr = [{ n: 1 }];
const copy = [...arr];
copy[0].n = 2;
console.log(arr[0].n);      // 2
```

<br/>

앞의 방어적 복사 글에서 본 그 문제다.

<br/>

깊은 복사가 필요하면 최근에 표준이 된 함수가 있다.

```javascript
structuredClone(arr)
```

<br/>

`JSON.parse(JSON.stringify(arr))` 를 쓰던 것을 대체한다.

함수나 `undefined` 가 사라지는 문제가 없다.

<br/>

## sort 는 원본을 바꾼다

```javascript
const sorted = arr.sort();      // arr 자체가 바뀐다
```

<br/>

```javascript
원본을 바꾸는 것 - sort, reverse, splice, push, pop
새 배열을 만드는 것 - map, filter, slice, concat
```

<br/>

이걸 헷갈리면 원본이 조용히 바뀌어 있는 버그가 생긴다.

<br/>

최근에 원본을 안 바꾸는 버전이 추가됐다.

```javascript
arr.toSorted()
arr.toReversed()
arr.with(0, 'x')
```

<br/>

앞의 SOLID 글에서 본 대로,

`이름만 보고 부작용이 있는지 알 수 있게` 만든 것이다.
