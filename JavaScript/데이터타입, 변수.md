## 궁금증!

```java
typeof 로 타입을 제대로 알 수 있나
```

찍어봤다.

```javascript
typeof null           = "object"
typeof []             = "object"
typeof function(){}   = "function"
```

<br/>

`null` 이 `object` 로 나온다.

<br/>

이건 언어의 버그다.

초기 구현에서 타입을 하위 3비트로 표현했는데, `object` 가 `000` 이었고

`null` 이 널 포인터라 전부 `0` 이었기 때문이다.

<br/>

고치면 기존 코드가 깨져서 그대로 두기로 한 것이다.

<br/>

앞의 인터페이스의 Default Method 글에서 본 것과 같은 얘기다.

`이미 배포된 것을 안 깨는 것` 이 우선인 것이다.

<br/>

## 배열도 object 다

```javascript
Array.isArray([])                      = true
Object.prototype.toString.call([])     = "[object Array]"
Object.prototype.toString.call(null)   = "[object Null]"
```

<br/>

배열을 확인하려면 `Array.isArray` 를 쓴다.

<br/>

`Object.prototype.toString.call()` 은 무엇이든 구분해준다.

`null` 도 `[object Null]` 로 정확히 나온다.

<br/>

라이브러리 안에서 타입 검사를 할 때 이 방식을 쓴다.

<br/>

## 원시 타입과 객체

```javascript
number, string, boolean, null, undefined, symbol, bigint    - 원시
object (배열, 함수, 날짜 포함)                                - 객체
```

<br/>

앞의 원시형과 참조형 글에서 본 자바의 구분과 비슷한데,

자바스크립트는 원시 타입에도 메서드를 부를 수 있다.

```javascript
"hello".toUpperCase()
```

<br/>

부르는 순간 임시로 객체로 감쌌다가 버린다.

<br/>

앞의 박싱, 언박싱 글에서 본 것과 같은 일이 자동으로 일어나는 것이다.

<br/>

## null 과 undefined 가 둘 다 있다

```javascript
undefined - 값이 아직 없다. 시스템이 준 것
null      - 값이 없다고 내가 정했다
```

<br/>

```javascript
null == undefined   -> true
null === undefined  -> false
```

<br/>

`==` 는 둘을 같게 보고 `===` 는 다르게 본다.

<br/>

그래서 `null` 과 `undefined` 를 한꺼번에 걸러낼 때 `==` 를 쓰기도 한다.

```javascript
if (value == null) { ... }      // null 과 undefined 둘 다 걸린다
```

<br/>

이건 `==` 를 쓰는 몇 안 되는 정당한 경우다.

<br/>

## 숫자가 하나뿐이다

```javascript
Number.MAX_SAFE_INTEGER = 9007199254740991
9007199254740993        = 9007199254740992      <- 값이 바뀐다
```

<br/>

정수와 실수가 나뉘어 있지 않다. 전부 64비트 부동소수점이다.

<br/>

앞의 실수 표현 글에서 본 IEEE 754다.

`2^53` 을 넘으면 정수를 정확히 표현할 수 없다.

<br/>

자바의 `long` 값을 JSON으로 보내면 이 문제가 터진다.

```java
id = 9007199254740993   ->  브라우저에서 9007199254740992 가 된다
```

<br/>

그래서 큰 ID는 문자열로 보내는 게 관례가 됐다.

<br/>

앞의 HTTP 요청 메시지 - JSON 글에서 본 그 변환 경계에서 생기는 문제다.

<br/>

`BigInt` 가 나중에 추가됐다.

```javascript
9007199254740993n      // n 을 붙인다
```

<br/>

다만 `JSON.stringify` 가 `BigInt` 를 처리 못 해서 여전히 번거롭다.
