## `Document.getElementById()`

메서드는 주어진 문자열과 일치하는 `id`속성을 가진 요소를 찾고, 

이를 나타내는 `Element`객체를 반환합니다. 

<br/>

ID는 문서 내에서 유일해야 하기 때문에 특정 요소를 빠르게 찾을 때 유용합니다.

ID가 없는 요소에 접근하려면 `Document.querySelector()`를 사용한다.

<br/><br/>

>**Reference** <br/>생활코딩 자바스크립트 : https://www.youtube.com/watch?v=dPRtcRwKo-Y&list=PLuHgQVnccGMBB348PWRN0fREzYcYgFybf

<br/>

## 궁금증!

```java
querySelector 와 getElementById 중 무엇을 쓰나
```

성능은 `getElementById` 가 빠르다.

```javascript
getElementById   - 브라우저가 id 색인을 들고 있다. O(1)
querySelector    - 선택자를 파싱하고 DOM 을 훑는다
```

<br/>

앞의 인덱스 구조 글에서 본 것과 같은 얘기다.

`색인이 있으면 바로 찾고, 없으면 훑는다.`

<br/>

다만 실무에서 이 차이가 문제가 되는 경우는 거의 없다.

반복문 안에서 수천 번 부르는 게 아니면 상관없다.

<br/>

`querySelector` 는 하나로 다 되니 그게 더 실용적이다.

<br/>

## 반환값이 다르다

```javascript
getElementsByClassName   -> HTMLCollection. 살아 있다
getElementsByTagName     -> HTMLCollection. 살아 있다
querySelectorAll         -> NodeList. 죽어 있다
```

<br/>

`살아 있다` 는 것은 DOM이 바뀌면 결과도 바뀐다는 뜻이다.

<br/>

```javascript
const items = document.getElementsByClassName('item');
console.log(items.length);      // 3
document.body.innerHTML += '<div class="item"></div>';
console.log(items.length);      // 4. 다시 안 불렀는데 늘었다
```

<br/>

편해 보이는데 함정이 된다.

```javascript
for (let i = 0; i < items.length; i++) {
    items[i].remove();          // 지울 때마다 length 가 줄어든다
}
```

<br/>

절반만 지워진다.

<br/>

`querySelectorAll` 은 그 순간의 스냅샷이라 이 문제가 없다.

<br/>

앞의 방어적 복사 글에서 본 것과 같은 구분이다.

`창` 인가 `복사본` 인가의 차이다.

<br/>

## NodeList 는 배열이 아니다

```javascript
const list = document.querySelectorAll('.item');
list.map(...)      // TypeError
```

<br/>

`forEach` 는 있는데 `map` 과 `filter` 는 없다.

<br/>

배열로 바꿔야 한다.

```javascript
[...list].map(...)
Array.from(list).map(...)
```

<br/>

`HTMLCollection` 은 `forEach` 도 없다.

<br/>

앞의 Function() 글에서 본 `arguments` 와 같은 `유사 배열` 이다.

`length` 와 인덱스는 있는데 배열 메서드가 없는 것이다.

<br/>

## 선택 범위를 좁히면 빨라진다

```javascript
document.querySelectorAll('.item')          // 문서 전체
container.querySelectorAll('.item')         // container 안에서만
```

<br/>

요소에서도 부를 수 있다.

<br/>

앞의 이벤트 글에서 본 이벤트 위임과 같이 쓰면 좋다.

```javascript
list.addEventListener('click', (e) => {
    const item = e.target.closest('.item');
    if (!item) return;
});
```

<br/>

`closest` 는 자기 자신부터 위로 올라가며 찾는다.

<br/>

버튼 안의 아이콘을 눌렀을 때도 버튼을 찾아준다.

`e.target` 만 보면 아이콘이 나와서 처리가 안 되는 것이다.

<br/>

## data 속성으로 값을 넘긴다

```html
<button data-member-id="1" data-action="delete">삭제</button>
```

```javascript
const id = button.dataset.memberId;      // "1"
const action = button.dataset.action;
```

<br/>

`data-member-id` 가 `dataset.memberId` 가 된다.

하이픈이 카멜케이스로 바뀌는 것이다.

<br/>

앞의 자바스크립트 인라인 each 글에서 본 대로,

정적 `.js` 파일에서는 타임리프 값을 못 쓰니 이 방식으로 넘긴다.

<br/>

값은 항상 문자열이다.

```javascript
const id = Number(button.dataset.memberId);
```

<br/>

숫자로 쓰려면 변환해야 한다.

<br/>

앞의 스프링 타입 컨버터 글에서 본 것과 같은 상황이다.

`HTML 로 오간 것은 전부 문자열` 인 것이다.
