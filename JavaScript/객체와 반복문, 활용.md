## 궁금증!

```java
객체의 키 순서가 보장되나
```

부분적으로만 보장된다.

```javascript
const obj = { b: 1, 2: 'x', a: 3, 1: 'y' };
Object.keys(obj)      // ['1', '2', 'b', 'a']
```

<br/>

규칙이 이렇다.

```java
1. 정수처럼 생긴 키가 먼저. 오름차순으로
2. 그 다음 문자열 키. 넣은 순서대로
3. 마지막에 심볼 키
```

<br/>

숫자 키가 끼면 순서가 뒤집히는 것이다.

<br/>

앞의 Map 정리 글에서 본 자바의 `HashMap` 은 아예 순서가 없는데,

자바스크립트는 이 규칙이라도 있는 셈이다.

<br/>

순서가 중요하면 `Map` 을 쓴다.

```javascript
const map = new Map();
map.set('b', 1);
map.set(2, 'x');
```

<br/>

넣은 순서 그대로 유지되고, 키로 아무 타입이나 쓸 수 있다.

<br/>

## 객체의 키는 문자열이나 심볼뿐이다

```javascript
const obj = {};
obj[1] = 'a';
obj['1'] = 'b';
console.log(obj[1]);      // 'b'. 같은 키다
```

<br/>

숫자 키가 문자열로 바뀐다.

<br/>

객체를 키로 쓰면 더 이상하다.

```javascript
const k1 = {}, k2 = {};
obj[k1] = 'a';
obj[k2] = 'b';
console.log(obj[k1]);      // 'b'. 둘 다 "[object Object]" 가 된다
```

<br/>

`toString()` 이 불려서 전부 같은 키가 되는 것이다.

<br/>

`Map` 은 참조로 구분하니 이 문제가 없다.

<br/>

## 객체를 순회하는 방법

```javascript
Object.keys(obj)      // ['a', 'b']
Object.values(obj)    // [1, 2]
Object.entries(obj)   // [['a', 1], ['b', 2]]
```

<br/>

`entries` 와 구조 분해를 같이 쓰면 읽기 좋다.

```javascript
for (const [key, value] of Object.entries(obj)) { ... }
```

<br/>

앞의 반복 글에서 본 타임리프의 `Map` 순회와 비슷한 모양이다.

<br/>

`for...in` 은 프로토타입까지 도니 피하는 게 낫다.

앞의 배열과 반복문의 활용 글에서 본 그 문제다.

<br/>

## 구조 분해가 편하다

```javascript
const { name, age } = member;
const { name, age = 0 } = member;           // 기본값
const { name: memberName } = member;        // 이름 바꾸기
const { address: { city } } = member;       // 중첩
```

<br/>

앞의 선택 변수 표현식 글에서 본 타임리프의 `th:object` 와 발상이 비슷하다.

`앞부분을 반복해서 안 적는다.`

<br/>

함수 파라미터에서 특히 유용하다.

```javascript
function draw({ x = 0, y = 0, color = 'black' } = {}) { ... }
draw({ x: 10 });
```

<br/>

이름으로 넘기니 순서를 안 외워도 된다.

<br/>

앞의 팩토리 메서드 패턴 글에서 본 그 이득이다.

<br/>

## 전개 연산자로 합칠 때

```javascript
const merged = { ...a, ...b };
```

<br/>

키가 겹치면 뒤의 것이 이긴다.

<br/>

한 겹만 합친다.

```javascript
const a = { nested: { x: 1 } };
const b = { nested: { y: 2 } };
{ ...a, ...b }      // { nested: { y: 2 } }. x 가 사라진다
```

<br/>

`nested` 를 통째로 덮어쓰기 때문이다.

<br/>

앞의 배열과 반복문의 활용 글에서 본 얕은 복사와 같은 문제다.

<br/>

## 옵셔널 체이닝

```javascript
member?.address?.city
```

<br/>

중간에 `null` 이나 `undefined` 면 거기서 멈추고 `undefined` 를 돌려준다.

<br/>

앞의 변수 - SpringEL 글에서 본 타임리프의 `?.` 와 같다.

<br/>

함수와 배열에도 쓸 수 있다.

```javascript
obj.method?.()
arr?.[0]
```

<br/>

`??` 와 같이 쓰면 기본값을 준다.

```javascript
member?.name ?? '이름 없음'
```

<br/>

`||` 와 다르다.

```javascript
0 || '기본'      -> '기본'      (0 이 falsy 라서)
0 ?? '기본'      -> 0           (null/undefined 만 본다)
```

<br/>

앞의 연산 글에서 본 타임리프의 Elvis 연산자와 같은 구분이다.

`값이 없다` 를 무엇으로 볼지의 문제인 것이다.

<br/>

숫자 `0` 이나 빈 문자열이 유효한 값이면 `??` 를 써야 한다.
