## World Wide Web

여러 정보들을 링크를 통해 효율적으로 접근할 수 있는 인터넷 상에서 동작하는 전 지구적인 정보 시스템이다.

```java
줄여서 부를 때는 "web" 이라고 부르고, 줄여서 쓸 때는 "www" 혹은 "w3"라고 쓴다.
```

<br/>

## Internet이란?

- 글로벌 네트워크

- 글로벌 인프라

<br/><br/>

## HTTP 프로토콜이란?

```java
http://
```

web의 토대가 되는 프로토콜 hypermedia 같은 정보를 주고 받기 위해 사용되는 프로토콜이다.

WWW는 웹 브라우저 입니다. (크롬, 오페라, 사파리 등,,)

<br/>

즉, 하이퍼텍스트를 열람 할 수 있는 ‘클라이언트 애플리케이션’ 명칭이라고 볼 수 있습니다. 

- (=WWW 혹은 웹이라고 불린다)

<br/>

WWW를 구성하는 기술로는 문서 기술 언어로는 HTML, 문서 전송 프로토콜로는 HTTP, 

문서의 주소를 지정하는 방법으로는 URL 등 세 가지가 있습니다.
<br/>

## 궁금증!

```java
"WWW 는 웹 브라우저" 라는 말이 맞을까?
```

정확히는 아니다. 다만 그렇게 오해할 만한 사연이 있다.

```java
WWW (World Wide Web) - 문서들이 링크로 이어진 정보 시스템 자체
웹 브라우저           - 그 시스템에 접근하는 클라이언트 프로그램
```

<br/>

`WWW` 는 크롬이나 사파리 같은 프로그램이 아니라, 그 프로그램들이 들여다보는 세계다.

<br/>

## 그런데 WorldWideWeb 이라는 이름의 브라우저가 실제로 있었다

`1990` 년에 팀 버너스리가 만든 세계 최초의 브라우저 이름이 `WorldWideWeb` 이었다.

<br/>

시스템 이름과 프로그램 이름이 똑같아서 혼란이 생겼고,

그래서 나중에 브라우저 이름을 `Nexus` 로 바꿨다.

<br/>

원문의 설명은 그 시절의 흔적으로 보인다.

지금은 `WWW` 라고 하면 시스템을 가리키고, 브라우저는 각각의 이름으로 부른다.

<br/>

## 세 가지 기술이 핵심이라는 말

원문 마지막의 그 셋이 지금도 그대로다.

```java
HTML - 문서를 어떻게 쓸 것인가
HTTP - 문서를 어떻게 주고받을 것인가
URL  - 문서를 어떻게 가리킬 것인가
```

<br/>

이 셋이 앞의 글들에서 다룬 내용과 그대로 이어진다.

```java
URL  -> 앞의 URI 글, 리소스 식별 글
HTTP -> 앞의 HTTP 메시지 글, 메서드 글, 상태 코드 글
HTML -> 앞의 form 태그 글에서 본 그 문법
```

<br/>

## 하이퍼텍스트가 왜 대단했는가

`링크로 이어진다` 는 것이 지금은 당연해 보이는데, 당시에는 새로운 발상이었다.

<br/>

그전에도 인터넷은 있었다. 파일을 주고받는 `FTP`, 메일을 보내는 `SMTP` 가 이미 있었다.

<br/>

그런데 그것들은 `어디에 무엇이 있는지 미리 알아야` 쓸 수 있었다.

<br/>

`링크` 는 그 문제를 뒤집었다.

문서 안에 다음 문서의 주소가 들어 있으니, 하나만 알면 거기서부터 따라갈 수 있다.

<br/>

검색 엔진이 가능한 이유도 이것이다.

링크를 따라다니면서 문서를 모으면 되니까, 세상의 모든 페이지를 알아낼 방법이 생긴 것이다.

<br/>

## 인터넷과 웹은 다른 말이다

```java
인터넷 - 컴퓨터들을 연결한 네트워크 그 자체
웹    - 그 위에서 도는 서비스 중 하나
```

<br/>

앞의 네트워크와 인터넷 개념 글에서 본 그 인터넷이 바닥이다.

<br/>

그 위에서 도는 것이 웹만 있는 것이 아니다.

```java
웹     - HTTP
메일   - SMTP, IMAP
파일   - FTP, SFTP
원격접속 - SSH
게임    - 대개 자체 프로토콜 (앞의 TCP, UDP 글에서 본 UDP 기반)
```

<br/>

앞의 TCP IP stack 글에서 본 계층 구조로 보면,

인터넷은 아래 세 계층이고 웹은 맨 위 응용 계층의 하나다.

<br/>

`인터넷이 안 된다` 와 `웹사이트가 안 열린다` 가 다른 문제인 이유가 이것이다.

앞의 OSI 글에서 본 대로, 어느 계층 문제인지부터 좁혀야 한다.
