## 궁금증!

```java
각 단계가 실제로 얼마나 걸리는지 재볼 수 있을까?
```

`curl` 이 단계별로 알려준다.

```java
$ curl -w "DNS 조회      : %{time_namelookup}s
TCP 연결      : %{time_connect}s
첫 바이트 수신 : %{time_starttransfer}s
전체          : %{time_total}s
" http://localhost:18083/etag

DNS 조회      : 0.000011s
TCP 연결      : 0.000232s
첫 바이트 수신 : 0.001041s
전체          : 0.001085s
```

<br/>

원문의 흐름이 이 숫자에 그대로 대응된다.

```java
1. DNS 로 IP 를 찾는다              -> time_namelookup
2. TCP 연결을 맺는다 (3 way handshake) -> time_connect
3. HTTP 요청을 보내고 응답을 기다린다  -> time_starttransfer
4. 응답을 다 받는다                  -> time_total
```

<br/>

같은 컴퓨터라 전부 밀리초 미만인데, 실제 인터넷에서는 각 단계가 수십에서 수백 밀리초다.

<br/>

## 어느 단계가 느린지로 원인을 좁힌다

이 숫자를 보면 문제의 위치를 알 수 있다.

```java
DNS 조회가 느리다        -> DNS 서버 문제. TTL 이나 DNS 제공자를 본다
TCP 연결이 느리다        -> 네트워크 거리 문제. CDN 을 고려한다
첫 바이트까지가 느리다    -> 서버가 느린 것. 앞의 DB 인덱스 글에서 본 쿼리를 본다
전체는 느린데 첫 바이트는 빠르다 -> 응답 크기가 큰 것. 압축이나 페이징을 본다
```

<br/>

`첫 바이트 수신` 을 `TTFB(Time To First Byte)` 라고 부른다.

서버가 요청을 받아서 응답을 만들기 시작할 때까지의 시간이라, 서버 성능의 지표로 쓴다.

<br/>

## 브라우저는 여기서 끝이 아니다

`curl` 은 응답을 받으면 끝인데, 브라우저는 그때부터 일이 시작된다.

```java
HTML 을 받는다
  -> 파싱하면서 <link>, <script>, <img> 를 발견한다
  -> 그것들을 또 요청한다 (각각 다시 위 4 단계를 거친다)
  -> CSS 를 받으면 스타일을 계산한다
  -> JS 를 받으면 실행한다
  -> 화면을 그린다
```

<br/>

그래서 페이지 하나를 여는 데 요청이 수십에서 수백 개 나간다.

<br/>

앞의 비 연결성 글에서 본 `연결 재사용` 과 `HTTP/2` 가 중요한 이유가 이것이다.

요청 하나마다 연결을 새로 맺으면 감당이 안 된다.

<br/>

## HTML 파싱이 멈추는 지점

```html
<script src="/js/app.js"></script>
```

<br/>

브라우저는 이 줄을 만나면 파싱을 멈추고 파일을 받아 실행한다.

자바스크립트가 문서 구조를 바꿀 수 있어서, 다 실행하기 전에는 다음 줄을 해석할 수 없다.

<br/>

그래서 `<script>` 를 `<head>` 에 두면 화면이 늦게 뜬다.

<br/>

해결 방법이 두 가지 있다.

```html
<script src="/js/app.js" defer></script>    <!-- 받아만 두고 파싱이 끝나면 실행 -->
<script src="/js/app.js" async></script>    <!-- 받는 대로 바로 실행 (순서 보장 안 됨) -->
```

<br/>

또는 `</body>` 직전에 두는 전통적인 방법도 있다.

<br/>

## 앞의 글들과 이어보면

한 번의 요청에 지금까지 본 것들이 전부 들어 있다.

```java
DNS 조회        -> 앞의 PORT, DNS 글
TCP 연결        -> 앞의 TCP 3 way handshake 글
요청 메시지      -> 앞의 HTTP 메시지 글
캐시 확인       -> 앞의 캐시 기본 동작 글, 검증 헤더 글
서버 처리       -> 앞의 디스패처 서블릿 글, DB 인덱스 글
응답 메시지      -> 앞의 상태 코드 글
```

<br/>

브라우저 주소창에 엔터를 치면 이 전부가 순서대로 일어나는 것이다.

면접에서 이 질문이 자주 나오는 이유가, 이 하나로 전 영역을 물어볼 수 있어서다.
