## HTTP 상태코드 소개 (2xx, 3xx)

100대, 200대, 300대, 400대, 500대 에러가 있는 것이다.

- 이중에서 100대 에러는 잘 사용하지 않는다.

<br/><br/>

## 상태 코드

클라이언트가 보낸 요청의 처리 상태를 응답에서 알려주는 기능이다

- `1xx` : 요청이 수신되어 처리중

- `2xx` : 요청 정상 처리

- `3xx` : 요청을 완료하려면 추가 행동이 필요

- `4xx` : 클라이언트 오류, 잘못된 문법등으로 서버가 요청을 수행할 수 없다

- `5xx` : 서버 오류, 서버가 정상 요청을 처리하지 못한다.

```java
"만약 299, 455, 588 이런식으로 온다면?"
-> 다 이해 하지 않아도 되고, 그냥 "2백대구나", "4백대구나" 라고 생각하면 된다.
```

<br/><br/>

## 202 Accepted

요청이 접수되었으나 처리가 완료되지 않았다.

- 배치 처리 같은 곳에서 사용한다.

- e.g.) 요청 접수 후 1시간 뒤에 배치 프로세스가 요청을 처리함.

<br/>

## 204 No Content

서버가 요청을 성공적으로 수행했지만, 응답 페이로드 본문에 보낼 데이터가 없다.

- e.g.) 웹 문서 편집기에서 save 버튼

- save 버튼의 결과로 아무 내용이 없어도 된다.

- save 버튼을 눌러도 같은 화면을 유지해야 한다.

- 결과 내용이 없어도 204 메시지 (2xx)만으로 성공을 인식할 수 있다.

<br/><br/>

## 3xx - 리다이렉션

- 클라이언트가 서버 요청을 했다.

    - 그러면 서버가 `“이, 요청을 완료 할려면 추가적인 작업이 필요해”` 말하고, 다시 클라이언트에게 보내는 것이다.
        

```java
"301 ~ 308까지가 중요하다"
```

<br/>

### 3xx : 요청을 완료하기 위해 유저 에이전트의 추가 조치 필요

- `300` : Muliiple Choices

- `301` : Moved Permanently

- `302` : Found

- `303` : See Other

- `304` : Not Modified

- `307` : Temporary Redirect


<br/><br/>

웹 브라우저는 `3xx` 응답 결과에 Location 헤더가 있으면, 

`Location` 위치로 자동 이동하는 것을 `리다이렉트` 라고도 부른다.

- 위 그림을 보면 1번 순서를 보면 `/event` 요청을 보낸다.

        `301 시리즈와 동시`에 `새로운 /new-event 를 보내주는 것이다.`

- 변경된 url로 요청을 다시 서버로 보내고, 마지막 5번 `“ok”`를 해야 끝나게 되는 것이다.

## 리다이렉션 이해

- 영구 리다이렉션 - 특정 리소스의 URI가 영구적으로 이동한다.

    - e.g. `/members → /users`

    - e.g. `/event → /new-event`

- 일시 리다이렉션 - 일시적인 변경

    - 주문 완료 후 주문 내역 화면으로 이동

    - PRG: `post / Redirect / Get`

- 특수 리다이렉션

    - 결과 대신 캐시를 사용


<br/><br/>

## 301, 308은 기능이 똑같다. (영구 리다이렉션)

- 리소스의 URI가 영구적으로 이동한다.

- 원래의 URL를 사용하지 않고, 검색 엔진 등에서도 변경을 인지한다.

- 301, 308 : 리다이렉트시 요청 메서드가 GET으로 변하고, 본문이 제거될 수 있다.

<br/>

## 302, 307, 303 (일시적인 리다이렉션)

```java
"302는 요청 메서드가 GET 으로 변할 수도 있고, 아닐수도 있다"
 -> 이걸 보완 한것이 303 인것이다. 
 -> 303은 무조건 GET으로 보낸다. (=302와 기능은 같다)
```

- 리소스의 URI가 일시적으로 변경
    - 따라서 검색 엔진 등에서 URL을 변경하면 안됨
- 리다이렉트시 요청 메서드가 GET으로 변하고, 본문이 제거될 수 있음.

<br/>

### 그렇다면 일시적인 리다이렉트 언제 사용할까?

```java
"PRG 순간에 사용한다"
```

1. POST로 상품 주문하기 `버튼을 누른다`

4. 그 POST의 데이터가 한번 더 들어가게 될 것이다.

## 궁금증!

```java
상태 코드가 실제 응답에서 어디에 찍히는지 보자
```

여러 코드를 내려주는 서버를 띄워서 확인해봤다.

```java
$ curl -i http://localhost:18083/status/200
HTTP/1.1 200 OK

$ curl -i http://localhost:18083/status/201
HTTP/1.1 201 Created
```

<br/>

첫 줄에 `HTTP 버전 + 숫자 + 설명` 이 들어간다. 이것을 `상태 줄` 이라고 한다.

앞의 HTTP 메시지 글에서 본 `status-line` 이 이것이다.

<br/>

뒤의 `OK` 나 `Created` 는 사람이 읽으라고 붙은 것이라 바꿔도 된다.

프로그램은 숫자만 본다.

<br/>

## 201 에는 Location 을 같이 준다

```java
HTTP/1.1 201 Created
Location: /members/100
```

<br/>

`만들었다` 만 알려주면 클라이언트가 그 자원이 어디 있는지 모른다.

그래서 새로 만들어진 곳의 주소를 `Location` 헤더로 알려준다.

<br/>

앞의 리다이렉트 글에서 본 `302` 의 `Location` 과 헤더 이름은 같은데 뜻이 다르다.

```java
3xx 의 Location - "저기로 다시 요청해라"
201 의 Location - "만들어진 게 여기 있다" (다시 요청하라는 뜻은 아니다)
```

<br/>

## 204 는 본문이 없어야 한다

```java
HTTP/1.1 204 No Content
```

<br/>

`처리는 됐는데 보여줄 내용이 없다` 는 뜻이다.

<br/>

`DELETE` 응답에 많이 쓴다. 지웠으니 돌려줄 것이 없다.

<br/>

여기서 규칙이 하나 있다. `204` 에는 본문을 넣으면 안 된다.

`Content-Length` 도 넣지 않는다. 넣으면 클라이언트가 혼란스러워한다.

<br/>

앞의 검증 헤더 글에서 본 `304` 도 같은 부류다. 본문 없이 헤더만 간다.

<br/>

## 202 는 아직 안 끝났다는 뜻이다

```java
HTTP/1.1 202 Accepted
```

<br/>

`요청은 받았는데 처리는 나중에 한다` 는 뜻이다.

<br/>

파일 변환이나 대량 메일 발송처럼 오래 걸리는 작업에 쓴다.

바로 처리하면 응답이 몇 분씩 걸리니, 일단 받았다고 답하고 나중에 처리한다.

<br/>

이때 진행 상황을 볼 주소를 같이 주는 것이 보통이다.

```java
HTTP/1.1 202 Accepted
Location: /jobs/abc123
```

<br/>

클라이언트는 그 주소를 주기적으로 조회해서 끝났는지 확인한다.

<br/>

## 3xx 는 방향을 바꾸라는 뜻이다

앞의 리다이렉트 글에서 실제로 확인한 그 동작이다.

```java
$ curl -i -X POST http://localhost:18081/order -d "item=book"

HTTP/1.1 302 Temporary Redirect
Content-length: 0
Location: /order/done
```

<br/>

본문이 없고 `Location` 만 있다.

<br/>

그리고 `302` 를 받으면 브라우저가 메서드를 `GET` 으로 바꿔서 다시 요청한다.

```java
$ curl -L -X POST http://localhost:18081/order -d "item=book"

주문 완료 화면
[최종 URL] http://localhost:18081/order/done
```

<br/>

이 성질 때문에 앞의 PRG 글에서 본 중복 주문 방지가 가능해진다.

<br/>

## 301 과 308, 302 와 307

두 쌍으로 나뉜다.

```java
301 Moved Permanently  - 영구. 메서드를 GET 으로 바꿀 수 있다
308 Permanent Redirect - 영구. 메서드를 유지한다

302 Found              - 임시. 메서드를 GET 으로 바꿀 수 있다
307 Temporary Redirect - 임시. 메서드를 유지한다
```

<br/>

`301` 과 `302` 는 원래 메서드를 유지하도록 정의됐는데,

브라우저들이 전부 `GET` 으로 바꾸도록 구현해버려서 그게 사실상 표준이 됐다.

<br/>

그래서 `메서드를 반드시 유지한다` 는 뜻으로 `307` 과 `308` 을 새로 만들었다.

<br/>

실무에서 `POST` 를 리다이렉트할 일은 드물어서 `301` 과 `302` 만으로 대개 충분하다.

다만 `301` 은 브라우저가 캐시해버리니 조심해야 한다.

```java
잘못 걸린 301 -> 사용자 브라우저에 남는다 -> 서버를 고쳐도 계속 옛 주소로 간다
```

<br/>

확실하지 않으면 `302` 로 시작하는 편이 안전하다.
