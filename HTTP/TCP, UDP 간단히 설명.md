## TCP 특징

### 전송 제어 프로토콜

- 데이터 전달 보증

<br/>

## UDP 특징

‘포트’ 라는게 추가 되는 것이다.

<br/>

### 포트 설명

한개의 PC에 IP는 한개 이다. 그런데 여기서 게임, 노래, 영화 다 할 수 있다.

그런데 게임용 패킷, 노래 패킷, 영화 패킷을 어떻게 구분 하지? 라고 할때 사용하는 것이 ‘포트’ 이다.

```java
- 햐얀 도화지에 비유(기능이 거의 없음)
- 연결지향 - TCP 3 way handshake X
- 데이터 전달 보증 X
- 순서 보장 X
- 데이터 전달 및 순서가 보장되지 않지만, 단순하고 빠름
```

<br/>

### 정리

- IP와 거의 같다. + PORT + 체크섬 정도만 추가

- 애플렠이션에 추가 작업 필요
<br/>

## 궁금증!

```java
UDP 가 "신뢰성이 없다" 는데 그럼 어디에 쓸까?
```

`늦게 오는 것보다 안 오는 게 나은` 경우에 쓴다.

<br/>

TCP는 패킷이 유실되면 다시 보낸다. 그동안 뒤의 데이터는 기다린다.

```java
화상 통화에서 0.5 초 전 화면이 늦게 도착한다
-> 그걸 보여주는 것이 의미가 있나?
-> 차라리 버리고 지금 화면을 보여주는 게 낫다
```

<br/>

그래서 실시간 스트리밍, 게임, 음성 통화가 UDP를 쓴다.

```java
TCP - 하나도 빠지면 안 되고 순서가 중요하다  (파일 전송, 웹, 메일)
UDP - 조금 빠져도 되고 지금이 중요하다      (스트리밍, 게임, DNS)
```

<br/>

## DNS 가 UDP 인 이유는 다르다

앞의 PORT, DNS 글에서 본 조회는 크기가 아주 작다.

```java
질문 : "example.com 의 IP 가 뭐야?"
답   : "172.66.147.243"
```

<br/>

이걸 위해 앞의 TCP 3 way handshake 글에서 본 왕복 `1.5` 번을 먼저 하는 것이 아깝다.

<br/>

UDP는 그냥 보내고 그냥 받는다. 왕복 한 번이면 끝난다.

응답이 안 오면 다시 물어보면 그만이다.

```java
TCP 로 DNS 조회 - 핸드셰이크 1.5 왕복 + 질문 답변 1 왕복 = 2.5 왕복
UDP 로 DNS 조회 - 1 왕복
```

<br/>

응답이 커서 UDP 한 패킷에 안 들어가면 그때는 TCP로 다시 물어본다.

<br/>

## HTTP/3 가 UDP 를 택한 것

앞의 비 연결성 글에서 본 그 이야기다.

```java
HTTP/2 - TCP 위에서 여러 요청을 동시에 처리한다
         그런데 패킷 하나가 유실되면 TCP 가 전부 멈춰 세운다
HTTP/3 - UDP 위에 QUIC 을 새로 만들었다
         스트림마다 독립적이라 하나가 유실돼도 나머지는 계속 간다
```

<br/>

`UDP 라서 신뢰성이 없다` 가 아니라, `TCP 를 안 쓰고 직접 신뢰성을 구현했다` 에 가깝다.

<br/>

QUIC은 재전송도 하고 순서도 맞춘다. 다만 그 단위를 스트림별로 잘게 나눈 것이다.

TCP는 커널에 박혀 있어서 고치기 어려운데, UDP 위에 만들면 애플리케이션 레벨에서 자유롭게 바꿀 수 있다.

<br/>

## 그래서 나누는 기준은 이렇게 정리된다

```java
데이터가 하나라도 빠지면 안 되는가
  예   -> TCP (또는 QUIC 처럼 그 위에 만든 것)
  아니오 -> UDP

지연이 늘어나는 것보다 데이터가 빠지는 게 나은가
  예   -> UDP
  아니오 -> TCP
```

<br/>

## 헤더 크기도 다르다

```java
TCP 헤더 - 최소 20 바이트 (순서 번호, 확인 번호, 윈도 크기 등)
UDP 헤더 - 8 바이트 (출발 포트, 도착 포트, 길이, 체크섬)
```

<br/>

UDP 헤더에는 `순서 번호` 가 없다. 순서를 보장하지 않으니 필요가 없다.

`확인 번호` 도 없다. 잘 받았는지 확인하지 않으니 필요가 없다.

<br/>

헤더에 무엇이 없는지를 보면 그 프로토콜이 무엇을 포기했는지가 그대로 보인다.

<br/>

## 포트는 둘 다 있다

```java
TCP 헤더 - 출발 포트, 도착 포트가 있다
UDP 헤더 - 출발 포트, 도착 포트가 있다
```

<br/>

앞의 PORT, DNS 글에서 본 대로, 포트는 `같은 컴퓨터 안의 어느 프로그램인지` 를 가린다.

<br/>

IP는 컴퓨터까지만 찾아준다. 그 안에서 어느 프로그램인지는 포트가 정한다.

이건 신뢰성과 상관없는 일이라 둘 다 갖고 있는 것이다.

<br/>

그래서 TCP `8080` 과 UDP `8080` 은 서로 다른 포트다. 동시에 열어둘 수 있다.
