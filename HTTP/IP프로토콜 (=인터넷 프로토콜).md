## IP프로토콜 (=인터넷 프로토콜)

<br/>

### 인터넷 프로토콜 역할

- 지정한 IP 주소(IP Address)에 데이터 전달

- 패킷(Packet)이라는 통신 단위로 데이터 전달


<br/>

### 패킷이란?

패키지나 소화물, 덩어리의 합성어를 패킷 이라고 한다.

즉, 실제 ‘택배 박스 보내듯’이 비슷한 느낌이라고 생각하면 된다.


<br/>

### e.g. 친구에게 메세지를 보내고 싶다.

그러면 필요한 것이 내 ip와 친구의 ip가 필요한 것이다.

그래서 노드끼리 서로 던지고 데이터를 보내면서 친구에게 도착하는 것이다.

![이미지](/programming/img/입문547.PNG)


<br/><br/>

## 하지만 문제가 있다.

친구의 서버가 죽었는지 살았는지 그런것도 모르고 일단 보낸다.

즉, 그냥 우표 보내듯이 친구가 이사를 갔는지 아닌지도 모른체 그냥 보내는 것이다.

또한, 한 구역에서 멧돼지나 다른 사람에게 타격을 입어 케이블이 고장 났을 경우도 있다. 

- 서버가 문제가 생긴다고 하더라도 패킷이 소실 되도 모른다.

![이미지](/programming/img/입문548.PNG)

<br/>

### 용량이 크다면 이렇게 끊어서 보낸다.

예제로 원래 Hello, world! 를 보내야 되는데, 끊어서 보낸 것이다.

그림에서 보이듯이 가능 방법이 다 다를 수 있고, 도착하는 순서도 다를 수 있다.

![이미지](/programming/img/입문549.PNG)


<br/>

### 이렇게 IP프로토콜 만으로는 이 문제들을 해결 할 수 없다.

이런 문제들을 해결해 주는 것이 바로. TCP 프로토콜이다.
<br/>

## 궁금증!

```java
IP 의 문제를 TCP 가 어떻게 해결하는지 하나씩 맞춰보면
```

원문에서 든 문제들에 해법을 짝지으면 이렇게 된다.

```java
비연결성 - 상대가 받을 수 있는지 모르고 그냥 보낸다
  -> TCP 의 3 way handshake 로 먼저 확인한다

비신뢰성 - 중간에 사라져도 모른다
  -> TCP 가 확인 응답(ACK)을 받고, 안 오면 다시 보낸다

순서 보장 없음 - 뒤에 보낸 것이 먼저 도착할 수 있다
  -> TCP 가 순서 번호를 붙여서 받는 쪽이 다시 정렬한다

프로그램 구분 없음 - 어느 프로그램에게 줄지 모른다
  -> TCP 헤더의 포트 번호로 구분한다
```

<br/>

앞의 TCP 3 way handshake 글과 TCP IP stack 글에서 본 것들이 전부 이 문제들의 해법이다.

<br/>

## 그런데 왜 IP 를 그렇게 만들었을까

일부러 단순하게 만든 것이다.

<br/>

중간의 라우터가 하는 일이 적을수록 빠르고, 고장 나도 다른 길로 우회하기 쉽다.

라우터가 순서와 재전송까지 챙기려면 각 연결의 상태를 기억해야 하는데,

수십만 개의 연결을 기억하는 라우터는 만들 수가 없다.

<br/>

그래서 `중간은 단순하게, 끝단이 알아서` 라는 방향을 택했다.

이것을 `End-to-End 원칙` 이라고 한다.

```java
IP  - 최선을 다해 보내본다. 안 되면 어쩔 수 없다
TCP - 양 끝단에서 확인하고 다시 보낸다
```

<br/>

앞의 TCP, UDP 글에서 본 대로, 신뢰성이 필요 없으면 UDP로 그 층을 건너뛸 수도 있다.

필요한 쪽만 비용을 내는 구조인 셈이다.

<br/>

## IP 주소가 하는 일

앞의 TCP IP stack 글에서 본 대로, IP는 최종 목적지만 가리킨다.

```java
IP 주소  : 출발지와 목적지가 끝까지 그대로다
MAC 주소 : 구간마다 바뀐다
```

<br/>

라우터는 목적지 IP를 보고 `다음에 어디로 넘길지` 만 정한다.

전체 경로를 아는 것이 아니라 한 걸음씩만 안다.

<br/>

앞의 네트워크와 인터넷 개념 글에서 본 `ISP 끼리 연결된다` 는 것이 이 걸음들의 연결이다.

<br/>

## IPv4 가 부족해진 이야기

```java
IPv4 - 32 비트. 약 43 억 개
IPv6 - 128 비트. 사실상 무한
```

<br/>

`43억` 개가 많아 보이는데, 전 세계 사람이 휴대폰과 컴퓨터를 여러 대씩 쓰면 부족하다.

<br/>

당장은 `NAT` 로 버티고 있다.

```java
집 안 : 192.168.0.2, 192.168.0.3, 192.168.0.4  (사설 IP)
공유기 : 공인 IP 하나
```

<br/>

공유기가 나갈 때 주소를 자기 것으로 바꾸고, 들어올 때 원래 기기로 돌려준다.

여러 기기가 공인 IP 하나를 공유하는 것이다.

<br/>

이때 구분하는 기준이 포트다. 앞의 PORT, DNS 글에서 본 임시 포트가 여기 쓰인다.

```java
192.168.0.2:52629 -> 공인IP:40001
192.168.0.3:52629 -> 공인IP:40002
```

<br/>

## NAT 때문에 생기는 제약

밖에서 안으로 먼저 연결할 수가 없다.

```java
공유기가 "이 요청을 안의 어느 기기에게 줄지" 를 모른다
-> 내가 먼저 나간 적이 있어야 그 대응 관계가 생긴다
```

<br/>

집에 서버를 두고 밖에서 접속하려면 `포트 포워딩` 을 설정해야 하는 이유가 이것이다.

`공인IP:8080 으로 오는 것은 192.168.0.5:8080 으로 보내라` 고 미리 적어두는 것이다.

<br/>

앞의 클라이언트 서버 구조 글에서 본 `클라이언트가 먼저 요청한다` 는 전제가

이 제약과 잘 맞아떨어진다.

<br/>

서버가 먼저 클라이언트에게 보내야 하는 경우가 어려운 이유도 이것이다.

푸시 알림이나 웹소켓이 `연결을 클라이언트가 먼저 열어두고 유지하는` 방식인 것이 그래서다.
