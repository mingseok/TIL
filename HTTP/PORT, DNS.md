## 이름 해결을 담당하는 DNS

DNS는 HTTP와 같이 응용 계층 시스템에서 도메인 이름과 IP 주소 이름 확인을 제공한다.

<br/>

### 무슨말인가?

컴퓨터는 IP 주소와는 별도로 호스트 이름과 도메인 이름을 붙일 수 있습니다.

예를 들어, “[www.mingseok.kr”](http://www.mingseok.xn--kr-02t/) 과 같이 적혀 있습니다

<br/>

주로 사용자는 IP 주소 대신 이름을 이용하여 상대의 컴퓨터를 지정합니다.

숫자를 나열하는 IP주소를 지정하는 것보다 영어로 표기해 컴퓨터의 이름을 지정하는 것이 인간에게 친숙합니다.

<br/>

그러나 컴퓨터에게는 반대입니다. 이 문제를 해결하기 위해 DNS가 있습니다.

DNS는 도메인명에서 IP 주소를 조사하거나 반대로 IP주소로부터 도메인명을 조사하는 서비스를 제공하고 있습니다.
<br/>

## 궁금증!

```java
DNS 조회가 실제로 어떤 결과를 돌려줄까?
```

`dig` 로 직접 물어봤다.

```java
$ dig +noall +answer example.com A

example.com.  56  IN  A  172.66.147.243
example.com.  56  IN  A  104.20.23.154
```

<br/>

IP가 두 개다. 한 이름에 여러 서버를 붙여둔 것이다.

<br/>

이러면 클라이언트가 그중 하나를 골라 접속한다.

서버 한 대가 죽어도 다른 IP로 접속되니 자연스럽게 이중화가 된다.

이 방식을 `DNS 라운드 로빈` 이라고 한다.

<br/>

앞의 `56` 은 `TTL` 이다. 초 단위로 `이 정보를 얼마나 캐시해도 되는지` 를 뜻한다.

`56` 초가 지나면 다시 물어봐야 한다.

<br/>

## TTL 이 짧으면 배포가 유연해진다

서버 IP를 바꿔야 할 때 이 값이 중요하다.

```java
TTL 이 3600 (1시간) -> IP 를 바꿔도 최대 1시간 동안 옛 IP 로 간다
TTL 이 60 (1분)     -> 1분 안에 새 IP 로 넘어간다
```

<br/>

그래서 서버를 옮기기 전에 미리 `TTL` 을 줄여두는 것이 관행이다.

<br/>

앞의 캐시 글에서 본 `max-age` 와 발상이 똑같다.

`얼마나 오래 믿어도 되는지` 를 알려주는 것이다.

<br/>

## 이름을 찾는 순서가 있다

DNS 서버에 물어보기 전에 먼저 보는 곳이 있다.

```java
1. 브라우저 캐시
2. OS 캐시
3. hosts 파일
4. DNS 서버
```

<br/>

`hosts` 파일을 열어보면 이런 줄이 있다.

```java
$ grep localhost /etc/hosts

127.0.0.1   localhost
::1         localhost
```

<br/>

`localhost` 가 `127.0.0.1` 인 것이 여기 적혀 있어서 그런 것이다.

DNS 서버에 물어보지 않고 파일에서 바로 찾는다.

<br/>

이걸 이용해서 개발할 때 도메인을 흉내내기도 한다.

```java
127.0.0.1   api.local.test
```

<br/>

이렇게 적어두면 브라우저에서 `api.local.test` 로 접속했을 때 내 컴퓨터로 온다.

쿠키 도메인 설정을 테스트할 때 유용하다.

<br/>

## 포트는 어떻게 확인하는가

```java
$ curl -w "로컬 포트 : %{local_port}\n원격 포트 : %{remote_port}\n" http://localhost:18083/etag

로컬 포트 : 52629
원격 포트 : 18083
```

<br/>

내가 요청한 서버 포트는 `18083` 이고, 내 쪽 포트는 `52629` 다.

<br/>

내 쪽 포트는 OS가 남는 번호 중에서 아무거나 골라준다.

이것을 `임시 포트(ephemeral port)` 라고 하고 대개 `49152~65535` 범위다.

<br/>

그래서 같은 서버에 여러 번 접속해도 구분이 된다.

```java
연결 1 : 내 IP:52629 <-> 서버 IP:18083
연결 2 : 내 IP:52630 <-> 서버 IP:18083
```

<br/>

이 네 개의 조합으로 연결 하나가 구분된다.

앞의 TCP/IP stack 글에서 본 `소켓` 이 이 조합이다.

<br/>

## 잘 알려진 포트

```java
20, 21 - FTP
22     - SSH
53     - DNS
80     - HTTP
443    - HTTPS
3306   - MySQL
5432   - PostgreSQL
6379   - Redis
```

<br/>

앞의 URI 글에서 본 `포트 생략` 이 `80` 과 `443` 덕분에 가능한 것이다.

<br/>

`1024` 미만은 관리자 권한이 있어야 열 수 있다.

그래서 스프링 부트 기본 포트가 `8080` 인 것이다. 권한 없이 열 수 있는 번호다.

<br/>

운영에서는 앞에 `Nginx` 를 두고 `80` 과 `443` 을 받게 한 뒤,

내부적으로 `8080` 으로 넘기는 구성을 많이 쓴다.
