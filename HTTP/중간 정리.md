## 중간 정리

### 복잡한 인터넷망에 메세지를 보내기 위해서 제일 먼저.

1. 인터넷 프로토콜 이라는 IP가 있어야 된다. (=IP 프로토콜이라고도 부른다.)

1. 그런데 IP 프로토콜만 가지고는 메세지가 잘 도착했는지 신뢰하기 어렵고, 
    
    ‘포트’ 라는 개념도 없고, 순서가 뒤죽박죽 일수가 있다.
    
2. 이런거에 대한 문제를 TCP 프로토콜이 해결해 준다.

1. UDP는 거의 IP랑 똑같은데 ‘포트’ 정도만 추가되는 백지 상태라고 생각하면 되고, 
    
    필요하면 UDP 프로토콜 위에 내 애플리케이션에서 기능을 확장 해볼 수 있다.
    
2. 그리고 PORT는 같은 IP 안에서 동작하는 것이며, 통신 할 애플리케이션을 구분하기 위해서 사용 한다. 
    
    쉽게 얘기하여 IP가 아파트고, 포트는 몇동 몇호가 되는 것이다.
    
3. DNS는 IP는 변하기 쉽고 외우기 어려운데, 도메인 명을 등록해서 사용할 수 있도록 도와 주는 것이다.

     -> 앞의 TCP, UDP 글. IP 의 부족한 점을 채운다

     -> 앞의 PORT, DNS 글. IP 는 컴퓨터까지, 포트는 프로그램까지

     -> 앞의 상태 코드 글. 200 인지 404 인지

## 각 계층이 무엇을 책임지는지로 다시 보면

```java
IP  - 목적지까지 어떻게든 보낸다. 도착 여부는 모른다
TCP - 도착했는지 확인하고, 순서를 맞추고, 프로그램을 구분한다
HTTP - 무엇을 원하는지, 결과가 어떤지를 표현한다
```

<br/>

앞의 TCP IP stack 글에서 본 캡슐화가 이 셋을 겹겹이 싸는 과정이다.

```java
[이더넷][IP][TCP][HTTP 메시지]
```

## UDP 가 백지라는 말

원문의 `UDP 는 IP 에 포트만 추가된 백지` 라는 표현이 정확하다.

<br/>

앞의 TCP, UDP 글에서 헤더를 비교해보면 그게 드러난다.

```java
TCP 헤더 - 최소 20 바이트 (순서 번호, 확인 번호, 윈도 크기 ...)
UDP 헤더 - 8 바이트 (출발 포트, 도착 포트, 길이, 체크섬)
```

<br/>

UDP 헤더에 순서 번호도 확인 번호도 없다.

없는 것을 보면 무엇을 포기했는지가 그대로 보인다.

<br/>

그래서 `HTTP/3` 가 UDP 위에 새로 만든 것도 이 백지 성질 덕분이다.

TCP는 커널에 박혀 있어 못 고치는데, UDP 위에는 원하는 대로 만들 수 있다.

<br/>

## DNS 를 쓰는 이유가 하나 더 있다

원문의 `IP 는 변하기 쉽고 외우기 어렵다` 에 더해서,

앞의 PORT, DNS 글에서 본 것처럼 한 이름에 IP를 여러 개 붙일 수 있다.

```java
example.com.  56  IN  A  172.66.147.243
example.com.  56  IN  A  104.20.23.154
```

<br/>

이러면 서버 한 대가 죽어도 다른 IP로 접속된다.

이름과 실제 위치를 분리해두면 뒤에서 무엇이 바뀌든 이름은 그대로 쓸 수 있는 것이다.

<br/>

앞의 뷰 리졸버 글이나 PSA 글에서 본 것과 같은 발상이 여기에도 있다.
