## 객체지향적 설계 예시

```java
class Solution {

        public int solution(final int num) {
            Number number = new Number(num);
            Count count = new Count();
            progress(number, count);
            return count.getValue();
        }

        private void progress(final Number number, final Count count) {
            while (number.isNotOne() && count.canProgress()) {
                calculate(number, count);
            }
        }

        private void calculate(final Number number, final Count count) {
            if (number.isEven()) {
                number.divide(2);
            } else {
                number.multiple(3);
                number.add(1);
            }
            count.add();
            if (count.canNotProgress()) {
                count.impossible();
            }
        }
    }

    class Number {

        private int value;

        public Number(int value) {
            this.value = value;
        }

        public boolean isEven() {
            return value % 2 == 0;
        }

        public boolean isNotOne() {
            return !isOne();
        }

        public boolean isOne() {
            return value == 1;
        }

        public void multiple(int count) {
            this.value *= count;
        }

        public void add(int add) {
            this.value += add;
        }

        public void divide(int value) {
            this.value /= value;
        }

        @Override
        public String toString() {
            return "Number{" +
                "value=" + value +
                '}';
        }
    }

     class Count {

        private static final int END_COUNT = 500;
        private int value = 0;

        public void add() {
            value++;
        }

        public boolean canProgress() {
            return 0 <= value && value < END_COUNT;
        }

        public boolean canNotProgress() {
            return value == END_COUNT;
        }

        public void impossible() {
            value = -1;
        }

        public int getValue() {
            return value;
        }
    }
```

public class LottoGame {

    public void run() {
        int money = readMoney();
        int count = money / 1000;

        List<List<Integer>> lottos = new ArrayList<>();
        for (int i = 0; i < count; i++) {
            List<Integer> numbers = new ArrayList<>();
            while (numbers.size() < 6) {
                int number = random.nextInt(45) + 1;
                if (!numbers.contains(number)) {
                    numbers.add(number);
                }
            }
            Collections.sort(numbers);
            lottos.add(numbers);
        }

        List<Integer> winning = readWinningNumbers();

        int[] result = new int[6];
        for (List<Integer> lotto : lottos) {
            int matched = 0;
            for (int number : lotto) {
                if (winning.contains(number)) {
                    matched++;
                }
            }
            if (matched >= 3) {
                result[matched]++;
            }
        }
        printResult(result);
    }
}

### 객체로 나누면

```java
public class LottoNumber {
    private static final int MIN = 1;
    private static final int MAX = 45;
    private final int value;

    public LottoNumber(int value) {
        if (value < MIN || value > MAX) {
            throw new IllegalArgumentException("로또 번호는 1~45 사이여야 합니다");
        }
        this.value = value;
    }
}

public class Lotto {
    private static final int SIZE = 6;
    private final Set<LottoNumber> numbers;

    public Lotto(Set<LottoNumber> numbers) {
        if (numbers.size() != SIZE) {
            throw new IllegalArgumentException("로또는 6개여야 합니다");
        }
        this.numbers = new HashSet<>(numbers);
    }

    public int matchCount(Lotto other) {
        return (int) numbers.stream().filter(other.numbers::contains).count();
    }
}

public class Lottos {
    private final List<Lotto> lottos;

    public Map<Rank, Integer> match(Lotto winning) {
        return lottos.stream()
                .map(lotto -> Rank.of(lotto.matchCount(winning)))
                .collect(groupingBy(rank -> rank, counting()));
    }
}
```

## 무엇이 달라졌는지 짚어보면

### 1) 규칙이 타입에 들어갔다

```java
int number          // 0 도 100 도 들어간다
LottoNumber number  // 만들어진 순간 1~45 가 보장된다
```

<br/>

앞의 객체지향 생활 체조 글의 `원시값 포장` 이다.

앞의 생성자를 왜 만들어야 하나요 글에서 본 `객체가 존재하면 조건이 지켜진 것` 이기도 하다.

<br/>

### 2) 중복 규칙이 자료구조로 표현됐다

`while` 문으로 중복을 걸러내던 것이 `Set` 하나로 끝났다.

앞의 자바 API를 사용하자 글에서 본 `직접 구현하기 전에 API 를 찾아본다` 가 이것이다.

<br/>

### 3) 계산이 그 데이터를 가진 쪽으로 갔다

```java
// 밖에서 센다
for (int number : lotto) {
    if (winning.contains(number)) matched++;
}

// 안에서 센다
lotto.matchCount(winning)
```

<br/>

앞의 객체는 객체스럽게 사용한다 글에서 본 그 이동이다.

<br/>

### 4) 테스트할 수 있게 됐다

```java
@Test
void 번호가_3개_일치하면_3을_반환한다() {
    Lotto lotto = new Lotto(numbers(1, 2, 3, 4, 5, 6));
    Lotto winning = new Lotto(numbers(1, 2, 3, 7, 8, 9));

    assertThat(lotto.matchCount(winning)).isEqualTo(3);
}
```

<br/>

콘솔 입출력 없이 규칙만 검증할 수 있다.

앞의 테스트 코드 작성 규칙 글에서 본 `작은 단위의 테스트` 가 가능해진 것이다.

<br/>

## 그런데 클래스가 다섯 개로 늘었다

이게 비용이다. 파일을 오가며 읽어야 한다.

<br/>

`LottoGame` 하나만 보면 전체 흐름이 한눈에 들어오는데,

나누고 나면 흐름을 알려면 여러 파일을 열어야 한다.

<br/>

앞의 트레이드 오프 글의 관점으로 보면 이렇게 갈린다.

```java
절차적   - 지금 읽기는 쉽다. 대신 바꾸기 어렵고 테스트가 안 된다
객체지향 - 파일이 늘어난다. 대신 바꿀 때 그 자리만 고치면 된다
```

<br/>

한 번 쓰고 버릴 코드면 절차적으로 짜는 것이 맞다.

오래 고쳐 쓸 코드면 나누는 비용이 금방 회수된다.

<br/>

기준을 하나 잡자면 `요구사항이 바뀔 것 같은가` 다.

바뀔 곳을 미리 나눠두는 것이지, 안 바뀔 곳까지 나눌 이유는 없다.
