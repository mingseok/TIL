## FrontController 패턴 특징

프론트 컨트롤러도 결국 서블릿이다. -> (클라이언트의 요청을 받음)

프론트 컨트롤러가 요청에 맞는 컨트롤러를 찾아서 호출

<br/>입구를 하나로!

공통 처리 가능.

<br/>

### 스프링 웹 MVC의 DispatcherServlet이 바로 FrontController 패턴으로 구현되어 있다는 것이다.

## 궁금증!

```java
DispatcherServlet 안이 실제로 어떻게 생겼을까
```

`javap` 로 메서드를 꺼내보면 흐름이 그대로 드러난다.

```java
$ javap -p org.springframework.web.servlet.DispatcherServlet

  protected void initStrategies(ApplicationContext);
  protected void doDispatch(HttpServletRequest, HttpServletResponse);
  protected HandlerExecutionChain getHandler(HttpServletRequest);
  protected HandlerAdapter getHandlerAdapter(Object);
  private void processDispatchResult(...);
  protected void render(ModelAndView, HttpServletRequest, HttpServletResponse);
```

<br/>

메서드 이름이 곧 순서다.

```java
doDispatch()             <- 요청이 들어오면 여기서 시작한다
  -> getHandler()        <- 이 URL 을 처리할 컨트롤러를 찾는다
  -> getHandlerAdapter() <- 그 컨트롤러를 부를 방법을 찾는다
  -> 핸들러 실행
  -> processDispatchResult()
       -> render()       <- 뷰를 찾아 화면을 만든다
```

<br/>

## 입구를 하나로 모으면 무엇이 좋아지는가

앞의 Front Controller 글에서 본 대로,

서블릿마다 반복되던 코드를 한 곳으로 모을 수 있다.

```java
로그인 확인
인코딩 설정
뷰 경로 조립
예외 처리
```

<br/>

그리고 컨트롤러가 서블릿을 상속할 필요가 없어진다.

`@Controller` 를 붙인 평범한 클래스가 될 수 있는 이유다.

<br/>

앞의 PSA(Portable Service Abstraction) 글에서 본 `POJO` 가 이것이다.

특정 기술에 묶이지 않은 평범한 자바 객체라서 테스트할 때 그냥 `new` 해서 쓸 수 있다.

<br/>

## initStrategies 라는 이름

`전략을 초기화한다` 는 뜻이다.

```java
HandlerMapping           - URL 로 컨트롤러 찾기
HandlerAdapter           - 찾은 컨트롤러 호출하기
HandlerExceptionResolver - 예외 처리하기
ViewResolver             - 뷰 이름으로 실제 뷰 찾기
```

<br/>

넷 다 인터페이스다. 그래서 필요하면 직접 만들어 끼울 수 있다.

<br/>

앞의 인터페이스를 왜 사용하는가 글에서 본 구조다.

`DispatcherServlet` 은 인터페이스만 알고, 구현이 무엇인지는 모른다.

```java
구체적인 것을 알면 -> 그게 바뀔 때마다 나도 바뀐다
인터페이스만 알면 -> 뒤에서 뭐가 바뀌든 나는 그대로다
```

<br/>

## 입구를 하나로 모은 대가도 있다

모든 요청이 한 곳을 지나가니, 그곳이 병목이 될 수 있다.

<br/>

앞의 서블릿 설명 내부 동작 글에서 본 대로 `DispatcherServlet` 은 하나뿐이다.

수백 개의 스레드가 같은 객체의 `doDispatch()` 를 동시에 실행한다.

<br/>

그래서 `DispatcherServlet` 은 필드에 상태를 두지 않는다.

```java
protected void doDispatch(HttpServletRequest request, HttpServletResponse response) {
    HandlerExecutionChain mappedHandler = null;    // 지역 변수
    ModelAndView mv = null;                        // 지역 변수
}
```

<br/>

앞의 싱글톤 패턴, 싱글톤 방식의 주의점 글에서 다루는 그 원칙을

프레임워크 자신이 지키고 있는 셈이다.
