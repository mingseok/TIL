## 흐름 

생성자에 들어가 있는 `‘키’` 값들은 `html`이나 `class` 주소들이 아니다.. (착각하지 말자.)

단지, `‘벨류’` 인 `객체`를 찾기 위해서 임의로 정해 놓은 문자열 일뿐이다.

1. 클라이언트의 모든 요청은 전체 컨트롤러가 요청을 받게 된다.

2. 전체 컨트롤러에서 해당 컨트롤러를 찾아 연결 시켜준다.
3. 해당 컨트롤러가 해당 뷰 페이지로 연결 시켜준다.
4. 클라이언트는 입력값을 입력한다. 그리고 서브밋 한다.
5. 다시 전체 컨트롤러로 와서 해당 URL의 컨트롤러를 찾는다.
6. 찾은 해당 컨트롤러로 가서 저장 시킬 데이터들은 저장 시키고,
7. 해당 뷰 페이지로 이동 된다.

## 궁금증!

```java
등록 화면을 부를 때와 등록을 처리할 때의 URL 이 같다
```

이게 처음엔 이상해 보인다.

```java
GET  /members/new    -> 입력 폼 보여주기
POST /members/new    -> 실제 등록 처리
```

<br/>

같은 주소인데 하는 일이 다르다.

<br/>

앞의 HTTP 메서드 글에서 본 대로 URL은 `대상` 을 가리키고,

메서드가 `그 대상에 무엇을 할지` 를 말한다.

```java
GET  = 달라
POST = 처리해줘
```

<br/>

`회원 등록` 이라는 같은 대상에 대해, 하나는 보여주기이고 하나는 처리하기다.

<br/>

## 그래서 컨트롤러도 둘로 나뉜다

```java
@GetMapping("/members/new")
public String form(@ModelAttribute MemberForm form) {
    return "members/newForm";           // 화면만 준다
}

@PostMapping("/members/new")
public String save(@ModelAttribute MemberForm form) {
    memberService.join(form);
    return "redirect:/members";         // 처리하고 목록으로 보낸다
}
```

<br/>

`GET` 쪽에 `@ModelAttribute` 가 붙어 있는 이유가 있다.

앞의 특별한 @ModelAttribute 사용법 글에서 본 대로, 빈 객체라도 모델에 담아야 뷰에서 쓸 수 있기 때문이다.

<br/>

## 출력에서 새로고침을 누르면

`POST` 로 처리하고 화면을 그냥 그리면 문제가 생긴다.

```java
@PostMapping("/members/new")
public String save(MemberForm form) {
    memberService.join(form);
    return "members/list";              // 화면을 바로 그렸다
}
```

<br/>

이 상태에서 새로고침을 누르면 브라우저가 `POST` 를 다시 보낸다.

회원이 한 명 더 등록된다.

<br/>

앞의 PRG(Post Redirect Get) 글에서 본 그 문제다.

```java
return "redirect:/members";
```

<br/>

리다이렉트를 하면 브라우저의 마지막 요청이 `GET /members` 가 되므로,

새로고침을 눌러도 목록을 다시 볼 뿐이다.

<br/>

## 등록 실패했을 때는 리다이렉트를 안 한다

```java
@PostMapping("/members/new")
public String save(@Validated @ModelAttribute MemberForm form, BindingResult bindingResult) {
    if (bindingResult.hasErrors()) {
        return "members/newForm";       // 리다이렉트가 아니다
    }
    memberService.join(form);
    return "redirect:/members";
}
```

<br/>

실패하면 입력 폼으로 다시 가는데, 여기서는 리다이렉트를 하면 안 된다.

<br/>

앞의 Validation 글에서 본 대로 `BindingResult` 에 담긴 오류와

사용자가 입력했던 값을 그대로 화면에 다시 보여줘야 하기 때문이다.

```java
리다이렉트  - 새 요청이라 앞 요청의 값이 사라진다
포워드      - 같은 요청이라 모델의 값이 살아 있다
```

<br/>

앞의 리다이렉트, 디스패처 글에서 본 그 차이가 여기서 실제로 쓰인다.

<br/>

## 정리하면 흐름은 이렇게 된다

```java
GET  /members/new   -> 빈 폼
POST /members/new   -> 검증 실패 -> 폼 다시 (값과 오류 유지)
                    -> 검증 성공 -> redirect:/members
GET  /members       -> 목록
```

<br/>

`성공하면 리다이렉트, 실패하면 그대로` 가 웹 폼의 기본 모양인 것이다.
