## 궁금증

리다이렉트는 페이지를 말 그대로 `새로고침` 하는 것이다. `“왜 사용 하는가?”`

어차피 해당 페이지를 들어가면 페이지가 ‘`새로고침`’ 되는데 왜 사용 하는가?

<br/><br/>

## 사용 이유는,

관리자 페이지에서 회원목록에 어떤 회원을 브론즈 등급에서 

실버 등급으로 수정 후 저장 버튼을 누르면 바로 최신화가 되어야 한다. → 그때 필요한게 `redirect:`이다.

수정 후 다시 최신화 정렬 같은게 필요하다면 `redirect:` 를 사용 하는 것이다.

<br/><br/>

## 디스패처

```java
String viewPath = "/WEB-INF/views/new-form.jsp";
RequestDispatcher dispatcher = request.getRequestDispatcher(viewPath);
dispatcher.forward(request, response);
```

<br/>

## 컨트롤러에서 뷰로 이동해야 되는 상황에서 사용한다.

1. 그때 사용하는 것이 `request.getRequestDispatcher()` 이다.

2. `dispatcher.forward(request, response)` 해준다면 

3. 그제서야, 컨트롤에서 뷰로 호출 해주는 것이다.

<br/><br/>

## 서버 내부에서 다시 호출이 발생한다.

클라이언트에서 서버로 호출을 하고, 그리고 서버 안에서 자기들끼리 

서블릿 호출 되었다가 → jsp 호출하고 → jsp에서 응답을 만들어서 고객한테 보낸 것이다. 

<br/><br/>

## `forward()` 추가 설명

forward() 메서드는 대상 자원으로 제어를 넘기는 역할을 합니다. 

브라우저에서 /a.jsp로 요청했을 때 a.jsp에서 forward()를 실행하여 b.jsp로 제어를 넘길 수 있다.

<br/>

제어를 넘겨 받은 b.jsp는 처리 결과를 최종적으로 브라우저에게 출력한다.

브라우저 입장에서는 /a.jsp를 요청했지만 받은 결과는 /b.jsp의 결과이다.

<br/>

이때 HTTP 리다이렉트 방식과는 달리 하나의 HTTP 요청(Request) 범위 안에서 동작이 이루어지는 것이다.

<br/><br/>

## 차이점

```
리다이렉트는 url 주소가 달라지고, 포워드는 url 주소가 달라지지 않는다.
```

## 궁금증!

```java
실제로 요청이 몇 번 가는지 확인해봤다
```

앞의 HTTP 상태 코드 글에서 만들었던 방식으로 서버를 띄우고 `curl` 로 찍어봤다.

<br/>

```java
$ curl -i http://localhost:18083/status/302
```

```java
HTTP/1.1 302 Found
Location: /members/100
```

<br/>

응답 본문이 아니라 `Location` 헤더가 왔다.

브라우저는 이 헤더를 보고 그 주소로 **다시 요청을 보낸다.**

<br/>

```java
$ curl -L -i http://localhost:18083/status/302

HTTP/1.1 302 Found
Location: /members/100

HTTP/1.1 200 OK          <- 두 번째 응답
```

<br/>

`-L` 을 붙이니 응답이 두 개 찍힌다. 왕복이 두 번인 것이다.

<br/>

## 포워드는 왕복이 한 번이다

```java
request.getRequestDispatcher("/WEB-INF/views/members.jsp").forward(request, response);
```

<br/>

이건 서버 안에서 넘기는 것이라 브라우저가 모른다.

```java
리다이렉트 - 브라우저에게 "저기로 다시 가" 라고 시킨다. URL 이 바뀐다
포워드     - 서버가 내부에서 넘긴다. URL 이 그대로다
```

<br/>

주소창을 보면 바로 구분된다.

<br/>

## 그래서 request 에 담은 값의 운명이 갈린다

```java
request.setAttribute("member", member);
```

<br/>

포워드는 같은 `request` 객체를 그대로 넘기므로 값이 살아 있다.

리다이렉트는 새 요청이 오는 것이라 앞의 `request` 는 버려진다.

<br/>

앞의 서블릿 설명 내부 동작 글에서 본 대로,

`HttpServletRequest` 는 요청 하나마다 새로 만들어졌다가 응답이 끝나면 버려진다.

<br/>

## 그럼 리다이렉트할 때 값을 어떻게 넘기나

두 가지를 쓴다.

```java
// 1. URL 에 붙인다
return "redirect:/members/" + savedId;

// 2. RedirectAttributes 를 쓴다
redirectAttributes.addAttribute("status", true);
return "redirect:/members/{id}";
```

<br/>

`addAttribute` 는 결국 쿼리 파라미터가 된다.

```java
/members/100?status=true
```

<br/>

한 번만 쓰고 사라져야 하는 값이면 `addFlashAttribute` 를 쓴다.

```java
redirectAttributes.addFlashAttribute("message", "등록이 완료되었습니다");
```

<br/>

이건 URL에 안 붙는다. 세션에 잠깐 넣었다가 다음 요청에서 꺼내고 지운다.

앞의 세션 동작 방식 글에서 본 세션을 이런 데에도 쓰는 것이다.

<br/>

## WEB-INF 안의 JSP 는 포워드로만 갈 수 있다

앞의 웰컴 페이지, WEB-INF 디렉토리 글에서 본 규칙이다.

```java
/WEB-INF/views/members.jsp   <- 브라우저가 직접 못 부른다
```

<br/>

그래서 리다이렉트로는 못 가고 포워드로만 갈 수 있다.

컨트롤러를 안 거치고 JSP에 바로 들어오는 것을 막기 위한 규칙인 셈이다.

<br/>

## 302, 303, 307 의 차이

앞의 HTTP 상태 코드 글에서 본 것을 여기에 붙이면 이렇다.

```java
302 Found              - 원래 뜻은 "임시 이동". 실제로는 대부분 GET 으로 바꿔서 보낸다
303 See Other          - "GET 으로 다시 요청해" 를 명확히 말한 것
307 Temporary Redirect - 메서드를 그대로 유지한다. POST 였으면 POST 로 다시
```

<br/>

`302` 는 스펙에는 메서드를 유지하라고 되어 있는데

브라우저들이 예전부터 `GET` 으로 바꿔 보내서 그게 굳어졌다.

<br/>

그래서 뜻을 분명히 하려고 `303` 과 `307` 이 나중에 생긴 것이다.

<br/>

스프링의 `redirect:` 는 기본이 `302` 다.

앞의 PRG(Post Redirect Get) 글에서 본 그 용도에는 `GET` 으로 바뀌는 게 맞으니 문제가 없다.
