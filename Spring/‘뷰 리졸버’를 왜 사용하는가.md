## ‘뷰 리졸버’를 왜 사용하는가?

<br/>

## 왜 개념을 분리 했는가?

- 논리 뷰 이름 : ‘members’

- 물리 뷰 경로 : ‘/WEB-INF/views/members.jsp’

```java
private static MyView viewResolver(String viewName) {
    return new MyView("/WEB-INF/views/" + viewName + ".jsp");
}
```

만약, 나중에 폴더 이름이 `‘views’` 되어 있는 것이, `‘jsp’`로 바뀌는 것이다.

<br/>

그러면 어떻게 해야 되는가? → `컨트롤러를 건들 필요가 없다!`

나는 위 코드인 `viewResolver()` 메서드만 변경하면 되는 것이다.

<br/>

그리하여 논리적인 이름과 물리적인 이름은 나눠 놓으면 변경 사항이 발생 했을때,

컨트롤러 코드는 변경하지 않아도 되는 장점이 있는 것이다.

<br/>

## 궁금증!

```java
뷰 리졸버가 여러 개 등록되어 있다는 것
```

앞의 뷰 리졸버(viewResolver) 사용 이유는 글에서 본 대로 `spring-webmvc` 안에 여러 구현이 있다.

```java
InternalResourceViewResolver     - JSP
AbstractTemplateViewResolver     - 템플릿 엔진 공통
FreeMarkerViewResolver           - FreeMarker
BeanNameViewResolver             - 뷰 이름과 같은 이름의 빈을 찾는다
ContentNegotiatingViewResolver   - 요청 헤더를 보고 뷰를 고른다
```

<br/>

`DispatcherServlet` 은 이것을 목록으로 들고 있다가 순서대로 물어본다.

```java
resolveViewName("members") 를 첫 번째에게 물어본다
  -> null 이면 다음에게
  -> View 를 돌려주면 거기서 멈춘다
```

<br/>

앞의 Handler vs HandlerAdapter 글에서 본 `어댑터를 고르는 방식` 과 완전히 같다.

<br/>

## 논리 이름과 물리 경로를 나눈 이득

```java
return "members";
```

<br/>

컨트롤러는 `members` 라는 이름만 안다.

`/WEB-INF/views/members.jsp` 인지 `templates/members.html` 인지는 모른다.

<br/>

그래서 JSP에서 타임리프로 바꿔도 컨트롤러가 안 바뀐다.

설정 한 줄만 바꾸면 된다.

```java
spring.mvc.view.prefix=/WEB-INF/views/
spring.mvc.view.suffix=.jsp
```

<br/>

앞의 스프링 메시지 적용하기 글에서 본 것과 같은 구조다.

```java
논리 뷰 이름 "members"  ->  물리 경로 /WEB-INF/views/members.jsp
메시지 키 "member.name" ->  실제 문구 "회원 이름"
논리 빈 이름 "payClient" ->  실제 구현체 TossPayClient
```

<br/>

전부 `부르는 이름` 과 `실제 대상` 을 분리해서, 실제가 바뀌어도 부르는 쪽은 안 바뀌게 하는 것이다.

<br/>

## 요즘은 뷰 리졸버를 안 타는 경우가 많다

```java
@RestController
public class MemberApi {

    @GetMapping("/api/members")
    public List<MemberResponse> list() { ... }
}
```

<br/>

앞의 API (json)방식 @ResponseBody 내부 동작 글에서 본 대로,

`@ResponseBody` 가 붙으면 `HttpMessageConverter` 로 간다.

```java
String 반환         -> ViewResolver 가 그 이름으로 화면을 찾는다
@ResponseBody 반환  -> HttpMessageConverter 가 JSON 으로 바꿔 바로 내려준다
```

<br/>

프론트를 따로 만들면 서버는 데이터만 내려주면 되니 뷰 리졸버가 거의 안 쓰인다.

<br/>

## 그래도 리다이렉트는 뷰 리졸버가 처리한다

```java
return "redirect:/members";
```

<br/>

앞의 리다이렉트, 디스패처 서블릿 글에서 본 그 흐름이다.

`redirect:` 라는 접두사를 보고 `UrlBasedViewResolver` 가 `RedirectView` 를 돌려준다.

<br/>

`forward:` 도 마찬가지다.

```java
return "forward:/members";     // 서버 내부에서 넘긴다
```

<br/>

문자열 앞의 접두사 하나로 응답의 성격이 완전히 달라진다.

이것도 `이름으로 판단한다` 는 같은 방식의 확장인 셈이다.
