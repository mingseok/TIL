## 궁금증!

```java
왜 같은 것을 두 이름으로 부를까
```

부르는 쪽이 다르기 때문이다.

```java
컨트롤러 - 우리가 부르는 이름. MVC 의 C
핸들러   - 스프링 내부가 부르는 이름. "요청을 처리하는 무언가"
```

<br/>

앞의 Handler vs HandlerAdapter 글에서 본 대로,

`DispatcherServlet` 은 그것이 컨트롤러인지 모른다.

```java
protected HandlerExecutionChain getHandler(HttpServletRequest request)
protected HandlerAdapter getHandlerAdapter(Object handler)
```

<br/>

두 번째 메서드의 파라미터가 `Object` 다.

`무엇인지는 모르겠고 이걸 처리할 어댑터를 찾겠다` 는 뜻이다.

<br/>

## 컨트롤러가 아닌 핸들러도 있다

```java
@Controller + @RequestMapping   - 우리가 만드는 컨트롤러
Controller 인터페이스 구현       - 옛날 방식
HttpRequestHandler 구현         - 정적 리소스 처리
```

<br/>

정적 파일을 내려주는 것도 핸들러다. 컨트롤러라고 부르기는 어색하다.

그래서 더 넓은 이름이 필요했던 것이다.

<br/>

앞의 Handler vs HandlerAdapter 글에서 본 대로,

이 여러 모양을 `handle()` 하나로 통일하는 것이 어댑터의 역할이다.

```java
DispatcherServlet 은 "핸들러" 만 안다
어댑터가 그것을 각자 방식으로 부른다
```

<br/>

## 핸들러 메서드라는 말도 있다

```java
@Controller
public class MemberController {

    @GetMapping("/members")
    public String list() { ... }        // 이것이 핸들러 메서드
}
```

<br/>

클래스가 핸들러이고 그 안의 매핑된 메서드가 핸들러 메서드다.

<br/>

실제로 `getHandler()` 가 돌려주는 것은 클래스가 아니라 `HandlerMethod` 객체다.

```java
if (handler instanceof HandlerMethod handlerMethod) {
    Method method = handlerMethod.getMethod();
    LoginRequired anno = method.getAnnotation(LoginRequired.class);
}
```

<br/>

앞의 필터, 스프링 인터셉터 설명 글에서 본 그 코드다.

인터셉터에서 메서드의 어노테이션을 볼 수 있는 것이 이 덕분이다.

<br/>

## 핸들러라는 이름이 넓게 쓰인다

스프링 밖에서도 같은 뜻으로 쓴다.

```java
HandlerExceptionResolver  - 예외를 처리하는 것
@ExceptionHandler         - 예외를 처리하는 메서드
ArgumentResolver          - 파라미터를 처리하는 것
ReturnValueHandler        - 반환값을 처리하는 것
```

<br/>

`무언가를 받아서 처리하는 것` 이면 대개 `Handler` 나 `Resolver` 라는 이름이 붙는다.

<br/>

앞의 클래스명, 메소드명, 변수명 규칙 글에서 본 대로,

이름이 그 역할을 알려주는 관례가 자리 잡은 것이다.

이름만 보고 `아 이건 무언가를 처리하는 자리구나` 를 알 수 있게 된다.
