## 동적 계획법의 개념

컴퓨터 공학의 꽃이라고 불린다. (=영어로는 “다이나믹 프로그래밍” 이라고 불리고, DP 라고 불린다)

<br/>

## “제일 작은거 부터 하나하나, 구하자” 
즉, 어차피 다 필요 할거면 위에서 밑으로 내려오지 말고, 
“밑에서 부터 위로 올라가자” 는 것이다 (= 바텀 업) 이라고도 부른다.

동적 계획법이란? 조금 더 작은 문제를 먼저 해결하고, 그 작은 문제를 해결한 것을 바탕으로 전체 문제를 해결 하는 것이 동적 계획법이다.

<br/>

분할 정복 알고리즘 이랑 헷갈릴수 있는데, 분할 정복법은 “큰 문제를 쪼개 내려가는 것” 이며,

다이나믹 프로그래밍(=DP) 는 “밑에서 부터 올라는 것이다”

<br/>

철학은 소문제를 풀고 나서 전체 문제를 푸는 것이다. 즉, 철학은 두개 똑같다.
다른 점은 방향이 다른 것이다.

‘나’ 를 해결함으로써 더 큰 ‘나’ 를 해결하는 것이다.

## 궁금증!

```java
DP 를 쓸 수 있는 조건이 무엇인가
```

두 가지다.

```java
1. 최적 부분 구조 - 작은 문제의 답으로 큰 문제의 답을 만들 수 있다
2. 중복 부분 문제 - 같은 작은 문제가 여러 번 나온다
```

<br/>

둘 다 있어야 한다.

<br/>

`1번` 만 있고 `2번` 이 없으면 그냥 분할 정복이다.

```java
합병 정렬 - 절반씩 나눠서 합친다. 같은 부분이 다시 안 나온다
피보나치  - fib(3) 이 몇 번이고 다시 나온다
```

<br/>

앞의 합병정렬 글에서 본 것과 이 차이로 갈리는 것이다.

<br/>

## 중복이 실제로 얼마나 되는지 재봤다

앞의 재귀함수 글의 측정이다.

```java
fib(35) 단순 재귀 = 호출 29860703 번
fib(35) 메모      = 호출 69 번
```

<br/>

43만 배다.

<br/>

`n` 이 커지면 이 배율이 지수적으로 커진다.

`O(2ⁿ)` 이 `O(n)` 이 되는 것이니 당연하다.

<br/>

## 두 가지 방식이 있다

```java
하향식 (메모이제이션) - 재귀 + 저장
상향식 (타뷸레이션)   - 반복문 + 표 채우기
```

<br/>

```java
// 하향식
long fib(int n, long[] memo) {
    if (n < 2) return n;
    if (memo[n] != 0) return memo[n];
    return memo[n] = fib(n-1, memo) + fib(n-2, memo);
}

// 상향식
long fib(int n) {
    long[] dp = new long[n + 1];
    dp[1] = 1;
    for (int i = 2; i <= n; i++) dp[i] = dp[i-1] + dp[i-2];
    return dp[n];
}
```

<br/>

## 어느 쪽이 나은가

```java
하향식 - 필요한 것만 계산한다. 점화식을 그대로 옮기니 쓰기 쉽다
상향식 - 재귀가 없어서 스택이 안 터진다. 보통 더 빠르다
```

<br/>

앞의 재귀함수 글에서 확인한 그 한계가 하향식에 걸린다.

```java
StackOverflowError. 깊이 = 6308
```

<br/>

`n` 이 10만이면 하향식은 못 쓴다.

<br/>

반대로 상태 공간이 아주 넓은데 실제로 쓰이는 게 일부면 하향식이 낫다.

전부 채우면 낭비이기 때문이다.

<br/>

## 공간을 줄일 수 있다

```java
long fib(int n) {
    long a = 0, b = 1;
    for (int i = 0; i < n; i++) {
        long t = a + b;
        a = b;
        b = t;
    }
    return a;
}
```

<br/>

배열이 필요 없다. 직전 두 개만 있으면 되기 때문이다.

<br/>

`O(n)` 공간이 `O(1)` 이 된다.

<br/>

배낭 문제도 2차원 표를 1차원으로 줄일 수 있다.

```java
for (int i = 0; i < n; i++)
    for (int w = maxWeight; w >= weight[i]; w--)      // 거꾸로 돈다
        dp[w] = max(dp[w], dp[w - weight[i]] + value[i]);
```

<br/>

거꾸로 도는 게 핵심이다.

앞에서부터 돌면 같은 물건을 여러 번 쓰게 된다.

<br/>

이 방향 하나로 `0-1 배낭` 과 `무한 배낭` 이 갈린다.

<br/>

## 상태를 정의하는 게 제일 어렵다

```java
dp[i] = 무엇을 뜻하는가
```

<br/>

이걸 정하는 게 DP 문제의 절반이다.

<br/>

```java
dp[i] = i 번째까지 봤을 때의 최댓값
dp[i][j] = i 번째까지 봤고 무게가 j 일 때의 최댓값
dp[i][j][k] = 상태가 세 개 필요한 경우
```

<br/>

상태가 늘어나면 차원이 늘어나고 메모리가 폭발한다.

<br/>

앞의 인접 행렬 글에서 본 것과 같은 문제다.

```java
dp[1000][1000][1000] = 10 억 칸
```

<br/>

이 정도면 방법을 바꿔야 한다는 신호다.

<br/>

## 실무에서 DP 를 쓸 일이 있나

직접 짜는 일은 드물다.

<br/>

다만 발상 자체는 자주 쓴다.

```java
계산 결과를 캐시에 저장한다
같은 쿼리를 두 번 안 날린다
```

<br/>

앞의 캐시 글에서 본 것도 결국 메모이제이션이다.

<br/>

앞의 N+1 문제 글에서 본 것도 `같은 것을 여러 번 조회하는` 문제다.

<br/>

`이미 계산한 것을 또 계산하고 있지 않은가` 를 묻는 습관이

DP를 배우면서 얻는 실질적인 것이라고 보면 된다.
