## 선형 리스트 란?

이러한 형태의 리스트를, 컴퓨터에서는 선형 리스트(Linear List)로 표현한다. <br/>선형 리스트의 핵심은 선처럼 연결된 리스트이기 때문에 "순서"가 중요하다.

<br/> 

**배열과 같이 연속되는 기억장소에 저장되는 리스트, 주로, 배열 이용 구현**


<br/>EX )  중국집 = (짜장면, 탕수육, 볶음밥 ... )




<br/>

### 분기별 판매량 선형 리스트를 1차원 배열로 구현.

```java
public class test {

    public static void main(String[] args) {

        int[] sale = new int[] { 157, 209, 251, 312 };

        for (int i = 0; i < 4; i++) {

            System.out.printf("%d/4분기 : sale[%d] = %d %n", i + 1, i, sale[i]);

        }
    }
}

----------------------------------------------------------------

출력 값 : 1/4분기 : sale[0] = 157 
					2/4분기 : sale[1] = 209
					3/4분기 : sale[2] = 251
					4/4분기 : sale[3] = 312
```

<br/>
<br/>

### 2차원 배열 순차 표현

```java
int sale[][] = new int[][] { { 1, 2, 3, 4}, {5, 6, 7, 8} };
```

<br/><br/>

2007, 2008 년 분기별 선형 리스트를 1차원 배열로 구현한 프로그램


```java
public class test {

    public static void main(String[] args) {

        int sale[][] = new int[][] { { 63, 84, 140, 130 }, { 157, 209, 251, 312 } };

        for (int i = 0; i < 2; i++) {
            for (int j = 0; j < 4; j++) {
                System.out.printf("%d/4분기 : sale[%d][%d]= %d%n", j + 1, i, j, sale[i][j]);
            }
            System.out.println();
        }
    }
}

---------------------------------------------------------

출력 값 
1/4분기 : sale[0][0]= 63 
2/4분기 : sale[0][1]= 84 
3/4분기 : sale[0][2]= 140
4/4분기 : sale[0][3]= 130

1/4분기 : sale[1][0]= 157
2/4분기 : sale[1][1]= 209
3/4분기 : sale[1][2]= 251
4/4분기 : sale[1][3]= 312

```

## 궁금증!

```java
ArrayList 는 크기가 꽉 차면 어떻게 되나
```

새 배열을 만들어서 복사한다.

```java
int newCapacity = oldCapacity + (oldCapacity >> 1);      // 1.5 배
```

<br/>

`>> 1` 은 2로 나눈 것이라 `기존 + 절반` 이 된다.

```java
10 -> 15 -> 22 -> 33 -> 49 ...
```

<br/>

앞의 비트 연산 글에서 본 시프트 연산이 여기 쓰인다.

<br/>

## 왜 1.5 배인가

너무 작게 늘리면 복사가 자주 일어난다.

너무 크게 늘리면 안 쓰는 메모리가 남는다.

<br/>

`2배` 를 쓰는 언어도 있다. C++의 `vector` 가 보통 2배다.

<br/>

`1.5배` 가 나은 점이 있다.

버려진 메모리 조각을 나중에 재사용할 가능성이 생기기 때문이다.

```java
2배   - 10, 20, 40, 80 ... 앞의 것을 다 합쳐도 다음 것보다 작다
1.5배 - 10, 15, 22, 33 ... 앞의 조각들을 합치면 다음 것을 담을 수 있다
```

<br/>

## 복사 비용이 얼마나 되나

한 번 늘릴 때는 `O(n)` 이다.

그런데 자주 안 일어나니 평균으로 보면 `O(1)` 이다.

<br/>

이걸 상환 분석이라고 부른다.

```java
1000 번 추가하는 동안 복사는 10번 남짓
전체 비용을 1000 으로 나누면 상수에 가깝다
```

<br/>

앞의 Big_O 글에서 본 표기가 `평균` 을 말하는 것인지

`최악` 을 말하는 것인지 구분해야 하는 이유다.

<br/>

## 미리 크기를 주면 복사가 없다

```java
List<Integer> list = new ArrayList<>(100000);
```

<br/>

들어올 개수를 알면 이렇게 주는 게 낫다.

<br/>

`HashMap` 도 마찬가지다.

```java
new HashMap<>(1000)
```

<br/>

다만 `HashMap` 은 이 값이 그대로 안 쓰인다.

`load factor 0.75` 를 곱한 시점에 늘어나기 때문이다.

```java
1000 개를 담으려면 1000 / 0.75 = 1334 를 줘야 안 늘어난다
```

<br/>

## 삭제도 밀어내기가 있다

```java
list.remove(0);
```

<br/>

맨 앞을 지우면 나머지를 전부 한 칸씩 당긴다.

<br/>

앞의 노드 글에서 잰 것과 같은 이유로 느리다.

<br/>

맨 뒤에서 지우면 밀 게 없어서 빠르다.

```java
list.remove(list.size() - 1);      // 빠르다
```

<br/>

그래서 반복문에서 지울 때는 뒤에서부터 도는 게 낫다.

```java
for (int i = list.size() - 1; i >= 0; i--) {
    if (조건) list.remove(i);
}
```

<br/>

앞에서부터 돌면 인덱스가 밀려서 하나씩 건너뛰는 버그도 생긴다.

<br/>

## remove 의 오버로딩 함정

```java
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));

list.remove(1);                    // 인덱스 1 을 지운다 -> 20 이 사라진다
list.remove(Integer.valueOf(10));  // 값 10 을 지운다
```

<br/>

`remove(int)` 와 `remove(Object)` 가 둘 다 있어서 그렇다.

<br/>

앞의 오토박싱 & 언박싱 글에서 본 것과 이어진다.

`list.remove(10)` 은 인덱스 10을 지우려 하고, 없으면 예외가 난다.

<br/>

## 그래도 대부분 ArrayList 를 쓴다

`LinkedList` 가 삽입이 빠르다고 해도 실무에서는 잘 안 쓴다.

<br/>

이유가 몇 가지 있다.

```java
1. 중간 삽입을 하려면 그 위치를 먼저 찾아야 한다 -> 찾는 게 O(n)
2. 노드마다 객체가 하나씩 더 생긴다 -> 메모리를 더 쓴다
3. 흩어져 있어서 CPU 캐시가 안 먹는다
```

<br/>

`3번` 이 생각보다 크다.

<br/>

배열은 나란히 붙어 있어서 하나를 읽으면 옆의 것도 캐시에 딸려 온다.

노드는 흩어져 있어서 매번 메모리를 다시 읽어야 한다.

<br/>

앞의 노드 글에서 잰 `조회 2ms vs 3986ms` 에는 이 차이도 섞여 있다.

<br/>

큐처럼 앞뒤로만 넣고 빼는 용도면 `ArrayDeque` 가 더 빠르다.

앞의 큐 글에서 다루는 그 구현이다.
