## 삽입 정렬

### ✔️[삽입 정렬 구현 코드](https://github.com/mingseok/TIL/blob/main/code/insertion.java)



<br/>
배열 있다고 가정 해보자.  

인덱스 1의 값을 확인하며 첫 번째 패스스루를 시작 한다.

```java
[ 4, 2, 7, 1, 3 ]
```

<br/>준비 : 임시로 2를 삭제하고 temp_value 라는 변수에 저장한다.

배열의 윗부분으로 이 값을 옮기겠다.

<br/>1단계 : 4와 temp_value 에 들어 있는 2를 비교한다.

2단계 : 4가 2보다 크므로 4를 오른쪽을 시프트(옆으로 옮긴다.) 한다. <br/>------->공백이 배열의 왼쪽 끝에 있으므로 더 이상 왼쪽으로 시프트할 수 없다.

3단계 : temp_value를 다시 배열에 삽입해서 첫 번째 패스스루를 끝낸다

<br/>

### 이제 두 번째 패스스루를 시작한다.

준비 : 두 번째 패스스루에서는 인덱스 2의 값을 임시로 삭제한다. 이 값을 temp_value에 저장한다. 이때 temp_value 는 7 이다.

4단계 : 4와 temp_value 를 비교한다. 4가 더 작으므로 시프트 하지 않는다. <br/>------->temp_value 보다 작은 값에 도달 했으므로 시프트 단계를 끝낸다.

5단계 : temp_value 를 다시 공백에 삽입하고 두 번째 패스스루를 끝낸다.

<br/>

### 세 번째 패스스루는 다음과 같다.

준비 : 임시로 1을 삭제하고 temp_value에 저장한다.

6단계 : 7과 temp_value를 비교한다.

7단계 : 7은 1보다 크므로 7을 오른쪽으로 시프트한다.

8단계 : 4와 temp_value 를 비교한다.

9단계 : 4는 1보다 크므로 마친가지로 시프트한다.

10단계 : 2와 temp_value를 비교한다.

11단계 : 2가 더 크므로 시프트한다.

12단계 : 공백이 배열의 왼쪽 끝에 있으므로 temp_value를 공백에 삽입하고 패스스루를 끝낸다.

<br/>

while (j >= 0) {

## 그래서 거의 정렬된 데이터에 아주 강하다

이미 정렬된 배열이면 비교가 `n-1` 번이다.

```java
매번 첫 비교에서 바로 멈춘다 -> O(n)
```

<br/>

앞의 Big_O 글에서 본 대로, `최선 O(n)` 인 유일한 축에 든다.

<br/>

실제 데이터는 완전히 무작위인 경우가 드물다.

```java
로그가 시간순으로 거의 정렬되어 있다
목록에 몇 건만 새로 추가됐다
```

<br/>

이런 상황이 흔하다.

<br/>

## 그래서 표준 정렬 안에 들어 있다

앞의 정렬(Sort) 글에서 본 `TimSort` 가 이 성질을 쓴다.

```java
1. 배열을 32 개 정도의 구간으로 나눈다
2. 각 구간을 이진 삽입 정렬로 정렬한다
3. 정렬된 구간들을 합병한다
```

<br/>

작은 구간에서는 삽입 정렬이 합병보다 빠르기 때문이다.

<br/>

`O(n log n)` 이 항상 `O(n²)` 보다 빠른 게 아니라,

`n` 이 충분히 클 때만 그렇다는 것이다.

<br/>

## 이진 삽입 정렬

자리를 찾는 데 이진 탐색을 쓸 수 있다.

```java
int pos = Arrays.binarySearch(a, 0, i, key);
```

<br/>

앞의 이진 탐색 글에서 본 대로 `O(log n)` 에 자리를 찾는다.

<br/>

그런데 전체가 빨라지지는 않는다.

<br/>

자리를 찾은 뒤에 밀어내는 작업이 여전히 `O(n)` 이기 때문이다.

```java
비교 횟수   O(n²) -> O(n log n)
이동 횟수   O(n²) 그대로
```

<br/>

비교가 비싼 경우에만 이득이다.

문자열 비교나 `Comparator` 호출이 무거우면 의미가 있는 것이다.

<br/>

## 안정 정렬이다

```java
if (a[j] <= key) break;      // <= 이라 같으면 멈춘다
```

<br/>

같은 값을 만나면 그 뒤에 넣으니 원래 순서가 유지된다.

<br/>

`<` 로 바꾸면 같은 값도 밀어내면서 순서가 뒤집힌다.

한 글자 차이인데 성질이 바뀌는 것이다.

<br/>

## 온라인 알고리즘이다

데이터가 다 있지 않아도 정렬을 시작할 수 있다.

```java
값이 하나 들어올 때마다 -> 정렬된 부분에 끼워 넣는다
```

<br/>

버블이나 선택은 전체를 알아야 시작한다.

<br/>

스트리밍으로 들어오는 데이터를 정렬된 상태로 유지해야 하면 이 성질이 유용하다.

<br/>

다만 실무에서는 `TreeSet` 이나 `PriorityQueue` 를 쓰는 게 낫다.

앞의 큐 글에서 본 대로 삽입이 `O(log n)` 이기 때문이다.

<br/>

## 카드를 정리하는 방식과 같다

손에 든 카드를 정렬할 때 사람이 하는 방식이 이것이다.

```java
새 카드를 뽑아서 -> 오른쪽에서 왼쪽으로 비교하면서 -> 자기 자리에 끼운다
```

<br/>

버블 정렬처럼 옆의 것과 계속 바꾸는 사람은 없다.

<br/>

알고리즘 이름이 직관적인 경우가 드문데, 이건 정확한 편이다.
