## 궁금증!

```java
트리가 한쪽으로 치우치면 어떻게 되나
```

연결 리스트가 된다.

```java
1
 \
  2
   \
    3
     \
      4
```

<br/>

높이가 `n` 이 되어서 탐색이 `O(n)` 이다.

<br/>

앞의 이진 탐색 글에서 본 `O(log n)` 이 사라지는 것이다.

<br/>

정렬된 데이터를 순서대로 넣으면 이렇게 된다.

```java
1, 2, 3, 4, 5 를 이진 탐색 트리에 넣으면
전부 오른쪽으로만 붙는다
```

<br/>

앞의 퀵정렬 글에서 본 것과 같은 아이러니다.

`이미 정렬된 데이터가 최악` 인 것이다.

<br/>

## 그래서 균형 트리가 나왔다

```java
AVL 트리       - 좌우 높이 차이를 1 이하로 유지
레드-블랙 트리  - 색깔 규칙으로 균형을 유지
B-트리         - 한 노드에 여러 값. 디스크용
```

<br/>

넣거나 지울 때 회전으로 모양을 고친다.

<br/>

자바의 `TreeMap` 과 `TreeSet` 이 레드-블랙 트리다.

<br/>

앞의 노드 글에서 본 대로 `HashMap` 도 버킷이 커지면 이걸 쓴다.

```java
연결 리스트 (8 개 초과) -> 레드-블랙 트리
```

<br/>

해시 충돌 공격으로 한 버킷에 몰려도 `O(log n)` 이 보장되는 것이다.

<br/>

## AVL 과 레드-블랙 중에 무엇을 쓰나

```java
AVL       - 더 엄격하게 균형. 조회가 빠르다
레드-블랙  - 덜 엄격. 삽입/삭제 때 회전이 적다
```

<br/>

`TreeMap` 이 레드-블랙을 쓰는 이유는 삽입과 삭제가 자주 일어나기 때문이다.

<br/>

읽기만 많으면 AVL이 낫다.

<br/>

## B-트리는 왜 다른 모양인가

디스크를 읽는 단위 때문이다.

<br/>

앞의 인덱스 구조 글에서 본 대로,

디스크는 한 번에 페이지 단위로 읽는다.

```java
이진 트리 - 노드 하나에 값 하나. 100 만 개면 20 번 읽는다
B+ 트리   - 노드 하나에 수백 개. 100 만 개면 3~4 번 읽는다
```

<br/>

한 번 읽을 때 최대한 많이 담는 게 유리한 것이다.

<br/>

메모리에서는 이 차이가 없어서 이진 트리를 쓴다.

`어디에 저장하느냐` 가 자료구조의 모양을 정하는 셈이다.

<br/>

## 트리 용어

```java
루트   - 맨 위 노드
리프   - 자식이 없는 노드
높이   - 루트에서 가장 깊은 리프까지의 거리
깊이   - 루트에서 특정 노드까지의 거리
차수   - 자식의 개수
```

<br/>

`높이` 와 `깊이` 를 헷갈리기 쉽다.

```java
높이 - 아래에서 위로 재는 것. 트리 전체의 성질
깊이 - 위에서 아래로 재는 것. 특정 노드의 성질
```

<br/>

`완전 이진 트리` 도 정의가 헷갈린다.

```java
포화 이진 트리 (perfect) - 모든 층이 꽉 차 있다
완전 이진 트리 (complete) - 마지막 층만 왼쪽부터 채워져 있다
정 이진 트리 (full)      - 자식이 0 개 아니면 2 개
```

<br/>

힙이 `완전 이진 트리` 다.

<br/>

앞의 큐 글에서 본 `PriorityQueue` 가 이 성질 덕분에 배열로 담긴다.

```java
i 번 노드의 자식 = 2i+1, 2i+2
i 번 노드의 부모 = (i-1)/2
```

<br/>

빈칸이 없으니 인덱스 계산으로 부모와 자식을 찾을 수 있는 것이다.

<br/>

노드 객체와 참조가 필요 없어서 메모리도 훨씬 덜 쓴다.
