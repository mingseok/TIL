## 스택 오버플로우, 언더플로우

스택이라는 자료구조가 있는데 

이 자료구조에 원소를 넣다가,, 더 이상 들어가지 못하는데 하나 더 넣으려고 하는 것이다.

그러면 “원소가 넘쳤다” 하여 스택 오버플로우가 발생했다 하는 것이다.

## 언더플로우란? 

스택안에 원소를 다 뺐는데 더 빼라고 한다면, 스택 언더플로우가 발생 하는 것이다.

스택이 비어 있을때, 또 빼려고 한다면? 언더플로우라 한다.

## 스택 구현

![이미지](/programming/img/알스택6.PNG)

```java
import java.util.Scanner;

class Stack {

  int[] data = new int[100];
  int len = 0; // 지금 내가 가지고 있는 원소의 갯수
  int capacity = 0; // 최대로 넣을 수 있는 크기.

  void create(int y) {
    capacity = y;
  }

  void push(int y) {
    if (len >= capacity) {
      System.out.println("Stack overflow!");

    } else {
      data[len++] = y;
    }
  }

  void pop() {
    if (len <= 0) {
      System.out.println("Stack underflow!");

    } else {
      data[len - 1] = 0;
      len--;
    }
  }

  int top() {
    // 스택에 아무것도 없다면 -1을 출력.
    if (len <= 0) {
      return -1;

    } else {
      return data[len - 1];
    }

  }

  int size() {
    return len;

  }

}

public class aaa {
  public static void main(String[] args) {

    Stack s1 = new Stack();

    s1.create(5);
    s1.push(1);
    s1.push(2);
    s1.push(3);
    s1.push(4);
    s1.push(5);
    s1.push(6); // 출력 -> 스택 오버플로우
    s1.push(7); // 출력 -> 스택 오버플로우
    System.out.println(s1.top()); // 출력 -> 5

    s1.pop();
    System.out.println(s1.top()); // 출력 -> 4

    s1.push(6);
    s1.push(7); // 출력 -> 스택 오버플로우

    System.out.println(s1.top()); // 출력 -> 6

    // 현재까지 스택의 상태는 1 2 3 4 6 이 되어 있는 것이다.

    s1.pop();
    s1.pop();
    s1.pop();
    s1.pop();
    s1.pop();

    s1.pop(); // 출력 -> 하면 스택 언더플로우 발생!
    System.out.println(s1.size()); // 출력 -> 0

  }
}
```

## 궁금증!

```java
자바의 Stack 클래스를 왜 안 쓰나
```

상속을 잘못했기 때문이다.

```java
public class Stack<E> extends Vector<E>
```

<br/>

`Vector` 를 상속해서 두 가지 문제가 생겼다.

<br/>

```java
1. Vector 의 모든 메서드가 synchronized 다 -> 느리다
2. Vector 의 메서드가 다 열려 있다 -> 스택이 아니게 된다
```

<br/>

```java
Stack<Integer> stack = new Stack<>();
stack.push(1);
stack.push(2);
stack.get(0);          // 스택인데 인덱스로 접근된다
stack.add(0, 99);      // 밑바닥에 끼워 넣을 수도 있다
```

<br/>

`LIFO` 라는 규칙이 지켜지지 않는다.

<br/>

앞의 SOLID 글에서 본 리스코프 치환 원칙과 이어진다.

`Vector` 자리에 `Stack` 을 넣을 수는 있는데, 그러면 스택의 의미가 없어진다.

<br/>

## 상속 대신 조합을 썼어야 한다

```java
public class Stack<E> {
    private final List<E> list = new ArrayList<>();     // 안에 들고만 있는다

    public void push(E e) { list.add(e); }
    public E pop() { return list.remove(list.size() - 1); }
}
```

<br/>

`ArrayList` 를 필드로 두면 `get` 이나 `add` 가 밖으로 안 새어나온다.

<br/>

앞의 상속보다 조합 글에서 본 그 판단이다.

`is-a` 가 아니라 `has-a` 였던 것이다.

<br/>

## 그래서 ArrayDeque 를 쓴다

```java
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
stack.pop();          // 2
```

<br/>

자바 문서에도 이렇게 적혀 있다.

```java
Deque 를 스택으로 쓰는 것이 Stack 클래스보다 낫다
```

<br/>

`ArrayDeque` 는 배열 기반이라 캐시에도 잘 맞는다.

<br/>

앞의 선형 리스트 글에서 본 대로,

`LinkedList` 도 `Deque` 를 구현하지만 노드가 흩어져 있어서 더 느리다.

<br/>

## 스택의 방향에 주의해야 한다

```java
Deque<Integer> d = new ArrayDeque<>();
d.push(1); d.push(2); d.push(3);

System.out.println(d);        // [3, 2, 1]
```

<br/>

`push` 는 앞에 넣는다. 그래서 출력하면 거꾸로 보인다.

<br/>

`addLast` 로 넣고 `pollLast` 로 빼도 스택이 된다.

이러면 출력 순서가 넣은 순서와 같아서 디버깅이 편하다.

<br/>

한 코드 안에서 `push` 와 `addLast` 를 섞으면 안 된다.

방향이 반대라 큐처럼 동작해버린다.

<br/>

## 재귀를 스택으로 바꿀 수 있다

```java
void dfs(Node node) {
    if (node == null) return;
    visit(node);
    dfs(node.left);
    dfs(node.right);
}
```

```java
void dfs(Node root) {
    Deque<Node> stack = new ArrayDeque<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        Node node = stack.pop();
        visit(node);
        if (node.right != null) stack.push(node.right);
        if (node.left != null) stack.push(node.left);
    }
}
```

<br/>

오른쪽을 먼저 넣는 게 포인트다.

스택이라 나중에 넣은 왼쪽이 먼저 나오기 때문이다.

<br/>

앞의 깊이 우선 탐색의 구현 글에서 본 그 방식이다.

<br/>

## 왜 굳이 바꾸나

앞의 재귀함수 글에서 확인한 그 문제 때문이다.

```java
StackOverflowError. 깊이 = 6308
```

<br/>

재귀는 JVM 스택을 쓰는데 크기가 정해져 있다.

직접 만든 스택은 힙에 있어서 훨씬 크게 쓸 수 있다.

<br/>

깊이가 수십만이 될 수 있으면 반복문으로 바꿔야 하는 것이다.

<br/>
