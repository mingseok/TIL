## 궁금증!

```java
트리와 그래프의 차이가 무엇인가
```

트리가 그래프의 한 종류다.

```java
그래프 - 정점과 간선의 집합
트리   - 사이클이 없고, 모든 정점이 연결되어 있고, 간선이 정점-1 개인 그래프
```

<br/>

세 조건 중 두 개만 만족해도 나머지 하나가 따라온다.

<br/>

```java
정점 5 개, 간선 4 개, 연결되어 있다  ->  사이클이 없다
정점 5 개, 간선 4 개, 사이클이 없다  ->  연결되어 있다
```

<br/>

간선이 하나만 더 있어도 사이클이 생기고, 하나만 없어도 끊긴다.

<br/>

## 방향이 있느냐 없느냐

```java
무방향 - 친구 관계. A 가 B 의 친구면 B 도 A 의 친구
방향   - 팔로우. A 가 B 를 팔로우해도 B 는 아닐 수 있다
```

<br/>

앞의 인접 행렬 글에서 본 대로,

무방향이면 행렬이 대각선을 기준으로 대칭이다.

<br/>

## 가중치가 있느냐 없느냐

```java
가중치 없음 - 연결되어 있느냐만 본다
가중치 있음 - 거리, 비용, 시간이 붙어 있다
```

<br/>

최단 경로를 찾을 때 이게 갈린다.

```java
가중치 없음 -> BFS 로 충분하다
가중치 있음 -> 다익스트라
음수 가중치 -> 벨만-포드
```

<br/>

앞의 너비 우선 탐색 구현 글에서 본 BFS가

가중치 없는 그래프에서는 최단 경로를 보장한다.

한 단계씩 퍼져나가니 먼저 도달한 것이 최단인 것이다.

<br/>

가중치가 있으면 이게 깨진다.

간선 하나로 가는 길이 간선 세 개로 가는 길보다 멀 수 있기 때문이다.

<br/>

## 실무에서 그래프로 보이는 것들

```java
SNS 친구 관계
지하철 노선도
웹 페이지의 링크 구조
클래스 의존 관계
빌드 순서
데이터베이스 테이블의 외래 키
```

<br/>

앞의 스프링 컨테이너, 스프링 빈, BeanDefinition 글에서 본

빈 의존관계도 그래프다.

<br/>

그래서 앞의 생성자 주입을 선택 글에서 본 순환 참조 검사가

`사이클 탐지` 알고리즘인 것이다.

```java
UnsatisfiedDependencyException
```

<br/>

DFS로 훑다가 이미 방문 중인 정점을 다시 만나면 사이클이다.

<br/>

## 위상 정렬

방향이 있고 사이클이 없는 그래프에서 순서를 정하는 것이다.

```java
빌드 순서 - A 를 컴파일해야 B 를 컴파일할 수 있다
과목 선수 관계 - 자료구조를 들어야 알고리즘을 들을 수 있다
```

<br/>

```java
1. 들어오는 간선이 없는 정점을 찾아 큐에 넣는다
2. 하나씩 꺼내면서 그 정점에서 나가는 간선을 지운다
3. 새로 간선이 없어진 정점을 큐에 넣는다
```

<br/>

앞의 큐 글에서 본 큐를 쓴다.

<br/>

정점이 남았는데 큐가 비면 사이클이 있는 것이다.

`순서를 정할 수 없다` 는 뜻이다.

<br/>

Gradle이나 Maven이 모듈 빌드 순서를 정하는 방식이 이것이다.

<br/>

## 그래프를 코드로 만들 때

정점을 숫자로 바꾸는 게 보통이다.

```java
Map<String, Integer> idOf = new HashMap<>();
```

<br/>

배열 인덱스로 쓰려면 `0 ~ n-1` 이어야 하기 때문이다.

<br/>

앞의 인접 리스트 글에서 본 구조가 이걸 전제로 한다.

```java
List<Integer>[] adj = new List[n];
```

<br/>

실무 데이터는 `회원 ID` 처럼 숫자가 띄엄띄엄이라

번호를 다시 매기는 단계가 항상 필요하다.

<br/>

`Map` 을 그대로 쓸 수도 있는데, 배열보다 느리고 메모리를 더 쓴다.

```java
Map<String, List<String>> adj = new HashMap<>();
```

<br/>

정점이 수만 개 이하면 이쪽이 코드가 짧아서 낫다.
