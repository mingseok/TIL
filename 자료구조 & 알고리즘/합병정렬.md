## 합병정렬의 시간복잡도

T(n) = n개의 숫자를 합병정렬 할 때의 시간복잡도

T(n) 이란 O(n log n) 이다.


![이미지](/programming/img/합병정렬3.PNG)



<br/>

각 층이 O(n) 만큼 걸리는 것이다.

그리하여 전체적으로 보자면 O(n log n) 이 걸리는 것이다.

![이미지](/programming/img/합병정렬4.PNG)


<br/><br/>



```java
import java.util.Scanner;

// 합병정렬 구현하기

class aaa {

  public static void mergeSort(int[] arr, int start, int end) {
    // arr의 start부터 end까지를 합병정렬하는 함수
    
    if(start >= end) { // 가장 단순한 경우. 즉, 숫자가 하나밖에 없을때
      return;

    } else {
      // 1. 왼쪽 절반을 합병정렬
      // 2. 오른쪽 절반을 합병정렬
      // 3. 그 둘을 합친다.

      int mid = (start + end) / 2; // 절반을 나눠야 되기 때문

      mergeSort(arr, start, mid);
      mergeSort(arr, mid+1, end);

      // arr[start~mid], arr[mid+1~end]는 정렬이 이미 되어 있음

      merging(arr, start, mid, mid+1, end); 
      // start, mid 두개는 왼쪽 절반을 의미한다.
      // mid+1, end 두개는 오른쪽 절반을 의미한다.
      // arr에 두개를 합치는 배열이 되는 것이다.
    }
    
  }

  public static void merging(int[] arr, int s1, int e1, int s2, int e2) {
    // arr의 s1~e1이 왼쪽 절반, s2~e2가 오른쪽 절반일 때,
    // 이 둘을 합쳐서 arr의 s1~e2를 정렬된 결과로 만드는 함수

    //----------------------------------------------------
    // 1 2 4 8    3 4 6 7
    // 1 2 3 

    // 위 정렬 할때 순서. 
    // 1-3 을 비교 1결정. -> 2-3 을 비교 2결정. -> 
    // 4-3 을 비교 3결정. -> ... 계속 이런식으로 가는 것이다.
    //----------------------------------------------------
    
    // 위 처럼 짜야 되는데, p , q 를 사용하는 것이다.
    // 1 2 4 8    3 4 6 7
    //     p      q
    // temp[] = 1 2 ... 정렬된 값들을 넣는 것이다.

    int p, q; // p와 q의 현재 최솟값을 가리키는 변수들 
    int[] temp = new int[100]; // 합쳐진 결과를 저장하는 임시변수
    int temp_inx = 0;

    p = s1;
    q = s2;

    // while문을 언제까지 돌려야 될까??
    // 1 2 4 8    2 5 7 9
    //          p          q
    // 이런 상황일때 그만 둬야 되는 것이다.
    while(p <= e1 && q <= e2) {

      if(arr[p] <= arr[q]) {
        temp[temp_inx++] = arr[p];
        p++;

      } else {
        temp[temp_inx++] = arr[q];
        q++;
      }
    }

    // 그리고 만약 나가게 된 경우이다. 즉,
    // 1 2 4 8    2 5 7 9
    //   p                 q
    // 이런 경우이다. p는 남아 있는데, q가 나가게 된 것이다.
    // 그렇다면 남아 있는 p도 모두 temp 에 담아야 되는 것이다.
    // 작성 해보자.
    if(p > e1) {
      for(int i = q; i <= e2; i++) {
        temp[temp_inx++] = arr[i];
      }

    } else {
      for(int i = p; i <= e1; i++) {
        temp[temp_inx++] = arr[i];
      }
    }

    // temp는 완성이 되었으니,
    // arr[s1~e2]까지에 temp의 값을 복사
    for(int i = s1; i <= e2; i++) {
      arr[i] = temp[i-s1];
    }
  }

  
  public static void main(String[] args) {

    Scanner sc = new Scanner(System.in);

    int[] numbers = new int[100];

    int n = sc.nextInt();

    for(int i = 0; i < n; i++) {
      numbers[i] = sc.nextInt();
    }

    mergeSort(numbers, 0, n-1);

    for(int i = 0; i < n; i++) {
      System.out.print(numbers[i] + " ");
    }

  }
}
```

## 궁금증!

```java
합병 정렬은 왜 최악도 O(n log n) 인가
```

나누는 방식이 데이터와 무관하기 때문이다.

```java
항상 절반으로 나눈다 -> 깊이가 항상 log n
각 깊이에서 n 개를 훑는다 -> n × log n
```

<br/>

앞의 퀵정렬 글에서 본 것과 대비된다.

퀵 정렬은 피벗이 한쪽으로 치우치면 깊이가 `n` 이 된다.

<br/>

## 실제 비교 횟수를 세어봤다

```java
n=10    합병=18
n=100   합병=547
n=1000  합병=8391
```

<br/>

이론값은 `n log₂ n` 이다.

```java
1000 × log₂(1000) ≈ 1000 × 10 = 10000
```

<br/>

`8391` 이 나왔으니 이론값보다 조금 적다.

<br/>

한쪽이 먼저 소진되면 나머지는 비교 없이 복사하기 때문이다.

```java
while (i <= mid && j <= hi) { 비교; }
while (i <= mid) tmp[k++] = a[i++];      // 비교 없이 복사
```

<br/>

이미 정렬에 가까운 데이터면 이 구간이 길어져서 비교가 더 줄어든다.

<br/>

## 추가 메모리가 필요하다

합치려면 임시 배열이 있어야 한다.

```java
int[] tmp = new int[a.length];
```

<br/>

앞의 Big_O 글에서 본 공간 복잡도가 `O(n)` 인 것이다.

<br/>

퀵 정렬은 제자리에서 하니 `O(log n)` 만 쓴다. 재귀 스택뿐이다.

<br/>

100만 개를 정렬하면 400만 바이트를 더 쓴다.

메모리가 빠듯한 환경에서는 이게 걸린다.

<br/>

## 임시 배열을 매번 만들면 안 된다

```java
void ms(int[] a, int lo, int hi) {
    int[] tmp = new int[hi - lo + 1];      // 재귀마다 새로 만든다
}
```

<br/>

이러면 객체가 수천 개 생긴다.

<br/>

앞의 GC 글에서 본 대로 짧게 살다 죽는 객체가 잔뜩 생기는 것이다.

<br/>

한 번 만들어서 넘겨쓰는 게 낫다.

```java
ms(a, 0, a.length - 1, new int[a.length]);
```

<br/>

같은 배열을 구간만 나눠 쓰면 되니 충돌이 없다.

<br/>

## 안정 정렬이다

```java
tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
```

<br/>

`<=` 가 핵심이다. 같으면 왼쪽 것을 먼저 넣는다.

<br/>

왼쪽이 원래 앞에 있던 것이니 순서가 유지된다.

<br/>

`<` 로 바꾸면 오른쪽이 먼저 들어가서 안정성이 깨진다.

<br/>

앞의 삽입 정렬 글에서 본 것과 같다.

부등호 하나가 정렬의 성질을 바꾸는 것이다.

<br/>

## 그래서 자바 객체 정렬에 쓰인다

```java
Arrays.sort(int[])       -> DualPivotQuickSort (안정성 필요 없음)
Arrays.sort(Object[])    -> TimSort (합병 정렬 기반. 안정)
Collections.sort(List)   -> TimSort
```

<br/>

원시형은 값만 있어서 안정성이 의미가 없다.

`3` 과 `3` 은 구분이 안 되기 때문이다.

<br/>

객체는 같은 키여도 다른 객체라 순서가 의미가 있다.

<br/>

앞의 정렬(Sort) 글에서 본 그 구분이다.

<br/>

## 연결 리스트에는 합병 정렬이 맞다

```java
배열   - 임시 배열이 필요하다
연결 리스트 - 포인터만 바꾸면 되니 추가 메모리가 O(1)
```

<br/>

앞의 노드 글에서 본 대로,

연결 리스트는 중간 삽입이 싸고 인덱스 접근이 비싸다.

<br/>

퀵 정렬은 인덱스로 접근하니 연결 리스트에 안 맞는다.

합병 정렬은 순차 접근만 하니 잘 맞는 것이다.

<br/>

`LinkedList.sort()` 도 결국 배열로 바꿔서 `TimSort` 를 돌린다.

직접 구현하는 것보다 그게 빠르기 때문이다.

<br/>

## 외부 정렬에도 쓴다

메모리에 안 들어가는 데이터를 정렬할 때다.

```java
1. 메모리에 들어갈 만큼씩 읽어서 정렬하고 파일로 저장
2. 정렬된 파일들을 합병한다
```

<br/>

합병은 양쪽을 앞에서부터 순서대로 읽으면 되니

파일을 처음부터 한 번씩만 읽으면 된다.

<br/>

퀵 정렬은 앞뒤를 오가야 해서 디스크에서는 아주 느리다.

`순차 접근만 한다` 는 성질이 여기서 결정적인 것이다.
