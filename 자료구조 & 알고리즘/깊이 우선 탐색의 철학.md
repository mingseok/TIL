## 깊이 우선 탐색의 철학

### 스택이란 것은 언제 쓰나?

A B C 의 일이 있다. 이, 일들 사이에 선행 관계가 존재 할 때 스택을 사용하는 것이다.

예를 들어, 

1. A 를 끝내기 전에는 B를 먼저 끝내야 되는 것이며, 
2. B를 끝내기 전에는 C를 먼저 끝내야 되는 것이다.

<br/>

## 스택 = 선행관계

선행 → ("어떠한 것보다 앞서가거나 앞에 있다”)

<br/>

## 궁금증!

```java
DFS 와 BFS 를 무엇으로 고르나
```

`무엇을 찾느냐` 로 갈린다.

```java
최단 경로            -> BFS
경로가 있는지만      -> 아무거나. DFS 가 코드가 짧다
모든 경로를 찾는다   -> DFS (백트래킹)
사이클 탐지          -> DFS
위상 정렬            -> DFS 또는 BFS
연결 요소 개수       -> 아무거나
```

<br/>

`최단` 이라는 말이 나오면 BFS다.

<br/>

## 왜 BFS 가 최단을 보장하나

한 칸씩 퍼져나가기 때문이다.

```java
거리 0 인 것들을 전부 본다
거리 1 인 것들을 전부 본다
거리 2 인 것들을 전부 본다
```

<br/>

목적지에 처음 도달한 순간이 최단이다.

더 짧은 길이 있었다면 그 전에 도달했을 것이기 때문이다.

<br/>

DFS는 한 방향으로 끝까지 가니, 먼저 도달했다고 그게 최단이 아니다.

<br/>

앞의 그래프 글에서 본 대로 가중치가 있으면 BFS도 안 된다.

간선 하나가 간선 세 개보다 멀 수 있기 때문이다.

<br/>

## 메모리 사용이 다르다

```java
DFS - 깊이만큼. O(h)
BFS - 한 층의 너비만큼. O(w)
```

<br/>

넓고 얕은 그래프면 DFS가 유리하다.

깊고 좁은 그래프면 BFS가 유리하다.

<br/>

이진 트리에서 이게 극적이다.

```java
높이 20 인 완전 이진 트리
DFS - 스택에 20 개
BFS - 큐에 최대 100 만 개 (마지막 층)
```

<br/>

층이 내려갈수록 두 배씩 늘어나니 마지막 층이 전체의 절반이다.

<br/>

## DFS 는 스택 깊이가 걸린다

앞의 재귀함수 글에서 확인한 그 한계다.

```java
StackOverflowError. 깊이 = 6308
```

<br/>

정점이 10만 개인 그래프가 한 줄로 이어져 있으면 터진다.

<br/>

앞의 스택 글에서 본 대로 반복문으로 바꾸면 힙을 쓰니 안 터진다.

<br/>

`-Xss` 로 스택을 늘릴 수도 있는데, 근본 해결은 아니다.

<br/>

## 되돌아오는 시점에 할 일이 있으면 DFS 다

```java
void dfs(int now) {
    visited[now] = true;
    선처리(now);                    // 들어갈 때

    for (int next : adj[now]) {
        if (!visited[next]) dfs(next);
    }

    후처리(now);                    // 나올 때
}
```

<br/>

`나올 때` 라는 시점이 DFS에만 있다.

<br/>

앞의 트리순회 글에서 본 후위 순회가 이걸 쓴다.

```java
자식을 다 처리한 다음에 나를 처리한다
```

<br/>

디렉토리 크기를 계산하거나, 트리를 삭제하거나 할 때 필요하다.

자식이 먼저 정리되어야 부모를 지울 수 있기 때문이다.

<br/>

위상 정렬도 이 시점을 쓴다.

`나올 때` 순서를 뒤집으면 위상 순서가 된다.

<br/>

BFS에는 `나올 때` 가 없다. 층 단위로 훑고 지나갈 뿐이다.

<br/>

## 백트래킹은 DFS 에만 붙는다

```java
선택();
dfs(depth + 1);
선택취소();          // 되돌린다
```

<br/>

앞의 완전탐색 글에서 본 그 구조다.

<br/>

`갔다가 돌아온다` 는 성질이 있어야 되돌릴 수 있다.

BFS는 여러 갈래가 동시에 진행되니 `지금 상태` 라는 게 하나가 아니다.

<br/>

그래서 모든 경우를 만들어보는 문제는 전부 DFS다.

```java
N-Queen
순열, 조합 만들기
스도쿠
```

<br/>

## 실무에서 만나는 자리

```java
파일 시스템 순회      - DFS. 디렉토리를 따라 내려간다
의존성 해석          - DFS. 사이클을 잡아낸다
크롤링               - BFS. 가까운 페이지부터
소셜 그래프의 친구 추천 - BFS. 2촌, 3촌
```

<br/>

앞의 생성자 주입을 선택 글에서 본 순환 참조 검사가

의존성 그래프를 DFS로 훑는 것이다.

<br/>

`이미 방문 중인 정점을 다시 만나면 사이클` 이라는 판정을 쓴다.

`방문 완료` 와 `방문 중` 을 구분해야 하는 것이 포인트다.
