## 전위순회 순서란?

1입장에서 자기가 root 이니깐 그 다음 → Left 를 하러 간다. 그렇게 되면

2로 가게 되는 것이다. 여기서 2 입장에서는 자기가 root 이다. 그러므로, 

Left 하러 또 다시 4로 내려가는 것이다. 또 다시 4 입장에서는 자기 자신이 root 인 것이다. 

<br/>

그런데 4입장에서는 root 이므로, 더 이상 Left로 갈곳이랑 Right 갈곳이 없는 것이다. 

그러면 4는 끝나는 것이다 !! 그렇게 다시 2 입장으로 돌아와서 Left 인 4를 했으니 이젠 

Right로 가게 되는 것이다. 


<br/> 

그리고 5 입장에서 내려와 Left, Right 아무것도 없으니, 

다시 2입장으로 올라와서 1입장으로 돌아오게 되는 것이다. 

이런 순으로 반복을 하게 되는 것이다.

## 궁금증!

```java
세 순회의 차이가 코드에서 한 줄이다
```

```java
void preorder(Node n) {
    if (n == null) return;
    visit(n);                    // 나 -> 왼쪽 -> 오른쪽
    preorder(n.left);
    preorder(n.right);
}

void inorder(Node n) {
    if (n == null) return;
    inorder(n.left);
    visit(n);                    // 왼쪽 -> 나 -> 오른쪽
    inorder(n.right);
}

void postorder(Node n) {
    if (n == null) return;
    postorder(n.left);
    postorder(n.right);
    visit(n);                    // 왼쪽 -> 오른쪽 -> 나
}
```

<br/>

`visit` 이 어디 있느냐만 다르다.

<br/>

이름의 `전/중/후` 가 `나를 언제 방문하느냐` 를 말하는 것이다.

<br/>

## 각각 쓰임새가 다르다

```java
전위 - 트리를 복사하거나 직렬화할 때. 부모를 먼저 만들어야 한다
중위 - 이진 탐색 트리를 정렬된 순서로 훑을 때
후위 - 트리를 지우거나 크기를 계산할 때. 자식이 먼저 정리되어야 한다
```

<br/>

앞의 깊이 우선 탐색의 철학 글에서 본 `나올 때` 시점이 후위다.

<br/>

디렉토리 크기를 재는 것이 대표적이다.

```java
long size(File dir) {
    long total = 0;
    for (File child : dir.listFiles()) {
        total += size(child);      // 자식을 먼저 다 센다
    }
    return total + dir.length();   // 그 다음에 나
}
```

<br/>

자식 크기를 모르면 내 크기를 계산할 수 없기 때문이다.

<br/>

## 중위 순회가 정렬 순서인 이유

이진 탐색 트리의 성질 때문이다.

```java
왼쪽 자식 < 나 < 오른쪽 자식
```

<br/>

`왼쪽 -> 나 -> 오른쪽` 순으로 가면 작은 것부터 나온다.

<br/>

앞의 트리의 개념 글에서 본 `TreeMap` 이 이 순회로 동작한다.

```java
for (String key : treeMap.keySet()) { ... }      // 정렬된 순서
```

<br/>

`HashMap` 은 순서가 없는데 `TreeMap` 은 정렬된 이유가 이것이다.

<br/>

## 레벨 순회는 DFS 가 아니다

```java
void levelOrder(Node root) {
    Queue<Node> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        Node n = q.poll();
        visit(n);
        if (n.left != null) q.offer(n.left);
        if (n.right != null) q.offer(n.right);
    }
}
```

<br/>

앞의 너비 우선 탐색 구현 글에서 본 BFS다.

<br/>

트리에서는 `visited` 배열이 필요 없다.

사이클이 없으니 같은 노드를 두 번 만날 일이 없기 때문이다.

<br/>

앞의 그래프 글에서 본 트리의 성질이 코드를 짧게 만드는 것이다.

<br/>

## 반복문으로 바꾸면 중위가 제일 까다롭다

```java
// 전위: 스택에 오른쪽 먼저
stack.push(root);
while (!stack.isEmpty()) {
    Node n = stack.pop();
    visit(n);
    if (n.right != null) stack.push(n.right);
    if (n.left != null) stack.push(n.left);
}
```

<br/>

전위는 앞의 스택 글에서 본 방식 그대로다.

<br/>

중위는 `왼쪽으로 끝까지 내려갔다가 올라오면서` 방문해야 한다.

```java
Node cur = root;
while (cur != null || !stack.isEmpty()) {
    while (cur != null) {
        stack.push(cur);
        cur = cur.left;          // 왼쪽으로 끝까지
    }
    cur = stack.pop();
    visit(cur);
    cur = cur.right;
}
```

<br/>

반복문이 두 겹이다.

<br/>

후위는 더 까다롭다. `양쪽 자식을 다 처리했는지` 를 기억해야 하기 때문이다.

<br/>

전위를 거꾸로 만드는 편법이 있다.

```java
전위(나-왼-오) 의 순서를 바꿔서 나-오-왼 으로 훑고
결과를 뒤집으면 왼-오-나 가 된다
```

<br/>

앞의 스택 글에서 본 대로,

`거꾸로 처리하고 뒤집는` 기법은 스택이 있으면 자주 쓴다.

<br/>

그래서 트리 순회는 재귀로 쓰는 게 낫다.

앞의 재귀함수 글에서 본 대로, 구조 자체가 재귀적인 문제이기 때문이다.
