이렇게 절반씩 지워 나가는 것이다.

![이미지](/programming/img/이진탐색17.PNG)

## 그러면 시간복잡도는 → O(log n) 이다

(log n) 에 뜻은 → “2를 몇번이나 곱해야 n이 되겠느냐” 하는 것이다.

똑같은 말로 얘기하면 “n을 몇번이나 2로 나눠야 1이 되겠느냐” 하는 거랑 똑같은 것이다.

<br/>

이렇게 숫자를 절반씩 지워가며 찾기 때문에 n개가 있다면, n이란 숫자를 2로 몇번이나 나눠야 1이 되겠느냐 라는 말이며, <br/>그말을 즉, O(log n) 번이라고 말한다.

<br/>

## 따라서 “log n 번만 비교를 하면 숫자를 찾을 수 있다” 라고 말할 수 있는 것이다.

### 2번. 함수가 기저조건에서 제대로 동작하게 작성한다.

즉, 가장 단순한 경우를 말한다. 

바이너리 서치 에서 가장 단순한 경우는 

- 내가 찾고자 하는 숫자가 없을 경우이다. → -1 반환 해준다.
- 숫자가 하나 밖에 없다면 이다. → 이땐 어떻게 하나? → 
하나 있는거 비교해 보면 되는 것이다. <br/>
그리하여 맞으면 s변수 반환, 아니면 -1 반환 하는 것이다.
- 코드로 다시 설명한다.

```java
int binarySearch(int arr[], int s, int e, int value) {

if(s > e) {
	return -1;

} else if(s == e) {

        if(value == arr[s]) { // 위에 설명에 숫자가 하나 밖에 없다면 s(스타트) 랑 e(end) 가
			      // 똑같다는 이야기 라서 return s 를 반환 한는 것이다.
				      
	    return s; // 있으면 위치를 반환 하는 것이다.

        } else {
	
	    return -1; // 없으면 -1
	}
}
```

<br/>

### 만약 위에 과정도 아니라면, 숫자가 여러개 있다는 뜻이고, 그땐 어떻게 숫자를 찾을 거냐? 할때 3번이 적용 되는 것이다.

<br/>

(주석 잘보기)

```java
int mid = (s + e) / 2; // 이렇게 하면 s 와 e 의 중간 지점을 찾게 되는 것이다.

if(arr[mid] == value) { // 만약에 arr[mid]가 즉, 중간값이 value랑 똑같다면 찾은 것이다.
		        // "아, mid 에 있구나" 라고 생각하고 mid 를 반환 하면 된다.
	return mid;

} else if(arr[mid] > value) { // 만약 찾지 못했다면, arr[mid] 보다 value가 더 작다.

						   // 왜 mid-1 인가? 이유는 mid를 포함하여 값이
	                                           // 없었기 때문이다.
		                                   

} else {

	return binarySearch(arr, mid+1, e, value); // 왼쪽도 아니라면, mid+1 한 인덱스 부터 
						   // 오른쪽 끝까지 다시 검사하게 하는 것이다.
```

## 정렬되어 있어야 한다는 전제

이게 큰 제약이다.

```java

```

## 오버플로 함정이 유명하다

```java
int mid = (lo + hi) / 2;
```

<br/>

`lo` 와 `hi` 가 크면 더할 때 `int` 범위를 넘는다.

```java
lo = 1,500,000,000
hi = 2,000,000,000
lo + hi = 3,500,000,000  ->  int 범위 초과 -> 음수
```

<br/>

앞의 Comparable과 Comparator 글에서 본 그 오버플로다.

<br/>

이렇게 쓰면 안 난다.

```java
int mid = lo + (hi - lo) / 2;
```

<br/>

자바 표준 라이브러리도 처음에는 이 버그가 있었다.

2006년에 고쳐졌다.

<br/>

```java
int mid = (lo + hi) >>> 1;      // 자바의 실제 구현
```

<br/>

부호 없는 시프트라 음수가 되어도 올바른 값이 나온다.

앞의 비트 연산 글에서 본 `>>>` 가 이럴 때 쓰인다.

<br/>

## 경계 조건에서 자주 틀린다

```java
while (lo <= hi)        // <= 인가 < 인가
hi = mid - 1;           // mid 인가 mid - 1 인가
```

<br/>

한 글자만 틀려도 무한 루프가 되거나 답을 놓친다.

<br/>

한 가지 형태를 정해서 외워두는 게 낫다.

```java
int lo = 0, hi = a.length - 1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] == key) return mid;
    if (a[mid] < key) lo = mid + 1;
    else hi = mid - 1;
}
return -1;
```

<br/>

`hi` 를 `length - 1` 로 잡으면 `<=` 와 `mid ± 1` 이 짝이다.

`hi` 를 `length` 로 잡으면 `<` 와 `hi = mid` 가 짝이다.

<br/>

섞으면 틀린다.

## 표준 라이브러리를 쓰면 된다

```java
Arrays.binarySearch(a, key)
Collections.binarySearch(list, key)
```

<br/>

없으면 음수를 돌려주는데, 그 값에 정보가 들어 있다.

```java
-(들어갈 자리) - 1
```

<br/>

```java
int idx = Arrays.binarySearch(a, key);
if (idx < 0) {
    int insertPoint = -idx - 1;      // 여기에 넣으면 정렬이 유지된다
}
```

<br/>

`-1` 을 빼는 이유는 `0번 자리에 넣어야 함` 을 표현하기 위해서다.

`-0` 은 `0` 이라 `찾았다` 와 구분이 안 되기 때문이다.

<br/>

앞의 삽입 정렬 글에서 본 이진 삽입 정렬이 이 값을 쓴다.

<br/>

## 값을 찾는 것 말고도 쓴다

`조건을 만족하는 경계` 를 찾는 데 더 많이 쓴다.

```java
lower bound - 조건을 만족하는 첫 번째 위치
upper bound - 조건을 만족하지 않는 첫 번째 위치
```

<br/>

```java
[1, 2, 2, 2, 3]

2 의 lower bound = 1
2 의 upper bound = 4
개수 = 4 - 1 = 3
```

<br/>

`Arrays.binarySearch` 는 같은 값이 여럿이면 어느 것을 돌려줄지 정해져 있지 않다.

개수를 세려면 경계를 직접 찾아야 하는 것이다.

## 정답을 이진 탐색하는 기법

```java
"최소 몇 개의 트럭이 필요한가"
"케이블을 최대 몇 미터로 자를 수 있나"
```

<br/>

답이 `크면 가능, 작으면 불가능` 처럼 단조로우면

답의 범위를 이진 탐색할 수 있다.

```java
lo = 최솟값, hi = 최댓값
while (lo < hi) {
    mid = 중간값
    if (가능한가(mid)) hi = mid;
    else lo = mid + 1;
}
```

<br/>

배열이 아니라 `답의 공간` 을 반씩 줄이는 것이다.

앞의 완전탐색 글에서 본 방식으로는 전부 시도해야 하는데,

단조성이 있으면 `log` 번에 끝난다.
