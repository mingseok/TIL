## 노드(Node)란 무엇인가

값 하나와, 다음 것이 어디 있는지를 같이 들고 있는 덩어리다.

```java
class Node {
    int data;        // 값
    Node next;       // 다음 노드가 어디 있는지
}
```

<br/>

이게 전부다. 특별한 문법이 있는 게 아니라 그냥 클래스 하나다.

<br/>

## 왜 이런 게 필요한가

배열은 자리가 정해져 있다.

```java
int[] arr = new int[5];
```

<br/>

메모리에 다섯 칸이 나란히 붙어 있다.

그래서 `arr[3]` 을 찾을 때 계산 한 번이면 된다.

```java
시작 주소 + (3 × 4바이트)
```

<br/>

문제는 크기를 미리 정해야 한다는 점이다.

여섯 번째를 넣으려면 새 배열을 만들어서 전부 복사해야 한다.

<br/>

노드는 나란히 안 붙어 있어도 된다.

```java
[10 | 주소A] ... 멀리 떨어진 곳 ... [20 | 주소B] ... [30 | null]
```

<br/>

각자 다음이 어디인지를 들고 있으니 흩어져 있어도 이어진다.

<br/>

## 그래서 삽입이 싸다

중간에 하나를 끼워 넣을 때 배열은 뒤를 전부 밀어야 한다.

노드는 주소 두 개만 바꾸면 된다.

```java
Node newNode = new Node(15);
newNode.next = a.next;      // 새 노드가 다음을 가리키게
a.next = newNode;           // 앞 노드가 새 노드를 가리키게
```

<br/>

앞의 선형 리스트 글에서 본 밀어내기가 사라지는 것이다.

<br/>

## 대신 조회가 비싸다

`3번째` 를 찾으려면 처음부터 따라가야 한다.

```java
Node current = head;
for (int i = 0; i < 3; i++) {
    current = current.next;
}
```

<br/>

계산으로 바로 못 간다. 밟아가야 한다.

<br/>

앞의 연결 리스트 표현 글에서 본 그 차이가 여기서 나온다.

<br/>

## 궁금증!

```java
이 차이가 실제로 얼마나 나는지 재봤다
```

10만 번씩 돌려봤다.

```java
List<Integer> al = new ArrayList<>();
List<Integer> ll = new LinkedList<>();
```

<br/>

### 결과

```java
맨 앞 삽입 10만 번   ArrayList = 451ms,  LinkedList = 4ms
인덱스 조회 10만 번  ArrayList = 2ms,    LinkedList = 3986ms
```

<br/>

100배 넘게 갈린다. 그것도 서로 반대 방향으로다.

<br/>

`ArrayList` 는 맨 앞에 넣을 때마다 뒤를 전부 밀어야 하고,

`LinkedList` 는 인덱스로 찾을 때마다 처음부터 밟아가야 하기 때문이다.

<br/>

## 노드는 여러 자료구조의 재료다

```java
연결 리스트  - next 하나
이중 연결 리스트 - next 와 prev
트리        - left 와 right (또는 자식 목록)
그래프      - 인접한 노드들의 목록
```

<br/>

전부 `값 + 연결` 이라는 같은 모양이다.

몇 개를 어떻게 가리키느냐만 다른 것이다.

<br/>

앞의 트리의 개념 글에서 본 트리도 노드로 만든다.

```java
class TreeNode {
    int data;
    TreeNode left;
    TreeNode right;
}
```

<br/>

`next` 가 `left` 와 `right` 두 개로 늘어난 것뿐이다.

<br/>

## 자바에서는 직접 만들 일이 적다

```java
LinkedList, HashMap, TreeMap
```

<br/>

표준 라이브러리가 안에서 노드를 쓴다.

<br/>

`HashMap` 의 버킷 안이 연결 리스트다.

앞의 해시(Hash) 글에서 본 충돌 처리가 그 방식이다.

<br/>

자바 8부터는 한 버킷에 8개가 넘으면 트리로 바꾼다.

```java
연결 리스트 -> 최악에 O(n)
레드-블랙 트리 -> 최악에 O(log n)
```

<br/>

노드의 모양을 바꿔서 최악의 경우를 개선한 것이다.

<br/>

## 그래도 알아둬야 하는 이유

면접에서 묻기도 하지만, 그것보다 실용적인 이유가 있다.

<br/>

`왜 이 자료구조가 이 연산에서 빠른가` 를 설명할 수 있게 된다.

```java
ArrayList 는 왜 조회가 빠른가   -> 붙어 있어서 계산으로 찾는다
LinkedList 는 왜 삽입이 빠른가  -> 주소만 바꾸면 된다
```

<br/>

앞의 Big_O 글에서 본 표기법이 이 구조에서 나오는 것이라,

구조를 알면 표기를 외울 필요가 없어진다.
