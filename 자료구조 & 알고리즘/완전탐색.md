## 궁금증!

```java
완전탐색이 가능한 크기가 어디까지인가
```

대략 이런 기준이 있다.

```java
1 초에 1 억 번 정도 연산한다고 잡는다
```

<br/>

```java
O(n)      -> n 이 1 억까지
O(n log n) -> n 이 500 만까지
O(n²)     -> n 이 1 만까지
O(n³)     -> n 이 500 까지
O(2ⁿ)     -> n 이 25 까지
O(n!)     -> n 이 10 까지
```

<br/>

앞의 Big_O 글에서 잰 결과와 맞춰보면 감이 온다.

```java
n=1000 에서 O(n²) 정렬이 비교 50 만 번
```

<br/>

`n=10000` 이면 5000만 번이니 1초 안에 들어온다.

`n=100000` 이면 50억 번이라 못 한다.

<br/>

## 그래서 제약 조건을 먼저 본다

문제에 `n ≤ 20` 이라고 적혀 있으면 `O(2ⁿ)` 을 써도 된다는 신호다.

```java
2^20 = 약 100 만
```

<br/>

`n ≤ 100,000` 이면 `O(n log n)` 이하로 풀어야 한다는 뜻이다.

<br/>

이게 문제를 푸는 실마리가 되기도 한다.

`어떤 복잡도로 풀어야 하는지` 가 정해지면 접근법의 범위가 좁아진다.

<br/>

## 완전탐색의 종류

```java
반복문 중첩   - 조합이 단순할 때
재귀          - 깊이가 정해지지 않을 때
비트마스크    - 부분집합을 다 볼 때
순열          - 순서가 중요할 때
BFS/DFS       - 그래프나 격자에서
```

<br/>

비트마스크가 편하다.

```java
for (int mask = 0; mask < (1 << n); mask++) {
    for (int i = 0; i < n; i++) {
        if ((mask & (1 << i)) != 0) {
            // i 번째를 선택한 경우
        }
    }
}
```

<br/>

앞의 비트 연산 글에서 본 그 연산들이다.

`n` 개의 부분집합 `2ⁿ` 개를 정수 하나로 표현하는 것이다.

<br/>

## 백트래킹으로 줄인다

전부 보되 가망 없는 가지는 자른다.

```java
void solve(int depth) {
    if (안 될 게 확실하면) return;      // 여기서 자른다
    if (depth == n) { 정답 처리; return; }

    for (선택지 : 후보) {
        선택();
        solve(depth + 1);
        선택취소();
    }
}
```

<br/>

N-Queen이 대표적이다.

<br/>

이론적으로는 여전히 `O(n!)` 인데, 실제로는 훨씬 적게 본다.

<br/>

앞의 깊이 우선 탐색의 철학 글에서 본 대로,

`끝까지 가보고 아니면 돌아온다` 는 구조에 가지치기를 붙인 것이다.

<br/>

## 중복 계산이 있으면 DP 로 간다

```java
피보나치를 완전탐색으로 = 호출 2986 만 번
메모이제이션으로       = 호출 69 번
```

<br/>

앞의 재귀함수 글에서 잰 수치다.

<br/>

`같은 상태를 여러 번 계산하고 있는가` 가 판단 기준이다.

<br/>

앞의 동적 계획법의 개념 글에서 본 그 전환이다.

```java
완전탐색 -> 중복 발견 -> 메모이제이션 -> DP
```

<br/>

DP 문제를 풀 때 완전탐색부터 짜보는 게 정석인 이유이기도 하다.

<br/>

먼저 `맞는 답` 을 만들고, 그 다음에 `빠르게` 만드는 순서인 것이다.

<br/>

## 실무에서도 쓴다

`n` 이 작다는 게 보장되면 완전탐색이 제일 안전하다.

```java
쿠폰 조합 중 최대 할인을 찾는다 (쿠폰 5 개)
배송 옵션 조합을 다 계산한다
```

<br/>

똑똑한 알고리즘은 틀릴 여지가 있는데,

전부 보는 것은 틀릴 여지가 없다.

<br/>

앞의 개발 사고방식 얘기와도 이어진다.

`빠른 답` 보다 `맞는 답` 이 먼저다.

<br/>

느려서 문제가 되면 그때 개선하면 되고,

대부분은 문제가 안 된다.
