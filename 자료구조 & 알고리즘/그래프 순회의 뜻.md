## 그래프 순회의 뜻

<br/>

순회를 한다 : 정점을 모두 방문 했다.

<br/>

### 이런식으로 노드들을 돌아 다닐 방법이 있어야 된다는 것이다.

이렇게 노드들을 돌아 다니면서, 그래프 안에 어떤 값이 저장되어 있는지를 파악하고 싶다는 것이다.

<br/>

## 그래프 순회가 왜 필요한가?

그래프 라는 자료구조 안에 어떤 값이 저장되어 있는지를 알기 

위해서 이리저리 돌아 다녀야 되기 때문에 필요한 것이다.

![이미지](/programming/img/그래프순회2.PNG)

<br/>

## 그래프를 순회하는 방법 중 가장 대표적인 두 가지

- 깊이 우선 탐색 (Depth First Search) == DFS

- 너비 우선 탐색 (Breadth First Search) == BFS

<br/>

## 목적은 둘 다 순회인 것이다.

![이미지](/programming/img/그래프순회3.PNG)

<br/>

## 궁금증!

```java
방문 표시를 어디서 하느냐가 왜 중요한가
```

BFS에서 실수하기 쉬운 부분이다.

```java
// 틀린 코드
while (!queue.isEmpty()) {
    int now = queue.poll();
    visited[now] = true;              // 꺼낼 때 표시한다
    for (int next : adj[now]) {
        if (!visited[next]) queue.offer(next);
    }
}
```

<br/>

같은 정점이 큐에 여러 번 들어간다.

<br/>

```java
A 가 B 를 큐에 넣는다
C 도 B 를 큐에 넣는다    <- B 는 아직 안 꺼내져서 visited 가 false 다
```

<br/>

큐가 계속 커지고, 심하면 메모리가 터진다.

<br/>

넣을 때 표시해야 한다.

```java
for (int next : adj[now]) {
    if (!visited[next]) {
        visited[next] = true;         // 넣을 때 표시
        queue.offer(next);
    }
}
```

<br/>

앞의 너비 우선 탐색 구현 글에서 본 그 순서다.

<br/>

## DFS 는 꺼낼 때 표시해도 된다

재귀로 하면 자연스럽게 그렇게 된다.

```java
void dfs(int now) {
    visited[now] = true;              // 들어오자마자
    for (int next : adj[now]) {
        if (!visited[next]) dfs(next);
    }
}
```

<br/>

들어오는 즉시 표시하니 문제가 없다.

<br/>

스택으로 바꾸면 BFS와 같은 문제가 생긴다.

앞의 스택 글에서 본 그 변환이다.

<br/>

## 순회와 탐색은 다른 말이다

```java
순회 (traversal) - 전부 방문한다
탐색 (search)    - 찾으면 멈춘다
```

<br/>

`DFS` 와 `BFS` 는 `Search` 인데 실제로는 순회에 더 많이 쓴다.

<br/>

연결 요소를 세거나, 거리를 전부 구하거나 하는 식이다.

<br/>

## 시작점이 여러 개일 수 있다

그래프가 끊어져 있으면 한 번으로는 전부 못 본다.

```java
for (int i = 0; i < n; i++) {
    if (!visited[i]) {
        dfs(i);
        count++;        // 연결 요소 개수
    }
}
```

<br/>

`dfs` 를 몇 번 불렀는지가 곧 덩어리 개수다.

<br/>

앞의 그래프 글에서 본 대로,

트리는 항상 연결되어 있어서 이 반복문이 필요 없다.

<br/>

## 다중 시작점 BFS

여러 곳에서 동시에 퍼지는 경우다.

```java
for (int start : 시작점들) {
    visited[start] = true;
    queue.offer(start);           // 처음부터 다 넣어둔다
}
```

<br/>

토마토가 익어가는 문제나 불이 번지는 문제가 이렇다.

<br/>

각각에서 따로 BFS를 돌리고 최솟값을 구하는 것보다 훨씬 빠르다.

```java
따로 돌리기 - O(시작점 수 × (V + E))
한 번에     - O(V + E)
```

<br/>

큐에 여러 개를 미리 넣어두면 알아서 가장 가까운 곳에서 퍼진다.

<br/>

## 방문 배열 대신 거리 배열을 쓰기도 한다

```java
int[] dist = new int[n];
Arrays.fill(dist, -1);
dist[start] = 0;
```

<br/>

`-1` 이 `아직 안 방문` 이다.

<br/>

방문 여부와 거리를 배열 하나로 처리할 수 있어서 코드가 짧아진다.

<br/>

앞의 인접 행렬 글에서 본 것과 같은 고민이다.

`0` 을 특별한 뜻으로 쓰면 실제 값 `0` 과 헷갈리니

`-1` 이나 큰 값을 쓰는 것이다.

<br/>

## 격자에서도 같은 구조다

```java
int[] dx = {0, 0, -1, 1};
int[] dy = {-1, 1, 0, 0};

for (int d = 0; d < 4; d++) {
    int nx = x + dx[d];
    int ny = y + dy[d];
    if (nx < 0 || ny < 0 || nx >= n || ny >= m) continue;
}
```

<br/>

격자를 그래프로 보면 각 칸이 정점이고 상하좌우가 간선이다.

<br/>

인접 리스트를 안 만들고 방향 배열로 대신하는 것이다.

<br/>

앞의 인접 리스트 글에서 본 구조를 만들 필요가 없다.

`규칙으로 이웃을 계산할 수 있으면 자료구조를 안 만들어도 되는` 경우다.
