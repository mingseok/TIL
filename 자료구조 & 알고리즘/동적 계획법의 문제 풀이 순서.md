## 동적 계획법의 문제 풀이 순서

## 1. 부분 문제를 정의한다.

동적 계획법이란? 조금 더 작은 문제를 먼저 해결하고, 

그 작은 문제를 해결한 것을 바탕으로 전체 문제를 해결 하는 것이 동적 계획법인데, 그럴려면

- 전체 문제는 뭐고?
  
- 소 문제는 뭐고?
  
- 소 문제 보다 → 더 작은 소문제는 뭐고?

<br/>

## 그리하여 소문제들을 우리가 “부분 문제” 라고 부른다

이 “부분 문제” 를 정확하게 정의 해야 되는 것이다. 어떻게? → 말로

예를 들어, “이, 소문제가 정확하게 의미 하는 것이 뭐냐?” , 

<br/>

“한개면 소문제냐?” , “여기서 부터 저기까지가 소문제냐?” 이런식으로 “부분 문제” 를 좀 더 명확하게 정의 하는 것이 “동적 계획법” 이다.


![이미지](/programming/img/동적계획법문제.PNG)

<br/>

## 궁금증!

```java
DP 문제를 어떤 순서로 접근하나
```

완전탐색부터 짜는 게 정석이다.

```java
1. 완전탐색으로 맞는 답을 만든다
2. 같은 계산이 반복되는지 본다
3. 반복되면 메모이제이션을 붙인다
4. 필요하면 상향식으로 바꾼다
5. 필요하면 공간을 줄인다
```

<br/>

앞의 완전탐색 글에서 본 그 흐름이다.

<br/>

처음부터 점화식을 세우려고 하면 막힌다.

`맞는 답` 을 먼저 만들고 `빠르게` 만드는 순서가 낫다.

<br/>

## 상태를 정의할 때 묻는 것

```java
지금까지 무엇을 결정했나
그 결정을 기억하려면 무엇이 필요한가
```

<br/>

두 번째가 상태의 차원이 된다.

<br/>

```java
"i 번째 물건까지 봤다"                  -> dp[i]
"i 번째까지 봤고 무게를 j 만큼 썼다"     -> dp[i][j]
"i 번째까지 봤고 무게 j, 마지막이 k"     -> dp[i][j][k]
```

<br/>

필요 없는 것을 상태에 넣으면 차원이 커져서 메모리가 터진다.

<br/>

앞의 동적 계획법의 개념 글에서 본 그 문제다.

<br/>

## 점화식을 세울 때 묻는 것

```java
지금 단계에서 선택지가 무엇인가
각 선택지를 고르면 어떤 상태로 넘어가나
```

<br/>

배낭 문제면 선택지가 둘이다.

```java
i 번째를 담는다   -> dp[i-1][w - weight[i]] + value[i]
i 번째를 안 담는다 -> dp[i-1][w]
```

<br/>

둘 중 큰 것을 고른다.

<br/>

계단 오르기면 선택지가 `한 칸` 과 `두 칸` 이다.

```java
dp[i] = dp[i-1] + dp[i-2]
```

<br/>

피보나치와 같은 식이 나온다.

<br/>

앞의 동적계획법의 예제 피보나치 수 글에서 본 그 점화식이다.

<br/>

## 초기값과 범위에서 자주 틀린다

```java
dp[0] = ?
dp[1] = ?
```

<br/>

점화식이 맞아도 초기값이 틀리면 전부 틀린다.

<br/>

작은 경우를 손으로 계산해서 맞춰보는 게 확실하다.

```java
n=1 일 때 답이 무엇인가
n=2 일 때는
```

<br/>

`dp` 배열 크기도 `n+1` 로 잡아야 `dp[n]` 을 쓸 수 있다.

```java
long[] dp = new long[n];        // dp[n] 에서 ArrayIndexOutOfBounds
long[] dp = new long[n + 1];    // 이렇게
```

<br/>

## 채우는 순서를 확인해야 한다

상향식은 `필요한 것이 이미 채워져 있어야` 한다.

```java
for (int i = 2; i <= n; i++) {
    dp[i] = dp[i-1] + dp[i-2];      // i-1 과 i-2 가 이미 있어야 한다
}
```

<br/>

2차원이면 순서가 더 헷갈린다.

```java
dp[i][j] 가 dp[i-1][j] 와 dp[i][j-1] 을 쓴다
-> i 를 바깥, j 를 안쪽으로 돌면 된다
```

<br/>

앞의 동적 계획법의 개념 글에서 본 배낭 문제의 역방향이

이 순서 때문에 필요한 것이다.

<br/>

## 오버플로를 조심해야 한다

```java
long[] dp = new long[n + 1];
```

<br/>

경우의 수를 세는 문제는 값이 금방 커진다.

```java
피보나치 92 번째부터 long 을 넘는다
```

<br/>

앞의 이진 탐색 글에서 본 그 오버플로다.

<br/>

문제에서 `1000000007 로 나눈 나머지` 를 요구하는 경우가 많은 이유다.

```java
dp[i] = (dp[i-1] + dp[i-2]) % MOD;
```

<br/>

더할 때마다 나머지를 취해야 한다.

다 더하고 마지막에 하면 이미 넘쳐 있다.

<br/>

## 안 풀리면 상태를 다시 본다

점화식이 안 나오면 대개 상태 정의가 잘못된 것이다.

```java
기억해야 할 정보를 빠뜨렸다
필요 없는 정보를 넣었다
```

<br/>

앞의 개발 사고방식 얘기와 이어진다.

`왜 안 되는가` 를 붙잡기보다 `전제가 맞는가` 를 다시 보는 게 빠를 때가 많다.
