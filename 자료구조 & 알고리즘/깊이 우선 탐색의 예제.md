## 연결 요소 세기

```java
int count = 0;
for (int i = 0; i < n; i++) {
    if (!visited[i]) {
        dfs(i);
        count++;
    }
}
```

<br/>

앞의 그래프 순회의 뜻 글에서 본 그 구조다.

<br/>

`dfs` 를 몇 번 시작했는지가 곧 덩어리 개수다.

한 번 들어가면 연결된 것을 전부 표시하고 나오기 때문이다.

<br/>

격자 문제에서 이게 자주 나온다.

```java
섬의 개수
단지 나누기
그림 개수와 크기
```

<br/>

`dfs` 가 돌려주는 값으로 크기도 같이 셀 수 있다.

```java
int dfs(int x, int y) {
    visited[x][y] = true;
    int size = 1;
    for (int d = 0; d < 4; d++) {
        ...
        size += dfs(nx, ny);
    }
    return size;
}
```

<br/>

앞의 그래프 순회의 뜻 글에서 본 방향 배열을 쓴다.

<br/>

## 모든 경로 찾기

```java
void dfs(int now, int target) {
    if (now == target) {
        정답++;
        return;
    }
    visited[now] = true;
    for (int next : adj[now]) {
        if (!visited[next]) dfs(next, target);
    }
    visited[now] = false;        // 되돌린다
}
```

<br/>

마지막 줄이 핵심이다.

<br/>

`경로가 있는가` 만 물으면 되돌릴 필요가 없다.

`모든 경로` 를 세려면 되돌려야 한다.

<br/>

되돌리지 않으면 한 번 지나간 정점을 다른 경로에서 못 쓴다.

<br/>

앞의 완전탐색 글에서 본 백트래킹이 이것이다.

<br/>

## 백트래킹의 되돌리기를 빼먹는 실수

```java
선택();
dfs(depth + 1);
// 선택취소() 를 안 함
```

<br/>

이러면 답이 적게 나온다.

<br/>

그리고 되돌리는 위치도 중요하다.

```java
for (선택지 : 후보) {
    선택();
    dfs(depth + 1);
    선택취소();          // 반복문 안이어야 한다
}
```

<br/>

반복문 밖에 두면 두 번째 후보를 시도할 때 첫 번째가 남아 있다.

<br/>

## 재귀 파라미터로 상태를 넘기는 방법도 있다

```java
void dfs(int now, List<Integer> path) {
    path.add(now);
    ...
    path.remove(path.size() - 1);      // 되돌리기
}
```

```java
void dfs(int now, List<Integer> path) {
    List<Integer> newPath = new ArrayList<>(path);      // 복사해서 넘긴다
    newPath.add(now);
    ...
}
```

<br/>

두 번째는 되돌릴 필요가 없다. 각자 자기 것을 갖고 있기 때문이다.

<br/>

대신 매번 복사해서 느리고 메모리를 많이 쓴다.

<br/>

앞의 방어적 복사 글에서 본 그 거래다.

`공유하고 조심하기` 와 `복사하고 안심하기` 중에 고르는 것이다.

<br/>

경로가 짧으면 복사가 편하고, 길거나 많으면 되돌리기가 낫다.

<br/>

## 순열과 조합 만들기

```java
// 순열: 순서가 중요. 이미 쓴 것은 못 쓴다
void perm(int depth) {
    if (depth == r) { 출력(); return; }
    for (int i = 0; i < n; i++) {
        if (used[i]) continue;
        used[i] = true;
        result[depth] = arr[i];
        perm(depth + 1);
        used[i] = false;
    }
}

// 조합: 순서 무관. 뒤쪽만 본다
void comb(int start, int depth) {
    if (depth == r) { 출력(); return; }
    for (int i = start; i < n; i++) {
        result[depth] = arr[i];
        comb(i + 1, depth + 1);
    }
}
```

<br/>

조합은 `used` 배열이 필요 없다.

`start` 부터만 보니 앞의 것을 다시 쓸 일이 없기 때문이다.

<br/>

`comb(i + 1, ...)` 이 `comb(start + 1, ...)` 이 아니라는 게 포인트다.

`i` 를 골랐으니 그 다음부터 봐야 한다.

<br/>

여기서 실수하면 같은 원소를 여러 번 고르는 중복 조합이 된다.
