## 리터럴

리터럴은 소스 코드상에 고정된 값을 말하는 용어이다.

예를 들어서 다음 코드에서 "Hello" 는 문자 리터럴, 10 , 20 는 숫자 리터럴이다.

```html
String a = "Hello"
int a = 10 * 20
```

<br/>

## 타임리프는 다음과 같은 리터럴이 있다.

문자: 'hello'

숫자: 10

불린: true , false

null: null

<br/><br/>

## 타임리프에서 문자 리터럴은 항상 ' (작은 따옴표)로 감싸야 한다.

```html
<span th:text="'hello'">
```

그런데 문자를 항상 ' 로 감싸는 것은 너무 귀찮은 일이다. 

공백 없이 쭉 이어진다면 하나의 의미 있는 토큰으로 인지해서 

<br/>다음과 같이 작은 따옴표를 생략할 수 있다.

```html
<span th:text="hello">
```



<br/><br/>

## 예시 - 리터럴 대체를 사용하자.

| | 안을 전부 문자로 놓고 ${} 부분만 치환해준다.

```html

<h1>리터럴</h1>
<ul>
    <!--주의! 다음 주석을 풀면 예외가 발생함-->
    <!-- <li>"hello world!" = <span th:text="hello world!"></span></li>-->

    <li>'hello' + ' world!' = <span th:text="'hello' + ' world!'"></span></li>
    <li>'hello world!' = <span th:text="'hello world!'"></span></li>
    <li>'hello ' + ${data} = <span th:text="'hello ' + ${data}"></span></li>

    <li>리터럴 대체 |hello ${data}| = <span th:text="|hello ${data}|"></span></li>
</ul>
```

## 궁금증!

```java
문자열에 공백이 있으면 왜 오류가 나나
```

타임리프는 공백이 없는 문자열은 따옴표를 생략할 수 있다.

```html
<span th:text="hello">             <!-- 된다 -->
<span th:text="hello world">       <!-- 오류 -->
<span th:text="'hello world'">     <!-- 된다 -->
```

<br/>

공백이 있으면 표현식이 끊긴 것으로 보기 때문이다.

<br/>

그래서 문자열은 항상 작은따옴표로 감싸는 습관을 들이는 게 낫다.

<br/>

## 이어 붙일 때가 더 번거롭다

```html
<span th:text="'안녕하세요 ' + ${name} + '님'"></span>
```

<br/>

따옴표와 더하기가 섞여서 읽기 어렵다.

<br/>

리터럴 대체 문법을 쓰면 낫다.

```html
<span th:text="|안녕하세요 ${name}님|"></span>
```

<br/>

세로 막대로 감싸면 안에서 `${...}` 를 그대로 쓸 수 있다.

<br/>

자바스크립트의 백틱과 같은 발상이다.

```javascript
`안녕하세요 ${name}님`
```

<br/>

## 리터럴 대체 안에서는 제약이 있다

```html
<span th:text="|합계: ${price * count}원|"></span>       <!-- 안 된다 -->
```

<br/>

안에서는 표현식만 되고 연산은 안 된다.

<br/>

계산을 하려면 밖으로 빼야 한다.

```html
<span th:text="|합계: ${price * count}|"></span>          <!-- 이건 된다 -->
```

<br/>

실제로는 `${...}` 안의 연산은 되고, 세로 막대 안에서 `+` 로 잇는 것이 안 되는 것이다.

<br/>

## 숫자와 불린도 리터럴이다

```html
<span th:text="10"></span>
<span th:text="10 + 2"></span>          <!-- 12 -->
<span th:text="'10' + 2"></span>        <!-- 102. 문자열이 된다 -->
<span th:if="true"></span>
<span th:if="${count} > 0"></span>
```

<br/>

`'10'` 은 문자열이라 `+` 가 연결이 된다.

자바스크립트와 같은 함정이다.

<br/>

앞의 데이터타입, 변수 글에서 본 그 문제다.

<br/>

## null 리터럴도 있다

```html
<span th:if="${member} == null">회원 정보가 없습니다</span>
<span th:if="${member} != null" th:text="${member.name}"></span>
```

<br/>

앞의 변수 - SpringEL 글에서 본 안전 탐색 연산자를 쓰면 더 짧다.

```html
<span th:text="${member?.name} ?: '회원 정보가 없습니다'"></span>
```

<br/>

## 메시지에서 파라미터를 넘길 때

```java
hello.name=안녕하세요 {0}님
```

```html
<span th:text="#{hello.name(${member.name})}"></span>
```

<br/>

앞의 스프링 메시지, 국제화 글에서 본 그 방식이다.

<br/>

문자열을 화면에서 이어 붙이는 것보다 이게 낫다.

<br/>

나라마다 어순이 다르기 때문이다.

```java
한국어  안녕하세요 {0}님
영어    Hello, {0}
일본어  {0}さん、こんにちは
```

<br/>

`'안녕하세요 ' + ${name} + '님'` 으로 화면에 박아두면

영어로 바꿀 때 화면 파일을 고쳐야 한다.

메시지 파일에 두면 파일만 추가하면 된다.

<br/>

앞의 뷰 리졸버를 왜 사용하는가 글에서 본 것과 같은 발상이다.

`부르는 이름` 과 `실제 내용` 을 나눠두면 내용이 바뀌어도 부르는 쪽은 안 바뀐다.
