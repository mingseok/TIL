## 속성 값 설정

<br/>

### 기존 코드

기존 name="mock" 는 사라지고, th를 지정한 것으로 변경되어 버린다.

```html
<input type="text" name="mock" th:name="userA"/>
```

<br/>

### 타임리프 렌더링 후 코드

```html
<input type="text" name="userA"/>
```

<br/><br/>

## 속성 추가 코드가 있다면,

```html
<input type="text" class="text" th:attrappend="class='large'" /><br/>


class="text" 부분이 → “textlarge” 가 되는 것이다. (합쳐 진다고 생각하면 된다.)
```

`th:attrappend` : 문자 뒤에 값을 추가한다.

`th:attrprepend` : 문자 앞에 값을 추가한다.

`th:classappend` : 타임리프가 알아서 합쳐준다고 생각하면 된다.

 

<br/><br/>



## checked 처리

결국, input 태그에 checked 속성이 true면 계속 동작하고, false면 그냥 사라진다는 것이다.

<br/>

### 렌더링 전 코드

```
- checked o <input type="checkbox" name="active" th:checked="true" /><br/>
- checked x <input type="checkbox" name="active" th:checked="false" /><br/>
```

<br/>

### 타임리프 렌더링 후:

```
<input type="checkbox" name="active" th:checked="checked"/>
<input type="checkbox" name="active"/>
```

## 궁금증!

```java
th:attr 를 안 쓰고도 되는 이유
```

자주 쓰는 속성은 전용 문법이 미리 만들어져 있기 때문이다.

```html
<input th:attr="value=${name}">
<input th:value="${name}">              <!-- 같다. 이게 훨씬 낫다 -->
```

<br/>

거의 모든 HTML 속성에 `th:` 를 붙일 수 있다.

```html
th:href, th:src, th:alt, th:title, th:placeholder, th:class, th:style,
th:id, th:name, th:type, th:action, th:method, th:colspan
```

<br/>

`th:attr` 는 표준에 없는 속성을 넣을 때만 쓴다.

```html
<div th:attr="data-member-id=${member.id}">
```

<br/>

사실 이것도 전용 문법이 있다.

```html
<div th:data-member-id="${member.id}">
```

<br/>

## 왜 이런 게 필요한가

브라우저가 원래 값을 먼저 보기 때문이다.

```html
<img src="/images/sample.png" th:src="@{/images/} + ${file}">
```

<br/>

파일을 그냥 열면 `sample.png` 가 보이고,

서버가 그리면 `th:src` 가 `src` 를 덮어쓴다.

<br/>

앞의 타임리프 소개 글에서 본 내추럴 템플릿이 이 방식으로 동작하는 것이다.

<br/>

## 값을 더하거나 덧붙이는 문법

```html
<div class="btn" th:classappend="${isActive} ? 'active'">
```

<br/>

`classappend` 는 기존 클래스에 추가한다.

`th:class` 를 쓰면 통째로 갈아치운다.

```html
th:class="'active'"        ->  class="active"       (btn 이 사라진다)
th:classappend="'active'"  ->  class="btn active"
```

<br/>

`th:styleappend` 도 있다.

<br/>

디자이너가 넣어둔 클래스를 안 지우려면 `classappend` 를 써야 하는 것이다.

<br/>

## 있으면 켜지는 속성들

```html
<input type="checkbox" checked>
<input type="text" disabled>
<option selected>
<input required>
```

<br/>

이런 것들은 값이 아니라 존재 자체가 의미다.

```html
<input type="checkbox" checked="false">      <!-- 그래도 체크된다 -->
```

<br/>

그래서 전용 문법이 따로 있다.

```html
<input type="checkbox" th:checked="${member.vip}">
<input type="text" th:disabled="${not editable}">
<option th:selected="${item.id == selectedId}">
```

<br/>

`false` 면 속성 자체를 안 만든다.

<br/>

`th:attr="checked=${...}"` 로 쓰면 이게 안 된다.

`checked="false"` 가 되어서 체크된 상태로 나오는 것이다.

<br/>

## th:field 를 쓰면 이걸 다 해준다

```html
<input type="checkbox" th:field="*{open}">
```

```html
<input type="checkbox" id="open" name="open" value="true" checked>
<input type="hidden" name="_open" value="on">
```

<br/>

앞의 @PostMapping(), form태그 글에서 본 그 숨은 필드까지 만들어준다.

<br/>

체크박스는 체크를 풀면 값 자체가 안 가니,

`_open` 을 같이 보내서 `false` 를 구분할 수 있게 하는 것이다.

<br/>

## 순서가 정해져 있다

같은 태그에 여러 개를 붙이면 우선순위대로 처리한다.

```java
1. th:each
2. th:if
3. th:object, th:with
4. th:attr, th:value, th:href
5. th:text, th:utext
6. th:fragment
7. th:remove
```

<br/>

앞의 조건부 if 글에서 본 그 표다.

<br/>

`th:each` 가 제일 먼저라 반복 안에서 조건이 평가된다.

`th:text` 가 나중이라 그 안의 내용이 최종적으로 덮인다.

<br/>

## th:remove 로 개발용 요소를 지운다

```html
<tr th:remove="all">
    <td>예시 데이터 1</td>
</tr>
```

<br/>

디자이너가 목록 예시로 넣어둔 행을 서버가 그릴 때만 지운다.

<br/>

```java
all       - 태그와 내용을 전부
body      - 내용만
tag       - 태그만 (내용은 남긴다)
all-but-first - 첫 번째 자식만 남긴다
none      - 아무것도 안 지운다
```

<br/>

`all-but-first` 가 목록에 잘 맞는다.

예시 행을 여러 개 넣어두고, 첫 번째만 `th:each` 로 쓰는 방식이다.
