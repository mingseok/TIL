## 체크 박스 - 단일

<br/>

### html form 안에 체크 박스 추가.

```html
<div>판매 여부</div>
<div>
   <div class="form-check">
      <input type="checkbox" id="open" name="open" class="form-check-input">
      <label for="open" class="form-check-label">판매 오픈</label>
   </div>
</div>
```

<br/>

### 체크 박스 관련 컨트롤러

```java
@PostMapping("/add")
public String addItem(@ModelAttribute Item item, RedirectAttributes redirectAttributes) {

     log.info("item.open={}", item.getOpen());

     Item savedItem = itemRepository.save(item);
     redirectAttributes.addAttribute("itemId", savedItem.getId());
     redirectAttributes.addAttribute("status", true);
     return "redirect:/form/items/{itemId}";
}
```

<br/><br/>


### (@ModelAttribute Item item)를 통해서 Item 클래스에 Boolean 형태로 값이 들어가게 되는 것이다.


```java
@Data
public class Item {
    
    // ... 생략
    
    private Boolean open; //판매 여부
}
```

<br/>


- Item 클래스의 변수명이 `open`인 이유

    - `form`태그의 체크 박스 `name`이 `"open"`이기 때문이다 `(name="open")`

- `(@ModelAttribute Item item)` 부분의 매개변수명이 `"item"`인 이유

    - `Item`이라는 저장 시킬 수 있는 클래스가 있기 때문이다.

## 문제 사항 - 체크 박스를 선택하지 않을 때

체크 박스를 선택하지 않고 실행 시키면 

`false` 가 뜨는게 아니고, `null` 이 출력 되는 것이다.

<br/>

HTML 체크박스는 선택이 안되면 클라이언트에서 서버로 값 자체를 보내지 않는다. 

수정의 경우에는 상황에 따라서 이 방식이 문제가 될 수 있다.


<br/><br/>

## 이걸 정리해주기 위해서는 히든 필드를 추가 해주면 된다.

포인트는 체크박스의 name인 "open" 을 가져와서 히든 타입인 name을 작성할때에는 
네임 앞에 "_" 만 추가해 주면 되는 것이다.

```html
<!-- single checkbox -->
<div>판매 여부</div>
<div>
  <div class="form-check">
   <input type="checkbox" id="open" name="open" class="form-check-input">
		
   <!--히든 필드 추가-->
   <input type="hidden" name="_open" value="on">
  </div>
</div>
```

## 체크 박스 체크

체크 박스를 체크하면 스프링 MVC가 `open` 에 값이 있는 것을 확인하고 사용한다. 

이때 `_open` 은 무시한다.

<br/>

## 체크 박스 미체크

`_open=on`

체크 박스를 체크하지 않으면 스프링 MVC가 `_open` 만 있는 것을 확인하고, open 의 값이 체크되지 않았다고 인식한다.



서버에서 `Boolean` 타입을 찍어보면 결과가 `null` 이 아니라 `false` 인 것을 확인할 수 있다.

## 궁금증!

```java
체크를 풀면 왜 값이 아예 안 오나
```

HTML 스펙이 그렇다.

```html
<input type="checkbox" name="open" value="true">
```

<br/>

```java
체크함  ->  open=true 가 간다
체크 안 함 ->  아무것도 안 간다. open=false 가 아니다
```

<br/>

체크박스는 `선택된 것만 보낸다` 가 원칙이기 때문이다.

<br/>

## 등록에서는 문제가 안 된다

```java
Boolean open = null;      // 값이 안 왔다
```

<br/>

`null` 이면 `false` 로 보면 되니 큰 문제가 없다.

<br/>

`boolean` 으로 받으면 기본값이 `false` 라 알아서 처리된다.

<br/>

## 수정에서 문제가 된다

체크되어 있던 것을 풀고 저장하면,

```java
값이 안 온다 -> 서버는 "이 필드는 안 건드렸구나" 로 볼 수 있다 -> 기존 값 유지
```

<br/>

체크를 풀었는데 그대로인 것이다.

<br/>

`왜 저장이 안 되지` 를 한참 찾게 된다.

<br/>

## 숨은 필드로 해결한다

```html
<input type="checkbox" name="open" value="true">
<input type="hidden" name="_open" value="on">
```

<br/>

`_open` 은 체크 여부와 상관없이 항상 간다.

```java
open 이 왔다   -> true
_open 만 왔다  -> false 로 판단한다
```

<br/>

`값이 없다` 와 `false 다` 를 구분할 수 있게 되는 것이다.

<br/>

앞의 검색 조건, NULL 값 글에서 본 것과 같은 고민이다.

`없음` 을 어떻게 표현할지의 문제다.

<br/>

## th:field 가 이걸 자동으로 만든다

```html
<input type="checkbox" th:field="*{open}">
```

```html
<input type="checkbox" id="open" name="open" value="true">
<input type="hidden" name="_open" value="on">
```

<br/>

앞의 속성 값 설정 글에서 본 대로

`th:field` 가 `id`, `name`, `value` 에 더해 숨은 필드까지 만든다.

<br/>

체크 상태면 `checked` 도 붙인다.

```html
<input type="checkbox" id="open" name="open" value="true" checked="checked">
```

<br/>

## checked="false" 는 안 통한다

```html
<input type="checkbox" checked="false">      <!-- 체크된다 -->
```

<br/>

`checked` 는 값이 아니라 존재 여부가 의미이기 때문이다.

<br/>

그래서 직접 만들 때는 `th:checked` 를 써야 한다.

```html
<input type="checkbox" th:checked="${item.open}">
```

<br/>

`false` 면 속성 자체를 안 만든다.

<br/>

앞의 속성 값 설정 글에서 본 그 처리다.

<br/>

## API 로 받을 때는 다르다

```java
@PostMapping("/api/items")
public String save(@RequestBody ItemRequest request) { ... }
```

<br/>

JSON은 체크박스 문제가 없다.

```json
{"open": false}
```

<br/>

`false` 를 그대로 보낼 수 있기 때문이다.

<br/>

앞의 HTTP 요청 메시지 - JSON 글에서 본 대로,

JSON은 `키가 없는 것` 과 `false` 를 구분할 수 있다.

<br/>

폼 형식이 평평한 문자열 목록이라 생긴 제약이었던 것이다.

<br/>

## 부분 수정에서는 또 다른 문제가 있다

```java
PATCH /items/1  {"open": false}
```

<br/>

앞의 요청 매핑 - API 예시 글에서 본 `PATCH` 다.

`보낸 것만 바꾼다` 가 원칙인데, JSON에서도 `null` 과 `안 보냄` 이 헷갈린다.

```json
{"open": null}     -- 명시적으로 비우겠다는 뜻인가
{}                 -- 안 건드리겠다는 뜻인가
```

<br/>

Jackson으로 받으면 둘 다 필드가 `null` 이라 구분이 안 된다.

<br/>

구분하려면 `JsonNullable` 같은 것을 쓰거나,

`어느 필드를 보냈는지` 를 따로 받아야 한다.

<br/>

체크박스의 숨은 필드와 결국 같은 발상이다.

`값이 없음` 을 표현할 방법을 따로 마련해야 하는 것이다.
