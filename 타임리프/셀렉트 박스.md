## 셀렉트 박스

셀렉트 박스는 여러 선택지 중에 하나를 선택할 때 사용할 수 있다. 

이번시간에는 셀렉트 박스를 자바 객체를 활용해서 개발해보자.

<br/>

## 배송 방식

- 빠른 배송

- 일반 배송
- 느린 배송
- 셀렉트 박스로 하나만 선택할 수 있다.

<br/>

## DeliveryCode 클래스

```java
/**
 * FAST: 빠른 배송
 * NORMAL: 일반 배송
 * SLOW: 느린 배송
 */
@Data
@AllArgsConstructor
public class DeliveryCode {
    private String code;
    private String displayName;
}
```



<br/><br/>

## 컨트롤러

```java
@ModelAttribute("deliveryCodes")
public List<DeliveryCode> deliveryCodes() {
	 List<DeliveryCode> deliveryCodes = new ArrayList<>();

	 deliveryCodes.add(new DeliveryCode("FAST", "빠른 배송"));
	 deliveryCodes.add(new DeliveryCode("NORMAL", "일반 배송"));
	 deliveryCodes.add(new DeliveryCode("SLOW", "느린 배송"));

	 return deliveryCodes;
}
```

DeliveryCode 라는 자바 객체를 사용하는 방법으로 진행하겠다.

DeliveryCode 를 등록 폼, 조회, 수정 폼에서 모두 사용하므로 @ModelAttribute 의 특별한 사용법을 적용하자.


<br/><br/>

## html 코드

```html
<!-- SELECT -->
<div>
   <div>배송 방식</div>
     <select th:field="*{deliveryCode}" class="form-select">
        <option value="">==배송 방식 선택==</option>
        <option th:each="deliveryCode : ${deliveryCodes}" 
	        th:value="${deliveryCode.code}" 
	        th:text="${deliveryCode.displayName}">
		FAST
	</option>	
     </select>
</div>
```

## 궁금증!

```java
select 는 왜 value 를 option 에 붙이나
```

`select` 는 껍데기이고 실제 값은 `option` 에 있기 때문이다.

```html
<select th:field="*{deliveryCode}">
    <option value="">배송 방식 선택</option>
    <option th:each="code : ${codes}"
            th:value="${code.code}"
            th:text="${code.displayName}"></option>
</select>
```

<br/>

`name` 은 `select` 에 붙고, `value` 는 `option` 에 붙는다.

<br/>

```html
<select name="deliveryCode">
    <option value="FAST" selected>빠른 배송</option>
</select>
```

<br/>

서버로는 `deliveryCode=FAST` 가 간다.

<br/>

## th:field 를 select 에 붙인다

```html
<select th:field="*{deliveryCode}">
```

<br/>

`option` 에는 안 붙인다.

`th:field` 가 `select` 의 값과 각 `option` 의 `value` 를 비교해서

맞는 것에 `selected` 를 붙여준다.

<br/>

앞의 라디오 버튼 글에서 본 것과 같은 처리인데,

라디오는 각 `input` 에 붙이고 셀렉트는 `select` 하나에 붙인다는 게 다르다.

<br/>

## 빈 옵션을 두는 이유

```html
<option value="">배송 방식 선택</option>
```

<br/>

이게 없으면 첫 번째 옵션이 기본으로 선택된다.

<br/>

사용자가 고른 것인지 그냥 첫 번째가 남은 것인지 구분이 안 된다.

<br/>

앞의 라디오 버튼 글에서 본 그 문제와 같다.

<br/>

빈 값을 두면 `@NotBlank` 나 `@NotNull` 로 걸러낼 수 있다.

<br/>

`enum` 으로 받으면 빈 문자열이 `null` 로 변환된다.

앞의 스프링 타입 컨버터 글에서 본 그 동작이다.

<br/>

## 여러 개를 고르게 하려면

```html
<select th:field="*{regions}" multiple>
```

<br/>

`multiple` 을 붙이면 여러 개를 고를 수 있다.

받는 쪽은 컬렉션이어야 한다.

```java
private List<String> regions;
```

<br/>

앞의 멀티 체크 박스 글에서 본 것과 같은 형태로 전송된다.

```java
regions=SEOUL&regions=BUSAN
```

<br/>

실무에서는 잘 안 쓴다.

`Ctrl` 을 누르고 골라야 한다는 걸 모르는 사용자가 많기 때문이다.

<br/>

여러 개를 고르게 할 거면 체크박스가 낫다.

<br/>

## 옵션이 많으면 select 도 불편하다

```java
시/군/구 목록 200 개
```

<br/>

스크롤이 길어져서 찾기가 어렵다.

<br/>

이럴 때는 두 단계로 나누거나 검색이 되는 입력으로 바꾼다.

```java
시/도 선택 -> 시/군/구 선택
```

<br/>

앞쪽을 고르면 뒤쪽 목록을 다시 받아와야 한다.

```javascript
fetch(`/api/districts?city=${city}`)
```

<br/>

앞의 Ajax 글에서 본 그 방식이다.

화면 전체를 다시 그리지 않고 목록만 바꾸는 것이다.

<br/>

## 서버 검증을 빠뜨리면 안 된다

```html
<option value="FAST">빠른 배송</option>
<option value="NORMAL">일반 배송</option>
```

<br/>

화면에는 두 개만 있지만, 요청은 다른 값으로 보낼 수 있다.

<br/>

앞의 조건부 if 글에서 본 그 얘기다.

`화면에서 고를 수 있는 것` 과 `서버가 받아들이는 것` 은 별개다.

<br/>

`enum` 으로 받으면 이게 자동으로 막힌다.

없는 값이면 변환에서 실패하기 때문이다.

<br/>

문자열로 받으면 검증을 직접 해야 한다.

```java
if (!deliveryCodes.containsKey(code)) {
    throw new ServiceException(ErrorCode.INVALID_DELIVERY_CODE);
}
```

<br/>

타입으로 막을 수 있는 것은 타입으로 막는 게 낫다.

검사를 빠뜨릴 여지가 없어지기 때문이다.
