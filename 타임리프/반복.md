## 반복

타임리프에서 반복은 `th:each` 를 사용한다. 


<br/>

## 반복 기능

```
<tr th:each="user : ${users}">
```

<br/>

반복시 오른쪽 컬렉션 ${users} 의 값을 하나씩 꺼내서 왼쪽 변수 user 에 담아서 태그를 반복 실행합니다.



```html
<h1>기본 테이블</h1>
<table border="1">
    <tr>
        <th>username</th>
        <th>age</th>
    </tr>
    <tr th:each="user : ${users}">
        <td th:text="${user.username}">username</td>
        <td th:text="${user.age}">0</td>
    </tr>
</table>
```

<br/><br/>

## 반복 상태 유지

`<tr th:each="user, userStat : ${users}">`

`user`는 우리가 알듯 정상 작동하고, `userStat`는 현재 동작하고 있는 상태를 알려주는 것이다.



<br/><br/>

## 반복 상태 유지 기능

`index` : 0부터 시작하는 값

`count` : 1부터 시작하는 값

`size` : 전체 사이즈

`even` , `odd` : 홀수, 짝수 여부( boolean )

`first` , `last` :처음, 마지막 여부( boolean )

`current` : 현재 객체

<br/>이런 느낌으로 사용하는 것이다.

```html
<tr th:each="user, userStat : ${users}">
   <td th:text="${userStat.count}">username</td>
   <td th:text="${user.username}">username</td>
   <td th:text="${user.age}">0</td>
	
   <td>
     index = <span th:text="${userStat.index}"></span>
     count = <span th:text="${userStat.count}"></span>
     size = <span th:text="${userStat.size}"></span>
   </td>
</tr>	
```

## 궁금증!

```java
th:each 를 어느 태그에 붙여야 하나
```

반복하고 싶은 태그 자체에 붙인다.

```html
<tr th:each="member : ${members}">
    <td th:text="${member.name}"></td>
</tr>
```

<br/>

`tr` 이 회원 수만큼 반복된다.

<br/>

바깥 `table` 에 붙이면 표가 여러 개 생긴다.

<br/>

## 상태 변수를 받을 수 있다

```html
<tr th:each="member, stat : ${members}">
    <td th:text="${stat.index}"></td>       <!-- 0 부터 -->
    <td th:text="${stat.count}"></td>       <!-- 1 부터 -->
</tr>
```

<br/>

들어 있는 것들이다.

```java
index    0 부터
count    1 부터
size     전체 개수
first    첫 번째인가
last     마지막인가
even     짝수 번째인가 (count 기준)
odd      홀수 번째인가
current  지금 원소
```

<br/>

`even` 과 `odd` 는 `count` 기준이라 첫 번째가 `odd` 다.

`index` 기준이면 첫 번째가 `even` 이었을 텐데 헷갈리기 쉽다.

<br/>

## 줄무늬를 넣을 때 쓴다

```html
<tr th:each="m, stat : ${members}"
    th:class="${stat.odd} ? 'odd-row' : 'even-row'">
```

<br/>

요즘은 CSS로 하는 게 낫다.

```css
tr:nth-child(odd) { background: #f5f5f5; }
```

<br/>

화면 꾸미기를 서버에서 계산할 이유가 없기 때문이다.

<br/>

## 상태 변수 이름을 생략할 수 있다

```html
<tr th:each="member : ${members}">
    <td th:text="${memberStat.count}"></td>
</tr>
```

<br/>

변수 이름 뒤에 `Stat` 를 붙인 이름이 자동으로 생긴다.

<br/>

명시하는 게 읽기 좋다. 자동으로 생기는 이름은 모르면 못 찾는다.

<br/>

## 반복할 수 있는 것들

```java
List, Set, 배열
Map            - Map.Entry 가 나온다
Iterable
Enumeration
```

<br/>

`Map` 을 돌리면 이렇게 쓴다.

```html
<tr th:each="entry : ${map}">
    <td th:text="${entry.key}"></td>
    <td th:text="${entry.value}"></td>
</tr>
```

<br/>

앞의 Map 정리 글에서 본 대로,

`HashMap` 은 순서가 정해져 있지 않으니 화면에 순서가 필요하면 `LinkedHashMap` 을 써야 한다.

<br/>

## null 이면 아무것도 안 그린다

```html
<tr th:each="m : ${members}">
```

<br/>

`members` 가 `null` 이면 예외가 아니라 그냥 0번 반복한다.

<br/>

편한데, `데이터가 없는 것` 과 `모델에 안 담은 것` 이 구분이 안 된다.

<br/>

화면이 비어 있을 때 원인을 찾기 어려워지는 것이다.

컨트롤러에서 빈 리스트라도 담아두는 게 낫다.

<br/>

## 목록이 비었을 때 안내 문구 넣기

```html
<tr th:each="m : ${members}">
    <td th:text="${m.name}"></td>
</tr>
<tr th:if="${#lists.isEmpty(members)}">
    <td colspan="3">등록된 회원이 없습니다</td>
</tr>
```

<br/>

`#lists.isEmpty` 는 `null` 도 `true` 로 본다.

<br/>

## 중첩 반복에서 조심할 것

```html
<div th:each="team : ${teams}">
    <span th:text="${team.name}"></span>
    <div th:each="member : ${team.members}">
        <span th:text="${member.name}"></span>
    </div>
</div>
```

<br/>

`team.members` 가 지연 로딩이면 여기서 쿼리가 나간다.

<br/>

앞의 N+1 문제 글에서 본 그 상황이다.

팀이 10개면 쿼리가 11번 도는 것이다.

<br/>

더 나쁜 것은 트랜잭션이 이미 끝나 있는 경우다.

```java
LazyInitializationException
```

<br/>

앞의 프록시 - 즉시 로딩과 지연 로딩 글에서 본 그 예외가

화면을 그리다가 터진다.

<br/>

응답이 이미 나가기 시작한 뒤라 오류 페이지도 제대로 안 나온다.

<br/>

그래서 화면에 넘길 때는 DTO로 바꿔서 넘기는 게 낫다.

앞의 API 방식(json), @ResponseBody 글에서 본 것과 같은 이유다.

`화면을 그리는 시점에는 DB 를 안 봐도 되게` 만들어두는 것이다.
