## 컨트롤러

```java
@Controller
@RequestMapping("/template")
public class TemplateController {

    @GetMapping("/layoutExtend")
    public String layoutExtend() {
        return "template/layoutExtend/layoutExtendMain";
    }
}
```

## html

### html 태그 부터 replace 해버리는 것이다. 그렇다면, 이 페이지를 통으로 교체가 되는 것이다.

### title 이랑 section 는 여기 페이지에 있는 해당 태그이다.

```html
<!DOCTYPE html>
<html th:replace="~{template/layoutExtend/layoutFile :: layout(~{::title}, ~{::section})}"
      xmlns:th="http://www.thymeleaf.org">
<head>
    <title>메인 페이지 타이틀</title>
</head>
<body>
<section>
    <p>메인 페이지 컨텐츠</p>
    <div>메인 페이지 포함 내용</div>
</section>
</body>
</html>
```


<br/><br/>

## html

title, content 이 두개가 넘어온 것이다.

content는 section이다.

```html
<!DOCTYPE html>
<html th:fragment="layout (title, content)" xmlns:th="http://www.thymeleaf.org">
<head>
    <title th:replace="${title}">레이아웃 타이틀</title>
</head>
<body>
<h1>레이아웃 H1</h1>
<div th:replace="${content}">
    <p>레이아웃 컨텐츠</p>
</div>
<footer>
    레이아웃 푸터
</footer>
</body>
</html>
```

## 궁금증!

```java
조각을 넣는 것과 레이아웃이 무엇이 다른가
```

방향이 반대다.

```java
조각    - 내 화면에 남의 것을 가져다 넣는다
레이아웃 - 큰 틀에 내 화면을 끼워 넣는다
```

<br/>

앞의 템플릿 조각 글에서 본 방식은 화면마다 이렇게 쓴다.

```html
<html>
<head>
    <div th:replace="~{common :: head}"></div>
</head>
<body>
    <div th:replace="~{common :: header}"></div>

    <h1>회원 목록</h1>

    <div th:replace="~{common :: footer}"></div>
</body>
</html>
```

<br/>

화면이 스무 개면 이 구조를 스무 번 적는다.

<br/>

`header` 위에 새 요소를 하나 추가하면 스무 파일을 고쳐야 한다.

<br/>

## 레이아웃 방식은 틀을 한 번만 적는다

```html
<!-- layout.html -->
<html th:fragment="layout(title, content)">
<head>
    <title th:replace="${title}">기본 제목</title>
    <link rel="stylesheet" href="/css/main.css">
</head>
<body>
    <header>공통 헤더</header>
    <div th:replace="${content}">본문 자리</div>
    <footer>공통 푸터</footer>
</body>
</html>
```

```html
<!-- members.html -->
<html th:replace="~{layout :: layout(~{::title}, ~{::section})}">
<head>
    <title>회원 목록</title>
</head>
<body>
    <section>
        <h1>회원 목록</h1>
    </section>
</body>
</html>
```

<br/>

`html` 태그 자체를 레이아웃으로 바꿔치기한다.

<br/>

`~{::title}` 은 `이 파일의 title 태그` 라는 뜻이다.

그것을 레이아웃의 `title` 자리에 넣는다.

<br/>

## 각 화면 파일이 그대로 열린다

```html
<!-- members.html 을 브라우저로 그냥 열면 -->
회원 목록
```

<br/>

`th:replace` 를 브라우저가 무시하니 원래 내용이 보인다.

<br/>

앞의 타임리프 소개 글에서 본 내추럴 템플릿이 레이아웃에서도 지켜지는 것이다.

<br/>

JSP의 `<jsp:include>` 방식은 이게 안 됐다.

<br/>

## head 를 합치는 방법

화면마다 다른 CSS나 스크립트가 필요한 경우가 있다.

```html
<!-- layout.html -->
<head th:fragment="common_header(title, links)">
    <title th:replace="${title}">기본</title>
    <link rel="stylesheet" href="/css/main.css">       <!-- 공통 -->
    <th:block th:replace="${links}" />                 <!-- 화면별 -->
</head>
```

```html
<!-- members.html -->
<head th:replace="~{layout :: common_header(~{::title}, ~{::link})}">
    <title>회원 목록</title>
    <link rel="stylesheet" href="/css/members.css">
</head>
```

<br/>

`~{::link}` 는 `이 파일의 link 태그 전부` 다.

<br/>

공통 CSS 뒤에 붙으니 화면별 스타일이 나중에 적용된다.

CSS의 우선순위 규칙과 맞물리게 순서를 잡은 것이다.

<br/>

## 라이브러리를 쓸 수도 있다

```java
thymeleaf-layout-dialect
```

<br/>

이걸 쓰면 문법이 더 짧아진다.

```html
<html layout:decorate="~{layout}">
<body>
    <section layout:fragment="content">
        <h1>회원 목록</h1>
    </section>
</body>
</html>
```

<br/>

`~{::section}` 같은 표현식을 안 써도 된다.

<br/>

스프링 부트에 기본으로 안 들어 있어서 의존관계를 추가해야 한다.

## 어디까지 나눌 것인가

```java
레이아웃  - 전체 뼈대. 한두 개
조각      - 재사용 단위. 헤더, 푸터, 카드, 페이지네이션
```

<br/>

레이아웃이 여러 개가 되면 관리가 어려워진다.

```java
layout.html          - 로그인한 사용자용
layout-guest.html    - 비로그인용
layout-admin.html    - 어드민
```

<br/>

이 정도가 한계다.

<br/>

더 나뉘어야 할 것 같으면 조각으로 처리하는 게 낫다.

```html
<div th:replace="${isAdmin} ? ~{common :: adminMenu} : ~{common :: userMenu}"></div>
```

<br/>

앞의 템플릿 조각 글에서 본 조건부 조각이다.

<br/>

레이아웃을 늘리면 공통 부분이 다시 복제되기 시작한다.

처음에 이걸 없애려고 레이아웃을 만든 것이니 본말이 뒤집히는 셈이다.
