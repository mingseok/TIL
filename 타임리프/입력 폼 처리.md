## 입력 폼 처리


<br/>

## `th:object` : 커맨드 객체를 지정한다.

- `*{...}` : 선택 변수 식이라고 한다. 

- `th:object` 에서 선택한 객체에 접근한다.

- `th:field` : HTML 태그의 id , name , value , 체크 박스 속성을 자동으로 처리해준다.

<br/><br/>

## 렌더링 전

```html
<input type="text" th:field="*{itemName}"/>
```

## 렌더링 후

```html
<input type="text" id="itemName" name="itemName" th:value="*{itemName}"/>
```

<br/><br/>


## 이렇게 사용하는 이유

그 이유는 수정폼 쪽에서 사용할 때 편하다는 것이다. 

사진 처럼 id, name, value 모두 생략 가능하게 되는 것이다.

## `th:object` 를 적용

먼저 컨트롤러에서 해당 긴 껍대기를 넘겨주어야 한다. 

등록 폼이기 때문에 데이터가 비어있는 빈 오브젝트를 만들어서 뷰에 전달하자.

```java
@GetMapping("/add")
public String addForm(Model model) {
    model.addAttribute("item", new Item());
    return "form/addForm";
}
```

<br/>

<br/>

### 이렇게 하면 좋은점은 프로그램을 실행 시켰을때 오류가 발생 했다는 것을 한 눈에 알 수 있다.

```html
<form action="item.html" th:action th:object="${item}" method="post">
   <div>
       <label for="itemName">상품명</label>
       <input type="text" id="itemName" th:field="*{itemName}"
        class="form-control" placeholder="이름을 입력하세요">
   </div>
   <div>
       <label for="price">가격</label>
       <input type="text" id="price" th:field="*{price}" 
       class="form-control" placeholder="가격을 입력하세요">
   </div>
   <div>
       <label for="quantity">수량</label>
       <input type="text" id="quantity" th:field="*{quantity}" 
       class="form-control" placeholder="수량을 입력하세요">
   </div>
```

<br/>

`th:object="${item}"` : 여기서 사용할 객체를 지정한다. 

선택 변수 식 `*{...}` 을 적용할 수 있다.

<br/>


## `th:field="*{itemName}”`

- `{itemName}` 는 선택 변수 식을 사용했는데, -> `${item.itemName}` 과 같다.
    
    앞서 `th:object` 로 `item` 을 선택했기 때문에 선택 변수 식을 적용할 수 있다.
    
- `th:field` 는 id , name , value 속성을 모두 자동으로 만들어준다.
    - id : `th:field` 에서 지정한 변수 이름과 같다. `id="itemName”`

    - name : `th:field` 에서 지정한 변수 이름과 같다. `name="itemName”`
    - value : `th:field` 에서 지정한 변수의 값을 사용한다. `value="”`
    - 체크 박스가 있을 경우도 추가 해준다.

<br/><br/>

## 렌더링 전

```html
<input type="text" id="itemName" th:field="*{itemName}" class="form-control" placeholder="이름을 입력하세요">
```



## 렌더링 후

```html
<input type="text" id="itemName" class="form-control" placeholder="이름을 입력하세요" name="itemName" value="">
```

수정 폼에도 이렇게 사용 할 수 있다.

## 궁금증!

```java
th:field 하나가 정확히 무엇을 만드나
```

세 가지를 한 번에 만든다.

```html
<input type="text" th:field="*{itemName}">
```

```html
<input type="text" id="itemName" name="itemName" value="기존값">
```

<br/>

```java
id     - 라벨 연결용
name   - 서버로 보낼 때의 키
value  - 지금 값
```

<br/>

앞의 @PostMapping(), form태그 글에서 본 대로

`name` 이 없으면 서버로 값이 안 간다.

`id` 만 적고 `name` 을 빠뜨리는 실수를 원천적으로 막아주는 것이다.

<br/>

## value 를 채워주는 게 실무에서 크다

검증에 실패해서 폼으로 다시 갈 때 필요하다.

```java
@PostMapping("/items/new")
public String save(@Validated @ModelAttribute ItemForm form, BindingResult bindingResult) {
    if (bindingResult.hasErrors()) {
        return "items/form";           // 리다이렉트가 아니다
    }
}
```

<br/>

앞의 입력 화면, 출력 화면 흐름 글에서 본 그 흐름이다.

<br/>

`th:field` 가 없으면 사용자가 적었던 값이 전부 사라진다.

긴 폼을 다시 채워야 하니 화가 나는 것이다.

<br/>

## 타입이 안 맞을 때도 원래 입력이 남는다

```java
가격 칸에 "천원" 이라고 적었다
```

<br/>

`Integer` 필드라 변환에 실패한다.

<br/>

앞의 HTTP 요청 파라미터 - @ModelAttribute 글에서 본 대로,

`@ModelAttribute` 는 `BindingResult` 에 `typeMismatch` 를 담고 컨트롤러까지 온다.

<br/>

이때 필드 값은 `null` 인데, 화면에는 `천원` 이 다시 보여야 한다.

<br/>

`BindingResult` 가 원래 입력 문자열을 따로 들고 있어서 가능한 것이다.

`th:field` 는 필드 값이 아니라 이걸 우선해서 쓴다.

<br/>

```java
FieldError 에 rejectedValue 라는 필드가 있다
```

<br/>

`@RequestBody` 로는 이게 안 된다.

객체를 아예 못 만들었으니 남길 것도 없기 때문이다.

<br/>

## th:object 가 있어야 한다

```html
<form th:object="${itemForm}" method="post">
    <input type="text" th:field="*{itemName}">
</form>
```

<br/>

앞의 선택 변수 표현식 글에서 본 그 짝이다.

<br/>

`th:object` 없이 `th:field="${itemForm.itemName}"` 으로 쓸 수도 있는데,

이러면 `name` 이 `itemForm.itemName` 이 되어서 서버가 못 받는다.

<br/>

## GET 요청에도 빈 객체를 담아야 한다

```java
@GetMapping("/items/new")
public String form(@ModelAttribute ItemForm itemForm) {
    return "items/form";
}
```

<br/>

`@ModelAttribute` 를 안 붙이면 이 오류가 난다.

```java
Neither BindingResult nor plain target object for bean name 'itemForm'
available as request attribute
```

<br/>

`th:object` 가 찾을 대상이 없기 때문이다.

<br/>

`model.addAttribute("itemForm", new ItemForm())` 을 써도 되는데,

`@ModelAttribute` 를 파라미터에 붙이면 한 줄이 준다.

<br/>

## 오류 표시와 이어 쓴다

```html
<input type="text" th:field="*{price}" th:errorclass="field-error">
<div class="field-error" th:errors="*{price}">오류 메시지</div>
```

<br/>

```java
th:errorclass - 오류가 있을 때만 class 를 추가한다
th:errors     - 오류 메시지를 출력한다. 오류가 없으면 태그 자체가 없다
```

<br/>

`th:errors` 는 여러 오류가 있으면 `<br/>` 로 이어서 출력한다.

<br/>

전체 오류는 따로 표시한다.

```html
<div th:if="${#fields.hasGlobalErrors()}">
    <p th:each="err : ${#fields.globalErrors()}" th:text="${err}"></p>
</div>
```

<br/>

앞의 Validation 글에서 본 `ObjectError` 가 이쪽으로 나온다.

`가격과 수량의 합이 만원을 넘어야 한다` 같은 필드 두 개에 걸친 규칙이다.

<br/>

## 폼 객체를 따로 두는 이유

```java
Item          - 엔티티
ItemForm      - 화면 입력용
ItemResponse  - 화면 출력용
```

<br/>

클래스가 늘어나서 귀찮은데 이유가 있다.

<br/>

엔티티를 폼으로 쓰면 화면 검증 규칙이 엔티티에 붙는다.

```java
@Entity
public class Item {
    @NotBlank                    // 등록 화면의 규칙이 엔티티에 들어와 있다
    private String itemName;
}
```

<br/>

등록할 때는 필수인데 수정할 때는 아닌 경우가 생기면 방법이 없어진다.

<br/>

그리고 화면에만 있는 필드도 생긴다.

```java
비밀번호 확인
약관 동의 여부
```

<br/>

엔티티에 저장할 필요가 없는 것들이다.

<br/>

앞의 API 방식(json), @ResponseBody 글에서 본 것과 같은 이유로

입력용 객체도 따로 두는 것이다.
