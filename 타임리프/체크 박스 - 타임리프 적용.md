## 타임리프가 제공하는 기능을 사용

이렇게 작성하면 해결 된다.


```html
--변경 전 코드--
<div>판매 여부</div>
<div>
  <div class="form-check">
   <input type="checkbox" id="open" name="open" class="form-check-input">
   <input type="hidden" name="_open" value="on">
  </div>
</div>


--변경 후 코드--
<div>판매 여부</div>
  <div>
     <div class="form-check">
     <input type="checkbox" id="open" th:field="*{open}" class="form-checkinput">
  </div>
</div>
```

<br/>

밑에 나온 것들을 타임리프가 자동으로 생성해주는 것이다.

```
type="hidden" id="open" name="_open" value="on"
```





<br/><br/>

## 타임리프의 체크 확인

```
checked="checked"
```

체크 박스에서 `판매 여부`를 선택해서 저장하면, 조회시에 `checked` 속성이 추가 된다.


타임리프는 값이 true이면 자동으로 checked를 넣고, 값이 false면 checked를 넣지 않는 것이다.


<br/>


다시 말해, 타임리프의 `th:field` 를 사용하면, 값이 `true`인 경우 체크를 자동으로 처리해준다.

## 궁금증!

```java
직접 쓴 것과 th:field 를 쓴 것의 차이
```

직접 쓰면 이렇게 된다.

```html
<input type="checkbox" name="open" value="true"
       th:checked="${item.open}">
<input type="hidden" name="_open" value="on">
```

<br/>

`th:field` 를 쓰면 이 네 가지가 한 줄이 된다.

```html
<input type="checkbox" th:field="*{open}">
```

<br/>

```java
id 를 필드명으로
name 을 필드명으로
value="true"
지금 값이 true 면 checked
숨은 필드 _open
```

<br/>

다섯 가지다.

<br/>

## 실수할 여지가 사라진다

직접 쓸 때 자주 틀리는 것들이다.

```java
name 을 안 적는다              -> 서버로 값이 안 간다
value 를 안 적는다             -> "on" 이 간다
숨은 필드를 빠뜨린다            -> 체크를 풀어도 저장이 안 된다
숨은 필드 이름의 밑줄을 빠뜨린다 -> 같은 문제
th:checked 대신 checked 를 쓴다 -> 항상 체크된다
```

<br/>

앞의 체크 박스 - 단일 글에서 본 것들이 전부 여기 걸린다.

<br/>

`value` 를 안 적으면 브라우저가 `on` 을 보낸다는 게 특히 함정이다.

```java
open=on
```

<br/>

`Boolean` 으로 받으면 변환에 실패한다.

<br/>

앞의 스프링 타입 컨버터 글에서 본 `ConversionService` 가

`"on"` 을 `true` 로 바꿔주기는 해서 우연히 동작하는 경우도 있다.

우연히 되는 것이 더 나쁘다.

## 만들어진 HTML 을 확인하는 습관

```html
<input type="checkbox" th:field="*{open}">
```

<br/>

이게 실제로 무엇이 됐는지는 개발자 도구로 보면 된다.

<br/>

`name` 이 예상과 다르면 서버가 못 받는다.

```html
<form th:object="${itemForm}">
    <input th:field="${itemForm.open}">      <!-- name="itemForm.open" 이 된다 -->
```

<br/>

`*{...}` 를 써야 `name="open"` 이 나온다.

<br/>

앞의 선택 변수 표현식 글에서 본 그 차이가 여기서 결과로 드러난다.

<br/>

## 조회 화면에서는 disabled 를 붙인다

```html
<input type="checkbox" th:field="*{open}" disabled>
```

<br/>

`disabled` 인 입력은 값이 서버로 안 간다.

<br/>

읽기 전용으로 보여주려다 저장할 때 값이 사라지는 문제가 생긴다.

<br/>

값도 보내야 하면 `readonly` 를 쓰는데, 체크박스에는 `readonly` 가 안 먹는다.

<br/>

그래서 이렇게 한다.

```html
<input type="checkbox" th:checked="*{open}" disabled>
<input type="hidden" th:field="*{open}">
```

<br/>

보이는 것은 비활성 체크박스, 실제로 보내는 것은 숨은 필드다.

<br/>

## 체크박스를 여러 개 만들 때

```html
<div th:each="region : ${regions}">
    <input type="checkbox" th:field="*{regions}" th:value="${region.key}">
    <label th:for="${#ids.prev('regions')}" th:text="${region.value}"></label>
</div>
```

<br/>

앞의 멀티 체크 박스 글에서 다루는 방식이다.

<br/>

`#ids.prev` 가 나오는 이유가 있다.

<br/>

`th:field` 가 `id` 를 자동으로 만드는데, 반복하면 같은 `id` 가 여러 개 생긴다.

그래서 타임리프가 뒤에 번호를 붙인다.

```html
id="regions1"
id="regions2"
```

<br/>

`label` 의 `for` 는 그 번호를 알아야 하는데,

`#ids.prev('regions')` 가 방금 만든 `id` 를 돌려주는 것이다.

<br/>

`id` 가 중복되면 라벨을 눌러도 엉뚱한 것이 체크된다.

앞의 CSS 선택자 글에서 본 대로 `id` 는 문서에서 유일해야 하기 때문이다.
