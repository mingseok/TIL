## 라디오 버튼

라디오 버튼은 여러 선택지 중에 하나를 선택할 때 사용할 수 있다. 

이번시간에는 라디오 버튼을 자바 ENUM을 활용해서 개발해보자.

<br/>

## 상품 종류

- 도서, 식품, 기타
- 라디오 버튼으로 하나만 선택할 수 있다.

<br/>

## 컨트롤러 추가.

```java
@ModelAttribute("itemTypes")
public ItemType[] itemTypes() {

     // enum에 있는 변수들을 배열로 넘겨 준다.
     ItemType[] values = ItemType.values();
     return values;
}
```

itemTypes 를 등록 폼, 조회, 수정 폼에서 모두 사용하므로 @ModelAttribute 의 특별한 사용법을 적용하자.

ItemType.values() 를 사용하면 해당 ENUM의 모든 정보를 배열로 반환한다. 

예) [BOOK, FOOD, ETC]


<br/><br/>

## html 파일

```html
<!-- radio button -->
<div>
   <div>상품 종류</div>
   <div th:each="type : ${itemTypes}" class="form-check form-check-inline">
     <input type="radio" th:field="*{itemType}" th:value="${type.name()}" class="form-check-input">
     <label th:for="${#ids.prev('itemType')}" th:text="${type.description}" class="form-check-label">
      BOOK
     </label>
   </div>
</div>
```



체크 박스는 수정시 체크를 해제하면 아무 값도 넘어가지 않기 때문에, 

별도의 히든 필드로 이런 문제를 해결했다. 

<br/>라디오 버튼은 이미 선택이 되어 있다면, 수정시에도 항상 하나를 선택하도록 되어 

있으므로 체크 박스와 달리 별도의 히든 필드를 사용할 필요가 없다.


<br/><br/>

## 주의:

item.html 에는 `th:object` 를 사용하지 않았기 때문에 `th:field` 부분에 `${item.itemType}` 으로 적어주어야 한다. 

`disabled` 를 사용해서 상품 상세에서는 라디오 버튼이 선택되지 않도록 했다


```html
<!-- radio button -->
<div>
   <div>상품 종류</div>
    <div class="form-check form-check-inline">
	<input type="radio" value="BOOK" class="form-check-input" id="itemType1" name="itemType">
	<label for="itemType1" class="form-check-label">도서</label>
    </div>

    <div class="form-check form-check-inline">
	<input type="radio" value="FOOD" class="form-check-input" id="itemType2" name="itemType" checked="checked">
        <label for="itemType2" class="form-check-label">식품</label>
    </div>

    <div class="form-check form-check-inline">
	<input type="radio" value="ETC" class="form-check-input" id="itemType3" name="itemType">
	<label for="itemType3" class="form-check-label">기타</label>
    </div>
</div>
```

## 궁금증!

```java
라디오 버튼에는 왜 숨은 필드가 안 생기나
```

체크를 풀 수가 없기 때문이다.

```html
<input type="radio" name="grade" value="GOLD">
<input type="radio" name="grade" value="SILVER">
```

<br/>

하나를 고르면 다른 것이 풀린다.

그런데 마지막 하나를 다시 눌러도 안 풀린다.

<br/>

```java
체크박스  - 켰다 껐다 된다 -> "안 보냄" 상태가 생긴다 -> 숨은 필드가 필요하다
라디오    - 한 번 고르면 못 푼다 -> 수정할 때 항상 값이 온다
```

<br/>

앞의 체크 박스 - 단일 글에서 본 그 문제가 라디오에는 없는 것이다.

<br/>

## 처음 등록할 때는 안 올 수 있다

아무것도 안 고르고 제출하면 값이 안 간다.

<br/>

그래서 필수면 검증을 걸어야 한다.

```java
@NotNull
private Grade grade;
```

<br/>

또는 하나를 기본으로 체크해두는 방법도 있다.

```html
<input type="radio" th:field="*{grade}" value="BRONZE" checked>
```

<br/>

기본값을 두면 `사용자가 고른 것` 과 `기본값이 그냥 남은 것` 이 구분이 안 된다.

의미가 있는 선택이면 기본값을 안 두는 게 낫다.

<br/>

## name 이 같아야 하나만 선택된다

```html
<input type="radio" name="grade" value="GOLD">
<input type="radio" name="grade" value="SILVER">
```

<br/>

`name` 이 다르면 각자 따로 동작해서 둘 다 켜진다.

<br/>

`th:field` 를 쓰면 `name` 이 자동으로 같아진다.

```html
<input type="radio" th:field="*{grade}" th:value="${grade}">
```

<br/>

같은 필드를 가리키니 `name` 도 같아지는 것이다.

<br/>

## enum 으로 목록을 만들 때

```java
@ModelAttribute("grades")
public Grade[] grades() {
    return Grade.values();
}
```

```html
<div th:each="grade : ${grades}">
    <input type="radio" th:field="*{grade}" th:value="${grade.name()}">
    <label th:for="${#ids.prev('grade')}" th:text="${grade.label}"></label>
</div>
```

<br/>

`th:value` 에 `${grade}` 를 그대로 넣어도 된다.

`toString()` 이 상수 이름을 돌려주기 때문이다.

<br/>

앞의 enum 은 어떻게 동작할까 글에서 본 그 동작이다.

<br/>

다만 `toString()` 을 오버라이딩해뒀으면 값이 달라진다.

```java
public enum Grade {
    GOLD("골드");

    @Override
    public String toString() { return label; }     // "골드" 가 나온다
}
```

<br/>

그러면 서버가 못 받는다. `valueOf("골드")` 는 실패하기 때문이다.

<br/>

그래서 `name()` 을 명시하는 게 안전하다.

`name()` 은 `final` 이라 오버라이딩이 안 된다.

<br/>

## 화면에 보이는 이름과 보내는 값을 나눈다

```html
<input type="radio" th:value="${grade.name()}">     <!-- GOLD -->
<label th:text="${grade.label}">골드</label>         <!-- 골드 -->
```

<br/>

값은 영문 상수, 표시는 한글이다.

<br/>

앞의 뷰 리졸버를 왜 사용하는가 글에서 본 것과 같은 발상이다.

`부르는 이름` 과 `보여주는 것` 을 나눠두면 표시를 바꿔도 데이터가 안 바뀐다.

<br/>

한글을 값으로 보내면 URL 인코딩도 신경 써야 하고,

문구를 바꿀 때 DB에 쌓인 값까지 고쳐야 한다.

<br/>

## 라디오와 셀렉트를 어떻게 고르나

```java
선택지 2~5 개   -> 라디오. 한눈에 다 보인다
선택지 6 개 이상 -> 셀렉트. 화면을 덜 차지한다
선택지가 아주 많음 -> 검색이 되는 입력으로
```

<br/>

라디오는 전부 보이니 무엇이 있는지 파악하기 쉽다.

셀렉트는 눌러야 보여서 한 단계가 더 걸린다.

<br/>

앞의 셀렉트 박스 글에서 본 대로,

동작 방식은 거의 같고 화면에서 어떻게 보이느냐만 다른 것이다.
