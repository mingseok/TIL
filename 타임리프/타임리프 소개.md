## 타임리프 사용 선언

```
<html xmlns:th="http://www.thymeleaf.org">
```


<br/>


## 타임리프 핵심

핵심은 th:xxx 가 붙은 부분은 서버사이드에서 렌더링 되고, 기존 것을 대체한다. 
- th:xxx 이 없으면 기존
html의 xxx 속성이 그대로 사용된다.


HTML을 파일로 직접 열었을 때, th:xxx 가 있어도 웹 브라우저는 th: 속성을 알지 못하므로 무시한다.

따라서 HTML을 파일 보기를 유지하면서 템플릿 기능도 할 수 있다.

## 궁금증!

```java
내추럴 템플릿이라는 게 무슨 뜻인가
```

서버 없이 브라우저로 열어도 화면이 보인다는 뜻이다.

```html
<span th:text="${member.name}">홍길동</span>
```

<br/>

```java
파일을 그냥 열면    ->  홍길동      (안에 적어둔 글자가 보인다)
서버가 그리면       ->  김민석      (th:text 가 안을 바꾼다)
```

<br/>

`th:text` 는 브라우저가 모르는 속성이라 무시하고,

태그 안의 내용만 보여주기 때문이다.

<br/>

## JSP 와 비교하면 확실하다

```html
<span><%= member.getName() %></span>
```

<br/>

이걸 브라우저로 열면 `<%= member.getName() %>` 라는 글자가 그대로 보인다.

앞의 JSP, 서블릿과 JSP의 한계 글에서 본 그 문제다.

<br/>

디자이너가 화면을 확인하려면 서버를 띄워야 하고,

서버를 띄우면 데이터도 있어야 한다.

<br/>

## 대신 자바 코드를 못 쓴다

```html
<%
    List<Member> members = repository.findAll();     // JSP 에서는 됐다
%>
```

<br/>

타임리프에는 이런 게 없다.

표현식으로 값을 꺼내는 것만 된다.

<br/>

일부러 막아둔 것이다.

앞의 JSP 글에서 본 대로 `할 수 있게 열어두면 하게 되기` 때문이다.

<br/>

## 그래서 화면 로직을 어디에 둘 것인가

```html
<span th:text="${member.age >= 20 ? '성인' : '미성년자'}"></span>
```

<br/>

이 정도는 화면에서 해도 된다.

<br/>

그런데 이런 게 늘어나면 문제가 된다.

```html
<span th:text="${order.amount > 50000 and member.grade == 'GOLD'
                 ? order.amount * 0.9 : order.amount}"></span>
```

<br/>

할인 규칙이 화면에 들어와 있다.

<br/>

앞의 SOLID 글에서 본 대로,

`할인 규칙이 바뀌면 화면 파일을 고쳐야 하는` 상태가 된 것이다.

<br/>

계산은 컨트롤러나 도메인에서 끝내고, 화면에는 결과만 넘기는 게 낫다.

```java
model.addAttribute("displayAmount", order.calculateFinalAmount(member));
```

<br/>

## 타임리프는 느리다는 얘기

JSP보다 느리다.

JSP는 서블릿으로 컴파일되는데, 타임리프는 실행할 때 파싱하기 때문이다.

<br/>

앞의 JSP 글에서 본 그 변환 과정이 타임리프에는 없다.

<br/>

3.0부터 많이 개선됐다.

전체를 DOM으로 올리지 않고 이벤트 방식으로 흘려보내게 바뀌었다.

<br/>

그래도 개발할 때는 캐시를 꺼야 해서 느리게 느껴진다.

```java
spring.thymeleaf.cache=false
```

<br/>

운영에서는 기본이 `true` 라 파싱 결과를 재사용한다.

<br/>

## 지금은 어떤 자리인가

프론트를 따로 만드는 곳이 늘면서 서버 템플릿을 안 쓰는 경우가 많아졌다.

<br/>

앞의 HTML, HTTP API, CSR, SSR 글에서 본 그 흐름이다.

<br/>

그래도 이런 자리에는 여전히 잘 맞는다.

```java
어드민 화면        - 검색 유입이 필요 없고, 빨리 만드는 게 중요하다
메일 본문          - HTML 을 서버에서 만들어야 한다
간단한 소개 페이지  - 프론트를 따로 둘 이유가 없다
```

<br/>

메일 템플릿에 쓰는 경우가 의외로 많다.

`뷰 이름` 대신 문자열로 결과를 받는 방법이 있기 때문이다.

```java
String html = templateEngine.process("mail/welcome", context);
```

<br/>

화면을 그리는 것과 같은 방식으로 메일 본문을 만들 수 있는 것이다.
