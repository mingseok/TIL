## 멀티 체크 박스

체크 박스를 멀티로 사용해서, 하나 이상을 체크할 수 있도록 해보자.

<br/>

## 등록 지역

- 서울, 부산, 제주

- 체크 박스로 다중 선택할 수 있다.

<br/>


## html 코드

- `th:field="*{regions}"` 의 `*{ … }`  부분은 `${item.regions}` 가 되는 것이다.

   - 위의 form 태그의 `th:object="${item}"` 객체에 의해 넘어 가는 것이다.


- `th:each="region : ${regions}"` 는 -> 컨트롤러에 있는 @ModelAttribute("regions") 를 말하는 것이다.

```html
<form action="item.html" th:action th:object="${item}" method="post">

<!-- multi checkbox -->
<div>
   <div>등록 지역</div>
   <div th:each="region : ${regions}" class="form-check form-check-inline">
      <input type="checkbox" th:field="*{regions}" 
             th:value="${region.key}" class="form-check-input">
      <label th:for="${#ids.prev('regions')}" th:text="${region.value}" class="form-check-label">서울</label>
   </div>
</div>
```
하지만, th:field="*{regions}" 를 -> th:field="${item.regions}" 으로 해야 동작이 될것이다. 

왜냐면? -> 현재 페이지에서는 th:object가 없었기 때문이다.


<br/>

## `th:value="${region.key}"` 설명

부분은 키 값을 가져와 뿌리는 것이다.

value=SEOUL

value=BUSAN

value=JEJU

<br/>

그렇게 하여 실질적으로 저장 되는 곳은 여기에 List 형식으로 저장 되는 것이다. 

서울, 부산 체크 하면 서울, 부산이 저장 되는 것이다.




```java
public class Item {

   // ... 생략

   private List<String> regions; //등록 지역
}
```

<br/><br/>


## 위 HTML 코드의 `th:for="${#ids.prev('regions')}"` 설명.

label 태그는 선택되는 부분의 id가 뭔지 알아야 되는 것이다. 

그래야 해당 선택 하는 것만 불이 들어 오는 것이다.



(부산을 선택하면 부산만 체크 되야 된다는 것) 

<br/>

### 그런데 현재 id가 `th:field` 를 통해 아이디가 자동 생성 되는 것이다.

`id=”regions1”`

`id=”regions2”`

`id=”regions3”`

이렇게 생성이 되어 있는 것이다.


<br/><br/>

## 그리하여 타임리프는 `#ids` 라는 것을 지원 해준다.

자동으로 생성되는 id를 타임리프가 알아서 연결 해주는 것이다.

`th:field`를 통해 자동으로 생성되는 id를 가져와서 사용하게 되는 것이다.

```
th:field="*{regions}"
th:for="${#ids.prev('regions')}"

위 코드 설명)
field에 사용된 이름인 regions가
ids.prev('regions') 사용되게 된 것이다.
```

## each로 체크박스가 반복 생성된 결과 - id 뒤에 숫자가 추가

```
<input type="checkbox" value="SEOUL" class="form-check-input" id="regions1" name="regions">

<input type="checkbox" value="BUSAN" class="form-check-input" id="regions2" name="regions">

<input type="checkbox" value="JEJU" class="form-check-input" id="regions3" name="regions">
```

HTML의 id 가 타임리프에 의해 동적으로 만들어지기 때문에으로 `label` 의

대상이 되는 id 값을 임의로 지정하는 것은 곤란하다. 

<br/>

타임리프는 `ids.prev(...)` , `ids.next(...)` 을 제공해서 동적으로 생성되는 id 값을 사용할 수 있도록 한다.

<br/><br/>

## 그리하여 결과를 보면 이렇다.

```html

   <div class="form-check form-check-inline">

   </div>

<!-- -->
```

`<label for="id 값">`에 지정된 id 가 `checkbox` 에서 동적으로 

생성된 regions1 , regions2 , regions3 에 맞추어 순서대로 입력된 것을 확인할 수 있다

## 궁금증!

```java
체크박스 여러 개를 어떻게 하나로 받나
```

`name` 을 같게 하면 배열로 온다.

```html
<input type="checkbox" name="regions" value="SEOUL">
<input type="checkbox" name="regions" value="BUSAN">
<input type="checkbox" name="regions" value="DAEGU">
```

<br/>

서울과 부산을 고르면 이렇게 간다.

```java
regions=SEOUL&regions=BUSAN
```

<br/>

앞의 HttpServletRequest, 쿼리 파라미터 조회 메서드들 글에서 본 대로,

같은 키가 여러 번 오는 형태다.

<br/>

받는 쪽은 컬렉션으로 선언한다.

```java
private List<String> regions;
```

<br/>

`getParameter` 로는 첫 번째만 나온다.

`getParameterValues` 를 써야 전부 나오는데, `@ModelAttribute` 가 알아서 처리해준다.

## 하나도 안 고르면 null 이다

앞의 체크 박스 - 단일 글에서 본 그 문제가 여기도 있다.

<br/>

`th:field` 를 쓰면 숨은 필드가 하나 생겨서 빈 리스트로 들어온다.

```html
<input type="hidden" name="_regions" value="on">
```

<br/>

그래서 `null` 체크를 안 해도 된다.

<br/>

직접 쓰면 `null` 이 와서 반복문에서 터진다.

<br/>

## th:field 가 checked 를 알아서 붙인다

```html
<input type="checkbox" th:field="*{regions}" th:value="${region.key}">
```

<br/>

`regions` 리스트 안에 이 `value` 가 있으면 `checked` 를 붙인다.

<br/>

직접 하려면 이렇게 써야 한다.

```html
th:checked="${#lists.contains(item.regions, region.key)}"
```

<br/>

수정 화면에서 기존에 고른 것을 표시하는 데 필요한 처리다.

<br/>

## id 중복 문제

```html
<div th:each="region : ${regions}">
    <input type="checkbox" th:field="*{regions}" th:value="${region.key}">
    <label th:for="${#ids.prev('regions')}" th:text="${region.value}"></label>
</div>
```

<br/>

`th:field` 가 만드는 `id` 에 번호가 붙는다.

```html
<input id="regions1" name="regions" value="SEOUL">
<label for="regions1">서울</label>
<input id="regions2" name="regions" value="BUSAN">
<label for="regions2">부산</label>
```

<br/>

`#ids.prev` 가 방금 만든 번호를 돌려준다.

<br/>

`label` 이 `input` 앞에 오면 `#ids.next` 를 쓴다.

아직 안 만들어진 것을 미리 계산해서 알려주는 것이다.

<br/>

`label` 을 붙이는 이유는 글자를 눌러도 체크되게 하려는 것이다.

체크박스는 작아서 누르기 불편하다.

<br/>

`label` 로 감싸는 방법도 있다.

```html
<label>
    <input type="checkbox" th:field="*{regions}" th:value="${region.key}">
    <span th:text="${region.value}"></span>
</label>
```

<br/>

이러면 `for` 와 `id` 를 안 맞춰도 된다.

<br/>

## 선택 목록을 어디서 가져오나

```java
@ModelAttribute("regions")
public Map<String, String> regions() {
    Map<String, String> regions = new LinkedHashMap<>();
    regions.put("SEOUL", "서울");
    regions.put("BUSAN", "부산");
    return regions;
}
```

<br/>

앞의 특별한 @ModelAttribute 사용법 글에서 본 방식이다.

이 컨트롤러의 모든 요청에서 미리 담긴다.

<br/>

`LinkedHashMap` 을 쓴 것은 순서 때문이다.

앞의 Map 정리 글에서 본 대로 `HashMap` 은 순서가 정해져 있지 않다.

<br/>

지역 목록이 매번 바뀌는 순서로 나오면 사용자가 헷갈린다.

<br/>

## enum 으로 두는 게 낫다

```java
public enum Region {
    SEOUL("서울"), BUSAN("부산"), DAEGU("대구");

    private final String label;
}
```

```java
@ModelAttribute("regions")
public Region[] regions() {
    return Region.values();
}
```

<br/>

앞의 enum 은 어떻게 동작할까 글에서 본 대로,

`values()` 는 선언 순서대로 돌려주니 순서가 보장된다.

<br/>

그리고 없는 값이 들어오면 변환에서 걸린다.

<br/>

문자열로 두면 오타가 조용히 넘어간다.

```java
regions=SEOUL
regions=SEOL      <- 오타. 문자열이면 그냥 저장된다
```

<br/>

앞의 스프링 타입 컨버터 글에서 본 대로

`enum` 은 변환에 실패하면서 `400` 이 나가니 여기서 걸리는 것이다.
