## 선택 변수 표현식


### 생략할 수 있다.

```
th:field="${item.open} -> th:field="*{open}" 으로 생략할 수 있다.
```

<br/>

### 전체 코드 보기.

```html
<form action="item.html" th:action th:object="${item}" method="post">
        <!-- single checkbox -->
        <div>판매 여부</div>
        <div>
            <div class="form-check">
                <input type="checkbox" id="open" th:field="*{open}" name="open" class="form-check-input">

                <!--히든 필드 추가-->
                <input type="hidden" name="_open" value="on">
                <label for="open" class="form-check-label">판매 오픈</label>
            </div>
        </div>
</form>
```

<br/><br/>


## 이렇게 생략 가능한 이유는?

맨위 `th:object="${item}"` 라고 지정 해줬기 때문에 타임리프가 알아서 렌더링 해주는 것이다.

## 궁금증!

```java
th:object 를 쓰면 무엇이 달라지나
```

반복되는 앞부분을 한 번만 적게 된다.

```html
<div>
    <span th:text="${member.name}"></span>
    <span th:text="${member.age}"></span>
    <span th:text="${member.email}"></span>
</div>
```

```html
<div th:object="${member}">
    <span th:text="*{name}"></span>
    <span th:text="*{age}"></span>
    <span th:text="*{email}"></span>
</div>
```

<br/>

`member` 를 세 번 안 쓴다.

<br/>

## 섞어 쓸 수도 있다

```html
<div th:object="${member}">
    <span th:text="*{name}"></span>
    <span th:text="${today}"></span>       <!-- 선택된 객체 밖의 값 -->
</div>
```

<br/>

`*{...}` 는 선택된 객체 안에서 찾고, `${...}` 는 모델 전체에서 찾는다.

<br/>

`th:object` 가 없는 곳에서 `*{...}` 를 쓰면 `${...}` 와 같아진다.

<br/>

## 진짜 쓸모는 폼에서 나온다

```html
<form th:object="${itemForm}" method="post">
    <input type="text" th:field="*{itemName}">
    <input type="text" th:field="*{price}">
</form>
```

<br/>

`th:field` 는 `th:object` 가 있어야 제대로 동작한다.

<br/>

`th:field="*{itemName}"` 하나가 세 가지를 한 번에 만든다.

```html
<input type="text" id="itemName" name="itemName" value="기존값">
```

<br/>

`id`, `name`, `value` 를 알아서 채우는 것이다.

<br/>

앞의 입력 폼 처리 글에서 다루는 그 동작이다.

<br/>

## 검증 오류와도 이어진다

```html
<input type="text" th:field="*{price}"
       th:errorclass="field-error">
<div th:errors="*{price}">오류 메시지</div>
```

<br/>

앞의 Validation 글에서 본 `BindingResult` 의 내용을 여기서 꺼내는 것이다.

<br/>

`th:errors` 는 오류가 없으면 태그 자체가 안 그려진다.

`th:if` 를 따로 안 써도 되는 것이다.

<br/>

`th:errorclass` 는 오류가 있을 때만 클래스를 붙인다.

<br/>

## th:object 에 넣는 것은 모델의 이름이다

```java
@GetMapping("/items/new")
public String form(@ModelAttribute ItemForm itemForm) {
    return "items/form";
}
```

<br/>

앞의 특별한 @ModelAttribute 사용법 글에서 본 대로,

`@ModelAttribute` 를 붙이면 모델에 `itemForm` 이라는 이름으로 담긴다.

<br/>

그래서 화면에서 `${itemForm}` 으로 꺼낼 수 있는 것이다.

<br/>

`GET` 요청에서도 `@ModelAttribute` 를 붙이는 이유가 이것이다.

빈 객체라도 모델에 있어야 `th:object` 가 동작한다.

<br/>

없으면 이런 오류가 난다.

```java
Neither BindingResult nor plain target object for bean name 'itemForm'
available as request attribute
```

<br/>

`th:field` 를 쓰려면 `BindingResult` 나 대상 객체가 있어야 한다는 뜻이다.

<br/>

## 중첩된 객체에도 쓸 수 있다

```html
<div th:object="${order}">
    <span th:text="*{orderName}"></span>

    <div th:object="*{address}">           <!-- 안으로 한 단계 더 -->
        <span th:text="*{city}"></span>
    </div>
</div>
```

<br/>

안쪽 `th:object` 에서 `*{address}` 를 쓴 게 눈에 띈다.

바깥에서 선택된 객체를 기준으로 다시 선택하는 것이다.

<br/>

폼에서도 된다.

```html
<input type="text" th:field="*{address.city}">
```

```html
<input type="text" id="address.city" name="address.city">
```

<br/>

앞의 HTTP 요청 파라미터 - @ModelAttribute 글에서 본

점 표기로 중첩 객체를 채우는 그 규칙과 정확히 맞물린다.

<br/>

화면이 만드는 `name` 과 서버가 읽는 규칙이 같아야 하니 당연한 것이다.
