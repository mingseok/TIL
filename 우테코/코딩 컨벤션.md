## 값을 하드 코딩하지 않는다

문자열, 숫자 등의 값을 하드 코딩하지 마라. 

![이미지](/programming/img/입문445.PNG)

즉, 노란색 부분처럼 하드코딩하면 되지 않는다는 것이다.

- `for(int i = 0)` -> `for(int index = START_MAKE)` 이런 느낌인 것이다.

- 매직넘버 사용하기.

```java
private static final String SUCCESS = "O";
private static final String FAILURE = "X";
```

이런식으로 뽑아서 사용하기.

<br/>


상수(static final)를 만들고 이름을 부여해 이 변수의 역할이 무엇인지 의도를 드러내자. 

```
구글에서 "java 상수"와 같은 키워드로 검색해 상수 구현 방법을 학습하고 적용해보자.
```

## 함수(메서드) 라인에 대한 기준

프로그래밍 요구사항을 보면 함수 15라인으로 제안하는 요구사항이 있다. 

이 기준은 **main()** 함수에도 해당된다. 공백 라인도 한 라인에 해당한다. 

15라인이 넘어간다면 함수 분리를 위한 고민을 한다.

<br/><br/>

## 함수가 한 가지 기능을 하는지 확인하는 기준을 세운다

만약 여러 함수에서 중복되어 사용되는 코드가 있다면 함수 분리를 고민해 본다. 

또한, 함수의 길이를 15라인을 넘어가지 않도록 

구현하며 함수를 분리하는 의식적인 연습을 할 수 있다.

<br/><br/>

## 구현 순서도 코딩 컨벤션이다

클래스는 상수, 멤버 변수, 생성자, 메서드 순으로 작성한다.

```java
class A {
    상수(static final) 또는 클래스 변수

    인스턴스 변수

    생성자

    메서드
}
```

<br/><br/>

## 의미 없는 주석을 달지 않는다

변수 이름, 함수(메서드) 이름을 통해 어떤 의도인지가 드러난다면 굳이 주석을 달지 않는다. 

모든 변수와 함수에 주석을 달기보다 가능하면 이름을 통해 의도를 드러내고, 

의도를 드러내기 힘든 경우 주석을 다는 연습을 한다.

## 궁금증!

```java
"함수가 한 가지 기능을 하는지" 를 어떻게 판단할까
```

앞의 클래스와 메소드의 사용 이유는 글에서 쓴 기준이 실용적이다.

`이 메서드가 하는 일을 한 문장으로 말해보고, ~하고 가 몇 번 나오는지 센다.`

```java
void order(Long memberId, Long itemId, int count) {
    Member member = memberRepository.findById(memberId).orElseThrow();
    Item item = itemRepository.findById(itemId).orElseThrow();

    if (item.getStock() < count) {
        throw new IllegalStateException("재고 부족");
    }
    item.setStock(item.getStock() - count);

    int price = item.getPrice() * count;
    if (member.getGrade() == Grade.VIP) {
        price = price * 90 / 100;
    }

    orderRepository.save(new Order(member, item, count, price));
}
```

<br/>

`조회하고, 재고 확인하고, 재고 줄이고, 할인 계산하고, 저장한다`

`~하고` 가 네 번 나온다. 나눌 때가 된 것이다.

<br/>

```java
void order(Long memberId, Long itemId, int count) {
    Member member = findMember(memberId);
    Item item = findItem(itemId);

    item.removeStock(count);
    int price = calculatePrice(member, item, count);

    orderRepository.save(new Order(member, item, count, price));
}
```

<br/>

`조회하고, 재고를 줄이고, 가격을 계산해서, 저장한다` 로 줄었다.

각 단계가 무엇을 하는지는 이름이 알려주고, 어떻게 하는지가 궁금할 때만 들어가면 된다.

<br/>

## 들여쓰기 깊이도 좋은 신호다

앞의 객체지향 생활 체조 글의 첫 번째 규칙이 이것이다.

```java
for (...) {
    if (...) {
        for (...) {          // 여기까지 오면 대개 문제가 있다
            if (...) {
```

<br/>

깊어지는 이유는 대개 둘이다.

```java
한 메서드가 여러 일을 한다      -> 나눈다
조건을 뒤에서 걸러내고 있다      -> 앞에서 빠져나간다
```

<br/>

두 번째는 이렇게 바꾼다.

```java
// 뒤에서 걸러낸다
if (member != null) {
    if (member.isActive()) {
        // 진짜 로직
    }
}

// 앞에서 빠져나간다
if (member == null) return;
if (!member.isActive()) return;
// 진짜 로직
```

<br/>

이것을 `early return` 이라고 한다.

들여쓰기가 한 단계로 줄고, 진짜 로직이 왼쪽 끝에 오게 된다.

<br/>

## else 를 안 쓰는 것도 같은 얘기다

```java
// else 를 쓰면
String grade;
if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";
} else {
    grade = "C";
}

// 바로 반환하면
if (score >= 90) return "A";
if (score >= 80) return "B";
return "C";
```

<br/>

변수를 미리 만들어두고 나중에 채우는 구조가 사라진다.

앞의 BE 코드 작성 컨벤션에서 본 `의미 없는 기본값으로 초기화 후 덮어쓰는 구조를 피한다` 와 같은 얘기다.

<br/>

## 하드 코딩을 상수로 빼는 기준

무조건 빼는 것이 답은 아니다.

```java
if (money < 1000) { ... }                    // 1000 이 무엇인지 모른다
if (money < LOTTO_PRICE) { ... }             // 의미가 드러난다

for (int i = 0; i < 3; i++) { ... }          // 이 3 은 굳이 상수로 뺄 이유가 없다
```

<br/>

판단 기준은 `그 숫자가 바뀔 수 있는가` 와 `이름이 없으면 뜻을 모르는가` 다.

<br/>

같은 값이 두 군데 이상 나오면 무조건 빼는 것이 맞다.

한 군데만 고치고 다른 데를 놓치는 사고가 나기 때문이다.

<br/>

## 공백 라인의 기준

원문의 `의미 있게 사용한다` 를 구체화하면 이렇다.

```java
문단을 나눌 때 한 줄       - 조회하는 부분과 계산하는 부분 사이
연속된 두 줄은 쓰지 않는다  - 한 줄이면 충분하다
메서드 첫 줄과 마지막 줄에는 넣지 않는다
```

<br/>

공백이 많으면 한 화면에 보이는 코드가 줄어든다.

앞의 코드를 보려고 스크롤을 올려야 하면 그만큼 읽기 어려워진다.

<br/>

## IDE 설정을 맞추는 것이 실제로 중요하다

원문의 `space 와 tab 을 혼용하지 않는다` 가 협업에서 크게 걸린다.

<br/>

서로 다른 설정으로 저장하면, 코드는 한 줄도 안 고쳤는데 파일 전체가 바뀐 것으로 나온다.

```bash
git diff
-    return name;
+	return name;          # 탭과 공백만 다르다
```

<br/>

리뷰할 때 진짜 변경이 이 노이즈에 묻힌다.

<br/>

그래서 `.editorconfig` 를 프로젝트에 두고 팀 전체가 같은 설정을 쓰게 한다.

```
[*.java]
indent_style = space
indent_size = 4
end_of_line = lf
insert_final_newline = true
```

<br/>

`end_of_line` 도 중요하다. 윈도우와 맥이 줄바꿈 문자를 다르게 써서, 이것도 전체 변경으로 잡힌다.
